## 5. 代理自述「规避掉的坑」（逐字要点）

1. **`nodeToJson` / `readJson` 会把 null 变成 `"[]"`**。`treeConfig`/`builderConfig` 若直接套用，源库 NULL 会被写成空数组 —— AC-1 要求逐字节相等，`NULL` vs `[]` 直接不等。两端都改走「源空则保持 null」。
2. **`bomRecursiveExpand` 用 `if (it.xxx != null)` 而不是 `if (Boolean.TRUE.equals(...))`**。包里的 `false` 是**有效值**，用真假判会把源库显式的 `false` 当成「没带」去猜，猜错方向刚好和 AC-3 的计数断言撞上。
3. **`assertTreeTokenGatesFor` 不能直接放进导入循环** —— 它内部走单点入口 `isTreeTab`，N 个组件 = N 次查库，正是 AC-13 要抓的东西。
4. **没把 `bundleVersion` 概念塞进 `ComponentService`** —— 那会把导入的职责漏进配置期。改成导入端算好提示串、`ComponentService` 只拼接。
5. **没复制一份坐标解析** —— `TabSemanticResolver` javadoc 明确警告「各写一份必然漂移」。
6. **`Map.of(id, null)` 会 NPE**（不接受 null 值），改用 `LinkedHashMap`。
7. **测试夹具自伤**：一度把 `status="INACTIVE"` 和 `tree_ref` 放进同一夹具导致红。查清是 `builderSemantics` 的查询带 `status='ACTIVE'` 过滤 ⇒ **INACTIVE 的 builder 视图不参与树身份判定**（既有行为，本次未改）。**没有去改生产代码迁就夹具**，改的是夹具。
9. **临时服务只调只读端点** —— 8199 用默认 profile 连的是共享开发库 `cpq_db_0724`，只跑 export / import **预览**，**没跑 commit**，不往共享库写组件。
