## 1. 测试策略

### 核心手法：同库跨目录往返（不需要第二台电脑）

本任务验的是「导出再导入是否保真」。用**同一个库的两个目录**做往返，等价于跨机器搬运，且完全可自动化：

```
现有目录（只读源）──导出──▶ 包 A ──导入──▶ 自建目录 M（"我的源"）
                                              │
                                    在 M 上造齐所有需要的字段形态
                                              │
                                    ──导出──▶ 包 B ──导入──▶ 自建目录 N
                                              │
                                    ◀── 逐字段比对 M vs N ──▶
```

**为什么绕一道目录 M，而不直接拿现有目录当源**：

AC-4（`tree_config`）和 AC-5（视图 `status='INACTIVE'`）在现网**没有样本**（实查：`tree_config` 非空 0 个、非 ACTIVE 视图 0 个），必须造数。
🚫 **不许在现有共享目录上改数据造样本** —— 那是共享写入面，会污染别人的环境，也让本片无法归为"私有写"。
✅ 先把现有目录**只读导入**成自己的副本 M，在 M 上随便改，全程私有。

### 🚨 两条必须先破的假绿

| 风险 | 为什么会假绿 | 破法 |
|---|---|---|
| **AC-8 空跑** | 实查全库 ACTIVE 组件含 `tree_ref`/`tree_attr` 的为 **0 个** —— 不造数的话，「树公式能导入」这条断言**没有输入**，用例照样绿 | 在目录 M 的 builder 树页签组件上**手工加一条含 `tree_ref` 的公式**，并**先断言这条公式确实存在**再验导入 |
| **AC-7 恒绿** | 反射契约测试如果白名单写宽了，它永远不会红，也就永远拦不住新增列 | **做还原实验**：临时给 `Component` 加一个字段 `foo` → 断言测试**变红**；删掉 → 断言恢复绿。**只跑"当前是绿的"不算验证** |

> 📌 第二条是 `CLAUDE.md` 记载的教训：「自己写的验证脚本首次 PASS 也可能是空验证 —— 必须做还原实验」。
> AC-7 验的是一个**防御机制**，而防御机制最典型的失效形态就是"它其实从来不会触发"。

### 比对手法：SQL 差集，不是人工逐项看

AC-6 的「全字段一致」用一条 SQL 表达，**差异行数必须为 0**：

```sql
-- 骨架（实现时按白名单补全列清单）
WITH m AS (SELECT code, name, component_type, column_count, data_driver_path,
                  tab_type, part_no_field, part_name_field, sort_field,
                  row_key_fields::text, fields::text, formulas::text, excel_columns::text,
                  tree_config::text, bom_recursive_expand,
                  element_code_field, element_price_field, element_currency_field, status
             FROM component WHERE directory_id = :dirM AND status='ACTIVE'),
     n AS (SELECT /* 同样的列 */ FROM component WHERE directory_id = :dirN AND status='ACTIVE')
SELECT COALESCE(m.code, n.code) AS code, 'DIFF' AS flag
  FROM m FULL JOIN n USING (code)
 WHERE m IS DISTINCT FROM n;
-- 期望：0 行
```

⚠️ **必须用 `IS DISTINCT FROM` 而不是 `<>`** —— `<>` 遇 NULL 返回 NULL 而非 true，两边都是 NULL 的差异会被**静默漏掉**，而"NULL 被写成空串"恰好是本任务要防的一类丢失（见 AC-2 的断言要求）。

⚠️ JSONB 列比对用 `::text`：AC-14 要求二次往返**逐字节相等**，`jsonb` 的等值比较会忽略键序，掩盖"导入时被重排"这类问题。

### S-全局 · 串行殿后（🚫 不与任何片并行）

| 项 | 内容 |
|---|---|
| **认领** | AC-8, AC-15 |
| **为什么是全局** | 两条都要**保存组件 / 保存取数配置器**。这两个动作的副作用面未查清 —— 已知取数配置器保存会触发**视图重编译，而重编译是全量的**（`CLAUDE.md` 记载：`recompileViews=98`）。按 `testing.md §4.5`「拿不准一律归 `S-全局`」处理 |
| **会动的全局状态** | ① 组件保存可能刷新组件快照；② 配置器保存触发**全量视图重编译**（影响全库所有 builder 视图的编译产物） |
| **还原要求** | `finally` 里删除自己建的组件与目录。⚠️ **视图重编译无法"还原"** —— 这正是它必须串行殿后的原因 |
| **解锁条件** | **S-A 与 S-B 全部跑完之后**才开跑 |

🚫 **一律不许清库、不许 `TRUNCATE`、不许 `DROP`**（`CLAUDE.md §3.2` 环境销毁红线，测试也算，写在 `beforeAll` 里也算）。
