## 2.1 组件模型

一份客户模板（`页签——<客户>.xls` 或 `组件模板 - <客户>.xlsx`）到 CPQ 组件配置的映射：

- **每个 sheet（页签）= 一个组件**（`component`，`componentType=NORMAL`；小计性质的 sheet 建 `SUBTOTAL`）。
- **每个列（表头字段）= 一个字段**（`fields[]` 里一项）。
- **每个组件配一个组件 SQL 视图**（`component_sql_view`，`$name`）当取数源；多行组件用它当 `data_driver_path` 驱动（见 `3-SQL视图.md`）。
- **模板目录 = 客户名称**（`component_directory.name = <客户名>`）。

### component（组件 = 页签）核心列

| 列（JSON 键） | 类型 | 含义 |
|---|---|---|
| `fields` | JSONB | 字段定义数组（每项结构见 §2.2 / §2.3） |
| `formulas` | JSONB | 公式 token 数组（见 `5-公式与Excel列.md §5.1`） |
| `excel_columns` | JSONB | Excel 视图列定义（见 `5-公式与Excel列.md §5.3`） |
| `data_driver_path` | text | 多行 driver 数据源；本项目一律 `$<sql_view_name>`（见 `3-SQL视图.md §3.1`），禁直引 V44 废弃表（AP-53） |
| `component_type` | enum | `NORMAL`（普通页签）/ `SUBTOTAL`（小计，无字段无 driver）/ `EXCEL` |
| `row_key_fields` | JSONB | 多行组件行唯一键（值 = 字段名，见 §2.4） |
| `tab_type` | text | 页签类型（`BOM`/`材质元素`/`零件`/`外购件`/`主件`，见 `4-页签属性与树.md §4.1`） |
| `part_no_field` | text | 料号列字段名（该组件某 `fields[].name`）。**可空**——客户模板无料号列时留空，由 `part_name_field` 担标识、料号只进 SQL JOIN；有料号列时绑值按语义层级。见 `1-总则与工作流.md §1.3` |
| `part_name_field` | text | 料号名称列字段名，可空 |
| `sort_field` | text | 多行页签数字感知升序字段（见 `4-页签属性与树.md §4.2`） |

### component_directory（目录 = 一套模板的组件容器）

- 一个客户一个目录，`name = <客户名>`。
- 目录导出（`GET /component-directories/{dirId}/export`）产出可复用 bundle JSON（含各组件 `fields`/`formulas`/`dataDriverPath`/`rowKeyFields` + 各组件 SQL 视图 + 依赖清单 + checksum）。交付方式见 `1-总则与工作流.md §1.4`。

### template + template_component（模板引用组件，不复制结构）

- 模板通过 `template_component` 关联表**引用**组件，**不复制**其结构。
- **H1 组件保存自动同步**（`C7`）：`ComponentService.update` 成功后自动调 `TemplateService.refreshSnapshotsByComponent`，所有引用该组件的 `template.components_snapshot` 立即刷新——改字段后**不需手工 SQL 改 snapshot**，报价单立即生效。
  - **例外**：手工 SQL 直 `UPDATE component SET fields=...` 绕过 service 不触发同步，须调 `POST /api/cpq/components/{id}/refresh-template-snapshots`（PRICING_MANAGER+）或批量 `POST /api/cpq/config-center/refresh-all-snapshots`（SYSTEM_ADMIN）。
- 已发布报价单不动（snapshot 冻结）；DRAFT 实时。

## 2.2 字段类型 field_type

「组件管理」→ 编辑组件 → 字段配置表（`FieldConfigTable`）。每个字段由 `field_type` 决定行为，「内容/配置」列按类型动态切换 UI。

**字段配置表列**：

| 列 | 说明 |
|---|---|
| 字段名 | `name` — 同时作为公式 token 的引用 key（`{"type":"field","value":"<name>"}`）；作 `rowKeyFields` 引用键 |
| 字段类型 | `field_type` — 见下 |
| 内容/配置 | 按类型动态：固定值框 / 路径徽章 / 数据源按钮 / 默认值来源 / 公式提示 |
| 金额 | `is_amount` — 渲染按货币格式化（见 §2.3） |
| 小计 | `is_subtotal` — 公式聚合用；**可多个**，每个被标记字段各算一列总计 |
| 备注 | `notes` — 配置者留言，渲染不展示 |

### 全集（后端 `ComponentService.VALID_FIELD_TYPES`，C1）

> **C1**：`field_type` 必须 ∈ `{FIXED_VALUE, INPUT_TEXT, INPUT_NUMBER, BASIC_DATA, DATA_SOURCE, FORMULA, LIST_FORMULA}`（前端 `types.ts` 的 `FIELD_TYPE_OPTIONS` 暴露这 7 种；另有 legacy `INPUT` 仅兼容旧数据，不在 UI 出现）。

| field_type | 数据来源 | UI 渲染 | 关键 JSON 字段 |
|---|---|---|---|
| `FIXED_VALUE` | 字面量 | 只读单元格 | `content`（`is_amount=true` 时 `content` 必须数字字面量） |
| `INPUT_TEXT` | 用户输入（文本） | 文本输入框 | `content`、`default_source` |
| `INPUT_NUMBER` | 用户输入（数字） | 数字输入框 | `content`、`default_source` |
| `BASIC_DATA` | BNF 路径查物理表/视图/SQL 视图 | 只读单元格 | `basic_data_path`、`global_variable_code`（只查不算，不写表达式） |
| `DATA_SOURCE` | 4 种数据源（DATABASE_QUERY / GLOBAL_VARIABLE / BNF_PATH / HTTP_API） | 只读 / 下拉 | `datasource_binding.{type,...}` |
| `FORMULA` | 公式引擎计算 | 计算结果只读 | `formula_tokens`（见 `5-公式与Excel列.md`） |
| `LIST_FORMULA` | 配置模板列表 × 逐项条件分支公式 | 列驱动多行 | `list_formula_config`（AP-37 联动，见 `5-公式与Excel列.md §5.2`） |

### 本项目判定规则（R1：统一 `INPUT_*` + `default_source` 绑基础数据）

> **R1**：**字段统一用 `INPUT_TEXT`（文本栏位）/ `INPUT_NUMBER`（数字栏位）+ `default_source` 绑基础数据**。不用只读 `BASIC_DATA`。连主键/标识字段（销售料号/元素/项次）也是 `INPUT_*`。列语义是文本→`INPUT_TEXT`，是量/率/金额→`INPUT_NUMBER`。

| 类型 | 用途 | 判定 |
|---|---|---|
| `INPUT_TEXT` | 标识 / 名称 / 单位 / 货币 / 料号 | 文本语义 |
| `INPUT_NUMBER` | 量 / 率 / 金额 / 厚度 / 汇率 | 数字语义；金额加 `is_amount=true`（`content="0"`，汇率 `content="1"`） |
| `LIST_FORMULA` | 列表 × 逐项条件分支公式 | 绑配置模板；改此类型跨 AP-44 联动，详见 `5-公式与Excel列.md §5.2` |
| `FORMULA` | 行内公式列 | `formula_tokens` 指向公式，详见 `5-公式与Excel列.md §5.1` |

`INPUT_TEXT`/`INPUT_NUMBER` 是报价单可编辑单元格，核心能力是 `default_source` 默认值机制（见 §2.3）。

## 2.3 default_source 绑定

### 字段结构（`fields[]` 一项）

```jsonc
{
  "name": "销售料号",             // 中文业务名，不带 _（R5）；作 rowKeyFields 引用键
  "field_type": "INPUT_TEXT",     // 文本→INPUT_TEXT，数值→INPUT_NUMBER（R1）
  "content": "",                  // 静态兜底值（数字列可填 "0"/"100"，汇率 "1"）
  "is_amount": false,             // 金额列 true（R6）
  "is_subtotal": false,           // 需被「小计」聚合的列 true
  "notes": "",
  "sort_order": 0,                // 列序，按模板列顺序
  "default_source": {             // 绑基础数据（R1）
    "path": "$cp_view._销售料号", // $视图._列（R4：列带 _；hf_part_no 除外）
    "type": "BASIC_DATA"
  }
}
```

### default_source.type 取值

| type | 形态 | 说明 |
|---|---|---|
| `BASIC_DATA` | `{"path":"$view._列","type":"BASIC_DATA"}` | 支持中文列，本项目主用 |
| `BNF_PATH` | `{"bnf_path":"表[谓词].列"}` | 物理路径 |
| `GLOBAL_VARIABLE` | `{"code":"CODE","key_field_refs":{}}` | 全局变量 |

### 运行期取值三级兜底

`用户输入 row[key] → default_source（解析 $view._列）→ content 静态兜底 → 0`。用户在报价单改的值只活在当前草稿，不回写基础数据。

- **无源字段（销售手填）**：不给 `default_source`，`content` 给默认（如「报价」列无源，销售手填，`content="0"`）。
- **C6 后端不强校验 `default_source`**（仅 `warnDefaultSourcePaths` 软告警列名）——路径写错不报错，但运行期取不到默认值，需自查。

### is_amount（金额，R6）

> **R6**：**金额性质字段标 `is_amount=true`**（费用/单价/金额类）。否则 footer 小计行不带 `¥`、不走货币格式化。

> 💰 **金额字段配置通则（2026-06-18）**：凡**金额性质**的字段（费用 / 金额 / 单价 / 金额类小计等），配置时**必须标 `is_amount=true`**，否则报价/核价表 footer 小计行不显示 `¥` 前缀、且单元格不走货币格式化。footer **严格按 `field.is_amount === true`** 决定是否加 `¥`，与 `is_subtotal` 无关（小计列不会"默认带 ¥"）。这是**按字段语义判断的通则**，由配置者对当前模板里**实际存在**的金额字段逐一判断标注，**不针对任何具体字段名/具体模板**。

### is_subtotal（小计聚合）

需被「小计」聚合的列标 `true`；**可多个**，每个被标记字段各算一列总计。小计组件（`componentType=SUBTOTAL`）本身无字段、无 driver、无 SQL 视图，靠公式 `component_subtotal` token 引用各 NORMAL 组件的 `is_subtotal` 列（见 `5-公式与Excel列.md`）。

## 2.4 rowKeyFields（行键）

多行可编辑组件的行唯一键。**因 R1 统一用 `INPUT_*`，凡多行组件都命中「可编辑」→ 都要 `rowKeyFields`**。

> **C2**：**多行 driver（`data_driver_path` 非空）+ 任一可编辑字段（`INPUT_TEXT/INPUT_NUMBER/LIST_FORMULA`）→ 必须声明 `rowKeyFields`**，否则**新建时抛异常**（`ComponentService.validateRowKeyConfig(hard=true)`）。

> **C3**：`rowKeyFields` 存**字段名**（如 `["项次","元素"]`），不是 SQL 列名；无稳定键用哨兵 `["__seq_no__"]` 按行号对齐。

- **值 = `fields[].name`**（中文原名，不带 `_`），不是 SQL 列名（field name 命名空间）。
- **撞键 = editRows 塌缩**：行键值空/重复 → 可编辑行 editRows 串行 / 末值×行数塌缩。唯一化加 `#序号`（前后端一致；存量须回填料件值，见 `docs/反模式.md` 行键唯一化 / 记忆 `cpq-rowkey-uniqueness-disambiguation`）。
- **一号多材质：材质字段必须进 `rowKeyFields`**。

> 🚨 **「一号多材质」铁律**（2026-07-16 森萨塔 QT-20260716-2046 事故沉淀）：**一个销售料号在同一客户下可合法对应多个 `material_part_no`**（多材质链）。「材质」必须逐行取自本行 `material_part_no`。**🔑「材质」字段必须进 `rowKeyFields`**（如 `["销售料号","元素","材质"]`）。否则多材质链下 `(项次,元素)` 撞键 → 可编辑行 editRows 串行 / 末值×行数塌缩。这是纯改视图 SQL **不够**、必须连组件 `rowKeyFields` 一起改的点。数据取数 SQL 见 `3-SQL视图.md` / `报价侧.md` 材料成本配方。

**本项目行键范例**：产品 `["销售料号"]`；材料成本 `["销售料号","元素","材质"]`；成品其他费用 / 加工费 `["销售料号","项次","要素名称"]`（无销售料号列的加工费模板用 `["项次","工序"]`）；电镀费（行转列后每料号一行）`["销售料号"]`；外购件成本 `["销售料号","组成件料号"]`，**模板无料号列时** `["销售料号","组成件名称"]`。

> 🚫 **行键只能用模板实有字段**：不得为了做行键而新增模板没有的料号列（同 `1-总则与工作流.md §1.3.1`）。代价是名称类行键遇同名多行会撞键——真遇到再找用户确认是否把料号列显出来，别自作主张加列。

## 2.5 `_` 前缀别名铁律

> **R4**：**所有 SQL 列别名加 `_` 前缀**（如 `_销售料号` / `_材质` / `_元素`）。目的：业务列不被隐式 JOIN 误当谓词注入。字段 `default_source.path` 对应写 `$view._列`。

> **R4-例外**：**`hf_part_no` 是唯一不带 `_` 的别名**。它是驱动键，隐式 JOIN 专门注入它做料号收窄；改名（如 `_hf_part_no`）会让视图返全表。

> **R5**：**字段名（`name`）保持中文业务原名，不带 `_`**。`_` 只加在 SQL 列别名 + `default_source.path` 上；字段显示名不变（如字段名 `损耗率%` 绑 `$mc_view._损耗率`）。

一句话：**字段 `name`（中文，不带 `_`）↔ SQL 列别名（`_` 前缀）↔ `default_source.path`（`$view._列`）三者对齐；唯 `hf_part_no` 全链不带 `_`**。`hf_part_no` 驱动键 + 隐式 JOIN 机制详见 `3-SQL视图.md §3.2`。

## 2.6 字段类型切换清理矩阵（§3.5）

UI 切 `field_type` 时自动清理冲突字段（就地修改，老 JSON 残留字段不影响业务但占体积）：

| 切换 | 自动清理 | 保留 |
|---|---|---|
| `INPUT_*` → `BASIC_DATA` / `DATA_SOURCE` | `default_source` / `content` | `name` / `notes` |
| `BASIC_DATA` → `DATA_SOURCE` | `basic_data_path` / `global_variable_code` | `name` / `notes` |
| `DATA_SOURCE` 内 `type` 切换 | 切走类型的配置（`datasource_id` / `bnf_path`…） | `type` 公用字段 |
| 任何 → `FORMULA` | 数据来源相关字段 | `name` / `notes` / `is_amount` / `is_subtotal` |

> ⚠️ **改 `field_type` / 新增枚举是特殊场景**：跨约 17 个协议检查点强联动（AP-44），漏一处必静默失败。详见 `5-公式与Excel列.md §5.2 字段类型联动协议`。本节的自动清理只处理**单字段就地字段冲突**，不覆盖 AP-44 的渲染/缓存/后端白名单等跨文件传播点。
