## 契约要点

核价侧与报价侧同一套组件/字段/SQL 视图机制，差异集中在**四个维度**：客户口径、料号键、版本、渲染服务。

- **客户口径 = 全局成本口径（无 `:customerCode`）**：核价是成本视角，不分客户；元素 / 子配件 / BOM 定价一律用 `_GLOBAL_`（`element_bom_item` / `material_bom_item` 的 PRICING 行 `customer_no='_GLOBAL_'`）。
  - 页签 `$view` 的 `WHERE` **禁加 `customer_no=:customerCode`**——执行器只注入料号数组，不注入客户上下文；客户过滤在核价侧无意义。分区条件（`system_type='PRICING'` / `customer_no='_GLOBAL_'` / `is_current`）由每条 SQL **自己写死**。
  - 报价与核价的元素单价**可以不同 = 预期特性**（两条价格线各取各的口径）。

- **料号键 = 销售料号 + JOIN `material_master` 桥接生产料号（part-key）**：核价基础资料以销售料号为主轴，需要生产料号时通过 `material_master` 桥接。递归树的 seed 是**生产料号**（`:production_part_nos`），页签取数用**销售料号 = 树料号并集**（`:total_material_no`）。

- **版本 = `:versionFilter` 宏，每 sheet 独立可切换**：
  - 每个 sheet（页签）独立版本，视图带 `view_version` 约定列，用 `:versionFilter` 宏收窄。
  - **仅 PENDING 状态可切换**版本；报价侧 frozen（冻结）不受影响。
  - 版本切换落 `override` 表 + `costing_render` / `costing_total_amount` 新列（详见 §版本切换）。

- **渲染服务**：`CardSnapshotService`（整份卡片快照）+ `BomTreeRenderService`（树骨架建树）；模板挂 `costingCardTemplateId`。

- **元素单价接价格策略 · 核价变体**（task-0722，来源 `docs/rule/报价模板生成规则.md §5.2.1`；**模板里该字段勾「接价格策略」即声明**，完整 7 硬约束见共性 `5-公式与Excel列.md` / 该源节）：
  - 驱动视图加（🔴 **2026-08-01 V369 起用 `f_material_element_price`**，核价侧的 `wl_ys_bom_view` 已随迁移切换；旧的 `f_customer_element_price` 降级为其内部 fallback，照抄旧写法会静默吃不到价格版本 —— 见 `报价侧.md §5.2.2`）：
    ```sql

      ON cep.element_code = ebi.component_no
     AND cep.material_no = <本视图 hf_part_no 的输出表达式，逐字照抄；wl_ys_bom_view 是平铺形态>
    ```

  - **传字面量 `'_GLOBAL_'`**（非 `:customerCode`）；`required_variables` 仅 `["priceBaseDate"]`，**不含 customerCode**。
  - **JOIN 键 = 元素符号 `component_no`**（非元素编号）；**必 `LEFT JOIN`**（禁 INNER，无价元素否则掉行）；**禁 `COALESCE(...,0)`**（无价留 NULL 手填）；**不绑「计价单位」**（那是 BOM 发料单位）；`:priceBaseDate` 后端自动注入（=报价单创建日）。

## §树主轴（核价核心）

**核价树 = 全局一条递归 SQL（产结构）+ 每个页签自己的 `$view`（产数据）**，后端按 `material_no` 把数据分配到各卡片、按 `node_path` 拼成树。物料 BOM = 核价树；每个核价组件出**整棵 spine**（缺数据补空行），**以 spine 为行主轴（非业务 row）**。

**执行次数 = 1（递归）+ N（模板页签数），与卡片数、树节点数无关。**

### 递归树 SQL（`costing_bom_tree_config`，usage=COSTING）

- **在哪配**：组件管理 → [核价树配置] 页签 → 新增 → 保存（dry-run 校验）→ **设为生效**（全局唯一，同一时刻只有一条生效）。
- **契约（逐字）**：
  - 输入变量 `:production_part_nos`（`text[]` = 本单所有生产料号），必须引用（+ `versionFilter` 宏收窄 BOM 版本）。
  - 输出 **5 列，列名逐字**：`root_no`（根生产料号，分组用）/ `material_no`（当前料号，显示）/ `bom_version`（当前料号自身版本，叶子可空）/ `parent_no`（上级料号，仅显示）/ `node_path`（节点物化路径，**建树结构的唯一真理源**）。少一列或拼错 → dry-run 拦（返 500「缺输出列: xxx」）。
- **硬规则**：
  1. **只认核价分区**：`system_type='PRICING'` + `customer_no='_GLOBAL_'` + `is_current=true`；不满足只出根一行。
  2. **展开方向**：`material_bom_item` 里 `material_no`=父、`component_no`=子；递归 `JOIN ... ON child.material_no = parent.material_no`，当前节点取 `component_no`。
  3. **`node_path` 每节点唯一**：根 = 单段（料号本身）；子 = 父路径 `|| '/' ||` 子料号。同一料号挂多父 → 不同路径 → 不同节点（多 occurrence 保留），各自子件按各自路径精确归位不挂错枝。
  4. **段内不含分隔符 `/`**（后端按最后一个 `/` 切父）。料号本系统是数字，安全；若将来含 `/`，路径段换边代理键（如 `ch.id`）。
  5. **全列 `::text`**：含 `CYCLE` 时循环列（`material_no`）seed 与递归分支类型须一致，否则报 `cannot compare dissimilar column types`；统一加 `::text` 最省事。
  6. **结尾无分号 `;`**：后端会包成 `SELECT * FROM (<你的SQL>) q ...`，尾分号 → 语法错（500）。
  7. **成环保护**：`CYCLE material_no SET is_cyc USING cyc_path` 切真环，不影响多父多 occurrence。

- **完整示例（真库跑通，直接可用）**：
  ```sql
  WITH RECURSIVE bom AS (
    -- 种子:每个生产料号 = 根节点(node_path 单段)
    SELECT
      p::text                                        AS root_no,
      p::text                                        AS material_no,
      (SELECT bv.bom_version::text
         FROM material_bom_item bv
        WHERE bv.material_no = p
          AND bv.customer_no = '_GLOBAL_'
          AND bv.system_type = 'PRICING'
          AND bv.is_current  = true
        LIMIT 1)                                     AS bom_version,   -- 根自身当前 BOM 版本
      NULL::text                                     AS parent_no,     -- 根无上级
      p::text                                        AS node_path      -- 根 = 单段
    FROM unnest(:production_part_nos) AS p

    UNION ALL

    -- 递归:material_no(父) → component_no(子)
    SELECT
      b.root_no,
      ch.component_no::text                          AS material_no,   -- 当前料号 = 子件
      (SELECT bv.bom_version::text
         FROM material_bom_item bv
        WHERE bv.material_no = ch.component_no
          AND bv.customer_no = '_GLOBAL_'
          AND bv.system_type = 'PRICING'
          AND bv.is_current  = true
        LIMIT 1)                                     AS bom_version,   -- 子件自身当前 BOM 版本(叶子→NULL)
      ch.material_no::text                           AS parent_no,     -- 上级料号 = 父件
      (b.node_path || '/' || ch.component_no)::text  AS node_path      -- 物化路径累加(每 occurrence 唯一)
    FROM material_bom_item ch
    JOIN bom b ON ch.material_no = b.material_no
    WHERE ch.customer_no  = '_GLOBAL_'
      AND ch.system_type  = 'PRICING'
      AND ch.is_current   = true
      AND ch.component_no IS NOT NULL
  ) CYCLE material_no SET is_cyc USING cyc_path
  SELECT root_no, material_no, bom_version, parent_no, node_path
  FROM bom
  ```

- **后端如何用这 5 列**（理解即可）：`card_material_no[root_no]` = 该 root 下 `distinct(material_no)`（含根）；`total_material_no` = 所有 `material_no` 去重（注入给页签 SQL）；`__nodeId = node_path`、`__parentId = node_path 去最后一段`、`__lvl = 段数`（根 parentId=null、lvl=1）；`parent_no` 仅作显示，结构由 `node_path` 决定。

### 树页签视图（按边键挂数据）

- **一个核价模板最多一个树页签**：组件勾字段 `bomRecursiveExpand`（列 `bom_recursive_expand`，语义 =「该页签渲染为树 + 三系统列」），超过一个保存/渲染前拦截。
- **树页签 `$view` 必须同时输出 `parent_no` + `material_no` 两列**（边键，逐字）——`parent_no`=父件料号、`material_no`=子件料号（当前节点）。后端按 **`(parent_no, material_no)` 边键**精确挂数据（2026-07-03 起）。对 `material_bom_item`：`parent_no = material_no(父)`、`material_no = component_no(子)`。
  - **为什么要 `parent_no`**：BOM 树每个节点的数据是「父→子」边特有的（如用量随父件不同）；仅按 `material_no` 会把同一子件在别父件下的边也挂进本节点 → 重复 / 挂错父。缺 `parent_no` → 退化为只命中根层空父 → 全落空。
- **系统列后端自动注入**（非配置员写）：`__hfPartNo`（=node.material_no）、`__bomVersion`（=node.bom_version）、`__parentNo`、`__nodeId`（=node_path）、`__parentId`（=去尾段）、`__lvl`（=段数）。前端渲染条件 = 核价侧 && 行里有 `__sys.nodeId` → **固定带出「料号 / 版本」两列** + 建树。产品卡片视图与 Excel 视图（`buildLineTreeRows`）共用同一份快照 `__nodeId` 骨架。
- **取料号 SQL 字段规则**：普通页签 `WHERE 料号列 = ANY(:total_material_no)` 且必出 `material_no`；树页签额外必出 `parent_no`。列名 ↔ 字段 `basic_data_path` 逐字一致，否则该格 `#ERROR` / 空。

## §导入口径收敛与数据来源边界（task-0812，2026-08-12）

> **为什么规则文档要写这节**：配组件时你判断「这个字段能不能绑」靠的是「这张表有没有数据」。
> 但**表里有存量数据 ≠ 这张表还在收新数据**。本次停用了 5 个导入 Sheet，几张表就此**只剩存量、不再有增量**——
> 绑上去当场看着正常（存量料号有值），换个新料号就整列空，且**不报错**。这是典型的静默失效，必须落规则。

### 1. 停用清单与落库表

核价基础数据导入的 Sheet 口径：**24 → 20**（已合 master `9477223b`）→ **19**（P03，分支 `feat/task-0812-停用汇率管理表` **在途未合**）。

| 元素核价价格表(P01) | `unit_price` `price_type='ELEMENT'` | **无**（元素价本就该走价格策略，见 §契约要点「元素单价接价格策略」） |
| 材料核价价格表(P02) | `unit_price` `price_type='MATERIAL_PRICE'` | **无** |
| 核价版本(P04) | `material_version_mgmt` | **无**（该表全库亦无读者 = 死表） |
| 宏丰-客户料号对应关系(P05) | `material_master` + `material_customer_map` | **仅报价侧** `Q02客户料号与宏丰料号的关系` |

### 2. 配置时的三条硬规则（本次新增）

- 🚫 **禁止再绑 `unit_price` 取元素价 / 材料价**（`price_type IN ('ELEMENT','MATERIAL_PRICE')`）。这两个桶已无增量，绑了只会拿到停用前的存量。元素单价一律走 `f_material_element_price`（现行）/ `f_customer_element_price`（fallback），规则见 §契约要点。
- 🚫 **禁止绑 `material_version_mgmt` 与 `exchange_rate_v6`**。前者已是死表；后者 P03 合并后同样无写入。核价侧需要汇率时用 `material_customer_map.exchange_rate`（该列由报价侧导入维护，与 `exchange_rate_v6` 是两回事——**别被表名带偏**）。
- ⚠️ **`material_master` 的「品名 / 规格 / 尺寸 / 旧料号」四列，对「只作父件出现的销售料号」已无导入来源**。
  - 实测依据：`P06MaterialBomHandler` 只对**组成料号**回填这三列且 `preserveDescriptive=true`（只补空不覆盖）；**父件行传 null**（源码注释：「本 Sheet 无父件名称列」）；`P24单重` 只写单重与生产料号；报价侧 `Q02` 明确拒绝写品名（注释：客户料号名称属客户维度语义，不是料件品名）。
  - **对配置的影响**：核价侧大量用 `COALESCE(mm.material_name, mr.name)` 取名（外购件 / 电镀 / 材质元素页签都是），对**纯成品料号**可能整列取空。绑这类「名称」字段前，先按 §6 自检第 2 项查一次目标料号的非空率，别只看有存量的老料号。
  - 缺失时的补法：主数据维护页人工录入（`MaterialMasterCrudService` 支持 CRUD）。

### 3. 导入模板里「看着像输入项、其实不读」的列

| 列 | 出现的 Sheet | 真相 |
|---|---|---|
| **取用的计算版本** | 产能 / 设备折旧成本 / 生产设备能耗 / 辅助设备能耗 | **handler 从不读**（全工程零处 `getStr`，只在 `TEMPLATE_HEADERS` 里声明）。`calc_version` 由 `VersionedV6Writer` **系统自增**（2000 起；实测 `capacity` 已到 2042） |
| **取用的耗材版本** | 生产耗材BOM / 包装材料BOM | 同上 |
| 各表的「版本 / 版本编号」列 | 电镀方案 / 电镀成本 等 | 同上，一律忽略，版本由系统按**内容是否变化**决定是否自增 |

> 🚨 **语义错位提醒**：「取用的计算版本」字面像「本行**引用**哪个版本」，但 `calc_version` 实际是「本行**自己是第几版**」，方向相反。
> **推论（做版本相关测试时尤其重要）**：版本号指挥不动，**只有内容真变了才会升版**（`VersionedV6Writer` 用 multisetEqual 判无变化则完全不写库）。
> 想造多版本数据，必须让**每个版本组**在相邻两次导入间都有实质差异，否则导入 N 次也只有 1 个版本。

## 核价侧速查（配完对照）

| 场景 | 硬规则 |
|---|---|
| 客户过滤 | 页签 `$view` **禁 `customer_no=:customerCode`**；一律 `_GLOBAL_`，执行器不注入客户/lineItem 上下文 |
| 递归树 | 5 列逐字（`root_no/material_no/bom_version/parent_no/node_path`）+ 引用 `:production_part_nos` + 全列 `::text` + 无尾分号 + `CYCLE` 防环 |
| `node_path` | 根单段 / 子累加 / 段内无 `/` / 每节点（含多 occurrence）全局唯一 |
| 树页签 | 一模板最多一个；`$view` 必出 `parent_no`+`material_no`（边键） |
| 普通页签 | `$view` 必出 `material_no` + `= ANY(:total_material_no)` |
| 元素单价 | `LEFT JOIN f_customer_element_price('_GLOBAL_', :priceBaseDate) ON element_code=component_no`；required 仅 `priceBaseDate`；禁 COALESCE、禁 INNER |
| 改配置后 | 改递归 SQL / 生效行 / 树勾选 / 页签视图或字段 → **必须重算报价单 + 强刷**（系统列是算快照那一刻烘进去的，不追溯旧单） |
| 存量单 | 硬切换不迁移存量；依赖旧 spineKeys/BomClosureService 的模板打开报错或空，按需清理后按新契约重配 |
| **无增量表**（task-0812） | 🚫 禁绑 `unit_price[price_type IN ('ELEMENT','MATERIAL_PRICE')]` / `material_version_mgmt` / `exchange_rate_v6` —— 只剩存量，新料号必空且不报错。汇率用 `material_customer_map.exchange_rate`（≠ `exchange_rate_v6`） |
| **`mm.material_name` 等描述列** | 对「只作父件的销售料号」已无导入来源（P05 停用）；绑名称类字段前先查目标料号非空率，别只验老料号 |
| **模板版本列** | 「取用的计算版本 / 取用的耗材版本 / 版本编号」**一律不入库**，`calc_version` 系统自增；版本只由「内容是否变化」驱动 |
