## 4.1 tabType / partNoField / partNameField（task-0721）

task-0721（报价侧 BOM 树）给**组件（页签）级**新增 3 个配置项，用于树的类型判定 + 加叶子候选采集：

| 配置（JSON 键 / 请求体 camelCase） | 含义 | 规则（`ComponentService.applyTabType`） |
|---|---|---|
| `tabType` | 页签类型 | `BOM`/`材质元素`/`零件`/`外购件`/`主件`（5 类，非法值 400；可空） |
| `partNoField` | 料号列字段名 | 该组件某字段 `name`，**可空**（客户模板无料号列时留空，见下方 §「模板没有料号列」） |
| `partNameField` | 料号名称列字段名 | 该组件某字段 `name`，可空 |

> 🚩 **`{材质元素,零件,外购件,主件}` 4 类的硬门槛是「`partNoField` 与 `partNameField` 至少配一个」**，不是「必配 `partNoField`」（`ComponentService.assertPartNoFieldRequirement`，2026-07-23 由「必配料号列」放宽——外购件/费用类页签常只有「组成件1」这样的名称列）。两者皆空才 400。

- **`tabType→characteristic`**：材质元素→`RECIPE`、零件→`ASSEMBLY`、外购件→`OUTSOURCED`；主件=成品/树根；`BOM`=树页签。
- `tabType='BOM'` 保存时后端**自动同步 `bomRecursiveExpand=true`**，且若组件已被 COSTING 模板引用会 **400**（组件级全局开关会波及核价，违反零回归）→ **报价侧树页签必须新建专用组件，不得复用核价树组件**。
- 类型判定/候选料号**严格按显式配置取值，禁按字段名启发式猜**：`QuotationTreeService` **优先 `partNoField`（取料号值），为空回落 `partNameField`（取名称值，如「组成件1」）**。
- 费用类页签（成品其他费用等）无物料语义 → `tabType` 留空，不参与树。
- ⚠️ **电镀费/电镀成本是费用类里的例外（repair-0802，2026-08-02）**：两个电镀 sheet 增加了**非必填**的【投入料号】【投入料号名称】列，`unit_price.code` 自此落**投入料号（零件料号）**、`finished_material_no` 落销售料号。模板配了投入料号列时 → `tabType=零件` + `partNoField=投入料号`（绑 `code`，🚫 禁绑销售料号，否则树把成品误判成零件节点）；模板没有该列 → 数据侧 `code` 回退为销售料号，仍按费用页签处理、`tabType` 留空。配置随动细则见 `报价侧.md §5.4 / §7.4`。

### 🚫 模板没有料号列（2026-07-24 用户定，优先于下方绑定值铁律）

**客户模板不显示料号是真实业务场景** → `partNoField` **留空**，由 `partNameField` 承担标识，料号**只在 SQL 里做 JOIN 键**（`AS hf_part_no` 收窄、JOIN 取名称、`ORDER BY` 分组），**不出可见列**。

> **禁止为凑 `partNoField` 而新增模板没有的可见字段**（历史上给材料成本加「材质料号」、给外购件加「组成件料号」的写法**已废止**）——会让报价单多出用户看不懂的空列。
> 代价：行键只能用名称等业务列，同名多行会撞键（editRows 塌缩）；真遇到再找用户确认是否把料号列显出来。完整正文见 `1-总则与工作流.md §1.3.1`。

### 🔑 料号列绑定值铁律（**模板确有料号列时**才适用；完整正文见 `1-总则与工作流.md §1.3.2`）

> 🚨 **料号列绑定值铁律（2026-07-23 用户定）：`partNoField` 绑的列必须是该 `tabType` 语义层级的料号，禁绑成品/主件料号。**
> 树类型判定（`BomNodeTypeResolver`）把每个「有类型」页签的 `partNoField` 取值收集为该类型的候选料号。若零件页签的料号列绑成了**成品料号**，成品的 `material_no` 会出现在零件页签的 `partNoField` → 树把**成品节点误判成零件**。

| `tabType` | 料号列语义 | 应绑的列（V6） |
|---|---|---|
| **主件** | 成品/产品料号 | `material_master.material_no`（产品自身） |
| **材质元素** | 材质料号 | `element_bom_item.material_part_no` |
| **零件** | 组成件料号 | `material_bom_item.component_no`（组成件）；费用类源（`unit_price`）取 **`code`**（该费用项针对的料号），**不是 `finished_material_no`（成品）** |
| **外购件** | 外购组成件料号 | `material_bom_item.component_no`（`characteristic='OUTSOURCED'`） |

> ✅ **`unit_price` 的列语义（2026-07-23 用户澄清）**：`code` = **零件料号**（该费用项针对的零件，如自制加工费=零件的加工费），`finished_material_no` = **成品料号**（该费用上卷到的成品）。故 `unit_price` 源的零件页签**料号列绑 `code`**（非 `finished_material_no`）。二者常同值（零件=成品自身时 `code=finished_material_no=成品`），但语义不同、别处会分叉（零件加工费上卷父成品时 `code`=零件≠`finished_material_no`=父成品）——按**语义**绑 `code`，别按值相等偷懒绑 `finished_material_no`。
> `hf_part_no`（驱动键，隐式 JOIN 按本行项目料号收窄）另说：费用类通常仍绑 `finished_material_no`（按成品收窄本报价行），与料号列绑 `code` 不冲突。

**本项目组件映射（2026-07-24 修订，以「模板有没有料号列」为准）**：

| 组件 | tabType | partNoField | partNameField | 备注 |
|---|---|---|---|---|
| 产品 | 主件 | 销售料号 | 客户料号名称 | 成品/树根；模板本就有销售料号列 |
| 材料成本 | 材质元素 | *(空)*，模板有料号列才配 | 材质 | `element_bom_item.material_part_no` **只作 JOIN 键**（逐行取材质名）+ `ORDER BY` 键；~~加「材质料号」字段~~ 已废止 |
| 外购件成本 | 外购件 | *(空)*，模板有料号列才配 | 组成件名称 | 源 `material_bom_item.characteristic='OUTSOURCED'`；`component_no` **只作取名 JOIN 键**；~~加「组成件料号」字段~~ 已废止 |
| 加工费（零件） | 零件 | 料号（模板确有此列） | 料件 | 绑 `unit_price.code`（零件料号），`hf_part_no` 另绑 `finished_material_no` |
| 成品其他费用 | *(空)* | — | — | 费用页签，不参与树 |
| 电镀费 / 电镀成本 | 零件（模板有投入料号列时）<br>否则 *(空)* | 投入料号 | 投入料号名称 | repair-0802 起；绑 `unit_price.code`（零件料号），`hf_part_no` 另绑 `finished_material_no` |

> ⚠️ **导出/导入 bundle 携带**：`tabType`/`partNoField`/`partNameField` 已于 2026-07-21 补进 `ComponentExportBundle.Item` + 导出(`ComponentExportService`)/导入(`ComponentImportService`，`BOM`→`bomRecursiveExpand=true`)两端（同 `rowKeyFields`）。老 bundle 无此字段导入后为 null。

## 4.2 sort_field（行排序，task-0722）

多行页签要按「项次/序号」数字正序显示 → 用组件 `sort_field`，**别指望视图 `ORDER BY`**：

- **坑**：DRAFT 报价单渲染时，`QuotePendingRewriter` 把视图包成带锚点列的复杂子查询、执行器再套 `SELECT * FROM (...) inner_q`（**无外层 ORDER BY**）→ 视图里写的 `ORDER BY` **PostgreSQL 不保证透传**，多行页签会按 driver 返回序（常见倒序）显示。视图 `ORDER BY` 只对**已提交/冻结**报价单有效（见 `3-SQL视图.md §3.6`）。
- **正解**：给组件设 **`sort_field`**（= 本组件 `fields[].name` 之一，如「项次」「序号」）。快照组装层（`ConfigureSnapshotService`）按该字段做**数字感知升序**（数字段数字序、文本段字典序），DRAFT + 冻结都稳。树页签（`tabType=BOM`）按树序，不受 `sort_field` 约束。
- **配法**：REST `PUT /components/{id}` 传 `sortField:"项次"`；或直接 `UPDATE component SET sort_field='项次' WHERE ...`（列 V353）。设后 `refresh-snapshot` 重算即生效。
- 本项目已配：`其他费用/电镀费用/自制加工费/组装加工费 → sort_field=项次`、`元素 → sort_field=序号`。

## 4.3 树契约（BOM 页签）与报价两种页签契约

树页签视图输出 `material_no`（本节点子件号）+ `parent_no`（父号），后端按 **`(parent_no, material_no)` 边键**把数据挂到树节点上（同子件挂多父不串边）。对 `material_bom_item`：`parent_no = material_no(父)`、`material_no = component_no(子)`。树页签只出树结构 + 主件表头；材质/工序等**数据仍在各自数据页签平铺渲染**，不挂到树节点上。

### 🚨 报价树渲染的两种页签契约（树页签 vs 数据页签，绑定变量不同，不可混——QT-2085 事故）

配了 `tabType=BOM` 树页签的模板，报价侧渲染（`ConfigureSnapshotService.snapshotLines`）**分两趟路由，两趟注入的绑定变量完全不同**：

| Pass | 覆盖的页签 | 引擎 | 框架注入的绑定变量 | 视图必须用的过滤契约 |
|---|---|---|---|---|
| **Pass 2 树渲染** | **仅 `tab_type='BOM'`**（判据 `BomTreeRenderService.isQuoteTreeTabType`） | `BomTreeRenderService.render(usage=QUOTE)` | **`:total_material_no`**（整棵 spine 的料号数组）+ `versionFilter` 宏 | `WHERE <料号列> = ANY(:total_material_no)`，且输出 `material_no`(本节点子件号) + `parent_no`(父号) 做边键匹配 |
| **Pass 1 普通平铺展开** | **其余所有数据页签**（材质元素/零件/外购件/费用页签…） | `componentDriverService.expand`（既有报价平铺路径） | **`:customerCode`** + 行料号（隐式 JOIN 注入 `hf_part_no`） | `WHERE ... customer_no = :customerCode`，输出 `<表>.material_no AS hf_part_no`（驱动键，接隐式 JOIN） |

**铁律**：
1. **`:total_material_no` 只在 Pass 2（BOM 树页签）注入**。数据页签走 Pass 1，`:total_material_no` **永不注入** → 若数据页签视图写 `= ANY(:total_material_no)`，运行时该变量无绑定 → **整表 0 行**（不报错、静默空）。这正是 QT-2085「只有产品页签有数据、材料成本/加工费全空」的根因。
2. **树页签**（产品/BOM）：视图用 `:total_material_no` + `material_no`/`parent_no` 边契约（见 `报价侧.md` §组件配方大全 7.0）。
3. **数据页签**（材质元素/零件/外购件/费用）：视图**照常用平铺契约**（`hf_part_no` + `:customerCode`），**不要**因为“模板里有树”就改成 `:total_material_no`。它们在报价侧渲染为**独立平铺页签**（每行项目一份数据），**不挂到树节点上**。
4. 树的深度由 `costing_bom_tree_config` 的递归 SQL 决定（递归 `material_bom_item` 子件）。若产品的子件是 `characteristic='RECIPE'`（材质），递归条件**不能限死 `='ASSEMBLY'`**，否则树只剩根节点。默认递归全子件（RECIPE 材质 + ASSEMBLY 组成件都成节点）。

> 一句话：**只有 BOM 树页签换契约（`:total_material_no`），其余页签一律保持 `:customerCode` 平铺契约。** 把数据页签也改成树契约 = 静默返 0 行。

## 4.4 两侧树契约差异（报价 vs 核价）

| 维度 | 报价（QUOTE） | 核价（COSTING） |
|---|---|---|
| 递归 SQL（`costing_bom_tree_config`） | usage=QUOTE，入参 `:production_part_nos` | usage=COSTING，入参 `:production_part_nos` + `versionFilter` 宏 |
| 树页签 `$view` 绑定变量 | `:total_material_no` | `:total_material_no` |
| 边键挂数据 | `(parent_no, material_no)` | `(parent_no, material_no)` |
| 客户口径 | 数据页签按 `:customerCode` 收窄（Pass1 平铺） | 无 `:customerCode`，全局 `_GLOBAL_` 成本口径 |
| 数据页签 vs 树 | 数据页签**独立平铺**（Pass1），不挂树节点 | 每个核价组件出**整棵 spine**（缺数据补空行），以 spine 为行主轴（非业务 row） |
| 版本 | 提交即冻结，不可切版本 | `:versionFilter` 每 sheet 独立，仅 PENDING 可切 |

- **报价树**：Pass2 仅 `tabType=BOM` 页签走树渲染，其余数据页签 Pass1 平铺；SQL 与配方详见 `报价侧.md`。
- **核价树**：物料 BOM = 核价树，每个核价组件按 spine 全节点渲染（缺数据补空行）；递归 SQL usage=COSTING，5 列 `root_no/material_no/bom_version/parent_no/node_path` 按 `node_path` 建树；SQL 与配方详见 `核价侧.md`。
