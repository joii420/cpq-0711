## 契约要点（报价侧特有）

- **客户口径**：`:customerCode` = 报价单客户的 `customer_no`，框架运行时注入，按客户收窄；dry-run 时按 NULL 兜底（返 0 行不报错）。
- **料号键**：报价侧「料号」= **销售料号** = `material_no`。视图把 `material_no`（或 `finished_material_no`）`AS hf_part_no` 接隐式 JOIN 做料号收窄。`hf_part_no` 是唯一不带 `_` 前缀的别名（R4-例外，改名则视图返全表）。`production_no`（生产料号）报价场景不用作键。
- **版本**：无——**提交即冻结**（frozen 逐字节隔离），不可切版本。报价单一旦提交，快照即定格，与后续 V6 基础数据变化解耦。
- **渲染服务**：`ConfigureSnapshotService.snapshotLines`，**两趟路由，两趟注入的绑定变量完全不同**（§5.6 铁律）：
  - **Pass 2 树渲染**：**仅 `tab_type='BOM'`**（判据 `BomTreeRenderService.isQuoteTreeTabType`），走 `BomTreeRenderService.render(usage=QUOTE)`，注入 **`:total_material_no`**（整棵 spine 料号数组）+ `versionFilter` 宏；视图用 `WHERE <料号列> = ANY(:total_material_no)` + 输出 `material_no`(子)/`parent_no`(父) 边键。
  - **Pass 1 平铺展开**：**其余所有数据页签**（材质元素/零件/外购件/费用页签），走 `componentDriverService.expand`，注入 **`:customerCode`** + 行料号（隐式 JOIN 注入 `hf_part_no`）。
  - 🚨 **数据页签禁用 `:total_material_no`**：Pass 1 永不注入该变量 → 数据页签视图若写 `= ANY(:total_material_no)` 则运行时无绑定 → **整表静默 0 行**（不报错，正是 QT-2085「只有产品页签有数据、材料/加工全空」根因）。

## 0. 客户模板 → 组件的映射心智

一份客户模板（`页签——<客户>.xls` 或 `组件模板 - <客户>.xlsx`）：

- **每个 sheet（页签）= 一个组件**（`component`，`componentType=NORMAL`；小计性质的 sheet 建 `SUBTOTAL`）。
- **每个列（表头字段）= 一个字段**（`fields[]` 里一项），**严格 1:1，不多不少**。🚫 **不得为了填 `partNoField` 而新增模板没有的「料号列」字段**（~~材料成本+材质料号、外购件成本+组成件料号~~ 2026-07-24 废止）——模板不显示料号是真实场景，`partNoField` 留空、名称列担标识、料号只进 SQL JOIN（§5.5）。
- **每个组件配一个组件 SQL 视图**（`component_sql_view`，`$name`）当取数源；多行组件用它当 `data_driver_path` 驱动。
- **组件按页签语义配 `tabType`**（主件/材质元素/外购件…，费用页签留空，§5.5）。
- **模板目录 = 客户名称**（`component_directory.name = <客户名>`）。

模板只给「结构」（组件数 + 字段名），**数据来源由 §5 的 V6 表映射规则补齐；每种页签的完整配方见 §7**。字段类型统一 `INPUT_*`、`default_source` 绑基础数据、SQL 列 `_` 前缀等共性规则见 `1-总则与工作流.md`（R1~R6）与 `2-组件与字段.md`。

## 5. V6 数据表映射规则（字段来源权威表）

> 料号口径：**报价侧「料号」= 销售料号 = `material_no`**（`material_master`/`material_customer_map`/`element_bom_item`/`material_bom_item` 的 `material_no`）。`production_no` 为生产料号，本报价场景不用作键。

### 5.1 产品信息（单行/成品级）——源 `material_customer_map` + `material_master`

| 模板字段 | V6 来源 |
|---|---|
| 销售料号 / hf_part_no | `material_master.material_no`（或 `material_customer_map.material_no`） |
| 客户料号名称 | `material_customer_map.customer_material_name` |
| 客户产品编号 | `material_customer_map.customer_product_no` |
| 客户图号 | `material_customer_map.customer_drawing_no` |
| 报价货币 | `material_customer_map.quote_currency` |
| 基础货币 / 汇率 / 付款方式 | `material_customer_map.base_currency / exchange_rate / payment_method` |
| 品名 / 规格 / 单重 | `material_master.material_name / specification / unit_weight` |

JOIN：`material_customer_map.material_no = material_master.material_no AND material_customer_map.customer_no = :customerCode`。

### 5.2 材料成本（多行/逐元素）——源 `element_bom_item`（材质经**本行 `material_part_no`** → `material_recipe` + 元素单价接价格策略）

**层级结构（务必理解）**：
- `element_bom_item` 是元素行驱动表：`.material_no` = **销售料号（成品）本身**，`.component_no` = **元素**（Ag/Cu/Ni…），`.seq_no` = 项次。
- `element_bom_item.material_part_no` = **本行元素所属的材质料号**（= 材质库配方码，如 991/99901）。
- `material_recipe.code` = 材质料号，`.name` = **材质名**（如 `H65带`/`Cu/Ag/Cu带`）；`material_master.material_no`（=material_part_no）的 `.material_name` 可作兜底名源。

🚨 **「一号多材质」铁律（森萨塔 QT-20260716-2046 事故沉淀 → COMP-0063/0066/0070 修复）**：
- **一个销售料号在同一客户下可合法对应多个 `material_part_no`**（多材质链，各一条独立 element BOM 版本链、各留一个 `is_current=TRUE`；导入按材质料号分链是正确行为，**勿改升版/Q04ElementBomHandler**）。
- **材质名必须逐行取自本行 `material_part_no`**（`LEFT JOIN material_recipe mr ON mr.code = ebi.material_part_no`）。**严禁**用 `material_bom_item` 子查询把整单聚合成一个材质值——那样多材质链的元素行会变成「值相同、无从区分的匿名重复行」，且客户 `material_bom` 为空时材质恒空（旧方案的双重坑）。
- **`material_part_no` 进 driver 排序**（`ORDER BY material_no, material_part_no, seq_no`）让同材质连续成组。
- **🔑「材质」字段必须进 `rowKeyFields`**（如 `["销售料号","元素","材质"]`）。否则多材质链下 `(项次,元素)` 撞键 → 可编辑行 editRows 串行 / 末值×行数塌缩（见 `2-组件与字段.md` 行键唯一化；记忆 `cpq-rowkey-uniqueness-disambiguation`）。这是纯改视图 SQL **不够**、必须连组件 `rowKeyFields` 一起改的点。
- **不要** DISTINCT/GROUP BY 压成一行（丢一种真实材质成本），也**不要**随便取一个材质料号只留一行（两种材质都是有效数据）。
- 「只显示客户实际报价的那一种材质」需另加锚点（母件 BOM `material_bom_item` INNER JOIN `ON child.component_no = ebi.material_part_no`，或报价行加「材质选择」字段），非改视图 SQL 能解决 → **另立需求**。

> 📌 `material_bom_item.characteristic` 有 `RECIPE`/`ASSEMBLY`/`(空)` 三态，其中 `RECIPE` 只是 task-0708 repair-2 开发期临时代码遗留脏数据（当前 `MaterialBomMergeHandler` 只写 `null`/`ASSEMBLY`），**任何按 characteristic 过滤都不可取**。

| 模板字段 | V6 来源 |
|---|---|
| 销售料号 / hf_part_no | `element_bom_item.material_no` |
| **材质** | `COALESCE(mr.name, mm2.material_name)`，`mr.code = ebi.material_part_no` / `mm2.material_no = ebi.material_part_no`（**逐行取，见铁律**） |
| （材质料号）| `element_bom_item.material_part_no` —— **默认只作 JOIN 键 + `ORDER BY` 键，不出可见列**；仅当客户模板确有「材质料号」列时才出 `_材质料号` 并配成 `partNoField` |
| 项次 | `element_bom_item.seq_no` |
| 元素 | `element_bom_item.component_no` |
| 损耗率% | `element_bom_item.scrap_rate` |
| 毛重（毛用量） | `element_bom_item.composition_qty`（与「毛用量单位」= `issue_unit` 成对） |
| 毛用量单位 | `element_bom_item.issue_unit` |
| 元素单价 | **接客户价格策略**：`LEFT JOIN f_customer_element_price(...)` 表函数按元素符号取价（见 §5.2.1）。 |

材质取数范式（逐行、经 material_part_no）：
```sql
COALESCE(mr.name, mm2.material_name) AS _材质
-- ...
FROM element_bom_item ebi
  LEFT JOIN material_recipe mr  ON mr.code = ebi.material_part_no
  LEFT JOIN material_master mm2 ON mm2.material_no = ebi.material_part_no
-- 组件 rowKeyFields 必须含「材质」：["销售料号","元素","材质"]
```

#### 5.2.1 元素单价接入客户价格策略（`f_customer_element_price`，task-0722）

**目标**：给元素类组件的「单价」列接客户价格策略，报价/核价渲染时**按客户自动取元素单价**（不让用户手填）。**只改组件 `$view` 的 `sql_template` + 字段取数配置，不改字段类型**（不触发 AP-44）。

**核心机制**：价格逻辑封装在 PG 表函数（**已落库**）：
```
f_customer_element_price(客户编号 TEXT, 基准日 DATE)
  → TABLE(element_code 元素符号, unit_price 最终单价(含系数加价), currency 货币, price_unit 价格计价单位)
```
一次返回该客户全部有价元素（非逐行调用，无 N+1）。视图里 `LEFT JOIN` 它，用**元素符号**关联。

**三步配置**：
1. 驱动视图 `FROM` 加 JOIN（**两侧客户参数不同**）：
   ```sql
   -- 报价侧(system_type='QUOTE')：传运行时真实客户
   LEFT JOIN f_customer_element_price(:customerCode, :priceBaseDate) cep ON cep.element_code = ebi.component_no
   -- 核价侧(system_type='PRICING')：传字面量 '_GLOBAL_'（见 核价侧.md）
   LEFT JOIN f_customer_element_price('_GLOBAL_', :priceBaseDate) cep ON cep.element_code = ebi.component_no
   ```
2. `SELECT` 加输出列，中文别名与组件字段名**逐字一致**：`cep.unit_price AS 单价, cep.currency AS 货币`（⛔ 不输出「计价单位」，见硬约束 4）。字段实际名叫「元素单价」就 `AS 元素单价`。
3. `component_sql_view.required_variables` 声明：报价侧 `["customerCode","priceBaseDate"]`；核价侧 `["priceBaseDate"]`（不含 customerCode，传的是字面量）。字段取数：报价侧字段 `default_source` 指 `$view.单价`/`$view.货币`（类型仍 `INPUT_*`）；核价侧 `basic_data_path` 指 `$view.单价`（类型 `BASIC_DATA`）。**字段类型一个字都不改**。

**🚨 硬约束（违反即出 bug，逐条自检）**：
1. **必须 `LEFT JOIN`，禁 `INNER JOIN`** —— 否则无价元素整行消失、行数变少、页签小计错。
2. **JOIN 键用元素符号列** `element_bom_item.component_no`（值如 Ag/Cu/301），**不是元素编号** —— 用错恒不命中，全表无价。
3. **禁 `COALESCE(cep.unit_price, 0)` 兜底** —— 无价必须留 `NULL` 触发「留空手填」；填 0 会静默算 0 元成本、不报错。
4. **⛔ 不要绑「计价单位」字段**。报价单「计价单位」列是 **BOM 发料单位** `ebi.issue_unit`（g/KG），被「毛用量/净用量」以 `unit_source_field` 引用做 g→KG 换算；改指价格 `price_unit`(元/kg) 会让换算读到非法 token、静默算错。**本期只绑「单价」+「货币」两字段**。
5. **核价侧传字面量 `'_GLOBAL_'`，且视图 WHERE 里不要加 `customer_no=:customerCode`** —— 核价基础数据 `customer_no` 恒 `'_GLOBAL_'`，加客户过滤一行查不到。
6. **别名与字段名逐字一致**（含全半角/空格）—— 否则路径解析不到、渲染空白。
7. **不为「源名/命中日期/取值方式」加额外输出列** —— 无消费方，徒增复杂度。

**前提与边界**：
- 客户没配价格策略 → 表函数返 0 行 → 元素行照常显示、单价留空手填（**设计如此，不报错**）。*（当前现网实测 `_GLOBAL_`/`CUST-1269` 均返 0 行 = 尚无策略数据，接上后暂全留空，待业务配策略后自动出价。）*
- `:priceBaseDate` 后端自动注入（=报价单创建日期；配置期预览回退今天），视图直接写占位符，不用自己算。已在 `SqlViewExecutor`（task-0722 §11.2）接好。
- 字段类型不变 → **不触发 AP-44**。

**自检**：`expand-driver` 端点或直接 SQL 实测——有价元素出数、无价元素返 `NULL`（不是 0、不是整行消失）；换一个没配策略的客户，元素行数不变、单价全空。

### 5.3 加工费（多行/逐要素）——源 `unit_price` price_type='PROCESS'（要素名称=工序名称）

| 模板字段 | V6 来源 |
|---|---|
| 销售料号 / hf_part_no | `unit_price.finished_material_no`（按成品收窄本报价行） |
| 料号列（零件料号，partNoField） | `unit_price.code`（该费用项针对的零件，非 `finished_material_no`，见 §5.5 料号铁律） |
| 项次 | `unit_price.seq_no` |
| **要素名称** | **`process_master.process_name`（工序名称），经 `process_master.process_no = unit_price.operation_no` 关联；兜底 `COALESCE(pm.process_name, up.operation_no)`** |
| 单价 | `unit_price.pricing_price` |
| 单位 | `unit_price.unit` |

过滤：`system_type='QUOTE' AND price_type='PROCESS' AND is_current AND customer_no=:customerCode`。

🔧 **要素名称=工序名称规则（2026-07-19 用户明确）**：
- **不要**用 `unit_price.cost_type` 当要素名称——它是统称（恒为「自制加工费」），无法区分工序。
- **要素名称 = 工序名称 = `process_master.process_name`**（`process_master.process_no = unit_price.operation_no`）。`process_master` 是 V6 工序主表（非废弃，可引；`mat_process`/`costing_part_process_cost` 是 V44/V76 废弃，禁用）。兜底 `COALESCE(pm.process_name, up.operation_no)`，缺工序名时至少显工序编号。
- **rowKeyFields 必须含「项次」**（如 `["销售料号","项次","要素名称"]`）：改前 cost_type 恒定→整料号加工费行同键撞键；改后要素名称变工序名，但同料号仍可能同工序重复，`项次`(seq_no) 才是料号内唯一保证。

### 5.4 其他常见来源（扩展页签时参考罗克韦尔母版）

| 页签类型 | 源 | 关键过滤 |
|---|---|---|
| 电镀费 | `unit_price` `price_type='PLATING'`（**行转列，见下**）| 料号在 `code` 列 |
| 成品其他费用 | `unit_price` `price_type='FINISHED_MATERIAL_OTHER'` | **料号在 `code` 列**；`要素名称=cost_type`（材料管理费/外购件管理费/利润/税率，非统称，**不走 process_master**）；`值=pricing_price`；每料号多行，rk=`[销售料号,项次,要素名称]` |
| 来料其他费用 | `unit_price` | `price_type='INCOMING_MATERIAL_OTHER'` |
| 外购件成本（组成件）| `material_bom_item`（`characteristic='OUTSOURCED'`，见 §7.5）+ `material_master`（组成件名称）| rk 按模板实有列：有料号列→`[销售料号,组成件料号]`，无→`[销售料号,组成件名称]`；tabType=外购件 |
| 组装/工序 | `labor_rate` / `production_energy` / `auxiliary_energy` / `tooling_cost` | 工序级 |

> **`material_bom_item.characteristic` 三态语义（task-0720 起）**：`RECIPE`=材质（材质页签走 `material_part_no`，不靠它过滤，见 §5.2）/ `ASSEMBLY`=组成件（零件，tabType=零件）/ `OUTSOURCED`=外购件（tabType=外购件）。现网实查：RECIPE / ASSEMBLY 有数据，`OUTSOURCED` 暂 0 行。

🔧 **电镀费「费用列」= 行转列 PIVOT（2026-07-20 森萨塔事故）**：
- 现网**绝大多数客户**的电镀数据在 `unit_price` `price_type='PLATING'`，且是**行式**：每料号两行（`cost_type='电镀加工费'` / `'电镀材料费'`，值在 `pricing_price`），**料号在 `code` 列**（`finished_material_no` 常为空）。`plating_fee`（费用列式）只有个别客户（如 8000143）有数据。
- 模板要「电镀加工费 / 电镀材料费」作**两列** → 必须 **CASE-WHEN 行转列 + GROUP BY 料号**（`plating_fee` 直取列的写法对绝大多数客户返 0 行，是错的，见 §7.4 完整 SQL）。
- PIVOT 后**每料号一行** → `rowKeyFields=["销售料号"]`（不是多行，别放电镀元素名称当行键，它恒 NULL）。
- 电镀元素名称/镀层厚度在 `unit_price` 无源（保留字段绑 NULL 列，待数据模型补 `plating_scheme` 链路）。个别用 `plating_fee`+`plating_scheme` 的客户可另走「`plating_fee` JOIN customer(id→code) LEFT JOIN plating_scheme(scheme_no=plating_plan_code)」逐元素式，但那是少数。

### 5.5 页签类型属性（tabType / partNoField / partNameField，task-0721）

task-0721（报价侧 BOM 树）给**组件（页签）级**新增 3 个配置项，用于树的类型判定 + 加叶子候选采集。完整规则见 `4-页签属性与树.md`；此处列报价侧要点：

| 配置（JSON 键 / 请求体 camelCase） | 含义 | 规则 |
|---|---|---|
| `tabType` | 页签类型 | `BOM`/`材质元素`/`零件`/`外购件`/`主件`（5 类，非法值 400；可空） |
| `partNoField` | 料号列字段名 | 该组件某字段 `name`，**可空**——客户模板无料号列时留空（见下方 🚫 段） |
| `partNameField` | 料号名称列字段名 | 该组件某字段 `name`，可空 |

> 🚩 4 类物料页签的硬门槛是**「料号列与名称列至少配一个」**（`ComponentService.assertPartNoFieldRequirement`，2026-07-23 放宽），两者皆空才 400；类型判定 `QuotationTreeService` **优先 `partNoField`、为空回落 `partNameField`**。
>

- 费用类页签（成品其他费用 / 电镀费）无物料语义 → `tabType` 留空，不参与树。

> 🚨 **料号列绑定值铁律（2026-07-23 用户定，仅在「模板确有料号列」时适用）：`partNoField` 绑的列必须是该 `tabType` 语义层级的料号，禁绑成品/主件料号。** 完整表见 `1-总则与工作流.md §1.3.2`。报价侧对照：

### 5.6 🚨 报价树渲染的**两种页签契约**（树页签 vs 数据页签，绑定变量不同，不可混——2026-07-22 QT-2085 事故）

配了 `tabType=BOM` 树页签的模板，报价侧渲染（`ConfigureSnapshotService.snapshotLines`）**分两趟路由，两趟注入的绑定变量完全不同**：

| Pass | 覆盖的页签 | 引擎 | 框架注入的绑定变量 | 视图必须用的过滤契约 |
|---|---|---|---|---|
| **Pass 2 树渲染** | **仅 `tab_type='BOM'`**（判据 `BomTreeRenderService.isQuoteTreeTabType`） | `BomTreeRenderService.render(usage=QUOTE)` | **`:total_material_no`**（整棵 spine 的料号数组）+ `versionFilter` 宏 | `WHERE <料号列> = ANY(:total_material_no)`，且输出 `material_no`(本节点子件号) + `parent_no`(父号) 做边键匹配 |
| **Pass 1 普通平铺展开** | **其余所有数据页签**（材质元素/零件/外购件/费用页签…） | `componentDriverService.expand`（既有报价平铺路径） | **`:customerCode`** + 行料号（隐式 JOIN 注入 `hf_part_no`） | `WHERE ... customer_no = :customerCode`，输出 `<表>.material_no AS hf_part_no`（驱动键，接隐式 JOIN） |

**铁律**：
1. **`:total_material_no` 只在 Pass 2（BOM 树页签）注入**。数据页签走 Pass 1，`:total_material_no` **永不注入** → 若数据页签视图写 `= ANY(:total_material_no)`，运行时该变量无绑定 → **整表 0 行**（不报错、静默空）。这正是 QT-2085「只有产品页签有数据、材料成本/加工费全空」的根因。
2. **树页签**（产品/BOM）：视图用 `:total_material_no` + `material_no`/`parent_no` 边契约（见 §7.0）。
3. **数据页签**（材质元素/零件/外购件/费用）：视图**照常用 §4/§7 的平铺契约**（`hf_part_no` + `:customerCode`），**不要**因为「模板里有树」就改成 `:total_material_no`。它们在报价侧渲染为**独立平铺页签**（每行项目一份数据），**不挂到树节点上**。
4. 树的深度由 `costing_bom_tree_config` 的递归 SQL 决定（递归 `material_bom_item` 子件）。若产品的子件是 `characteristic='RECIPE'`（材质），递归条件**不能限死 `='ASSEMBLY'`**，否则树只剩根节点。默认递归全子件（RECIPE 材质 + ASSEMBLY 组成件都成节点）。

> 一句话：**只有 BOM 树页签换契约（`:total_material_no`），其余页签一律保持 `:customerCode` 平铺契约。** 把数据页签也改成树契约 = 静默返 0 行。

### 7.0 🌳 产品（BOM 树页签，`tabType=BOM`）——树契约，非平铺

> **仅当产品页签要渲染成 BOM 树时用本配方**（否则产品用 §7.1 平铺主件）。走 Pass 2 树渲染，绑定变量是 `:total_material_no`（**不是** `:customerCode`），输出 `material_no`(本节点子件号)/`parent_no`(父号) 做树边匹配（§5.6）。
>
> 前置：① 该组件 `tabType=BOM`（保存自动 `bomRecursiveExpand=true`；被 COSTING 引用会 400 → 须新建报价专用组件）；② 建一条 `costing_bom_tree_config`（`usage=QUOTE`, active）的递归 SQL，递归 `material_bom_item` **全子件**（RECIPE 材质 + ASSEMBLY 组成件都成节点，别限死 ASSEMBLY），输出 `root_no/material_no/bom_version/parent_no/node_path`，入参 `:production_part_nos` + 客户传播列 `_cust`。

`driver=$cp_view` · `rowKeyFields=["销售料号"]` · `partNoField=销售料号` · 字段绑定同 §7.1（`$cp_view._销售料号` 等）。

```sql
-- $cp_view（树契约：边式全子件 + 根分支；material_no=子, parent_no=父）
SELECT
  mbt.component_no AS material_no,          -- 本节点（子件号）
  mbt.material_no  AS parent_no,            -- 父节点
  mbt.component_no AS _销售料号,
  mcm.customer_material_name AS _客户料号名称, mcm.customer_product_no AS _客户产品编号,
  mcm.quote_currency AS _报价货币, mm.standard_unit AS _单位, mcm.exchange_rate AS _汇率
FROM material_bom_item mbt
LEFT JOIN material_master mm        ON mm.material_no  = mbt.component_no
LEFT JOIN material_customer_map mcm ON mcm.material_no = mbt.component_no
WHERE mbt.system_type='QUOTE' AND mbt.is_current
  AND mbt.component_no = ANY(:total_material_no)
UNION ALL   -- 根分支：无 ASSEMBLY/子件父边的成品自身（树根）
SELECT mm.material_no, NULL::text,
  mm.material_no, mcm.customer_material_name, mcm.customer_product_no,
  mcm.quote_currency, mm.standard_unit, mcm.exchange_rate
FROM material_master mm
LEFT JOIN material_customer_map mcm ON mcm.material_no = mm.material_no
WHERE mm.material_no = ANY(:total_material_no)
  AND NOT EXISTS (SELECT 1 FROM material_bom_item x
                  WHERE x.component_no = mm.material_no AND x.system_type='QUOTE' AND x.is_current)
```

> ⚠️ 树页签只出树结构 + 主件表头；材质/工序等**数据仍在各自数据页签（§7.2/§7.6）平铺渲染**，不挂到树节点上。

```sql
  ebi.material_no AS hf_part_no,
  ebi.material_no AS _销售料号,
  COALESCE(mr.name, mm2.material_name) AS _材质,   -- 逐行取自本行 material_part_no

  ebi.base_qty AS _组成数量,
  ebi.seq_no AS _项次,
  ebi.component_no AS _元素,
  ebi.content AS _组成含量,
  ebi.scrap_rate AS _损耗率,
  ebi.composition_qty AS _毛重,
  ebi.issue_unit AS _毛用量单位,
  cep.unit_price AS 单价,        -- 价格策略列：别名逐字、不加 _（硬约束 6）
```

```sql
SELECT
  mbi.material_no AS hf_part_no,
  mbi.material_no AS _销售料号,
  mbi.component_no AS _组成件料号,          -- ⚠️ 仅模板确有「组成件料号」列时才输出；否则删本行（只当取名 JOIN 键）
  COALESCE(mm.material_name, mr.name) AS _组成件名称,   -- material_recipe 兜底（V341/V342 口径）
  mbi.composition_qty AS _组成数量,
  mbi.issue_unit AS _组成单位
FROM material_bom_item mbi
  LEFT JOIN material_master mm ON mm.material_no = mbi.component_no
  LEFT JOIN material_recipe mr ON mr.code = mbi.component_no
WHERE mbi.system_type = 'QUOTE' AND mbi.is_current AND mbi.characteristic = 'OUTSOURCED'
  AND mbi.customer_no = :customerCode
ORDER BY mbi.material_no, mbi.seq_no
```
> ⚠️ 无料号列时行键靠「组成件名称」，**同名多行会撞键**（editRows 塌缩）；真遇到再找用户确认是否把料号列显出来。

### 7.6 加工费（legacy——sheet 名叫「加工费」时用；`tabType` 空或零件）
`driver=$pf_view` · `rowKeyFields=["销售料号","项次","要素名称"]` · 要素名称=工序名（§5.3）。
> ⚠️ 与 §7.3 成品其他费用区别：加工费=`price_type='PROCESS'` + 要素名称走 `process_master.process_name`；成品其他费用=`price_type='FINISHED_MATERIAL_OTHER'` + 要素名称=`cost_type`。**按 sheet 名选**。
> ⚠️ 若本页签设 `tabType=零件`，`partNoField` 绑「零件料号」列（视图加 `up.code AS _料号`），**非 `finished_material_no`**（§5.5 料号铁律）。`hf_part_no` 仍绑 `finished_material_no` 按成品收窄。

字段：销售料号/[零件料号]/项次/要素名称/值(¥)/[货币]/单位。
```sql
-- $pf_view
SELECT
  up.finished_material_no AS hf_part_no,     -- 驱动键：按成品收窄本报价行
  up.finished_material_no AS _销售料号,
  up.code AS _料号,                          -- 零件料号（partNoField，零件页签绑此列）
  up.seq_no AS _项次,
  COALESCE(pm.process_name, up.operation_no) AS _要素名称,
  up.pricing_price AS _值,
  up.unit AS _单位
FROM unit_price up
  LEFT JOIN process_master pm ON pm.process_no = up.operation_no
WHERE up.system_type = 'QUOTE' AND up.price_type = 'PROCESS' AND up.is_current = true
  AND up.customer_no = :customerCode
ORDER BY up.seq_no
```

### 7.7 小计（`componentType=SUBTOTAL`）
sheet 名含「小计」时建 SUBTOTAL 组件：**无字段、无 driver、无 SQL 视图**。成本聚合靠模板/组件的 `component_subtotal` 公式 token 引用各 NORMAL 组件的 `is_subtotal` 列，见 `5-公式与Excel列.md`，本文不展开。

> **数据现状提示**：客户未登记 / V6 无数据时，视图 dry-run 通过但返 0 行，字段仍可输入（三级兜底见 `2-组件与字段.md`），数据导入后自动显值。`OUTSOURCED` 当前全表 0 行。
