## 1. 背景与目标

核价基础数据导入（`PricingImportService`，`system_type='PRICING'`）目前一次处理 24 个 Excel Sheet。其中 4 个 Sheet 的数据在当前系统里已经**没有消费方**，或**已被更新的机制取代**，继续导入只会产生无人读取的存量数据、拉长导入耗时、并让业务误以为这些页填了会生效：

| Sheet | 落库表 | 现状核查结论（2026-08-12 实测 `cpq_db_0724`） |
|---|---|---|
| 元素核价价格表 | `unit_price` (price_type=`ELEMENT`，现存 3 行) | **无人读**。元素单价 2026-07 起改走价格策略链路 `f_customer_element_price` / `f_material_element_price` + `element_daily_price` + `element_price_strategy`（V356~V358、V369），不再读 `unit_price` |
| 材料核价价格表 | `unit_price` (price_type=`MATERIAL_PRICE`，2 行) | **无人读**。全库 `component_sql_view` / `template_sql_view` 对 `MATERIAL_PRICE` 命中 0 条 |
| 核价版本 | `material_version_mgmt`（4 行） | **无人读**。除建表迁移 V218/V277 与 `MaterialMasterCrudService` 的一句注释外，无任何查询方 |
| 宏丰-客户料号对应关系 | `material_master` + `material_customer_map` | **仍有读者**（见 §7 风险），但业务决定停用该入口 |

**目标**：从源头（读取 + 存储 + 模板）停用这 4 个 Sheet，导入口径由 24 Sheet 收敛为 20 Sheet；**Handler 类与其落库逻辑代码全部保留**，仅摘除调用点，以便日后需要时按名字加回即可恢复。

## 8. 已知坑位

1. **`orderedHandlers()` 顺序是写入依赖序**，只删不排（§5.3）。历史上 `material_master` 由 P24/P05/P06 三处共写，顺序变化会改变 upsert 的最终值。
2. **`PricingTemplateServiceTest` 是双向守卫**：它同时断言「catalog 数 == handler bean 数」与「模板 sheet 数 == catalog 数」。只改 catalog 不改测试 → 测试红；只改测试不改 catalog → 守卫失效。两处必须同批改。
3. **共享 dev server 不服务 worktree 代码**（`cpq-worktree-frontend-selfcheck`）：worktree 内的前端自检需软链 `node_modules` + 另起临时端口，或在合并后于主工作区复验。后端同理。
4. **提交纪律**：只 `git add` 本次明确改动的文件，严禁 `git add -A`（多会话并发，历史已两次夹带他人改动）。
5. **`grep` 在本环境是 `ugrep -I`**，会把中文注释多的大源文件静默判为二进制返空。核查「无消费方」这类结论必须用 `/usr/bin/grep -a`（本文件所有实测结论均已按此执行）。
