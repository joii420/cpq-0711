## 3. 方案总纲

### 3.1 patch 语义（替代原 §规则四「丙 全量对齐」）

对每个受影响的（表 → V6 组）：

1. **基底行集**（新增概念，权威来源是 DB 不是页签）
   - 本单在该组有 pending 行 → 基底 = 本单全部 pending 行
   - 否则 → 基底 = 该组 `is_current=true AND pending_quotation_id IS NULL` 的正式行
   - 两者皆无 → 基底为空（纯新增组）
2. **列级 patch**：某基底行被页签以 `__v6_id` 表征时，把该页签映射出的**非空**列值覆盖到该行；未映射列保持基底值。
3. **删除**：被墓碑命中且能定位 `__v6_id` 的基底行，从有效集剔除。
4. **新增**：手工新增行（树叶子 `__manual` / 平铺 `_origin:'manual'`）合成后追加。
5. **路径判定**
   - 有效集为空 → `OFFLINE`（整组下线，语义不变）
   - 有效集 ≡ 基底、基底来自 pending、无 patch/删除/新增 → `FLIP`（沿用现有零成本转正）
   - 其余 → `REBUILD`（喂 `VersionedV6Writer` 的是**完整行集**，不再是页签投影）

**语义变化说明（需求方已认可）**：原文档 §4.3 规则四写「增删改全进、未出现即删除」。新语义下**删除必须由墓碑显式表达**，「页签里没出现」不再等同于「用户删了它」。理由：页签本来就只是 V6 组的投影（过滤谓词 / 闭包 / 列子集），把投影当全集是 D1/D2 的根。

**已知限制（不在本次修，写入文档）**：用户把某格清空为 NULL 时，`mapColumns` 的 `isNull → continue` 使其等同「未提供」，清空不传导。区分「未提供」与「清空」需要额外信息，登记 BACKLOG。

### 3.2 锚点支持顶层集合运算（D3）

`QuotePendingRewriter.rewrite`：顶层 set-op 不再整体降级，改为**逐分支注入**——
- 分支 FROM/JOIN 含白名单表 → 注 `<alias>.id AS __v6_id`
- 否则（如 `$bom_view` 第二分支 `FROM material_master`）→ 注 `NULL::uuid AS __v6_id`
- 各分支注入在自身 SELECT 列表同一位置，列数/位置天然对齐
- 所有分支都无白名单表 → 维持 `anchorInjected=false`
- 分支内含 `GROUP BY` → 该分支注 `NULL::uuid`（行级不可回填，不阻断整视图）

`QuoteBackfillColumnMapper`：set-op 视图取**第一个含白名单表的分支**单独 `LIMIT 0` 探测列映射（分支间列位置必须对齐是 SQL 语义保证）；非白名单分支的行 `__v6_id` 为 NULL，收集器天然跳过。

`QuoteViewValidationService` 启动校验按同口径放行。

⚠️ 不动 `BomTreeRenderService:384` 显式 `injectAnchor=false` 的 spine 递归 SQL —— 骨架不需要锚点。

### 3.3 预览重做（D4+D5）

- **如实性**由 3.1 保证：patch 语义下不存在「隐式删除」，预览显示 0 变更就真的 0 变更。仍保留「零差异组不展示」，但此时它是真结论。
- **按产品聚合**：组 → 产品归属推导 —— `material_bom_item`/`element_bom_item`/`capacity` 取轴 `material_no`；`unit_price` 取 `finished_material_no` 兜底 `code`；`plating_scheme` 无产品维度 → 归入独立「全局共享」分区并保留红色警示。
- **业务语义化**：
  - 表 → 业务类别中文名（BOM 组成 / 材质元素构成 / 单价 / 工时产能 / 电镀方案）
  - 轴列 / 内容列 → 中文标签：优先取**页签列别名**（`colToBase` 反查，去前导 `_`，本就是用户配的中文列名），兜底静态物理列字典
  - 料号带品名（批量 JOIN `material_master`，禁 N+1）、客户号带客户名
- 前端 Drawer 重做为「产品卡片 → 业务类别分节 → 行级中文差异」。

## 4. 验收标准

| # | 验收项 | 判定标准 |
|---|---|---|
| **AC-R1** | 投影页签不丢行 | 造 D1 场景（组 4 行，仅 1 行被 `characteristic='OUTSOURCED'` 页签表征）→ 核价通过后该组仍为 4 行，另 3 行逐字段不变 |
| **AC-R2** | 未暴露列不丢值 | 造 D2 场景（`base_qty` 不被任何页签暴露）→ 通过后新版本 `base_qty` 与基底逐字段相等 |
| **AC-R3** | 树锚点 + 传导 | `$bom_view` 型顶层 `UNION ALL` 视图 driverRow 带 `__v6_id`（根分支行为 NULL）；树内删一行 → 通过后该行从新版本消失、老版本 `is_current=false` 留存；树内改值 → 新值进新版本 |
| **AC-R4** | 预览 ≡ 执行 | 预览「0 变更」→ 执行后该组逐字段零 diff（行数、列值）；预览「删 N 行 / 改 M 行」→ 执行后恰好删 N、改 M。二者用同一 plan，测试须断言 DB 前后快照 |
| **AC-R5** | 预览可读性 | 抽屉按产品卡片聚合；每行显示中文列名 + 旧值→新值；料号显示「料号 + 品名」；客户显示客户名；`plating_scheme` 独立分区红色标注「全局共享，影响所有客户」 |
| **AC-R6** | 闭包跨组精确 | 闭包页签（`$jg_view`/`$mc_view`/`$wg_view`）表征的行分属多个组时，各行 patch 落到自己所属组，不跨组污染 |
| **AC-R7** | 既有语义零回归 | task-0721 原 AC-1~AC-19 全部复跑通过（延迟生效 / 他单隔离 / 闸门 / FLIP / OFFLINE / 主子同步 / previewToken 幂等 / 核价侧零回归） |
| **AC-R8** | 无 N+1 | 基底行集装载、品名/客户名解析均为批量 SQL；代码审查 + SQL 计数 |

## 5. 影响面与风险

| # | 风险 | 应对 |
|---|---|---|
| R-1 | `previewToken` 口径随 plan 内容变化 → 部署瞬间在途 token 全部 409 | 可接受（财务重新预览即可），写进发布说明；不改 token 算法本身 |
| R-2 | 锚点注入扩展到 set-op 视图 → 影响所有报价侧 `$view` 执行路径 | 启动期 `QuoteViewValidationService` 全量校验 + 逐视图 `LIMIT 0`；失败指名视图。核价侧（PRICING）不走该改写，零影响 |
| R-3 | patch 语义下「页签没出现即删除」不再成立，可能有依赖旧语义的既有测试 | 既有 backfill 测试须按新语义重写（backtask B5 明列），重写而非删除 |
| R-4 | 基底行集多取一次 DB → 首存/通过耗时 | 按（表 → 轴集合）批量一次查，禁逐组；核价通过非热路径 |
| R-5 | 同一行同一列被多个页签同时 patch 且值不同 | 按组件 sortOrder 先到先得 + WARN 日志 + 预览标注冲突；概率极低（不同页签列基本不重叠） |

## 6. 不做什么

- 不动核价侧（`system_type='PRICING'`）任何逻辑。
- 不修复已损坏的存量数据（需求方决策 4，登记 BACKLOG）。
- 不改 `field_type` / 组件配置 schema → **AP-44 的 17 点联动协议不触发**。
- 不改报价渲染读 `snapshot_rows` 的基线（三大核心模块基线不受影响）。
