# 主线复核 · 「页面算对了但 costing_card_values 仍是 0」的机制

- 时间：2026-09-11
- 起因：测试工程师 S1 回报 §🚨② —— 修复态前端页面显示 `5438667.5`，但库里 BOM 小计仍是 `0`，`sha` 逐字节未变。它明确说「判断要读实现，那是主线的活，我不下结论」。
- 复核人：主线（读实现 + 实查库），**不采信任何一方的推断**。

## 结论：测试工程师的观察正确，成因是「本行没变 ⇒ 不失效卡片值」，**不是本次修复的缺口**

### 机制（读实现所得，均为 worktree 内路径）

| 环节 | 事实 | 出处 |
|---|---|---|
| saveDraft 主循环 | **只有「本行真的变了」（`invalidateCardValues`）才把 `quoteCardValues` / `costingCardValues` 置 `NULL`**；不变的行保持旧值 | `QuotationService.java:3225-3233`，注释原文：「置 NULL = 让 `CardSnapshotService#ensureCardValues` 的『… IS NULL』谓词下次选中本行重算。不置 NULL 的行保持旧值 ⇒ 报价侧与核价侧都不重算」（task-260901 B-1c） |
| 补算谓词 | `ensureCardValues(quotationId)` 默认 `forceRecomputeAll=false`，**只补 `IS NULL` 的行** | `CardSnapshotService.java:1500-1502` |
| 强制重算 | `ensureCardValues(quotationId, true)` **仅提交路径使用**，无视 `IS NULL` 谓词强制重算整单 | `CardSnapshotService.java:1504-1546` 的 doc 注释；调用点 `QuotationService.java:1195`（在 `submit()` 内，方法起始 `:1046`） |
| 核价侧单独刷新 | `refreshCostingCardValuesForLine` / `refreshCostingCardValues` 的生产调用点只有三处：管理端点 `QuotationAdminResource:150/165`、复制报价单 `QuotationService:2008`、选配配置产品 `ConfigureProductResource:140`、价格调整更新任务 `MaterialVersionUpgradeService:359-366`。**saveDraft 不在其中** | `grep -rn refreshCostingCardValues` |

### 为什么测试工程师那次保存没有触发重算

它为了把表单弄脏，改的是**单据级的「备注」**，不是**行级数据** ⇒ `invalidateCardValues` 为 false ⇒ 卡片值不置 NULL ⇒ `ensureCardValues` 的 `IS NULL` 选不中 ⇒ 旧的全 `0` 原样留着。**这与本次修复是否生效无关**，是 task-260901 B-1c 的既有设计（它要治的是「每次保存都全量补算拖 54s」）。

## 🚨 由此引出的两件事（主线自己的更正与新增风险）

### 更正一：我在闸门 A 告诉用户的「存量单据随下次编辑自然重算」说得太笼统

准确口径应为三条：

| 触发 | 会不会自愈 |
|---|---|
| 编辑**该行的数据**（真的改了值） | ✅ 该行置 NULL → 下次 warm/读取时 `ensureCardValues` 重算 |
| **提交**（submit） | ✅ `forceRecomputeAll=true` 强制重算整单 |
| 只改**单据级字段**（备注 / 客户 / 联系人等） | ❌ **不自愈**，旧的 0 原样留着 |

### 风险二（新发现，须在闸门 B 前处置）：本单库值现在是「带修复后端算出来的」，而主仓 8091 尚未合并修复

`quotation_line_item.costing_card_values` 现在存的是 `5438667.5`，它由测试工程师的 **8093（worktree 带修复）** 算出。而用户在用的 **8091 是主仓代码、尚未合并本次修复**。

⇒ 若在合并前于 `5090/8091` 上编辑该行或提交本单，未修复的后端会**把它重算回 `0`**。

**处置**：合并前不要在 5090 上编辑或提交 `QT-20260911-0010`；主线亲验改在**带修复的 `5091/8093`** 上做（同库 `cpq_db_0910`、同真实单据，满足亲验四条中的「真实环境 + 真实数据」）。合并后 8091 热重载即与之一致。
