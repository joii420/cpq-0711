## 3. 需要主线裁决或知悉的问题（只报告，未改任何文档）

**问题 1（阻塞 AC-8 第 3 步两条断言）· 复制单带来的正式账不是「重算后的正式账」**
- 探查（`260918-2148-探查AC8前提/PROBE-AC8.log`，私有单 `e85fbd59`，已删除）：
  - A 复制后 ensure：`['1.978941064', '0.317766357', '1.804589425']`（与源单 0881 的旧正式账相同，ensure 没有重算）
  - B 正式账置 NULL 后重算，输入**没改**：`['1.726122101', '0.14567008', '1.705315785']`
  - C 加工费改为原值 `39.54034733`：`['1.726122101', '0.14567008', '1.705315785']`（与 B 相同）
  - D 加工费改为 `50`：`['1.726122101', '0.14567008', '1.715775438']`
- 结论：AC-8 原文里的 V1 取的是复制带来的旧正式账。改值会触发整卡重算，col_1/col_2 本身就会变（1.978941064→1.726122101），col_3 反而下降（1.804589425→1.715775438）。所以 P3 的「col_1/col_2 与 V1 相同」「V2.col_3 > V1.col_3」**在 master 和本分支上都必然红**，与本次改动无关。若以 B 为基线（先置 NULL 再重算），D 相对 B 满足 col_1/col_2 不变、col_3 上升 1.705315785→1.715775438，与 AC 的手算方向一致。
- 另外，0881 源单的正式账（1.978941064…）与现在重算的结果不一致，原因未查（可能是开发库价格变过）。它**可能影响 S1 AC-1/AC-2 判定值的时效口径**，报主线知悉。
