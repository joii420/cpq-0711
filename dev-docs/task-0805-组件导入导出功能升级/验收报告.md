## 4. 过程中我发现并要求修复的问题

| # | 问题 | 处置 |
|---|---|---|
| 1 | `FormulaBindingInspector` 判条件公式多要求 `rules` 是数组，与 `FormulaIdBinder` 的豁免判据不一致 → 「只配 default 无 rules」的字段会被 preview 判 `UNRESOLVABLE` 阻断，而 commit 实际放行 = **假阻断** | 已要求后端对齐并修复；实测该形态在 18 份包与开发库均 0 命中（潜伏边界非现网故障），测试已补 `U-B2-10` 用例 |
| 2 | 既有缺陷：checksum 警告塞进 `blockers` 但 `canCommit=true`，而前端只在 `!canCommit` 时渲染 blockers → **该警告用户从来没看见过** | 本任务顺手修：新增 `warnings` 与 `blockers` 分家，前端无条件渲染 |
| 3 | 我的实现计划 §5-11 定的两条反向门禁**在数学上无法生效**（往返对拍比的是同一份代码连续处理两次的产物，某步骤整体缺失时两侧一致地错、字面相等反而成立） | 由测试工程师发现、我复核确认后采纳，门禁改挂 AC-6 单次导入断言；需求 §3.6 已补澄清 |
| 4 | 测试工程师自查发现：其 AC-6 断言②在 `formula_id` 为空时 `continue` 跳过 → G-GATE-01 生效时会**静默假绿** | 已改为「preview 报可解析就必须非空，否则直接判失败」，修复后三条门禁均如实变红 |
