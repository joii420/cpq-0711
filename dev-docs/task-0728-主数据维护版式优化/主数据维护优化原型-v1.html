统一规范速查 4

以「工序」页签为基线，四个页签同一套骨架；后续新增主数据页签也照此实现。
区域规范
外壳不套 Card、不写页内标题（页签名即标题）。现「材质管理」「元素管理」两个 Card 拆掉。
工具栏一行两组：左＝查询（搜索框 280px → 过滤下拉，各 150px 起）；右＝动作（次级下拉 → 刷新 → 导入 → 新建）。flex + wrap，窄屏自动折行。
搜索框统一 Input.Search、宽 280px、allowClear、防抖 300ms、占位文案格式「搜索 字段A / 字段B」。
过滤下拉Select + allowClear，占位「维度名：全部」。料号核价＝配置状态；材质＝类型 + 状态；元素＝状态；工序＝是否外协 + 工序分类。与搜索合并成一次查询。
按钮新建＝primary + PlusOutlined（永远最右）；导入＝default + ImportOutlined（统一图标，材质页现用 UploadOutlined）；刷新＝default + ReloadOutlined；次级功能收进下拉。
动作条沿用 SelectableTable 选择驱动条（编辑靠左、危险动作靠右、禁用带 tooltip 原因）。料号核价除外（例外白名单）。
表格size="small"；首列为主入口链接（点击进详情/编辑抽屉）；空值统一渲染 —。
分页右下角；showTotal 显示「共 N 条」；showSizeChanger 页大小 10 / 20 / 50 / 100，默认 20；搜索或过滤变化后重置到第 1 页。
列排序 7每个数据列表头可点，三态循环：升序 → 降序 → 取消（回默认序）；当前排序列表头文字变蓝、对应三角高亮。同一时刻只有一列生效（单列排序）。详见下一节。
页签分页实现说明
料号核价服务端（已有）后端已支持 page/size，仅补过滤参数。
工序服务端（已有）后端已支持 page/size，前端解开写死的 PAGE_SIZE=20、打开 showSizeChanger。
材质前端分页（新增）现役 39 条，后端 list 返全量。用 Table 内置分页即可，不改后端。
元素前端分页（新增）现役 24 条，同上。

列排序 7

四个页签的每个数据列表头都可点击。交互沿用 Ant Design Table 默认三态： 第一次点＝升序　→ 第二次点＝降序　→ 第三次点＝取消（回到该页签的默认排序）。 同一时刻只有一列生效；勾选列不可排序。
⚠️ 这条需求会拉上后端：服务端分页的页签，排序必须由数据库做。 如果只在前端排当前这一页的 20 行，用户点「料号↑」看到的是「第 1 页那 20 条里最小的」而不是「全部 82 条里最小的」—— 这是看起来能用、其实是错的，属静默错误，不能这么做。
页签排序实现要不要改后端说明
材质前端排序不用全量 39 条已在内存，Table sorter 函数即可。
元素前端排序不用全量 24 条，同上。
料号核价服务端排序要列表接口加 sortBy + sortOrder 两个参数，ORDER BY 走字段白名单（防注入）；前端 sorter: true 受控、切页保持排序。
工序服务端排序要同上，改 ProcessMasterResource 列表端点。
页签默认排序（第三次点击回到这里）不参与排序的列

材质启用优先 → 修改时间 ↓ → 创建时间 ↓（现有后端口径，不变）无
元素启用优先 → 最后修改时间 ↓（现有后端口径，不变）无

两个细节：① 排序状态不跨页签保留，切走再切回恢复默认序；② 排序变化后回到第 1 页（与搜索/过滤一致）；③ 中文列（品名、名称、工序名称等）按数据库默认排序规则走，不额外做拼音排序 —— 如果业务要按拼音排，得单独提。
