## 2. 需求背景与目标

### 2.1 要解决什么问题

「主数据维护」（`/master-data-hub`）是把 6 个原本独立的管理页拼进一个壳页形成的，各页签由不同时期、不同任务分别落地，**从未做过统一**，导致同一个菜单下四种交互习惯：

| 页签 | 容器 | 搜索框 | 按钮位置 | 分页 | 列排序 |
|---|---|---|---|---|---|
| 工序 | 裸 | 工具栏**左**，240px | 工具栏左侧 | 服务端，写死 20 条不可改 | 无 |
| BOM | 裸 | 工具栏左 | — | 服务端 | 无 |
| 材质 | **Card**「材质管理」 | Card **右上**，260px | Card 右上角 | **无分页**（全量渲染） | 无 |
| 元素 | **Card**「元素管理」 | Card **右上**，260px | Card 右上角，**并排 4 个** | **无分页**（全量渲染） | 无 |
| 数据模板 | 独立页 | — | — | — | 无 |
| 料号核价 | 裸 | 工具栏**左**，320px | 无 | 服务端，可改页大小 | 无 |

具体痛点：
- 搜索框三种宽度（240 / 260 / 320）、两种位置（左上 / 右上），肌肉记忆失效；
- 材质、元素**一次性渲染全量**，条数增长后必然卡；
- **任何一列都不能点击排序**，只能接受后端写死的默认序；
- 导入按钮图标 `UploadOutlined` / `ImportOutlined` 混用；「元素」标题栏并排 4 个按钮，窄屏必折行；
- 4 个导入抽屉的文件选择框（`Upload.Dragger`）用默认尺寸，高约 180px 占满首屏，结果报告要滚动才看得到；「下载导入模板」按钮埋在说明文字里，位置各不相同；「开始导入」有的在正文、有的在标题栏 extra；
- 「导入核价数据」按钮挂在**壳页顶部**，与它实际服务的「料号核价」页签分离，其它页签下也一直显示。

### 2.2 目标

1. 页签精简到 4 个并按业务主次排序；
2. 四个页签共用一套版式骨架（搜索 / 过滤 / 按钮 / 动作条 / 分页 / 排序），新增页签照此实现；
3. 每个页签都能分页、每个数据列都能点击排序；
4. 四个导入抽屉共用一套骨架，文件框收窄，模板下载按钮位置与风格统一。

### 2.3 不做什么（边界）

- **不改任何列表的取数口径与业务字段**：列还是那些列、值还是那些值，只改版式与查询参数；
- **不改导入/写库逻辑**：导入抽屉只动 UI 布局与模板下载按钮，解析、落库、报告结构一律不动；
- **不动组件管理 / 模板管理 / 报价渲染三大核心基线**，不触碰 `field_type`（AP-44 不触发）；
- 不做多列组合排序（单列排序）、不做拼音排序、不做排序状态持久化。

### 4.3 统一版式规范（需求 4）

**以「工序」页签为基线**，四个页签同一套骨架：

| 区域 | 规范 |
|---|---|
| 外壳 | 不套 `Card`、不写页内标题（页签名即标题）。拆掉「材质管理」「元素管理」两个 Card |
| 工具栏 | 一行两组：**左＝查询**（搜索框 → 过滤下拉）；**右＝动作**（次级下拉 → 刷新 → 导入 → 新建）。`flex` + `wrap`，窄屏自动折行 |
| 搜索框 | `Input.Search`、宽 **280px**、`allowClear`、防抖 **300ms**、占位文案格式「搜索 字段A / 字段B」 |
| 过滤下拉 | `Select` + `allowClear`，占位「维度名：全部」，最小宽 150px。与搜索合并为一次查询 |
| 按钮 | 新建＝`primary` + `PlusOutlined`（永远最右）；导入＝`default` + `ImportOutlined`（统一图标）；刷新＝`default` + `ReloadOutlined`；次级功能收进下拉 |
| 动作条 | 沿用 `SelectableTable` 选择驱动条（编辑靠左、危险动作靠右、禁用带 tooltip 原因）。**料号核价除外**——它是 Master-Detail 纯查看页，属《列表操作规范》例外白名单 |
| 表格 | `size="small"`；首列为主入口链接（点击进详情 / 编辑抽屉）；空值统一渲染 `—` |
| 分页 | 右下角；`showTotal` 显示「共 N 条」；`showSizeChanger` 页大小 `10 / 20 / 50 / 100`，默认 **20**；搜索 / 过滤 / 排序变化后**重置到第 1 页** |
| 列排序 | 每个数据列表头可点，三态循环（升序 → 降序 → 取消回默认序）；单列排序；勾选列不排序 |

### 4.4 过滤维度（需求 4 · D5）

| 页签 | 过滤项 | 取值 | 落到哪 |
|---|---|---|---|
| 料号核价 | 配置状态 | 已配齐（`configuredCount >= totalSheets`）/ 未配齐 | 后端新增 `configured` 参数 |
| 材质 | 类型 | 标准锁定 `locked` / 含量可调 `editable` / 部分可调 `partial` | 前端过滤（全量在内存） |
| 材质 | 状态 | 启用 `ACTIVE` / 停用 | 前端过滤 |
| 元素 | 状态 | 启用 `ACTIVE` / 停用 | 前端过滤 |
| 工序 | 是否外协 | 外协 / 自制 | 后端新增 `isOutsource` 参数 |
| 工序 | 工序分类 | 取自现有数据 `distinct process_category` | 后端新增 `processCategory` 参数；选项由后端另给或前端从当前页去重（见 `api.md`） |

### 4.5 分页与排序的前后端分工（需求 3 / 7 · D2）

| 页签 | 数据量 | 分页 | 排序 | 动后端？ |
|---|---|---|---|---|
| 料号核价 | 82 条（会随业务增长到千级） | 服务端（已有） | **服务端** | ✅ 加 `sortBy` / `sortOrder` / `configured` |
| 工序 | 36 条 | 服务端（已有，页大小写死） | **服务端** | ✅ 加 `sortBy` / `sortOrder` / `isOutsource` / `processCategory`；解开页大小 |
| 材质 | 39 条 | **前端（新增）** | 前端 | ❌ 后端 `list` 返全量不变 |
| 元素 | 24 条 | **前端（新增）** | 前端 | ❌ 同上 |

> **为什么服务端分页必须服务端排序**：只在前端排当前页的 20 行，用户点「料号 ↑」看到的是「第 1 页那 20 条里最小的」而非「全部 82 条里最小的」——看起来能用、实则错误，属静默错误，不允许这么做。

**各页签默认排序**（第三次点击回到这里）：

| 页签 | 默认序 |
|---|---|
| 料号核价 | 最近更新 ↓（现有 `ORDER BY a.u DESC NULLS LAST, a.mno`，不变） |
| 材质 | 启用优先 → 修改时间 ↓ → 创建时间 ↓（现有后端口径，不变） |
| 元素 | 启用优先 → 最后修改时间 ↓（现有后端口径，不变） |
| 工序 | 工序编号 ↑ |

排序状态**不跨页签保留**，切走再切回恢复默认序。中文列按数据库默认排序规则，不做拼音排序。

## 8. 验收标准

**结构（需求 1 / 2 / 6）**
1. 「主数据维护」只有 4 个页签，顺序自左至右为 料号核价 / 材质 / 元素 / 工序；
2. 进入页面默认停在「料号核价」页签；
3. 壳页顶部无「导入核价数据」按钮；该按钮出现在「料号核价」页签工具栏右侧，点击打开原抽屉、导入行为逐字不变；
4. 侧边菜单与路由表中不再有「数据模板」，手输 `/config/config-templates` 也进不去；`ConfigTemplateManagement.tsx` 文件仍在仓库中；
5. `V6BomQueryTab.tsx` 文件仍在仓库中且无编译告警（仅无人引用）。

**版式（需求 4）**

6. 四个页签的搜索框宽度均为 280px、位于工具栏左侧第一位、`allowClear`、输入 300ms 后触发查询；
7. 材质 / 元素页签不再有 Card 外壳与「材质管理」「元素管理」标题；
8. 四个页签的导入类按钮统一 `ImportOutlined`；新建类按钮统一 `primary` 且位于工具栏最右；
9. 元素页签工具栏为 `[元素价格▾] [刷新] [＋新建元素]`，下拉展开含 价格源管理 / 价格导入 / 元素价格表 三项，点击后打开的抽屉与改造前一致。

**分页（需求 3）**

10. 四个页签都有分页器，位于表格右下角，显示「共 N 条」，页大小可选 10/20/50/100、默认 20；
11. 材质 / 元素页签在数据超过 20 条时只渲染当页行数（DOM 行数 = 当前页大小）；
12. 搜索或过滤条件变化后，页码重置到第 1 页。

**过滤（需求 4 · D5）**

13. 料号核价选「未配齐」后，列表中不出现 `configuredCount == totalSheets` 的行，且「共 N 条」随之变化（服务端计数，不是前端过滤后的残余）；
14. 工序选「外协」后只剩 `isOutsource=true` 的行，分页总数同步；
15. 材质选「类型=标准锁定」+「状态=启用」后，两个条件同时生效（与关系）；
16. 每个过滤下拉都能清空回「全部」。

**排序（需求 7）**

17. 四个页签的每个数据列表头可点击，三态循环：升序 → 降序 → 取消（回默认序），当前列表头有视觉高亮；
18. **料号核价按「料号」升序后翻到第 2 页，第 2 页首行的料号 > 第 1 页末行的料号**（证明是全表排序而非当前页排序）；工序同理；
19. 排序变化后页码重置到第 1 页；
20. 排序与搜索、过滤可叠加生效；
21. 切走页签再切回，排序恢复默认序。

**导入抽屉（需求 5）**

22. 四个导入抽屉宽度均为 840px；
23. 四个抽屉的「下载模板」按钮均在说明 Alert 右上角，样式为 `default` + `DownloadOutlined`，文案「下载模板」；
24. **核价数据导入抽屉的「下载模板」能下到一个 .xlsx，用它作为输入回传给导入端点不报「缺少 Sheet」类错误**（Sheet 名与导入器识别的 24 个 sheet 逐字一致）；
25. 四个抽屉的文件选择框高度明显缩小（图标与文案同一行），选完文件后仍能看到文件名与移除按钮；
26. 「开始导入」按钮统一在抽屉 footer 右下角；未选文件时禁用；
27. 四个导入的解析结果、报告内容、成功/失败提示与改造前逐字一致。

**回归**

29. 后端 `mvnw test` 相关模块全绿；

## 9. 依赖与风险

**前置依赖**：无。

**风险**

| 风险 | 说明 | 应对 |
|---|---|---|
| SQL 注入 | 排序字段来自前端 | `ORDER BY` **必须走字段白名单映射**，不允许拼接前端原串；白名单外的值回退默认序（不报错） |
| 料号核价排序列是聚合子查询别名 | `a.mno` / `a.c` / `a.u` 来自 UNION 子查询，`mm.material_name` 来自 LEFT JOIN | 白名单要映射到**已存在的投影别名**，不能新写表达式；实现时逐个跑 SQL 验证 |
| 核价模板 24 Sheet 名不一致 | 模板 Sheet 名与 `P01~P24` handler 的 `sheetName()` 必须逐字相同，否则下载的模板导不进去 | 模板生成**遍历 handler 注册表**取名，禁止手写常量数组（验收标准 24 专门验这条） |
| 「导入核价数据」权限 | 该按钮原在壳页顶部，移入页签后可见性口径不能变 | 按钮可见性沿用现有判断，不新增角色门 |
| 元素页签 3 个入口进下拉 | 抽屉挂载点从工具栏移到下拉菜单项 | 抽屉组件本身与 props 不动，只改触发入口 |

**关联**：`docs/列表操作规范.md`（工具栏动作模式）、`docs/反模式.md` AP-50（详情/编辑渲染 single-source，本任务不触碰但同属主数据区）。
