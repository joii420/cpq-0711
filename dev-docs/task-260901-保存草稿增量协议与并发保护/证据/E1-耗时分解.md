# E1 · 耗时分解（实测原文）

采集环境：dev server 8081（worktree 启动，共享），库 `cpq_db_0724`，2026-08-31 ~ 09-01。
基准单：`QT-20260901-0218`（id `46e5428f-f0ee-4dbb-93cb-cd6a4db9da6b`），1845 行 / 9225 组件行。

## 1. 用户「只改一个格子」的保存（本任务的直接触发场景）

```
2026-09-01 02:04:36.077 INFO  [QuotationService] [saveDraft-diag] id=46e5428f received lineItems=1845 batchStage1=true
2026-09-01 02:05:12.450 INFO  [QuotationService] Saved draft for quotation id=46e5428f
2026-09-01 02:05:19.345 DEBUG [QuotationResource] [draft-profile] id=46e5428f total=43204ms | S1.saveDraft=40056ms S2.snapshotRows=2622ms S3.priceReconcile=526ms
2026-09-01 02:06:19.089 INFO  [CardSnapshotService] [ensure-cardvalues] quotation=46e5428f 补算 1845 行（分 7 批，chunk=300，总耗时=54444ms，失败 0 批/0 行）
```

- **`received lineItems=1845`** —— 改一个格子，前端仍发全部 1845 行
- 02:04:36 → 02:05:12 = **36.4 s** 主循环（中间零埋点）
- S1 40.056 s − 36.4 s ≈ **3.7 s** 构建返回 DTO（实体在一级缓存中，故快于冷路径）
- **端到端 = 43.2 + 54.4 = 97.6 s**

## 2. 同一张单建单时已经算过一遍

```
2026-09-01 02:00:29.092 [ensure-cardvalues]  补算 1845 行，总耗时=11074ms   ← 建单物化③
2026-09-01 02:00:38.444 [lazy-excel] ensureExcelValues 补算 1845 行，总耗时=9256ms  ← 建单物化④
```

另一张同型单的完整四步（`77ffe749`）：

```
[create-quotation-timing] ①snapshotQuotation=22676ms ②ensureStructure=399ms
                          ③ensureCardValues=27257ms ④ensureExcelValues=47152ms 总计=97484ms
```

⇒ 建单时报价侧与核价侧卡片值**一起入库**（`CardSnapshotService:830` 的 UPDATE 一条语句同时写 `quote_card_values` 与 `costing_card_values`），不等 saveDraft。saveDraft 是它们的**失效**时机而非入库时机。

## 3. 空 patch 对照（分离「处理明细」与「组装返回体」）

对同型单发 `PUT /draft` body=`{}`（`lineItems` 为 null ⇒ 明细整块跳过）：

```
[draft-profile] id=1288120e total=37680ms | S1.saveDraft=18834ms S2.snapshotRows=5654ms S3.priceReconcile=13192ms
响应 24612102 字节
```

- S1 = **18.8 s**，其中不含任何明细行处理 ⇒ 该 18.8 s ≈ **组装返回体的成本**
- 与场景 1 的 S1=40.1 s 相减 ⇒ 处理 1845 行明细 ≈ **21.3 s**
