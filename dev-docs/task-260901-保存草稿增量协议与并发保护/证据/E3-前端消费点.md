# E3 · saveDraft 响应的前端消费点（④ 的改动依据）

穷举 `QuotationWizard.tsx` 中对 `saveDraft` 响应的使用，共 **2 处**：

## 1. `syncLineItemsFromResponse`（`:794`）

每行**只读 6 个字段**：

```js
if (r.id != null && String(r.id) !== String(item.id)) patch.id = r.id;
if (r.partVersionLocked != null && ...) patch.partVersionLocked = r.partVersionLocked;
for (const k of ['quoteCardValues','costingCardValues','quoteExcelValues','costingExcelValues']) {
  if (r[k] != null && r[k] !== item[k]) patch[k] = r[k];
}
```

⚠️ **两个约束**：
- `if (respLines.length !== prev.length) return prev;` —— **按下标对齐**，长度不一致则整体放弃回填
- `if (r[k] != null)` —— saveDraft 刚把两个 CardValues 置 NULL，故这两项回传即为 null、前端也跳过

**`componentData` 从未被读取。**

## 2. `setQuotationPreservingStructures`（`:783`）

只用单头字段，并保护 4 份结构快照不被抹成 undefined：

```js
const merged = { ...resData };
for (const k of ['quoteCardStructure','costingCardStructure','quoteExcelStructure','costingExcelStructure']) {
  if (merged[k] == null && prev?.[k] != null) merged[k] = prev[k];
}
```
