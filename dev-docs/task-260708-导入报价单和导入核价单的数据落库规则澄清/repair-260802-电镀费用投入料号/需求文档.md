## 1. 背景与动机

### 1.1 用户诉求

给电镀 sheet 增加两列：**【投入料号】【投入料号名称】**（均**非必填**）。理由：电镀费用页签的**页签类型是「零件」**，零件类型页签必须能拿到该费用项针对的**实际零件料号**。

### 1.2 现状问题（数据实证）

当前两侧 handler 都把**销售料号写进 `unit_price.code`**，且 `finished_material_no` 恒空：

| | 报价侧 `Q17PlatingCostHandler` | 核价侧 `P22PlatingCostHandler` |
|---|---|---|
| `code` | `row.getStr("销售料号","宏丰料号")` | `row.getStr("销售料号","宏丰料号")` |
| `finished_material_no` | 不写（NULL） | 不写（NULL） |

**但实测数据显示，业务实际填进「销售料号」列的已经是零件料号**：

```
QUOTE / PLATING 现役 18 行（9 加工费 + 9 材料费）：code 全部 = 'S-80011'
material_master: S-80011 → material_name='投入零件1', material_type='零件'
真正的销售料号是 S-3120014539（material_name='主料1'）
```

即：**业务本就按零件维度记电镀费用，只是 sheet 没有专门的列，被迫塞进了「销售料号」列**。这导致：

1. `code` 语义与全表其余 sheet 不一致（详见 §2）；
2. `finished_material_no`（成品轴）丢失，费用无法上卷到成品，BOM 闭包类视图取不到数；
3. 若把该列当销售料号绑给零件页签的 `partNoField`，`BomNodeTypeResolver` 会**把成品误判成零件节点**（`dev-docs/rule-260724-组件模板配置/4-页签属性与树.md:33` 明列此坑）。

## 2. 口径核查：`unit_price` 全表两列语义（本次改造的依据）

对全部 **14 个写 `unit_price` 的 handler** 逐个核查源码，结论**无一例外**：

| 分类 | Sheet（handler） | `code` | `finished_material_no` |
|------|------------------|--------|------------------------|
| **有零件/来料维度** | 来料固定加工费(Q06)、来料其他费用(Q07)、来料年降(Q08)、来料回收折扣(Q09)、自制加工费(Q10)、组成件其他费用(Q13)、来料加工费(P15)、来料其他费用比例(P16)、来料其他固定费用(P17) | **零件料号**（投入料号 / 来料料号 / 组成件料号） | **销售料号** |
| **无零件维度（退化）** | 成品其他费用(Q11)、组装加工费年降(Q15)、生产耗材BOM(P13)、包装材料BOM(P14)、加工费&组装费(P18)、成品其他比例·固定(P19/P20)、其他外加工(P23) | 退化为**销售料号** | 不写（Q15 例外：也写销售料号） |
| **主数据轴（无成品维度）** | 元素核价价格表(P01)、材料核价价格表(P02) | 元素代码 / 材料料号 | 不写 |

**实测数据佐证**（10 行 `finished_material_no` 非空的现役行，`code ≠ finished_material_no` 100%）：

```
PRICING INCOMING_PROCESS 来料加工费  code=S-2120011658  fmn=S-3120018220
QUOTE   COMPONENT_OTHER  材料费      code=W-1001(组成件1) fmn=S-3120014539
QUOTE   PROCESS          自制加工费  code=S-80011(投入零件1) fmn=S-3120014539
```

**权威规则**（`dev-docs/rule-260724-组件模板配置/4-页签属性与树.md:42`，2026-07-23 用户澄清）：

> `code` = **零件料号**（该费用项针对的零件），`finished_material_no` = **成品料号**（该费用上卷到的成品）。二者常同值，但语义不同、别处会分叉——按**语义**绑 `code`，别按值相等偷懒绑 `finished_material_no`。

> ✅ **结论**：本次改造 = 让电镀两个 sheet **归队到"有零件维度"分类**，与 Q06/Q07/Q13/P15 完全同构。**无需任何 DDL** —— `finished_material_no` 早已在 `uq_unit_price` 13 维唯一键内（`V276`）。

## 3. 目标落库口径（改造后）

### 3.1 报价侧「电镀费用」（Q17 → `unit_price`，`system_type=QUOTE`，`price_type=PLATING`）

| Excel 列 | 目标字段 | 必填 | 说明 |
|---------|---------|:----:|------|
| **投入料号**（新增） | `code` | ❌ | 零件料号。有值→沿用原始码（不 resolve、不铸号，对齐 Q06/Q07） |
| **投入料号名称**（新增） | 不落 `unit_price` | ❌ | 仅在「料号空 + 名称有值」时用于反查/铸号，并 upsert `material_master`(material_no + material_name + material_type) |
| 销售料号 | `finished_material_no` | ✅ | **改**：原落 `code`，现落成品轴 |
| 电镀方案编号 | 不落库 | — | 非空→整行跳过（行为不变） |
| 版本编号 | 不落库 | — | 忽略，`version_no` 系统自增 2000 起（行为不变） |
| 电镀加工费 | `pricing_price`（`cost_type=电镀加工费`） | — | 空→`ZERO`（行为不变） |
| 电镀材料费 | `pricing_price`（`cost_type=电镀材料费`） | — | 空→`ZERO`（行为不变） |
| 货币 / 计价单位 / 不良率 | `currency` / `unit` / `defect_rate` | — | 行为不变 |
| 固定值 | `system_type=QUOTE`、`price_type=PLATING`、`customer_no`=导入上下文 | — | 行为不变 |

**groupKey**：`(system_type, customer_no, price_type, cost_type, code, finished_material_no)`
—— 比现状多 `finished_material_no`，与 Q06/Q07 一致。
**content**：`[pricing_price, currency, unit, defect_rate]`（不变）。

### 3.2 核价侧「电镀成本」（P22 → `unit_price`，`system_type=PRICING`，`price_type=PLATING`）

| Excel 列 | 目标字段 | 必填 | 说明 |
|---------|---------|:----:|------|
| 生产料号 | `production_no` | ❌ | descriptor（不进唯一键、不进升版比对）；行为不变 |
| **投入料号**（新增） | `code` | ❌ | 零件料号，进 content（组内明细维度，对齐 P15） |
| **投入料号名称**（新增） | **不落库、不参与解析** | ❌ | 与 P15/P16/P17 的「品名」列一致：核价侧物料均已有正式码，名称仅供 Excel 可读；渲染取名由视图 `JOIN material_master` 负责 |
| 销售料号 | `finished_material_no` | ✅ | **改**：原落 `code`，现落成品轴并作为分组锚点 |
| 电镀方案编号 / 版本编号 | 不落库 | — | 行为不变 |
| 电镀加工费 / 电镀材料费 | `pricing_price`（拆两条 `cost_type`） | — | 行为不变 |
| 货币 / 计价单位 / 不良率（%） | `currency` / `unit` / `defect_rate` | — | 行为不变 |

**groupKey**：`(system_type, price_type, finished_material_no)` —— 锚点从 `code` 换成 `finished_material_no`，**与 P15 完全同构**（一个销售料号 = 一个版本组，任一明细变化整组升版）。
**content**：`[cost_type, code, pricing_price, currency, unit, defect_rate]`（新增 `code`）。
**descriptor**：`[production_no]`（不变）。
**组内去重键**：`(code, cost_type)` —— 现状是 `cost_type`，扩一维以支持"同一成品下多个被电镀零件"。

### 3.3 「非必填」的三种情形（两侧一致）

| 情形 | `code` 落值 | 说明 |
|------|------------|------|
| 投入料号**有值** | 投入料号原始码 | 名称列忽略（有码沿用原码，对齐 Q06/Q07 U10 §6.1 第 1 条） |
| 投入料号空、**名称有值** | **报价侧**：按 `TypeIndex` 推类型 → 材质查 `material_recipe`、零件/外购件走 `MaterialNoResolver` 反查或铸号 + upsert `material_master`<br>**核价侧**：不解析，同下一行（回退销售料号） | 报价侧沿用 Q06/Q07 既有机制；核价侧保持与 P15 一致不引入新语义 |
| **两列都空** | **回退为销售料号** | 语义 = 「电镀针对成品自身」。`code` 是 `NOT NULL` 且在唯一键内，不允许留空；此回退与 **Q15 组装加工费年降**（无零件列时 `code` 与 `finished_material_no` 同写销售料号）是同一范式 |

> 📌 **不报错**是「非必填」的硬要求：现有 Q06/Q07/Q09 在「料号与名称均为空」时 `recordError`，电镀两个 handler **不得**照抄该分支。

## 7. 验收标准

1. 报价侧导入含【投入料号】【投入料号名称】的电镀费用 sheet，`unit_price` 中 `code` = 投入料号、`finished_material_no` = 销售料号；
2. 只填名称不填料号时，报价侧能反查/铸号并 upsert `material_master`，且该解析发生在 **Phase 1**（零写库阶段）；
3. 两列都空时**不报错**，`code` 回退为销售料号，落库结果与改造前逐字段一致；
4. 同一销售料号下多个投入料号各占独立行（不再互相覆盖）；重复导入幂等、单值变更只升本组版本；
5. 核价侧「电镀成本」同口径落库，`dj_view` 与 COMP-0063 取数正确（销售料号列显示销售料号、新增两列显示投入料号与名称）；
6. 存量 18 行清理后无重复行；
7. 两份落库方案文档与实现逐字段一致，含 §6 偏差修正。
