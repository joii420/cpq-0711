# 需求文档：自制加工费可选工序名称字段

> 状态：路径 A，方案唯一（语义图查名边），待实现与验收。建立日期：2026-10-22。

## ① 背景与目标

组件管理的「取数配置 → 自制加工费」字段面板目前只有「工序编号」，配置人员无法选择工序名称。目标是在工序编号之后增加可选的「工序名称」字段，并由 `process_master` 按工序编号关联查询 `process_name`。

## ② 范围

### 做什么

- 在报价侧自制加工费字段树中提供可拖拽的「工序名称」字段。
- 字段顺序紧跟「工序编号」之后。
- 编译生成的 SQL 使用 `LEFT JOIN process_master`，连接 `operation_no = process_no`，输出 `process_name`。
- 未匹配工序时保留自制加工费原行，工序名称为空，不影响已有字段和行数。

### 明确不做

- 不修改自制加工费导入模板、`ds_quote_self_process_fee` 表结构或工序主数据维护功能。
- 不给其他费用数据源批量增加工序名称字段；如有需要另立任务。
- 不修改已有组件已保存字段配置；存量组件需由配置人员按需重新打开并拖入新字段。
- 不生成部署包（用户未明确要求打包/部署）。

## ③ 验收标准（AC）

- **AC-1 字段可选且顺序正确**：以配置角色打开组件管理中的取数配置，选择数据源「自制加工费」；字段树中存在「工序编号」和「工序名称」，且「工序名称」紧跟「工序编号」之后，可将「工序名称」拖入已选输出列。
- **AC-2 编译查询工序名称**：选择自制加工费的工序编号、工序名称后执行编译/预览；生成 SQL 含 `LEFT JOIN process_master`，连接条件等价于 `process_master.process_no = ds_quote_self_process_fee.operation_no`，并选择 `process_master.process_name` 作为工序名称列。
- **AC-3 空工序名不丢行**：准备一条工序编号在自制加工费中存在但 `process_master` 无匹配的行，预览仍返回该行，工序名称为 NULL/空值；已有工序编号和值列保持原值。
- **AC-4 存量回归**：不选择工序名称时，原有自制加工费字段树、编译 SQL 的已有列和行数不发生变化。
- **AC-5 自检证据**：后端迁移成功，语义图加载无错误；相关后端测试通过，前端 TypeScript 检查通过。

## ④ 依赖与影响面

- 依赖语义图表（`semantic_node`、`semantic_node_column`、`semantic_edge`、`semantic_edge_key`）和 `FieldTreeBuilder` / `SemanticCompiler` 的通用查名机制。
- 影响组件取数配置字段树、编译 SQL、预览及由该配置生成的新组件视图；报价渲染层沿用现有 `BASIC_DATA` 路径，不新增字段类型或接口形状。
- 需要回归自制加工费字段树、编译、预览及已有配置器三套数据集路径。
- 不触碰 `docs/架构基线.md` 的数据模型基线；仅补充现有语义图声明与迁移。
