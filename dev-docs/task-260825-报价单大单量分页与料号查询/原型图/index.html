设计要点（三条，都跟需求直接对应）
要点为什么这么定
分页栏独立一行，在两级 Segmented 之下它同时作用于「报价单 / 核价单」×「产品卡片 / Excel 视图」四种组合。放进任一 Segmented 同行都会暗示「只管这个视图」，与需求 2「两侧渲染一致、同步分页参数」相悖。
顶部 + 底部各一个分页器每页最多 500 张卡片，只放顶部则必须滚到顶才能翻页；只放底部则进页就得先滚到底。这是长列表的既定做法。
序号用全局序号，不用页内序号第 2 页从 11 起。用页内序号（每页都从 1 起）会让用户对不上「这是第几个产品」，也对不上导出 Excel 里的行序。
已知边界（写在这里，免得当成缺陷）
① 服务端零改动：全量 23.04 MB 仍一次性返回、101 MB 数据仍常驻内存。分页砍的是「渲染」那 426 MB（占 73%）。58 + 101 = 159 MB 是本方案踩不穿的地板。
② 打开耗时只省渲染那一段：Step1 的 22.2 s（取数+解析）不变，Step2 的 32.0 s 降到约 1.7 s。
③ 首存 / 建单超时本期不解决，需服务端 partial 语义，已转二期。
④ 比对视图不动——它已有自己的前端分页与料号过滤。
