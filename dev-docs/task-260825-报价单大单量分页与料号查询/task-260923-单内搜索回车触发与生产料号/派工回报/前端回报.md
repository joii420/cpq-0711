## 5. 规避掉的坑

1. **antd `onPressEnter` 的 keyLock**：实测只派发 keydown、没有 keyup 时，第二次回车会被吞掉（probe 结果 1→1）。E2E 如果用 `dispatchEvent` 模拟回车，AC-8「组字回车后再按一次普通回车」这类连续操作就可能假红，真实用户也可能碰上（比如回车后焦点没离开、keyup 丢了）。所以不用 `onPressEnter`，改为自己写 `onKeyDown` 加 `isSubmitEnterKey`。另外确认过：antd `onPressEnter` **本身会忽略** `nativeEvent.isComposing=true` 的回车（源码 `@rc-component/input` 1.1.2 `es/Input.js:117`，probe 实测 0 次）。
2. **Safari 组字确认**：Safari 先派发 compositionend，再派发确认上屏的那次 keydown，这时 `isComposing` 已经是 false，只能靠 `keyCode === 229` 认出来。只判 `isComposing` 的话，Safari 上组字的回车会被当成搜索。已排除。
3. **「删光即恢复」不能分两次 setState**：草稿和生效查询放在同一个 state 里一次性更新，避免出现「框已经空了、列表还是过滤状态」的中间帧；也不需要额外的 effect 去监听草稿。
4. **空态引号本来要跟着草稿变**：两处都用的是 `pgSearchInput`，不改的话，AC-7「追加 -9 后不变」会失败。两处都改成了 `pgSubmittedSearchText`。
5. **`PagingBar` 的 `onSearchSubmit` 设成必填**：这样漏接回车的调用方会被 `tsc -b` 直接拦下，不会静默变成「按回车也搜不了」。
6. **lint 误归因**：4 个文件原本就有 289 条 lint error，我先记了改动前的基线，再逐条比对，确认新增为 0，没有把旧问题算成本次引入，也没有顺手去修。
7. **证伪实验的还原**：用绝对路径 `cp` 还原，再比 sha1、看 Vite 返回的模块内容，确认已经还原（testing.md §5.7①③）。
