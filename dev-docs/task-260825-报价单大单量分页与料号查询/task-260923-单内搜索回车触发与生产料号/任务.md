## ① 背景与目标

**现状**（2026-09-23 读码 + 实测）：报价单编辑页、报价单详情页、核价工作台三处，分页栏里有同一个料号搜索框（组件 `PagingBar` + `usePagedSearch`，`task-260825` 交付）。

- **触发方式**：框里停止输入约 **0.2 秒**就自动过滤（`usePagedSearch.ts` 的 `SEARCH_DEBOUNCE_MS = 200`）。用户原话称「失焦自动触发」，实际是「停止打字即触发」，与失焦无关。
- **匹配字段**：销售料号（`productPartNo`）、客户产品编号（`customerProductNo`）、客户料号名称（`customerPartName`），大小写不敏感子串匹配。**不含生产料号。**
- **生产料号在哪**：卡片右上「销售料号」徽标点开的浮层，第一行「料号：」（`hfPartInfo.partNo`，后端按「本单客户 + 销售料号 → `ds_quote_material.production_no`」取，已按客户过滤，见 `QuotationService.java` 生产料号注入段）。编辑页、详情页走 `GET` 报价单接口下发；核价工作台走**提交时冻结**的 `costing_order.frozen_dto`，同样带这个字段（开发库实查：99 张核价单中 68 张冻结数据含该字段、19 张有值）。

> 🚨 **术语别混**：`task-260825` 的需求文档（AC-10）与原型把 `productPartNo` 写成「生产料号」—— 按现行口径（决策台账 `production_no` 条：`material_no` = 销售料号、`production_no` = 生产料号）**它其实是销售料号**。
> **本任务所说的「生产料号」一律指 `production_no`**（= 徽标浮层里的 `hfPartInfo.partNo`）。对照 `task-260825` 旧 AC 时按此换算。

**目标**：

1. 搜索改为**按回车才触发**。
2. 同一个框里**加上生产料号**的模糊匹配（不加新框）。

**不做会怎样**：要按生产料号找产品，只能逐张卡片点开徽标看；大单（开发库最大 1845 个产品）里等于找不到。
