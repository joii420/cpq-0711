## 3. AC-13 原文无法按原文执行 / 有歧义的地方

1. **「该产品的客户产品编号按回车能搜到」在 QT-20260908-0628 上无法执行。** 接口 `GET /api/cpq/quotations/22b14b66-…` 返回的 1845 行里，`customerProductNo` 有值的是 **0/1845**（`customerPartName` 也是 0/1845，`hfPartInfo` 也是 0/1845）。`material_customer_map`、`ds_quote_customer_part` 里都查不到 `T260907T-B%` 在 CUST-0004 下的记录。行上只有 `customerPartNo`（如 `ZT-BULK-01200`），但它不属于 D-3 列出的匹配字段。⇒ T-10b 只能跳过。**需要主线裁决**：换样本、造数，或者把这一项从 AC-13 里去掉/改写。🚫 我没有自行换成按 customerPartNo 搜。
2. **「控制台无 error」的采集范围有歧义。** 探针在 master 上打开这个页面、**还没搜索时**，控制台就已经有 6 条 `console.error`，都是 React/antd 开发模式的警告（`[antd: Drawer] width is deprecated`、`message Static function…`、`<form> cannot be a descendant of <form>` ×2、`[antd: Alert] message deprecated`、`[antd: Spin] tip deprecated`）。原 T-11 从进入页面起就开始收集并断言 `== []`，所以即使前置问题消失，**它在 master 和分支上都会稳定变红**，原因与搜索无关。可选做法：①把采集范围收窄到「按回车之后」；②只统计 `pageerror`（task-260923 AC-12 的口径）。这属于改验证口径，**我没有改**，请主线裁决。
3. 「第 1200 位」我按 `sort_order` 升序的第 1200 行（下标 1199）取，本轮是 `T260907T-B01200`（沿用原 spec 的口径）。
4. AC-12 换算成默认页大小 10 后，原 spec 只断言「第 2 页**包含**命中集合第 11~20 条」，没有断言「不多出别的」。这是原 spec 的松紧度，本轮没有收紧。
