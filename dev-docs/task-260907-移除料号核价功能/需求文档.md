## ① 背景与目标

### 现状

「料号核价」是主数据维护壳页（`/master-data-hub`）的**第 1 个页签，也是默认落点**（`MasterDataHubPage.tsx:23,35`）。

它是 `task-0712`（核价基础数据维护）+ `task-0728`（版式优化）建的 **V6 老核价数据维护 UI**：

- 前端走 `/api/cpq/pricing-basic-data/*` 七个端点；
- 后端由 `com.cpq.basicdata.v6.maintenance` 整包承载，按 `PricingSheetRegistry` 登记的 **16 个"版本组"**读写 V6 表（`unit_price` / `material_bom_item` / `element_bom_item` / `production_energy` / `capacity` / `labor_rate` / `tooling_cost` 等）；
- 页签内还内嵌了「导入核价数据」按钮 → `PricingBasicDataImportDrawer` → `POST /basic-data-import/v6/pricing` + `GET /basic-data-import/v6/pricing/template`。

### 为什么现在移除

`task-260902-报价与核价建表与导入方案新规范` 交付后，核价基础数据已改由**「基础核价」/「详细核价」两个新页签**按新数据集规范维护（读写 `ds_cost_*` 新表，走 `/api/cpq/dataset/{dataset}/*`）。「料号核价」这条老链路业务上不再使用，但仍占着壳页的默认落点。

继续保留它的代价：

1. **入口误导** —— 打开主数据维护，第一眼落在一个已停用的页签上；
2. **维护负担** —— 前后端合计约 2500 行代码（后端整包 1765 行 + 前端专属 756 行）+ 3 个后端测试类 + 4 个 E2E spec，每轮重构都要跟着改；
3. **公共件被拖累** —— 它与三个新页签共用 `EditableSheetTable` / `SheetPartListTab` / `types.ts` / `createSheetApi`，公共件每次演进都要额外兼顾一条已停用的调用路径（`task-260902` 的 `AC-42「现有料号核价页签零回归」`就是这个负担的具体形态）。

### 目标

移除页签入口与其专属前后端代码；**在此前提下，共用公共件与其余 6 个页签零回归、V6 表数据零变化、核价单渲染零变化。**

### 不做会怎样

已停用的入口继续做默认落点，且每次改公共件都要为它多做一轮回归验证。

> 🚨 **2026-09-07 修正（后端代理提出，主线复核确认）**：本条原写 `POST /v6/pricing → 404`，**该值不可达**。
> 根因：`/pricing` 是**单段子路径**，删掉 `@POST @Path("/pricing")` 后，它落到同类保留的 `@GET @Path("/{recordId}")` 模板上；
> JAX-RS **先按路径模板匹配、再匹配 HTTP 方法**，该模板只有 GET 没有 POST ⇒ 返 **405 Method Not Allowed**（UUID 转换根本没走到）。
> 实测对照（已复核 `BasicDataImportV6Resource.java:153-156` 确认模板仍在）：
> ```
>                                              master(8081)   本分支(8099)
> POST /v6/pricing                                401       →     405     ← 端点被删的证据
> POST /v6/zzz-not-a-path                         405             405     ← 405 是 /{recordId} 的既有兜底，master 上本来就有
> GET  /v6/pricing                                401             401     ← 走 /{recordId} 的 GET，被鉴权拦下
> ```
> ⚠️ **所以「等于 405」这个绝对值不是证据**（乱打一个不存在的路径也是 405），**「401 → 405」这个变化量才是**。
> 🚫 **不许为了凑 404 去改 `@Path("/{recordId}")` 加 UUID 正则约束** —— 那会改到必须保留的端点（`api.md §2`）。
- 🔁 **反向对照**：`GET /api/cpq/basic-data-import/v6/{recordId}`，`recordId` 取**执行时实查** `SELECT id FROM import_record LIMIT 1` 的任一现存值 → HTTP **200** 且响应体 `data` 非 null
> ⚠️ 反向对照与被删的两个端点在**同一个 Resource 类**里，专门证明「删的是方法不是整个类」。
> 🚨 **2026-09-07 修正（并发撞车）**：本条反向对照原为 `POST /v6/quote` 不传 `customerId` → 400。并发任务 `task-260907-报价导入建单切ds新表`（其 B-10）要把 `/quote` 改为返 **410**，若沿用旧对照，本 AC 会在对方合并后变成必然失败的假红。改用 `GET /{recordId}` —— **该端点两条任务线都明确保留**（对方 `api.md §4` 写「必须保留」，本任务「不做」第 6 条同样不碰），故判据不受对方进度影响。
