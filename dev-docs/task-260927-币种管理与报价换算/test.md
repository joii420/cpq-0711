# 测试方案与 AC 追溯矩阵

## 1. 测试分片

| 分片 | 写入面 | AC | 隔离口径 |
|---|---|---|---|
| S-API | 币种、汇率、汇率历史导入、客户、元素价格、报价单服务 | AC-1~12、AC-18~25、AC-27 | 每个用例使用 `FX260927_` 前缀；数据库夹具只写本分片对象 |

## 2. 自动化测试类型

- 单元测试：换算方向、12 位计算、9 位展示、CNY 自身汇率、缺汇率/负汇率、同日最后一条有效记录、汇率导入整批校验。
- 集成测试：币种/汇率 CRUD、客户默认币种、客户汇率策略与试算、价格导入归一化、同日最后有效记录、历史兼容和报价创建快照事务。
- 日期策略测试：指定日期、上月某天、每月（指定日）、上月最后一天；每月（指定日）未到达时取上月同日，短月跳过；指定日期控件不得选择未来日期；命中日期无汇率时报错；同日多条只取最后更新值。
- 数据库测试：迁移成功、唯一约束、旧表数据不变、新表只产生新记录、无 `exchange_rate_v6` 读写耦合。
- 前端测试：批次币种选择、导入结果、汇率策略配置/试算、报价单创建只读快照、报价侧单币种小计、核价侧双币种小计、比对外币列、组件公式 `[汇率]` 标签、禁用和错误态。AC-12 断言报价卡片存在 `15,000.000000000 JPY` 且无 CNY 小计行，现有列名未追加币种；切到核价卡片，断言同时存在 CNY 700 与 JPY 14,583.333333333，再切回报价卡片仍仅一行 JPY 小计且不出现 `￥`/`¥`。单头的汇率方向含 CNY 属正常上下文，不作为“报价侧显示 CNY 小计”的判据。
- 前端测试：币种历史 Drawer 按当前币种过滤、汇率导入单币种选择/预览/错误态/成功回刷。
- E2E：创建客户→配置汇率策略→导入元素价格→创建报价单→验证汇率快照→打开核价和比对视图→修改策略后确认原报价单不变。

## 3. 关键证伪实验

1. USD=7.2、720 CNY 创建 USD 报价单后必须为 100 USD；反向把汇率当乘数必须失败。
2. 同一币种同一天存在多条汇率时，策略试算必须只采用当天最后一条；平均窗口不得重复计权。
3. 修改客户默认币种后，已建报价单的币种、汇率和金额逐字段不变。
4. 报价单创建后不存在切换/刷新入口；修改客户策略后，原报价单快照和所有产品金额字节级不变。
5. 核价侧始终使用报价单创建时固化的汇率快照；CNY 公式结果不被外币小计反向污染。
6. 历史 `element_daily_price` 记录不具备新归一化字段时仍能被旧策略取价；新记录必须使用 CNY 基准字段。
