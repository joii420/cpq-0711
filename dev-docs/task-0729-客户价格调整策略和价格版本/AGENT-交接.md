## 3. 核心模型速记（背下来）

```
客户调价策略（周期 + 执行时刻 + 料号范围 + 参与元素 + 毛利预警线 + 比对列配置）
   │
   │ 到点触发（定时扫描每 15 分钟 / 或手动「立即生成一次」）
   ▼
元素价格版本 V26080501       ← V + YYMMDD + 两位当日流水
   ├── 报价侧快照：该客户 element_price_strategy 算出的元素价
   └── 核价侧快照：_GLOBAL_ element_price_strategy 算出的元素价    ← 裁决 41，双侧同源
   │
   │ 系统预算：受影响料号两侧各预演重算 → 按客户比对列出差异
   ▼
料号待办池（跨客户）
   │ 财务逐料号审核，依据 = 该料号【最近一张单】的比对列差异
   ├── 通过 → 料号版本指针 V26070501 → V26080501
   │          所有活单中该料号的【报价侧 + 核价侧】卡片重走公式
   │          单据产生/并入 R 版本（R + YYMMDD + NN，一期一版）
   └── 驳回 → 指针不动，两侧原样，下一期重新评估
```

**四个层次不要混**：

| 概念 | 粒度 | 编号 | 谁持有 |
|------|------|------|--------|
| 元素价格版本 | 客户 × 一次调价 | `V26080501` | 客户 |
| 料号版本指针 | 客户 × 料号 | 指向某个 `V` | 料号 |
| 报价单快照版本 | 报价单 × 一期 | `R26080501` | 报价单 |
| 比对列配置 | 客户 | — | 客户 |

## 4. 🔴 硬约束（违反即返工，不接受"我觉得这样更好"）

### 4.1 隔离纪律（本方案的生命线）

1. **只对被升版的料号行执行重算与 `recompute`**。哪怕输入没变，也**不得**"整单重算一遍" —— 会走引擎兜底路径造成静默漂移。
2. 通过料号 A 后，料号 B 的 `quote_card_values` / `snapshot_rows` / `line_total_amount` / `discountRateApplied` 必须**逐字节不变**。这是验收要点 #14，会被逐字段断言。
3. 单据级聚合（`quotation.total_amount`、税额）随之变化是**预期**，不算破坏隔离。

### 4.2 核价侧纪律

4. **只动 `quotation_line_item.costing_card_values`**（报价单内的核价卡片值）。
5. **核价单 `costing_order` 的 frozen 快照逐字节不动**（task-0713 冻结语义）。验收要点 #21 会断言。
6. **禁止把客户策略价用于核价侧** —— 核价侧只能用 `_GLOBAL_` 口径，否则成本会随客户不同而不同，破坏成本口径。

### 4.3 版本纪律

7. 版本号 `V/R + YYMMDD + 两位当日流水`，流水按**客户 + 日期**（`R` 按**单 + 日期**）独立计数。**不要**用自增整数。
8. **`R` 版本一期一版**：同一 `V` 版内多次料号升版**合并**进同一 `R`（更新「最后更新」+ 追加「已升版料号」），**不新建版本号**。
9. 新版生成即把上一版**整体作废**，未处理料号随之失效；**已通过并执行的更新不回滚**。

### 4.4 取价纪律

10. **新建函数 `f_material_element_price`，不要改 `f_customer_element_price` 的签名** —— 后者被 6 个 `mc_view` 在用，改签名等于强制一次性全量迁移且无法回滚。
11. 6 个 `mc_view` 的 `sql_template` 迁移必须**可逆**（保留原文备份）。
12. `DataLoader.resultCache` 等按 `$view` 的缓存键**必须含客户 + 料号维度**，否则跨单串价（历史教训：`$view 缓存 key 需含 componentId`）。
13. **改视图 / DDL 后必须重启 Quarkus**（`ImplicitJoinRewriter.tableColumnsCache` 等是进程级缓存，见 CLAUDE.md「视图 DROP CASCADE / 重建后必须重启」）。

### 4.5 UI 纪律

14. 屏 3 待办池**严格按 `docs/列表操作规范.md`**：行内零动作按钮、动作上提工具栏、禁用态**置灰 + hover 说明原因**（**禁止** `if (...) return null` 隐藏）。
15. **一律 Drawer，不用 Modal** —— 唯一例外是屏 5 的危险动作二次确认（列表规范明确允许）。
16. 元素矩阵（屏 1）必须**一次 pivot 查完**（元素 × 版本），**不得**逐元素查 10 次。

### 4.6 范围纪律

17. **§11.12「明确不做清单」14 条**，一条都不要"顺手"加回。特别是：不做抓价爬虫、不做手工值保护/已改标记、不做编辑锁、不做版本回滚、不硬阻断跌破毛利线的通过。

全部在澄清期间用 SQL / 源码查证过，可直接引用：

| # | 事实 | 影响 |
|---|------|------|
| 1 | `f_customer_element_price(p_customer_no, p_base_date)` **只有两个入参**，返回 `(element_code, unit_price, currency, price_unit)`，**无料号维度** | 必须新建料号级函数（裁决 31） |
| 2 | 全库 **6 个 `mc_view`** 以 `ON cep.element_code = ebi.component_no` 接入该函数；视图内**本就有 `ebi.material_no`** | JOIN 条件加得上，不用改数据源 |
| 3 | `quotation` 表**零个** lock / edit 列，全系统只有 `ProductImportLock` / `DdlOperationLock` | 无编辑锁 → 用乐观时间戳（裁决 32） |
| 4 | 卡片值按 `quotation_line_item` 存（1 line_item = 1 销售料号 = 1 产品卡片） | 料号级隔离天然成立 |

| 6 | `discountRateApplied` 的 **4 个写入点全是前端草稿的持久化人工值**，后端无"按总额匹配折扣阶梯"逻辑 | 料号 A 涨价不会让 B 的折扣率跳档 |
| 7 | `ComparisonViewService` 的 `productTotal` = SUBTOTAL 组件页签 `subtotal`；同款算法 `CostingSubtotalUtil#extractUnitSubtotal` | 比对/毛利口径**直接复用**，与 task-0717 逐位同口径 |
| 8 | `quotation_comparison_config`（`quotation_id` + `bucket` + `columns` jsonb），`ColumnDef` schema 见 task-0717 api.md §5 | 比对列 schema 原样复用；但存储维度要改成**按客户** |
| 9 | `ScheduledTaskService` 已有三个 `@Scheduled` 任务（00:30 / 01:00 / 03:00） | 新增扫描任务与之并列即可 |
| 10 | `material_customer_map`：客户料号 = `customer_product_no`，名称 = `customer_material_name`，销售料号 = `material_no`；**`customer_product_no` 现网大量为空** | 屏 1 料号矩阵按此取数，空值显示「—」但可勾 |

## 8. 本任务特有的坑（预警）

| 坑 | 说明 | 规避 |
|----|------|------|
| **预算与实际不一致** | 若核价侧预算用实时价、执行用版本价，两者会差 | 严守裁决 41：两侧都从**同一版本快照**取，禁止任何一端实时算 |
| **视图迁移后不重启** | 改 `sql_template` 后进程级缓存残留，BNF 路径求值不注入谓词 → 视图返全表 | 改完**必须重启 Quarkus**，并用含料号的端点验证返单值 |
| **缓存串价** | `$view` 缓存键漏料号维度 → A 料号拿到 B 料号的价 | 缓存键含 `customerCode + materialNo`；写完用两个不同料号交叉验证 |
| **跨客户列表列不统一** | 比对列按客户配置，待办池是跨客户的 | 列表固定列 + 汇总标记，抽屉才展开（裁决 43，已在原型体现） |
| **`_GLOBAL_` 无策略** | 某元素没有 `_GLOBAL_` 取价策略 → 核价侧无价 | 版本明细该元素核价侧标「无价」，审核页显式提示，**不要**回退到客户价 |
| **手工值被冲掉** | 裁决 37 明确直接覆盖，但销售会懵 | 完成通知里**必须**带"此前手工调整可能已被覆盖，请复核" |
| **grep 静默返空** | 本环境 `grep` 是 `ugrep -I` | 用 `/usr/bin/grep -a` 复核 |

## 9. 三处"明示接受的取舍"（验收不得以此判不通过）

1. **单内同一元素可能有多个价**（§11.1.1）：料号 A 已升版、B 被驳回时，Ag 在两张卡片里价格不同。**是预期行为**，屏 7 料号级版本表逐行可查证。
2. **销售手工值被覆盖**（裁决 37）：系统不记录哪些值被手改过，升版一律覆盖；只在通知里提示复核。
3. **快照永久保留**（裁决 38）：不做清理，需配套库体积监控。
