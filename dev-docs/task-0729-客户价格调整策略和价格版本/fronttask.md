## 1. 屏 1 · 价格调整策略 Tab

**落位**：定价管理 → 定价策略 → 选中客户 → **第 3 个 Tab**（新增）。

### 1.1 策略表单

- 周期**四形态**联动切换：每天 / 每周[星期几] / 每月[N 号] / 每月第[N]周[星期几]。
- **执行时刻** `HH:mm`（策略配置，**不写死**）。
- 料号范围模式：所有料号 / 指定料号。
- **成本差额预警线**：🔒 **金额输入**（E13，**不是百分比**），默认 `0`，提示「报价侧成本 − 核价侧成本 < 该值即标红」。
- 启用状态开关：提示「停用后不再自动生成版本；已生成版本与已生效价格不受影响」。
- 表头显示「最新已生成版本」+「🕘 变更历史」按钮（Drawer 展示 `GET .../logs`）。

### 1.2 指定料号矩阵

- 四列：客户料号 / 客户料号名称 / 对应销售料号 / 对应销售料号名称。
- **四个筛选框**均模糊匹配、**可组合**；🔒 **勾选跨页保留**；「只看已选」用于提交前复核。
- ⚠️ `customerPartNo` 现网**大量为空** → 显示「—」但**照常可勾**（策略记录的是**销售料号**）。
- 🔒 **移出料号需二次确认**：保存时后端返 `409 REMOVAL_NEEDS_CONFIRM` + 影响面 → 弹确认「移出 N 个料号：其 `待处理` 审核记录将作废退出待办池，且这些料号在存量单上的元素单价列将解锁为可编辑」→ 用户确认后带 `confirmRemoval:true` 重试。

### 1.3 参与调价元素矩阵

- 左侧元素行（可过滤分页），右侧 **10 列 = 最近 10 个版本**：单价（大字）+ 较上一版涨跌幅（小字，**涨红跌绿**）。
- 列头 = 完整版本号 + **两态**（`待处理` / `已被新版取代`）。
- 🔒 **两种空值必须渲染不同**：`priceState=NOT_IN_LIST` → `—`（当时不在清单）；`priceState=NO_PRICE` → `无价`（在清单但算不出值）。
- 🔒 **已停用元素必须可见**：`elementEnabled=false` 的行标「**已停用**」，**照常在清单里**（禁止前端自行过滤掉）。默认 `includeDisabled=true`。
- 🔒 **取消勾选需二次确认**：后端返 `409 UNSELECT_NEEDS_CONFIRM` → 弹「该元素将退出调价机制，N 张存量单上它的单价列将解锁为可编辑，销售可能改动」。
- 历史不足 10 版按实有出列。

### 1.4 比对列配置区

- 🔒 顶部加**模板系列选择器**（`GET .../template-series`，标出各系列最新版本号与 `is_default`），**选中后才连线**。
- 复用 **task-0717 的连线配置抽屉**（`ColumnDef` schema 一致）。
- 默认「产品总价」列 `removable:false`，**不可删除**。
- 🔒 **这是比对列的唯一写入口**（屏 4 只读）。
- 保存后提示「已触发 N 个待处理料号的预算重算」（读响应 `affectedReviewCount`）。

### 1.5 版本轨迹 + 立即生成一次

- 轨迹表：版本号 / 基准日 / 状态（两态）/ 触发方式 / 进度摘要（通过 N / 驳回 M / 待处理 K，**服务端实时派生**）。
- 「立即生成一次」：
  - 后端返 `400 STRATEGY_NO_ELEMENTS` → **就地提示**「未配置参与调价元素，本策略不会生成版本」（不弹全局 error）。
  - 后端返 `409 PENDING_VERSION_EXISTS` → 🔒 **弹二次确认**，文案含「`V26080501` 将被作废，其中 **N 个待处理料号**退出待办池（**已通过的 M 个不回滚**），确定重新生成？」→ 确认后带 `confirmSupersede:true` 重试。

## 2. 屏 3 · 价格调整审核 · 料号待办池

**落位**：定价管理 → **价格调整审核**（新增菜单项，限 `PRICING_MANAGER` / `SYSTEM_ADMIN`）。

### 2.1 列表（`SelectableTable`）

**固定列**（跨客户，**不随客户配置变化**）：客户 / 料号（**主入口链接**）/ 料号名称 / 当前版本 → 目标版本 / 依据单号+日期 / 报价侧成本(现→调整后) / 核价侧成本 / 差异 / **比对状态** / 审核状态。

🔒 **比对状态标记格式**（红橙**分开计数**，禁用旧写法「M/N 列跌破」）：

| 标记 | 条件 | 整行标红 |
|---|---|---|
| `✓ N 列全通过` | `breachedCount=0 && amberCount=0` | 否 |
| `🟠M / X列` | 有橙无红 | **否** |
| `🔴N 🟠M / X列` | `breachedCount > 0` | **是** |
| `⚪K` 追加 | `missingCount > 0`（缺数据） | 计入红（后端已算进 `breachedCount`） |

🚨 **整行标红严格 = `rowRed`（服务端给）**，**不是**「产品总价差异 < 0」。原型屏 3 第 5 行 `10120240` 镀银铜带就是样例：产品总价 +4.05 健康，但自定义列已卖穿 → **整行必须红**。此条专防实现写成 `产品总价差异 < 0 ? 标红 : 不标红`（验收 #25）。

### 2.2 🆕 预算中间态（E14-3，**原型上没有，必须新增**）

| `budgetStatus` | 呈现 | 动作按钮 |
|---|---|---|
| `QUEUED` / `COMPUTING` | 该行比对列区显示「**预算计算中**」（骨架/Spin） | 🔒 「通过并升版」「驳回」**置灰 + hover 说明「预算尚未计算完成」**（**不是隐藏**） |
| `READY` | 正常显示 | 可用 |
| `FAILED` | 标「**预算失败**」 | 提供「重算」入口（`POST .../recompute-budget`） |

预算算完后**无需用户手动刷新即可转可审**（轮询或重新拉列表均可，自行选实现）。

### 2.3 工具栏动作（**行内零按钮**）

| 动作 | `enabledWhen` |
|---|---|
| 通过并升版（N） | 选中 ≥1 且**全部** `reviewStatus=PENDING && budgetStatus=READY`，否则禁用并给原因 |
| 驳回 | 同上；点击弹 Drawer 填**必填原因** |
| 重算预算 | 选中项含 `budgetStatus=FAILED` |

🔒 **料号链接点击 → 打开屏 4 抽屉，须 `e.stopPropagation()`**；点行内其他位置 = **切换选中**（保留批量语义）。

## 3. 屏 4 · 料号审核抽屉（1100px Drawer）

**三段结构**（对应财务思考顺序，缺一不可，§11.5.2）：

1. **为什么变** —— 元素 / 命中规则 / 上版价 / 本版价 / 涨跌 / **该料号用量** / **对单价影响**；底部合计须与「调整后报价 − 现报价」**对得上**（财务自检位）。
2. **能不能接受** —— 🔒 **按该料号所属模板系列的配置逐列完整展开**（这是比对项的**唯一完整体现处**）。着色：`RED` 红 / `AMBER` 橙 / `NORMAL` 正常 / `MISSING` 显示「**—（缺数据）**」/ `STALE` 显示失效提示（**不标红**）。
3. **下钻** —— 逐单明细，最近一张挂 `判断依据` 标签，其余标「仅作参考」；每张单直达 task-0717 比对视图。🔒 **本抽屉不重复实现页签级比对**。

🔒 **抽屉内无任何可修改比对列的控件**（只读展示，§11.5.3(4)）—— 改比对列 = 改审核判断标准，且会触发预算重算，财务正在看的这屏数据会当场变化。

## 6. 屏 7 · 报价单价格版本抽屉（1000px Drawer）

**入口**：报价单**详情页 + 编辑页**顶部「价格版本」按钮。销售**可见但只读**。

### 6.1 两张表

**① 整单版本轨迹表**（一期一行）：`R` 版本号 / 依据 `V` 版本号 / 已升版料号 / 首次生效 / 最后更新 / 报价总额 / 操作（切版预览）。
- 🔒 **涨跌对比按料号级对齐**（§11.7.0 边界 2）：两版都有 → 算涨跌；只在新版有 → 标「**本期新增**」不算涨跌；只在旧版有 → 标「**已移除**」。**不逐行对齐**（两版结构可能不同），**不得因行数不同报错或错位**。

**② 料号级价格版本表**（单内每个料号各处在哪一版）—— 这是 §11.1.1「单内混合价」的**可查证据**：

| `state` | 呈现 |
|---|---|
| `UPGRADED` | 显示当前版本号 |
| `REJECTED` | 显示停留版本号 + 「未升版」 |
| 🔒 `NOT_UPDATED` | **必须显式标「尚未更新」**，**不得**直接显示已推进的新版本号 —— 否则这张证据表会说谎（§11.6.3.1 后果 2） |
| `NOT_PARTICIPATING` | 「未参与调价」 |

### 6.2 切版只读预览

🔒 **预览态必须禁用**：所有输入框 / 保存 / 提交 / **导出**（避免导出一份并非单据真值的报价发给客户）。退出预览恢复。
🔒 **双侧都从快照渲染** —— 报价侧与核价侧**都取 `preview` 接口返回的快照值**，**禁止核价侧读当前值**（验收 #55 专防；这种错误"报价侧看着完全正常"，极难发现）。
