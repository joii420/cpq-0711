### 错值来源：缩到两个写入方 + 关键判别证据

- **(a)** 前端「快照回填 bake」effect：`cpq-frontend/src/pages/quotation/QuotationStep2.tsx:2495-2545`，按 `ri` 下标把 `exp.rows[ri].basicDataValues` 解析出的默认值写进 `comp.rows[ri]`

### 🚨 顺带证实的后端真实隐患（可证伪、可复跑）

`CardSnapshotService.seedEditRowsFromRowData` 号称有「逐行内容校验，不等即跳过」的护栏（javadoc 第 3 条），实测在本例数据形态下**空转**：
- 配对键 = `usableKeyPartIndexes(rkfNames, flatRows)` 挑出的 `row_key_fields` 段 → 这里只有「销售料号」一段；
- `buildFlatRowIndex`（`:3762`）把 4 行 row_data 全部塞进**同一个** key `R0910S3-M1` 的 `ArrayDeque`；

⇒ **当多行的 `row_key_fields` 值全同时，这条护栏检测不出任何错位** —— 它比对的正是那几列全同的值。
