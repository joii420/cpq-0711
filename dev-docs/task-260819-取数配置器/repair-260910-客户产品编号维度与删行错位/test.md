## 3. 🚨 本任务专属的假绿陷阱（测试员必须逐条规避）

| # | 陷阱 | 规避动作 |
|---|---|---|
| ① | **"1 行"可能是碰巧** | 本 bug 上一次就是这么漏掉的：`repair-260908` 验收时该料号在客户料号表里**恰好只有 1 行**，缺维度不产生可观测差异。⇒ **AC-1 的前置数据必须确保该料号在 `ds_quote_customer_part` 里有 ≥2 行**，先跑 `SELECT count(*)` 确认再验 |
| ② | **断言空跑** | 断言行内容前先断言「结果非空」；要求用例**打印实际值**，不要只比较布尔 |
| ③ | **测到旧代码** | 改后端必须确认服务真的热重载了（大范围变化会重编译，期间 8081 短暂无响应属正常）。判后端健康看业务端点返 **401**，🚫 不要用 `/q/health`（未装 smallrye-health，恒 404，**它不是健康探针**） |
| ④ | **还原实验（本任务强制）** | 🚨 **本行原写「把 B-2 的谓词改回去重跑」，已于 2026-09-10 由 S2 实测证伪并作废** ——实测：视图重生成**之前**，跑着 B-1~B-5 全部 Java 改动的实例产品页签**仍是 4/7/4 行**，与 master 逐字节相同。⇒ **决定渲染行为的是已落库的 `sql_template`，不是编译器的实时产出**；回滚编译器而不重编译视图，结果必然不变，按原判据会被误读成「白测」（`testing.md §5.5` 形态②：验了一个恒真的东西）。而真回滚＝改共享库 `sql_template`＝全局写入，测试片无批准权。<br>✅ **改用这三个（S2 已执行，全部在私有写入面内）**：**E3 两版视图定义对跑**（同时刻同夹具，旧模板 4 行 / 新模板 1 行 ⇒ 证明绿不是恒真）·**E1 正向控制**（改明细行客编 → 渲染值跟着变 ⇒ 证明绑定是活的）·**E2 ON/WHERE 判别**（填表中不存在的客编 → **1 行且客编空**；0 行＝误入 WHERE，4 行＝谓词未生效） |
| ⑤ | **E2E 基线漂移** | `quotation-flow.spec.ts` 在干净 master 上**恒有 3 条失败**（夹具单缺产品分类致 Step1「下一步」禁用）。⇒ 判回归必须**同型 A/B 对比**，🚫 不许把这 3 条记成本次引入 |
| ⑥ | **`mvnw test` 不可能全绿** | `mat_*` 表在本库**从未创建**，25 个测试夹具 / 235 处红是既有状态。⇒ **只对本次相关的测试类做绿判**，不把全量绿当门槛 |
| ⑦ | **必现 ≠ 缺陷** | 确定性复现只证明「不是 flaky」，不证明「是缺陷」。报缺陷前先补一个「用户实际看到的是什么」的维度（`testing.md §4.1.5`） |
