## v1 为什么作废（三处都是「判据无论好坏都给同一答案」）

| # | v1 的做法 | 为什么是假的 |

| ② | 「保存是否真发生」读 `it.cardSnapshotAt` | **DTO 上没有这个字段** ⇒ 恒 `null`。改读 `userDataVersion`（saveDraft 必 +1） |

## 量具自证（🚫 判据不许恒定）

```
页签按钮 12 个；「产品」页签命中 4 个卡片      ← 0 = 找不到元素，不是「0 行」
对照 BOM 页签 = [4,6,6,5]  ≠  产品 [1,1,1,1]  ← 行数确实随页签变，不是恒 1
```

## ⚠️ 本轮量具造成的一处损伤，已按原路复原

`inputs.first()` 落在**销售料号**（行键）上，把一张卡片的 `S0001` 写成了 `QY615055`。

- **权威层未受损**：`snapshot_rows` 里 `hf_part_no` / `_物料_销售料号` 仍是 `S0001`，
  受影响的只有派生层 `row_data[0].销售料号`。
- **复原走同一条 UI 路径**（`quote-card-edit` + 保存草稿），🚫 没有动生 SQL —— 见 `复原记录.log`。
- **教训**：随机取 `first()` 的可编辑格可能正好是**行键列**。
  写入型 AC 的目标格必须**显式避开行键**，否则「值没保住」会被读成产品缺陷，
  而实际是行身份被改掉了。
