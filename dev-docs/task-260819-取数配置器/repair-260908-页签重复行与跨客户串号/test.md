🚫 **共库片禁用全局计数断言**（`testing.md §4.5`）：不许写「`component_sql_view` 共 28 条」
这类断言 —— 并发线随时可能建新视图，会被打红而且**红得像业务回归**。
一律断言「我自己造的那些对象」。

🚨 **同一 worktree 内不得并发跑 `mvnw`（S-2 2026-09-08 实证，主线定为硬纪律）**

S-1 与 S-2 共用同一棵树的 `target/`，两个 maven 同时跑会**互相清写 class 文件**。
S-2 头两轮的 4 项失败全部由此而来，且**每次症状都不一样**：

```
第 1 轮  NoClassDefFoundError: SqlViewRuntimeContext$Snapshot / CostingTreeSqlValidator$Result
         （嵌套类加载不到，但文件明明在）
第 2 轮  Could not load class PreviewLiteralBindingAcTest（自己的类没了）
等 S-1 的 maven 退出后复跑同一份代码 → 6/6 绿
```

⇒ **根因在共享临时目录，不在业务代码**，但它**长得像回归**（`testing.md §4`「随机挂一条、每次挂的还不一样」）。
**处置：主线按片串行解锁，同一时刻只有一个分片在跑 `mvnw`。** 🚫 不采用「给一片隔离副本」——
那会引入第二棵树，与「任务文档只在一个地方改」同型的分叉风险。

🚨 **证伪实验若需改动实现文件，测试员必须先报主线**（S-2 2026-09-08 自曝）

`testing.md §4.4` 要求每片做还原实验，但改实现文件越过了「测试员不写业务代码」（`CLAUDE.md §4.0`）那条线。
S-2 这次做得干净（约 60 秒窗口、仅一行、还原后 `git status` 空 + 与副本 `diff` 逐字节一致 + 复跑 6/6 绿），
**且它自己报了备** —— 但纪律要写死：**改实现做证伪 ⇒ 先报主线**，由主线决定是自己改、派后端配合、还是授权测试员改。

🚫 **S-全局 的 `confirm=true` 不由子代理执行。** 子代理只跑 `confirm=false` 预览、把影响面数字交回；
真执行属 `CLAUDE.md §3.2` 边缘，由**主线报用户批准后**进行。失败时**保留现场不回滚**。

## 2.5 🚨 一个现成的「量具失效」反面样本（并发线 2026-09-08 实测，直接拿来用）

对方采基线时第一版清点 SQL 拿 `component.row_key_fields`（`["销售料号","料号"]`）去 `formulaResults` 里取值，
**四个页签全返 `<null>`** —— 看起来像个结论（「行键字段没落库」），实际是
`formulaResults` 的元素形状是 `{rowKey, values}`，**业务列根本不在顶层**。

⇒ **判据指向了不存在的键，产出的是恒 `<null>`，不是发现。**

- 反面样本原件：对方证据目录的 `99-量具失效样本-恒null.txt`
- **要从 `row_key_fields` 反推行键时，直接读 `fr->>'rowKey'`**，别走那条弯路

📌 这与 `AC-16` 必须写成结构断言是同一类问题：**判据落在恒成立（或恒为空）的维度上时，不是弱证据而是零证据。**

## 3. 量具自证（🚨 强制，不许跳）

`task-260907` 一天内造过三次假绿，共同点是**量具本身是坏的**。本次每个量具**先在已知答案上跑一遍**：

| 量具 | 自证方式 |
|---|---|
| **表名匹配正则** | 先拿 `ds_quote_material` 对 `ds_quote_material_bom` 跑一次，**必须不命中**；再对 `ds_quote_material` 跑，**必须命中**。两个方向都过才用 |
| **编译产物 diff** | 先人为改一个字符，确认 diff **报红**；再还原，确认 **为空**。🚫 不许拿两个空文件比出「相同」就打勾 |
| **行数计数器** | 先打一个已知返回 N 行的请求，确认计数器**读出 N**；计数器恒返 0 的量具不许用 |
| **400 断言** | 先确认该请求在**提供** `customerCode` 时确实 200 —— 否则「400」可能来自别的原因（`task-260907` 的 `AC-16` 就栽在「操作根本没执行」） |

🚨 **一条来自并发线的实证教训（写进本片的验收前提）**：对方用正则 `FROM\s+(ds_quote_\w+)` 抽主表，

**「歪打正着」比明确的错更危险，因为它让人以为判据是对的。**
⇒ S-1 的判据**必须显式区分「外层 FROM」与「子查询 FROM」**，并各自独立断言（`AC-2b` 管外层，`AC-16` 管桥）。
| S-2 | 把 400 改回静默 `NULL` | `AC-5` **必须变红** |
| S-3 | 把 `SELF` 分支改回恒加宽 | `AC-1`（行数=1）**必须变红** |
