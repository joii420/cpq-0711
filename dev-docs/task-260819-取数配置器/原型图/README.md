## 相对 v8 原型改了什么（逐条对应裁决）

| 裁决 | 改动 |
|---|---|
| **D-12** | 每行两个名字：**字段名**（可改，= 模板上显示的名）+ **视图列名**（灰色只读，系统按来源生成） |
| **D-13** | 视图列名统一 `_<Sheet简称>_<原列名>`，是 (Sheet,列) 的**纯函数**（`_材质库_材质名称` / `_元素BOM_组成含量`） |
| **D-09** | 价格策略三列渲染为**一个带框的块**，整块拖动，删块三列同走，「货币」可单删 |
| **D-08** | 与已选展开维度打架的整组列**拖拽期直接置灰 🚫** + 悬停给原因 |
| **D-10** | 改名体检去掉冻结单阻断，改为「视图列名与绑定路径不变，已存在单据零影响」 |
| **D-14** | 打开时的过期提醒条 |
| **D-20 → D-25** | 料号/名称/行键/排序 **5 列复选框取消**。角色**不是配置器里的东西** —— 它是**字段树声明的属性**（字段声明里直接写 `PART_NO`/`PART_NAME`/`ROW_KEY`/`SORT`），配置器**只读展示、无任何修改入口**：左侧字段树里拖之前就看得见标记，已选列里显示为不可点击的徽章 |
| **D-26** 🐛 | 附属源的维度声明改为「**相对主源额外增加的维度**」。原先照抄 Sheet 自身维度，导致材质元素页签下「物料BOM（材质边）」整组被冲突判定**误置灰**（而 AC-5 恰恰要求能拖它）。修后置灰数 9→0，拖入后粒度不变、仍是标量子查询；主件的真冲突仍拦 5 列 |
| **D-21** | 「查看生成的 SQL」从弹层改为**右侧常驻面板**，随拖拽实时刷新（`white-space:pre` + 横向滚动，不折断 SQL） |
| **D-22** | 体检只显示阻断与告警，通过时只一行「检查通过」 |
| **D-23** | 真实预览**常驻页面下方**；底部只剩 `⋯` / 取消 / 保存，「转为手写 SQL」收进 `⋯` |
| **D-24** | 剥离全部讲解内容，另存方案说明版 |
| 🐛 **顺带修的 v8 原型 bug** | 主件页签收窄条件全在 JOIN 里 → 条件为空时原本会吐出一个**裸 `WHERE`**（非法 SQL）。已改为条件为空时不输出 |
| **D-27 ~ D-30** 🆕 | 语义图谱页抬头改为「读 `semantic_*` 6 张表呈现」口径 + 四道保存期校验说明 + 「改动不触达存量视图」提示；边基数说明块改为**保存期拦截 + CI 兜底**双层。**删掉「声明源码」视图整段**（展示 `QuoteSemanticGraph.java` 与「没有配置页面，也不需要」，与 D-27 正相反）。内嵌模拟数据的注释补上「真实实现读表，勿当实现形态参考」 |
| 🐛 **本次修的定稿版 bug（P0）** | `nav()` 仍在遍历 `['cfg','graph','src']`，而 D-24 剥离时已删掉 `nv-src` 导航项 → 访问 `null.className` **抛错并中断 `nav()`**，写在 forEach 之后的 `renderGraphPage()` **根本执行不到** → 点「语义图谱」得到**一片空白**。已改为 `['cfg','graph']` 并清掉 `view-src` / `renderSrcPage` 死代码 |

## 分期归属

- **一期**：5 类平铺页签（主件 / 材质元素 / 零件 / 外购件 / 费用类）的全部交互
- **二期**：**BOM 树**页签、🔄 **语义图管理页**（顶栏「语义图谱」入口；D-27 后由「只读图谱」升级为**看/改两级**，非 `SYSTEM_ADMIN` 不渲染任何输入控件）
