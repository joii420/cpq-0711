# API 契约：报价卡片含税总计展示

## 1. 结论：HTTP / JSON 契约零变更

本任务不新增、删除或修改任何 HTTP 端点，不改请求方法、路径、参数、JSON 字段、字段类型、错误码或权限。因此测试完成后不回写 `dev-docs/main-api.md`，但必须在 `test-report.md` 明记“本次无契约变更，无需回写”。

## 2. 现有输入契约

前端继续从既有报价查询响应读取：

| 值 | 现有形态 | 本任务用途 |
|---|---|---|
| 产品小计 | canonical decimal string | 第一行原值，以及含税派生值的乘数 |
| `vatRateRatio` | canonical decimal string，语义为 `0..1` 比率 | 含税派生值的优先税率来源 |
| `vatRate` | canonical decimal string，语义为百分比数值 | 仅在 ratio 缺失时作兼容回退，使用前除以 100 |
| 报价币种 | 既有 string | 两行同币种展示，不作汇率换算 |

前端派生规则：`taxInclusive = productSubtotal × (1 + vatRateRatio)`。这是展示规则，不改上表字段的传输语义。

## 3. 查询与保存契约不变

- `GET /api/cpq/quotations/{id}` 和报价编辑依赖的既有查询继续返回原产品小计、`vatRate`、`vatRateRatio` 和快照；不新增 `taxInclusive*` / `vatInclusive*` / `display*` 字段。
- 草稿保存、卡片编辑、重算、快照、对账和提交的请求/响应不携带新派生金额。
- 销售角色看到的 4 位文本与其他角色看到的 9 位文本都不能回写 API；查询 JSON 仍是角色无关的原 decimal string。
- 历史报价仅使用自身已冻结的 VAT 字段；前端不调用产品或税务主数据接口补值。

## 4. 错误、权限与降级

- 未登录、无查看/编辑权限、报价不存在等响应状态码和错误体保持不变。
- VAT 快照缺失/非法不产生新 HTTP 请求或新错误码；卡片第二行本地降级为 `(VAT) -`，第一行与页面其他区域继续渲染。
- 本任务不扩大定价经理/销售/系统管理员的原有路由与操作权限。

## 5. 回归确认与二期触发条件

- 测试要对保存前后 JSON 字段集合和目标 decimal string 做逐字比较，不用“页面看起来没变”代替契约证据。
- 只有后续要求保存、导出、汇总或在后端计算含税金额时，才允许增加 API/DTO/数据库契约，并需重走用户裁决。

## 6. AC 对应关系

| AC | 本契约中的落点 |
|---|---|
| AC-1、AC-2、AC-4 | §2 现有输入与前端派生规则；§4 税率异常本地降级。 |
| AC-3 | §3 编辑/详情共用同一现有 JSON 契约。 |
| AC-5 | §3 保存不新增派生字段、不回写显示值。 |
| AC-6 | §2/3 核价数据与响应形状不变。 |
| AC-7、AC-8 | 不改 API；由前端渲染/构建回归完成。 |
