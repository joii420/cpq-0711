# API 契约：报价结果按角色显示精度

## 1. 总则

本任务不新增或删除 URL，不改变请求方法、参数、JSON 字段、错误码或权限白名单。变化只发生在服务端生成的 HTML/xlsx/邮件附件文本：最大显示位数由发起请求的已认证会话角色决定。

| 当前角色 | 报价计算结果最大显示位数 |
|---|---:|
| `SALES_REP` | 4 |
| `SALES_MANAGER` | 4 |
| `PRICING_MANAGER` | 9 |
| `SYSTEM_ADMIN` | 9 |

共同规则：`HALF_UP`、去尾零；字段显式配置位数低于角色上限时取较小值。角色只能来自服务端会话，客户端不得通过 body、query 或 header 自报显示位数。

## 2. JSON 查询与保存契约不变

以下响应继续返回现有 canonical decimal string / 数据库精度值，不按角色预舍入，也不新增 `displayValue`：

- 报价列表和 `GET /api/cpq/quotations/{id}`。
- 报价 Excel 视图、比对视图所依赖的 JSON 数据端点。
- 草稿保存、重算、快照、对账、提交等请求和响应。

示例：底层值为 `"1.2345678915"` 时，销售经理和系统管理员拿到的 JSON 值相同；前端分别显示 `1.2346` 与 `1.234567892`。销售经理保存无关文本字段后，该字符串和数据库值逐字不变。

原始输入/基础属性同样不套角色上限，包括用户输入数字、汇率、税率、利润快照及基础资料取数值。

## 3. 服务端输出端点

### `POST /api/cpq/quotations/{id}/export/html`

query `showDiscount`、`showProcesses`、`showTabDetails` 不变。HTML 中计算金额按当前会话角色显示 4/9 位；HTTP 内容类型、文件名和状态码不变。

### `POST /api/cpq/quotations/{id}/export/pdf`

请求 body 不变；当前实现仍返回浏览器打印用 HTML。其计算金额与 HTML 导出使用同一当前角色上限。

### `POST /api/cpq/quotations/{id}/export/excel`

请求 body 的 `showDiscount`、`includeRawData` 不变。摘要 Sheet 的计算金额写为精度安全文本并按当前角色显示；原始数据 JSON 和非计算值不被统一压到 4 位。

### `GET /api/cpq/quotations/{id}/export-excel-view`

计算列类型 `FORMULA`、`CARD_FORMULA`、`TAB_JOIN_FORMULA`、`EXCEL_FORMULA` 按当前角色上限；取数列/输入列保留原精度。列配置 `display_format.decimals` 小于角色上限时优先。

### `POST /api/cpq/quotations/{id}/comparison/export`

`ComparisonExportRequest` 保持现有 decimal string 请求体，不增加角色或位数字段。后端以当前会话决定报价值和核价值的输出上限；阈值、差异分类和请求原值不受格式化影响。

### `POST /api/cpq/quotations/{id}/send`

`to`、`cc`、`subject`、`body`、`attachExcel` 不变。HTML 附件及可选 Excel 附件使用发起发送操作的当前会话角色上限；收件人身份不参与显示位数判定。既有“仅 APPROVED 可发送”、收件人校验和 `SENT` 状态流转不变。

## 4. 错误与权限

- 未登录且 RBAC 开启：仍返回 401，不因显示策略回退为任意角色。
- 无报价查看/导出/发送权限：维持现有 403/业务错误；本任务不扩大权限。
- 报价不存在、状态不允许发送、参数非法：沿用现有错误码和消息。
- 不识别的角色不得由客户端构造；服务端会话角色枚举仍以现有四个值为准。

## 5. 兼容性与总账

- 旧前端 + 新后端：普通 JSON 完全兼容；下载文件按当前用户角色改变最大显示位数。
- 新前端 + 旧后端：页面可按角色显示，但旧后端下载仍为最多 9 位；验收/部署必须保持前后端同版本。
- 数据库和历史报价零迁移；同一历史报价由不同角色查看/导出只改变文本，不触发重算或回写。
- 本任务改变了既有输出端点的可观察 body，测试完成后必须回写 `dev-docs/main-api.md` 对应六个端点；普通 JSON 端点因契约未变不覆盖总账。

## 6. 测试身份与数据契约

- 集成/E2E 使用隔离数据库和独立前后端端口，不连接共享开发/验收库。
- 四角色测试账号统一使用 `T261027_RDP_` 前缀在隔离库创建；不得修改既有账号角色。口令仅在测试环境使用，结束时只清理本前缀账号及其私有报价。
- 私有报价、客户/产品/模板夹具统一使用 `T261027_RDP_FLOW_` 前缀；不得断言全局行数。
- 输出测试必须保留底层值 `1.2345678915` 及边界值 `12.500000000000`、`1.23444`、`1.23445` 和对应负数，并同时记录输出文本与保存前后原始值。
- 浏览器连续角色切换必须退出并重新登录，打开同一私有报价；断言修改时间、快照摘要和金额字段均未变化。

## 7. AC 对应关系

| AC | 本契约中的落点 |
|---|---|
| AC-1、AC-2、AC-6 | §1 角色映射、舍入和去尾零；§2 JSON 原值不变。 |
| AC-3 | §1 显式位数取最小值；§3 Excel 视图计算列契约。 |
| AC-4 | 页面入口属于前端呈现契约；§2 明确其依赖的 JSON 不变，不新增接口。 |
| AC-5 | §3 六个输出端点与邮件附件。 |
| AC-7、AC-8 | §2 保存/查询值不变；§5 历史报价零迁移。 |
| AC-9 | §2 原始输入/基础属性不套角色上限；§3 原始列不变。 |
| AC-10 | §4 鉴权、权限和伪造角色边界。 |
| AC-11 | §5 前后端同版本兼容与总账回写；接口结构无额外变化。 |
