### 1.2 用户原话（两次，逐字一致）

**立项期**（归档在 `task-260910/需求文档.md:467`）：

> 「…需要**选配新增一个销售料号来绑定客户料号**,此时这个选配新增的料号在各个 `ds_quote_*` 表中一定是不存在的,
> **然后是选择新建零件/已有零件**, 已有零件同上,直接带入,新建零件选择材质和工序后…」

**验收期**（2026-09-11，更细）：

> 「选配侧 首先输入客户编号,然后选择是否绑定已有销售料号,
> 如果选择已绑定,则直接建立绑定关系,
> 如果客户选择已有零件,则证明当前没有销售料号可以与客户料号绑定,**则生成一个新的销售料号与客户绑定,然后让已有零件组成这个新料号的 BOM**.
> 同理,如果客户选择新建零件,则**既要生成一个新的料号与客户料号绑定,又要创建一个新的零件作为这个料号的 BOM**. 这样理解有问题吗?」

⇒ **「销售料号」与「零件」在两次表述里都是两件事。**

### 1.3 目标模型（三层）

```
客户产品编号  ↔  销售料号 P（产品层 · 绑客户料号 · 选配时新铸）
                      └─ BOM: 零件 C（零件层 · 新建或已有）
                                  └─ 材质 1..N（各带占比 Σ=100%）
```

### 1.4 三条路径的目标行为

| 用户在第 2 步选什么 | 目标行为 | 现状 |
|---|---|---|
| **直接绑定已有销售料号** | 直接建立绑定关系（客户产品编号 ↔ 已有销售料号），不铸号、不进指纹、不写 BOM | ✅ **已正确**（`task-260910` AC-18，亲验通过） |
| **已有零件** | **铸一个新销售料号 P** 与客户料号绑定，**让已有零件 C 组成 P 的 BOM** | ❌ 直接把 C 当产品，不铸 P |
| **新建零件** | **铸 P，同时新建零件 C**，C 作为 P 的 BOM | ❌ 只铸一个号，直接挂材质 |
