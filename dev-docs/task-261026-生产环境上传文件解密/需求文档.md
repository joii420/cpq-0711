# 需求文档：生产环境上传文件解密

> **立项日期**：2026-10-26
> **状态**：🟠 开发中 · 闸门 A 已通过（2026-10-26；路径 A 标准档）
> **需求依据**：[`docs/文件加解密服务接口调用文档.md`](../../docs/文件加解密服务接口调用文档.md)

## ① 背景与目标

当前 CPQ 的上传与导入入口直接解析或保存浏览器提交的原始文件。生产环境收到天锐加密文件时，Excel/JSON 解析器会将密文当成损坏文件，3D 模型链路还可能把密文落盘并登记为正常版本。

本任务的目标是：

- 当 Quarkus 活动 profile **精确为 `prod`** 时，所有有效文件上传入口在原有解析、导入或落盘之前，统一调用加解密服务识别文件；如为密文则解密，再把明文交给原业务链路。
- 开发、测试及其他非 `prod` profile **不发起任何加解密服务请求**，原文件按现状处理。
- 生产环境不允许在识别、解密或调用配置异常时继续解析或保存未受信的字节；故障必须拒绝本次上传。
- 加解密服务的基础地址使用精确配置项 `file.encryption.server`，默认值为 `http://172.16.18.45:9502`，可改配置文件，也可用 JVM 启动参数覆盖。配置内只放 **IP／主机＋端口**，不放接口全路径。

不做本任务的直接后果是：生产上传的同一份文件可能因加密状态不同而随机成功或失败；不同 Resource 各自增加特殊判断又会形成漏接和错误口径漂移。

## ② 范围

### 做什么

1. 覆盖上一轮调查确认的 **13 个用户功能点**：客户导入、报价数据导入建单、组件 Bundle JSON 导入、材质、元素、元素价格、工序、基础核价、详细核价、3D 模型配置、用户、汇率批量、产品导入。
2. 按闸门 A0 裁决，安全边界扩展为全部有效后端入口：**18 个现有 multipart 操作＋2 个组件 Bundle multipart 操作，共 20 个 HTTP 操作**。端点总表见 `api.md § 4`。
3. 新增统一的后端文件安全处理服务；每个文件入口在原业务解析或存储之前显式调用，不使用无法准确获取业务文件名的全局 multipart 过滤器。
4. `prod` 下对每个文件先调用 `/v1/inspect`；`encrypted=true` 或兼容字段 `isEncrypted=true` 时再调用 `/v1/decrypt`。明文文件不调用 decrypt。
5. 3D 模型上传的必选 `glbFile` 和可选 `thumbnailFile` 按两份独立文件处理；全部处理成功后才允许落盘和登记版本。
6. 组件 Bundle 从“前端 `FileReader` 解析后发 JSON”改为“前端保留 `File` 并用 multipart 发给后端”；预览与提交均上传同一原文件，后端解密后解析 JSON。原有 JSON body 接口保留兼容，但它不是文件上传入口，不调用加解密服务。
7. 请求使用原始二进制体、Bearer 令牌、RFC 3986/`encodeURIComponent` 等价编码的 `X-File-Name`和可追踪的 `X-Request-Id`。同一文件的 inspect/decrypt 共用一个请求编号。
8. 新增统一、不泄密的错误信封，区分本地配置缺失、上游拒绝、上游不可用与超时；保留请求编号和允许列表内的上游错误码，不透传原始错误体。
9. 在 `application.properties` 中保留以下基础地址配置，启动参数可覆盖：

   ```properties
   file.encryption.server=http://172.16.18.45:9502
   ```

   ```bash
   java -Dfile.encryption.server=http://<ip>:<port> -jar quarkus-run.jar
   ```

10. 加密服务令牌只从后端受控配置取得；仓库中只保留空占位，不写入真实令牌。

### 🚫 明确不做什么

| 不做 | 去向／理由 |
|---|---|
| 下载时加密、在线预览加解密 | 本期只处理上传与导入；未立项，不自动扩围 |
| 历史已上传文件迁移／重写 | 需单独制定版本与回滚方案，本期不做 |
| 增加“系统设置开关” | 闸门 A0 已裁决为 **仅由 active profile 决定**；`prod` 强制启用，其他 profile 强制不启用 |
| 把令牌或加解密调用放到前端 | 已否决；会向浏览器暴露服务凭证 |
| 更改现有 Excel/JSON/GLB 业务字段、导入语义、权限、交易或响应数据 | 解密后回到原链路；现有业务契约是回归基线 |
| 修改数据库 schema 或新增 Flyway 迁移 | 本任务无数据结构需求 |
| 实现 UG NX `.prt` / STEP 转换上传骨架 | `PartModelResource` 仍是 `not_implemented`，本期保持不变 |
| 处理已永久停用的 `POST /api/cpq/basic-data-import/v6/quote` | 该端点继续恒返 410，不读文件、不调外部服务 |
| 自动打包或更新 `deploy/` | 用户未明确要求打包／部署，保持 `deploy/` 现状 |

## ③ 验收标准（AC）

### 单点与契约

| 编号 | 前置状态 | 操作 | 可观测断言 |
|---|---|---|---|
| **AC-1** | 应用分别以 `dev`、`test` 和一个非 `prod` 自定义 profile 启动；设置一个可记录请求的假加解密服务 | 各上传一份可被原业务处理的明文文件 | 假服务收到 **0** 个请求；业务结果与改造前一致，文件字节逐位不变 |
| **AC-2** | 应用以 `prod` 启动；假服务对 inspect 返回 `{"encrypted":false}` | 上传一份明文 Excel，完成原导入操作 | 每份文件只有 **1** 次 `POST /v1/inspect`，**0** 次 `/v1/decrypt`；原导入成功数、失败数和业务返回形状不变 |
| **AC-3** | 应用以 `prod` 启动；假服务对加密 Excel 返回 `encrypted=true`，解密返回一份含唯一前缀 `T261026-CRYPTO-` 的有效明文表格 | 通过客户导入和数据集导入两类代表链路执行导入 | 每份文件按 inspect → decrypt 各 **1** 次调用；导入结果只包含解密后的前缀数据，不存在密文解析错误，不落库原密文 |
| **AC-5** | `prod` 下准备一份加密 GLB 和一份加密预览图；假服务分别返回可识别的明文字节 | 一次提交 `POST /api/cpq/model-configs`，然后下载该版本的两份文件 | 外部服务收到 **2 组** inspect → decrypt；下载字节分别与两份明文逐位相等，库内文件大小和摘要基于明文；任一文件处理失败时本次无新版本、无残留文件 |
| **AC-6** | `application.properties` 含 `file.encryption.server=http://172.16.18.45:9502`；另启动一个临时假服务 | 先不加覆盖启动一次，再用 `-Dfile.encryption.server=http://127.0.0.1:<port>` 启动 `prod` 并上传文件 | 配置文件值仅为基础地址，不含 `/v1/*`；启动参数覆盖生效，实际请求精确到 `<base>/v1/inspect` 和 `<base>/v1/decrypt`，不会出现重复斜杠或重复路径 |
| **AC-7** | `prod` 下配置测试令牌；文件名为 `罗格朗 014整改报告.xlsx` | 上传加密文件并捕获 inspect/decrypt 两次原始请求 | 两次请求均为 `application/octet-stream`，body 与当次输入字节逐位相等；`Authorization` 为 `Bearer <token>`；`X-File-Name` 等于 `encodeURIComponent` 结果（空格是 `%20`，不是 `+`）；两次 `X-Request-Id` 非空且相同 |
| **AC-8** | `prod` 下假服务分别返回 `{"isEncrypted":true}`、`{"encrypted":false}` 和不含两个字段的 JSON | 依次上传三份文件 | 第一份进入 decrypt；第二份不进入 decrypt；第三份被当作无效 inspect 响应拒绝，不得默认成明文继续处理 |
| **AC-11** | 启用可记录外部请求的 `prod` 测试 profile，准备 `api.md § 4` 的入口矩阵 | 对矩阵中 20 个有效文件操作逐一发起上传，同时请求已停用 V6 报价端点 | 20 个操作的每个文件位都在业务解析／落盘前触发 inspect，密文还触发 decrypt；已停用端点仍恒返 **410** 且外部请求计数不增加 |
| **AC-12** | 令牌设为唯一哨兵值 `T261026-SECRET-MUST-NOT-LEAK`，文件体也含唯一哨兵串 | 执行一次成功解密和一次上游失败，归档后端日志和 HTTP 错误响应 | 响应与日志均不含令牌、Authorization 头、原文件体、解密文件体或上游原始错误体；日志只保留 requestId、操作、大小、耗时和结果等允许字段 |
| **AC-13** | 使用改造前已支持的角色、multipart 字段和同一份明文夹具 | 分别在非 `prod` 和 `prod` 执行代表性导入，并以无权角色重复请求 | 除组件 Bundle 新增 multipart 形态外，现有方法、路径、字段名、成功响应、业务校验、交易和权限与基线一致；无权请求仍返原 401/403，且在权限校验失败时外部请求计数为 **0** |

### 序列

| 编号 | 前置状态 | 操作 | 可观测断言 |
|---|---|---|---|
| **AC-4** | `prod` 下选中一份含唯一组件 code 的加密 Bundle；目标目录中无该 code | 选文件 → 预览 → 改变冲突策略后再预览 → 提交 → 关闭抽屉、切走再切回目录页并刷新 | 前端三次请求都以 multipart `file` 发送原文件，浏览器不出现令牌；每次后端均完成 inspect → decrypt → JSON 解析；两次预览结果分别反映当次策略，提交后刷新仍可见该唯一 code，不重复建组件 |

### 边界与失败关闭

| 编号 | 前置状态 | 操作 | 可观测断言 |
|---|---|---|---|
| **AC-9** | `prod` 下分别构造：令牌缺失；上游 401/413/422/500/503；连接失败；超时；inspect 非法 JSON；decrypt 空响应 | 对一个会写库的导入入口和 3D 文件入口逐一发起请求 | 每次都以 `api.md § 3` 约定状态码和错误信封拒绝；业务数据、导入成功记录、模型版本和存储目录均无新增；不将原密文交给业务解析器 |
| **AC-10** | 准备空文件、刚好在 CPQ 现有请求上限内的文件，以及超出现有 100M 请求上限的文件 | 在 `prod` 下逐一上传 | 空文件在业务解析前返 400；上限内文件按 inspect/decrypt 正常处理；超出 100M 的请求仍由现有 HTTP 限制拒绝，不因上游支持 2GiB 而放宽 CPQ 上限 |

## ④ 依赖与影响面

### 已裁决的方案边界（闸门 A0）

| 决策 | 结论 |
|---|---|
| A0-1 端点覆盖 | 所有有效后端文件上传入口，不只限于 13 个当前可达 UI 功能点 |
| A0-2 启用口径 | 仅 active profile 精确为 `prod` 时启用；无运行时系统设置开关 |
| A0-3 失败策略 | 生产失败关闭：配置、inspect、decrypt 任一环节失败即拒绝上传 |
| A0-4 接入架构 | 统一后端处理服务，各业务入口显式接入；不使用全局 multipart 过滤器 |
| 用户补充 | 基础地址配置名固定为 `file.encryption.server`，值为如 `http://172.16.18.45:9502` 的 IP／主机＋端口，不是接口全路径 |

### 外部依赖

- 基础地址：`file.encryption.server=http://172.16.18.45:9502`。
- 固定路径：`POST /v1/inspect`、`POST /v1/decrypt`。
- 鉴权：`Authorization: Bearer <CRYPTO_API_TOKEN>`；令牌仅在后端配置。
- 外部服务请求和 decrypt 成功响应均为原始字节。
- 2026-10-26 从当前开发环境请求 `/healthz`，5 秒内无响应并得到 HTTP 000；这只证明当前网络不可达，不能推导生产服务故障。自动测试使用本地可控假服务，真服务连通性在部署验收时单独记录。

### 代码与回归影响

- 后端：17 个有效 Resource 类、统一文件安全处理包、3D 文件存储入参、组件 Bundle 解析入口、统一异常映射和后端配置。
- 前端：仅组件导入抽屉的文件持有方式与 service 请求体。页面、抽屉、控件、顺序和布局不变，属纯取数／协议逻辑改动，不触发 HTML 原型。
- 数据库：无 schema 变更、无迁移。
- 架构基线：不修改 `docs/三大核心模块基线.md` 中的快照、公式、驱动和渲染不变量；组件 Bundle 解密后仍交给原导入服务。
- 启动：本任务修改启动配置，命中冷启动验证触发条件。
- 接口总账：组件 Bundle 新增 multipart 契约；测试完成后、合并 master 前必须回写 `dev-docs/main-api.md`。
