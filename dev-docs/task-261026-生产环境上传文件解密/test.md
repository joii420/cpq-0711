# 测试方案与 AC 可追溯矩阵

> 本文是闸门 A 前置产物，从 `需求文档.md § ③` 的 AC 派生；不是开工后对着实现补的测试清单。
> 测试工程师在用例代码首次定稿前，**禁止读取** `cpq-backend/src/main/java/` 和 `cpq-frontend/src/`；只可读本任务的 `需求文档.md`、`api.md`、`test.md` 以及既有测试工具说明。契约信息不足就报主线，不许翻实现猜答案。

## 0. 测试前提与夹具

### 0.1 可控假加解密服务

自动化不依赖 `172.16.18.45:9502` 的当前网络可达性。在本机临时端口启动一个可编程假服务，必须能：

- 记录方法、精确 path、头部、body SHA-256、body 字节数、到达顺序和时间；
- 分别返回 `encrypted`、`isEncrypted`、两字段缺失、非法 JSON、指定 HTTP 状态与指定原始明文；
- 阻塞响应以验证超时；
- 以实例 ID 验明正身，避免探活误连到别人的端口。

假服务的原始捕获不得打印 Authorization 值到普通测试日志；安全断言在进程内对值比较，只输出“匹配／不匹配”。

### 0.2 文件夹具

| 夹具 | 要求 |
|---|---|
| `plain-valid.xlsx` | 一份现有导入器可成功处理的最小表格，数据值带 `T261026-CRYPTO-` 前缀 |
| `cipher.xlsx` | 不能被原 Excel 解析器当成有效表格的密文代用字节；假 decrypt 返回 `plain-valid.xlsx` |
| `plain-bundle.json` | 含唯一组件 code `T261026-CRYPTO-COMP-*`，能走预览和提交 |
| `cipher-bundle.json` | 密文代用字节；假 decrypt 返回 `plain-bundle.json` |
| `cipher.glb` / `cipher.png` | 两份不同密文；假 decrypt 分别返回可逐位比对的 GLB/PNG 明文 |
| 文件名夹具 | `罗格朗 014整改报告.xlsx`，专门验证 `%20` 和中文百分号编码 |
| 大小边界 | 0 字节、HTTP 限制内的大文件和超出 100M 的请求；动态生成，不把大文件提交进 Git |

每个实际会写库的夹具都必须使用分片前缀，断言只查该前缀，不使用全局计数。

## 1. 分片与执行编排

本任务由 **1 名测试工程师**产出用例，按写入面分成三个可独立解锁的执行片。不存在 `S-全局`片，不改角色、权限、系统开关、公共基础数据或已发布模板。

| 分片 | 写入面／隔离 | 认领 AC | 解锁条件 |
|---|---|---|---|
| **S-CONTRACT** | 只读；假服务和后端均使用独立临时端口，入口矩阵使用会在业务写入前终止的夹具 | AC-1, AC-2, AC-6, AC-7, AC-8, AC-11, AC-12 | 后端完成 |
| **S-PRIVATE** | 私有写；数据前缀 `T261026-CRYPTO-BE-`，3D 存储指向本轮 `mktemp -d` 目录；用例 `finally` 只清理自建记录／文件 | AC-3, AC-5, AC-9, AC-10, AC-13 | 后端完成，且同 worktree 无其他 Maven 在写 `target/` |
| **S-UI** | 私有写；数据前缀 `T261026-CRYPTO-UI-`，仅创建自己的测试目录／组件，`finally` 清理；不读不改其他分片数据 | AC-4 | 前后端都完成；临时 Vite 先预热；E2E 时间盒 30 分钟 |

执行期间不运行清库脚本，不新建／删除数据库，不需要待回收库清单。S-PRIVATE 和 S-UI 不并发写同一对象。

## 3. 关键断言口径

### 3.1 “零外呼”不得空验证

T-C01 先在 `prod` 用同一假服务发一份文件，断言计数从 0 增为 1，证明观测手段能抓到请求；再清空计数，切换非 `prod` 验证为 0。

### 3.2 入口矩阵必须先断言数量

T-C09 在执行后先断言结果行数精确为 **20**，再逐行断言端点、文件位、inspect/decrypt 计数。对 `model-configs` 额外断言已出现 glb／thumbnail 两个不同 requestId，避免“少测一个却全绿”。

### 3.3 A/B 回归

T-P12 在同一测试环境使用同一夹具：

1. 在未改动基线树上执行代表性明文导入，归档 HTTP 状态、字段集、嵌套结构和导入报告；
2. 在本分支的非 `prod` 与 `prod + inspect=false` 各执行一次；
3. 先断言三次都进入真实业务分支、结果非空，再比对形状与关键业务值；不对时间、UUID 等天然变量做逐字节比较。

### 3.4 失败关闭

T-P05~P08 的每个失败样本必须同时断言：HTTP 状态、`detail.bizCode`、请求编号（如已产生）、业务前缀记录零新增、存储目录零新增，以及解析器成功计数为 0。只断言“返了错”不合格。

## 4. 证伪实验

首次全绿后必须执行以下证伪，实验产物写入独立目录，不覆盖通过证据。实验前先建立 Git 检查点，干预后先证明运行时已生效，用绝对路径还原后再复验。

| 编号 | 干预 | 必须变红的用例 |
|---|---|---|
| R-1 | 临时让非 `prod` 也进入 inspect | T-C01 的零外呼断言 |
| R-2 | 临时将 `isEncrypted=true` 按明文处理 | T-C06 的 decrypt 计数与明文结果 |
| R-3 | 临时移除矩阵中一个有效入口的统一处理调用 | T-C10 入口覆盖守卫 |
| R-4 | 临时把组件预览发送改回 JSON body | T-U01 的 multipart `file` 网络断言 |
| R-5 | 把哨兵字符串写入一份专用阳性对照日志（不是应用日志） | T-C12 使用的搜索命令必须能报出该对照；再证明应用日志为 0 命中 |

## 5. 冷启动与最终回归

本任务修改启动配置，**强制触发冷启动验证**：

1. 从本任务 worktree 的干净产物构建可运行后端，不复用主工作区 `target/`。
2. 以一个非 `prod` profile 启动，在未配令牌时执行明文上传，证明可正常处理且零外呼。
3. 以 `-Dquarkus.profile=prod -Dfile.encryption.server=http://127.0.0.1:<fake-port>` 和测试令牌启动，执行一次明文与一次密文上传。
4. 归档实际命令、应用端口、假服务实例 ID、HTTP 状态和请求计数。
5. 在 `test-report.md` 写“冷启动：已跑 ✅”，结案时在 `docs/RECORD.md` 对应条目标记 `[冷启动✓]`。

分片各自通过后，结案前必须在同一代码头部串行跑一次全部点名用例，确认分片组合不会互相污染。

## 6. 证据与 `test-report.md`

- 测试框架默认输出不作为持久证据；每片结果复制到 `证据/测试/<分片>/<run-id>/`，复跑不得覆盖旧 run。
- 保留具体数值：测试数，fail/error/skip，HTTP 状态，20 入口行数，外呼计数，请求 path，文件 SHA-256，前后 SQL 行数，存储文件数。
- `test-report.md` 在测试执行后创建，逐 AC 记录通过／失败／未验证、原始命令、证据路径、证伪结果、冷启动结果和所有外部环境限制。
- 真实 `172.16.18.45:9502` 的连通性和真实天锐密文解密结果如本环境仍不可达，必须显式写“未验证”；假服务契约全绿不得改写这一事实。
