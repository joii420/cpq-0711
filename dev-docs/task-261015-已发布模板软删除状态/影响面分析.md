# 软删除状态影响面分析（只读勘察）

> 勘察日期：2026-10-15。本文记录 A0 前的事实证据与待裁决问题，不记录尚未获得用户批准的候选实现方案。

## 1. 现有状态与删除入口

- `template.status` 是字符串字段，源码迁移 `V7__create_template_tables.sql` 的 CHECK 约束只有 `DRAFT/PUBLISHED/ARCHIVED`。
- `TemplateService.delete` 只允许 `DRAFT`，随后物理删除 `template` 行；`TemplateResource DELETE /api/cpq/templates/{id}` 仅允许销售经理和系统管理员。
- `TemplateService.archive` 只允许 `PUBLISHED`，并在归档前检查进行中的报价和产品绑定；归档时对没有快照的模板补冻。
- 前端 `TemplateList` 当前只把 `DRAFT` 标为可删除，提示已发布版本改为归档。

## 2. 物理删除的引用风险

源码数据库约束显示，模板被多个业务表引用；大部分外键不是级联删除：

| 引用表 | 当前约束 | 共享开发库只读计数（2026-10-15） |
|---|---|---:|
| `quotation.customer_template_id` | `REFERENCES template(id)` | 184 |
| `quotation.costing_card_template_id` | `ON DELETE SET NULL` | 61 |
| `quotation_line_item.template_id` | `REFERENCES template(id)` | 5252 |
| `product_template_binding.template_id` | `REFERENCES template(id)` | 0 |
| `template_component_snapshot.template_id` | `ON DELETE CASCADE` | 342 行 / 56 个模板 |
| `template_component` | `ON DELETE CASCADE` | 需保留以支持历史追溯/审计 |
| `template_global_variable_binding` | `ON DELETE CASCADE` | 0 |
| `template_sql_view` | `ON DELETE CASCADE` | 0 |
| `import_record` / `import_mapping_template` | 默认外键行为 | 当前引用 0 |

当前共享开发库模板状态分布为 `PUBLISHED=45`、`ARCHIVED=12`；其中 `PUBLISHED` 模板关联 181 张报价和 5246 条报价明细，`ARCHIVED` 模板关联 3 张报价和 6 条报价明细。物理删除发布模板不能作为业务删除语义。

## 3. “不可被引用”与历史读取是两条不同链路

### 新引用链路

- `QuotationService.validateTemplateBinding` 在新绑定时要求模板存在、类型匹配且 `status=PUBLISHED`。
- 该方法对“请求模板 ID 与当前已保存值相同”的情况有豁免，目的是让已归档模板的历史草稿报价继续保存；`DELETED` 是否沿用此豁免需要 A0 决定。
- `ProductTemplateBindingService` 创建绑定时明确要求 `PUBLISHED`。
- `TemplateService.matchCustomerQuoteTemplate`、自动默认模板和核价模板过滤均使用 `status=PUBLISHED`，删除状态原则上不能进入新选择，但仍需补显式回归断言。

### 历史读取链路

- 发布时 `TemplateService.publish` 写入 `template_component_snapshot`、`components_snapshot`、组件 SQL 视图快照和模板 SQL 视图快照。
- `PublishedTemplateReader.isFrozenStatus` 当前只识别 `PUBLISHED/ARCHIVED`；`DELETED` 若要保持历史报价可读，必须在同一冻结语义中处理，否则可能被误判为非冻结并回落活表或返回错误。
- `ConfigureSnapshotService`、`BomTreeRenderService`、`ExcelViewService` 等存在各自的 `PUBLISHED/ARCHIVED` 判断，不能只改 Reader 一个点。
- 报价侧已有 `quotation_view_structure` 和行级卡片值快照；共享开发库有 462 个结构行、覆盖 173 张报价。历史报价优先应继续读取这些快照。

## 4. 列表与前端入口

- `TemplateService.list` 的默认条件是 `1=1`，只有调用方传 `status` 才过滤状态；因此后端需要定义“不传状态”的默认排除口径。
- `TemplateList` 的状态筛选目前只有草稿、已发布、已归档；状态颜色和类型联合定义也没有 `DELETED`。
- 报价创建、复制报价、Excel 导入等多个前端入口显式请求 `status=PUBLISHED`；这些入口不会因列表隐藏自动获得历史读取保障，仍需要接口层回归。
- `GET /api/cpq/templates/{id}` 当前按 ID 返回任何存在模板；是否允许管理员/历史报价内部读取 `DELETED`，需要与“列表不查询”区分。

## 5. 当前已识别的状态判断点

至少包括：

1. `TemplateService`：列表、删除、发布、归档、版本号计算、客户匹配、快照维护。
2. `PublishedTemplateReader`：冻结状态识别、零快照错误和快照读取。
3. `ComponentSqlViewService`：模板是否冻结。
4. `ConfigureSnapshotService` / `BomTreeRenderService`：选择活表还是模板快照。
5. `ExcelViewService`：模板页签定义和冻结元数据读取。
6. `QuotationService`：创建、保存、复制时的模板绑定校验。
7. `TemplateFreezeDriftService` / 管理端冻结体检：默认只覆盖 `PUBLISHED/ARCHIVED`，是否纳入 `DELETED` 取决于审计需求。
8. 前端 `TemplateList`、模板类型定义和状态展示。

## 6. A0 裁决结果

1. 只允许 `PUBLISHED -> DELETED`；`ARCHIVED` 不进入本期删除流转。
2. `DELETED` 是终态，不支持恢复；`SYSTEM_ADMIN` 可以打开它并基于它创建独立的新 `DRAFT` 模板。
3. “不可被引用”只限制新引用；已绑定该模板的历史报价和 DRAFT 报价允许继续保存，保存时不改模板外键。
4. 默认列表隐藏 `DELETED`；`SYSTEM_ADMIN` 可以显式按 `status=DELETED` 查询，普通角色不能使用该历史查询口径。
5. `SYSTEM_ADMIN` 可以按 ID 打开 `DELETED` 模板；历史报价渲染走内部快照链路，不依赖前端列表。
6. 删除不沿用归档的进行中报价/产品绑定阻断，只更新目标模板状态；所有其他引用保持不变，报价查询继续带出模板。
7. `DELETED` 纳入冻结快照读取语义；是否进入漂移/闭包体检由实现按“历史可读、不可新增引用”原则处理，不提供恢复写入口。

## 7. A0 后的实现原则

- 复用现有 `DELETE /api/cpq/templates/{id}` 路径：DRAFT 保持原物理删除语义；PUBLISHED 只更新为 DELETED；ARCHIVED/DELETED 拒绝。
- 新增状态只做加法迁移，不改写已有模板状态和引用数据。
- `DELETED` 与 `PUBLISHED/ARCHIVED` 共用冻结快照读取网关；不得因为状态不是原两值而回落活表。
- 删除后的历史查询与管理员“从此模板创建新模板”是管理能力，不是恢复能力；新草稿必须是新 ID，源模板状态不变。
