# 测试计划与 AC 追踪

## 测试分片

| 分片 | 范围 | 数据与环境边界 |
|---|---|---|
| S1 | 后端迁移、状态机、权限、列表/引用 API | 独立 PostgreSQL 16 测试库或事务内前缀数据；禁止共享库批量删除；数据前缀 `TMPLDEL-261015-S1-` |
| S2 | 历史报价快照与渲染回归 | 使用已有发布模板/报价的只读副本或事务回滚；验证报价查询、卡片、BOM、Excel/PDF，不改存量快照 |
| S3 | 前端列表、管理员历史查看、新建模板交互 | 私有前端进程；角色会话分别使用 `SYSTEM_ADMIN` 与普通模板管理角色；覆盖原型图状态 |
| S0 | 主线全局回归 | S1/S2/S3 完成后执行；不清库、不物理删除共享数据 |

## AC 追踪矩阵

| AC | 证据分片 | 主要证据 |
|---|---|---|
| AC-1 | S1 | DELETE 返回、状态变更、模板行仍在、已有引用数量不变 |
| AC-2 | S1 | 新建/切换/复制/绑定/匹配接口对 DELETED 返回 400 |
| AC-3 | S1+S3 | 默认列表无 DELETED；管理员显式状态查询可见；普通角色 403 |
| AC-4 | S2 | 删除前后外键、模板快照、报价快照逐字节/哈希不变；报价查询带出模板 |
| AC-5 | S2 | 删除后历史报价打开，QUOTE_CARD/BOM/Excel/PDF 仍有非空快照结果 |
| AC-6 | S1+S2 | 原 DRAFT 报价同模板保存 200；切换到 DELETED 返回 400 |
| AC-7 | S1+S3 | SYSTEM_ADMIN 从 DELETED 创建新 DRAFT；源模板仍 DELETED；无恢复接口 |
| AC-8 | S1 | DRAFT 保持物理删除；ARCHIVED/DELETED 拒绝；404、重复删除和事务回滚 |
| AC-9 | S1+S3 | 角色矩阵：普通角色拒绝历史查看/新建，管理员允许 |
| AC-10 | S2 | Reader/渲染链路把 DELETED 当冻结状态，不读活表、不抛未冻结 |
| AC-11 | S1 | 已有引用保留，新引用拒绝；引用表行数和 ID 不变 |
| AC-12 | S3 | 原型逐屏：默认列表、已删除筛选、禁用态、详情管理员动作、错误态 |

## 反向覆盖与假绿防护

- 先断言测试数据确实包含至少一条 PUBLISHED 模板、至少一张已引用报价和至少一份模板组件快照，再执行删除断言。
- S2 不以“接口 200”作为渲染通过依据，必须断言结构非空、组件名称/字段和值与删除前一致。
- S1 的引用不变断言使用删除前后按模板 ID 的快照计数、外键计数和哈希，而非全库固定总数。
- 权限用例必须携带真实角色会话；不能通过关闭 RBAC 让管理员路径假绿。

## Gate A 入口条件

- `需求文档.md`、`a0-技术勘察.md`（如需补充）、`api.md`、`backtask.md`、`fronttask.md`、`test.md` 和原型图完成。
- 每条 AC 有且仅有一个主证据分片，正向与反向覆盖闭合。
- 用户确认完整文档和派工计划后，才创建 worktree、派遣前端/后端/测试代理并开始编码。
