## 1. §4 三问的答案

### 结论先行

🚨 **「选配行不写 `template_id` 是有意设计」这个说法不成立。** 那句注释在一个标题为
**「Schema 偏差说明（相对 T20/T21 原始规格）」**的 javadoc 块里，它解释的是
**「为什么这条 INSERT 语句可以不写这两列而不报错」**，不是「选配行不该有模板」。
四条独立证据把它推翻（下面逐条给原文）。

### Q1 · V30 当初为什么把它改成 nullable、为什么选配行不写它？

**V30 原文**（`cpq-backend/src/main/resources/db/migration/V30__import_v4_costing_sheet.sql:34-36`）：

```sql
-- v4 基础数据驱动: product_id 允许 null（导入产品不强制关联 Product 表）
ALTER TABLE quotation_line_item ALTER COLUMN product_id DROP NOT NULL;
ALTER TABLE quotation_line_item ALTER COLUMN template_id DROP NOT NULL;
```

- V30 的标题是 `-- V30: 导入 v4 改造`，动机写得很清楚：**导入链路**的产品不在 `product` 表里，
  所以 `product_id` 不能 NOT NULL。**`template_id` 那行没有自己的注释**，是跟着一起放开的。
- V30 **比选配功能早得多**（选配是 T20/T21，`mat_part` 时代；V30 是导入 v4）⇒
  V30 放开约束时**根本不知道有选配这回事**，不可能是「为选配行留空」而设计的。
- 🔑 **V30 亲手服务的那条导入链路，今天照样写 `template_id`**：
  `cpq-backend/src/main/java/com/cpq/basicdata/v6/service/QuotationLineItemMaterializeService.java:100-103`
  的批量 INSERT 列清单里**第三列就是 `template_id`**（值来自入参 `templateId`）。
  ⇒ 放开约束换来的是「**可以为空**」，不是「**应该为空**」。

### Q3 · 写什么值？

`quotation.customer_template_id`，**用 INSERT 内联子查询取，不多发一次查询**：

```java
// ConfigureProductService.insertLineItem（唯一插入点，两个重载都走它）
"INSERT INTO quotation_line_item " +
"(id, quotation_id, product_part_no_snapshot, " +
" parent_line_item_id, composite_type, sort_order, created_at, template_id) " +
"VALUES (:id, :q, :pn, :pp, :ct, 0, NOW(), " +
"        (SELECT customer_template_id FROM quotation WHERE id = :q))"
```

- **拿得到**：`configure()` 入口本来就要从 `quotation` 表拉 `customer_id`（见类 javadoc「P4 批2补丁」），
  同一张表同一主键，子查询零成本。
- **为空时的行为 = 写入 NULL，与今天完全一致，🚫 不抛异常**。依据：
  `CreateQuotationRequest.java:32` 原文「留空则后续在报价单 Step2 中由用户手工选择」——
  D-30/D-31 的「先加产品后选模板」是产品上允许的路径。用户在 Step2 选了模板之后，
  `saveDraft` 的既有兜底（`QuotationService:557`）会把它补上，**链路自愈，无需新增补丁**。
- **插入点唯一**：全后端 `INSERT INTO quotation_line_item` 只有 3 处 ——
  `ConfigureProductService:2393`（选配，本次改）、`QuotationLineItemMaterializeService:100`（导入，**已写**）、
  `ConfiguratorInstanceService:225`（3D 选配器 mock 链路，**已写**，值取 `SELECT id FROM template LIMIT 1` 兜底）。
  ⇒ 改完之后**三条插入路径口径一致**，选配是唯一的例外，改完例外消失。

### N+1 自检

> **N+1 自检：本次改动 0 处循环 —— 改动是「单条 INSERT 加一列 + 同表同主键的内联子查询」，
> 每行 line item 仍只发 1 条 SQL，条数与料号数/行数/页签数无关 ✅**
> 机器核对：`git diff -U0` 的新增行里 `for (` / `forEach` / `stream()` 命中数 = **0**。
> 🔑 之所以选内联子查询而不是「先 `SELECT customer_template_id` 再 INSERT」，正是为了不在
> `buildLineItems` 的父/子件循环里多出一次查询（COMPOSITE 有 1 父 + N 子，那会是标准的 N+1）。
