### 问题 1 · 客户产品编号为空

组件 `221dc766`（名为「产品」）的视图 SQL：

```sql
LEFT JOIN ds_quote_customer_part dqcp
  ON dqcp.material_no = dqm.material_no
 AND dqcp.customer_no = :customerCode
 AND dqcp.customer_product_no = :customerProductNo   -- ← repair-260910 新加
```

`:customerProductNo` 是 `repair-260910-客户产品编号维度与删行错位` 的 A0 裁决「甲」新增的**运行时占位符**（合入 master `5c3efb13`，2026-09-11 01:37 UTC；视图库内 `updated_at` = 09-11 02:53）。
**选配建单的渲染路径没有注入这个占位符** ⇒ JOIN 落空 ⇒ `_客户料号_客户产品编号` 为 `null`。

**证据**：`snapshot_rows` 原文 `"_客户料号_客户产品编号": null`，而 `ds_quote_customer_part` 实有 `CUST-0004 | 7789 | 0028-2609000039`。

### 问题 2 · BOM 非树 + 一行空行


`__lvl` / `__parentNo` / `__nodeType='材质'` 全有值，组件 `bom_recursive_expand = t`（树渲染已开），**但 UI 平铺**。
📌 该组件 `tab_type` 为**空** —— 是否与前端的树渲染判据有关，待返修查证。

**合成根行**（`BomTreeRenderService` 的 `treeRowNode(node, null)`）在**非树渲染**下就表现为一行空行。

### 问题 4 · BOM 没有项次

数据层 `_物料BOM_项次: 1` / `2` **有值**（只有合成根行是 null），UI 却空。
**同卡片对照**：「材料名」「销售料号」都正常显示 —— 三者同为 `BASIC_DATA` 取数源，**唯一差别是字段类型**：

| 字段 | `field_type` | UI |
|---|---|---|
| 材料名 / 销售料号 | `INPUT_TEXT` | ✅ 显示 |
| **项次** | **`INPUT_NUMBER`** | ❌ 空 |

⇒ 疑为 **`INPUT_NUMBER` + `BASIC_DATA` 的渲染回填缺口**，属 **AP-37 / AP-44「字段类型联动协议」**族。
