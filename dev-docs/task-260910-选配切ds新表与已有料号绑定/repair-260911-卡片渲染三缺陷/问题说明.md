
`:customerProductNo` 是 `repair-260910-客户产品编号维度与删行错位` 的 A0 裁决「甲」新增的**运行时占位符**（合入 master `5c3efb13`，2026-09-11 01:37 UTC；视图库内 `updated_at` = 09-11 02:53）。

### 问题 2 · BOM 非树 + 一行空行

🔴 **根因已由专项诊断查实**（全文见同目录 `诊断-非树与缺项次.md`）：

卡片取数有**两条通道** —— 读**快照**（`quote_card_values`）与**实时** `batch-expand`。

- 前端判「树 vs 平铺」的**唯一判据**是 `rows[*].__sys.nodeId` 是否存在（`QuotationStep2.tsx:2977-2982`）
- 而 `__sys` **只有快照通道**才注入（`:2196-2203` 的 `buildSnapshotExpansions`）
- **实时通道的响应 DTO 结构上就没有这组字段** —— `ExpandDriverResponse.Row` 只有 `driverRow` + `basicDataValues`

**时序实证（决定性）**：用户截图 `shot_20260911_003932` = **07:39:32 UTC**，而该单 `quote_values_at` = **08:43:09 UTC** ⇒ **截图那一刻快照还没算出来**（晚 64 分钟）⇒ `useSnapQuote=false` ⇒ 走实时 ⇒ `__sys` 缺失 ⇒ 平铺。

**那行空行 = 树的根节点**（`BomTreeRenderService.treeRowNode`）。树渲染下它会长出「BOM」固定列（显示料号）+ 缩进 + `▼`；平铺时那一列整块不渲染（`:3595`），于是九个业务列全 null ⇒ 视觉上一行全空。

> ❌ **两条判否，不要再花时间**：
> ① **`tab_type` 为空与本条无因果** —— 前端树判据既不读 `tab_type` 也不读 `bom_recursive_expand`（全量 grep 口径，本节初稿那个 📌 已划掉）
> ② 🚫 **不要从 `snapshot_rows` 剔除根行** —— 它是合法根节点，剔除会与 `BomNodeTypeResolver` 的 `__lvl==0` 根判定、`task-260909` B-1 守卫打架

### 问题 4 · BOM 没有项次

🔴 **根因已查实**：`inputDefaults.ts:52`

```ts
if (typeof resolved === 'number') return undefined;   // ← 裸 JS number 被静默丢弃
```

**引入提交**：`fd83cac1`（2026-08-11）`feat(task-0810): 前后端统一十进制精度契约`，原文是 `return resolved` ⇒ **在那之前数值型 BASIC_DATA 默认值能显示**。

**为什么「材料名」能显示而「项次」不能** —— 差别**不在 `field_type`，在源值的 JSON 类型**：

| 通道 | 解析器 | `项次` 到前端的类型 | 结果 |
|---|---|---|---|
| 快照 | `tryParseSnapshotJsonLossless` | `"1"`（字符串） | ✅ 过守卫 |
| **实时 `batch-expand`** | axios 默认 `JSON.parse`（**无 lossless**） | `1`（JS number） | ❌ 被丢弃 |

而 `材料名="AgNi25C2"` 是字符串，两条通道都过守卫。

**U1 已闭合**（主线 2026-09-11 补证）：
- DB 的 `row_data` 在截图前 32 秒就含 `"项次": 1/2`，`row_version=0` 此后未改
- 接口 `GET /quotations/{id}` **确实返回** `rowData`（含项次，类型 `int`）
- `EditableCellInput` 的 `norm = v => v == null ? '' : String(v)` ⇒ **`norm(1)==='1'`，输入框不吞数字**
- ⇒ 三者叠加只剩一个解释：**截图那一帧前端的 `comp.rows` 还没有这份 `row_data`**（走的是选配返回体/内存态）⇒ 全靠 bake ⇒ 撞上 `:52`

⚠️ **主线曾据「现在接口有值」误判为「根因另有其处」，是拿现在的状态推截图那一刻** —— 现在快照已算好（走快照通道），与截图那刻不同。**已更正。**
