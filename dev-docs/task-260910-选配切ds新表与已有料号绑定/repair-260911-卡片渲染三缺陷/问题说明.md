## ② 根因（三条独立，全部实证）

### 问题 1 · 客户产品编号为空

组件 `221dc766`（名为「产品」）的视图 SQL：

```sql
LEFT JOIN ds_quote_customer_part dqcp
  ON dqcp.material_no = dqm.material_no
 AND dqcp.customer_no = :customerCode
 AND dqcp.customer_product_no = :customerProductNo   -- ← repair-260910 新加
```

`:customerProductNo` 是 `repair-260910-客户产品编号维度与删行错位` 的 A0 裁决「甲」新增的**运行时占位符**（合入 master `5c3efb13`，2026-09-11 01:37 UTC；视图库内 `updated_at` = 09-11 02:53）。
**选配建单的渲染路径没有注入这个占位符** ⇒ JOIN 落空 ⇒ `_客户料号_客户产品编号` 为 `null`。

**🔴 根因已进一步钉死（2026-09-11 主线实查，修正了本节初稿的归因）：根子在选配侧少写一列。**

占位符的值从哪来 —— `SqlViewExecutor.queryLineItemCustomerPartNo`：

```java
"SELECT customer_part_no FROM quotation_line_item WHERE id = ?"
```

⇒ 它读的是 **`quotation_line_item.customer_part_no`**。而选配的 `insertLineItem` 写的列是：

```
(id, quotation_id, product_part_no_snapshot, parent_line_item_id, composite_type, sort_order, created_at, template_id)
```

⇒ **没有 `customer_part_no`**。

**实证（全库口径，选配建的行）**：

| 是否点过保存草稿 | 编号 | 行数 |
|---|---|---|
| 从没点过 | 有值 | 37（经查属导入/性能造数等**别的路径**建的） |
| 从没点过 | **空** | **35** |
| **点过** | **空** | **4** |

⇒ **`saveDraft` 也不补这一列**（与 `template_id` 不同 —— 那个有 `QuotationService:557` 的兜底）。
⇒ 用户那张「正泰 报价单」`user_data_version=**27**`（改过 27 次、点过保存草稿），`customer_part_no` **至今仍是 NULL**。

**`repair-260910` 的角色是「暴露」而非「导致」**：它给视图加了 `AND dqcp.customer_product_no = :customerProductNo` 条件；在那之前视图只按 `(material_no, customer_no)` JOIN，即使行上没有客户产品编号也能取到（代价是那个任务要修的「放大成 4 行」）。加了条件后，行上没值 ⇒ 占位符不注入 ⇒ JOIN 落空。

🔑 **⇒ 修在选配侧，与 `task-260910` 的 `D-38` 完全同型**（同一条 INSERT 补一列），且值就在手边 —— 选配第 1 步用户填的客户产品编号。
📌 **这与 `BL-0202` 是同一条 INSERT 少写的两列**：`D-38` 补了 `template_id`，`customer_part_no` 还缺着。

⚠️ 仍需与 `repair-260910` 那条线**对齐一次**（确认占位符注入口径不再变），但🚫 **不要等它** —— 本条的修法不依赖它。

### 问题 2 · BOM 非树 + 一行空行

**数据层是对的**，`snapshot_rows` 原文：

```
行1: __lvl=1, __nodeId=0028-2609000039, __parentNo=null,  业务列全 null   ← 空行的来源 = 合成根行
行2: __lvl=2, __nodeId=…/00005, __parentNo=0028-2609000039, 项次=1, 材料名=AgNi25C2
行3: __lvl=2, __nodeId=…/992,   __parentNo=0028-2609000039, 项次=2, 材料名=AgNi11#-Ⅰ
```

`__lvl` / `__parentNo` / `__nodeType='材质'` 全有值，组件 `bom_recursive_expand = t`（树渲染已开），**但 UI 平铺**。
📌 该组件 `tab_type` 为**空** —— 是否与前端的树渲染判据有关，待返修查证。

**合成根行**（`BomTreeRenderService` 的 `treeRowNode(node, null)`）在**非树渲染**下就表现为一行空行。

### 问题 4 · BOM 没有项次

数据层 `_物料BOM_项次: 1` / `2` **有值**（只有合成根行是 null），UI 却空。
**同卡片对照**：「材料名」「销售料号」都正常显示 —— 三者同为 `BASIC_DATA` 取数源，**唯一差别是字段类型**：

| 字段 | `field_type` | UI |
|---|---|---|
| 材料名 / 销售料号 | `INPUT_TEXT` | ✅ 显示 |
| **项次** | **`INPUT_NUMBER`** | ❌ 空 |

⇒ 疑为 **`INPUT_NUMBER` + `BASIC_DATA` 的渲染回填缺口**，属 **AP-37 / AP-44「字段类型联动协议」**族。
