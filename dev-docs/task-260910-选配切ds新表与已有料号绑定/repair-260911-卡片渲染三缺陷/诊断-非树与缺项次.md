## 1. 两条各一句话结论

**问题 2（非树 + 空行）**：前端判定「树 vs 平铺」的**唯一判据**是 `activeDriverExpansion.rows[*].__sys.nodeId` 是否存在；而 `__sys` **只有快照通道**（`buildSnapshotExpansions` 读 `quote_card_values`）才注入，**实时 `batch-expand` 通道的响应 DTO 结构上就没有这组 spine 系统列**。该卡片渲染那一刻 `quote_card_values` 还是 NULL → 走实时通道 → `__sys` 恒 undefined → 树判据恒 false → 平铺；合成根行随之退化成一行空行。

**问题 4（项次全空）**：`inputDefaults.ts:52` 的 `if (typeof resolved === 'number') return undefined;`（2026-08-11「十进制精度契约」引入）把**任何裸 JS number 的 BASIC_DATA 源值静默丢弃**；实时 `batch-expand` 走 axios 默认 `JSON.parse`（**没有** lossless 解析），`"_物料BOM_项次": 1` 到前端就是 JS `number` → 被丢弃。
🔴 **与 `field_type` 无因果，是「源值 JSON 类型」的关系** —— `INPUT_NUMBER` 只是与数值列强相关而已。

## 3. Q2 · 那行「空行」该不该渲染出来

**判据：它在 `snapshot_rows` / `row_data` 里是对的，不该删；它变成空行是 Q1 的副产物。**

1. **它是树的根节点，树渲染下有意义** —— 生产者 `BomTreeRenderService.java:1109-1137 treeRowNode(node, bizRowOrNull)`。本例根行其实**业务行非 null**（视图的根分支）。
2. **视图设计就出一支根分支**，删掉会打回另一个已修的守卫 —— `BomTreeRenderService.java:650-656` 注释原文：
   > 🚨 task-260909 B-1：判据由「值为 NULL」改为「列不存在」。原判据把**根行的合法 NULL 父件**当成缺列 —— 配置器自 2026-09-07 起生成的树页签 SQL 带一支根分支（`parent_no` 恒 NULL 是设计）
   DB 实测根行确有 driverRow（不是空壳）：`{"parent_no": null, "hf_part_no": "0028-2609000039", "material_no": "0028-2609000039", 全部 _物料BOM_* = null}`
3. **它只在平铺下才是空行** —— 树渲染时该行会长出固定列「BOM」（`:3244` 表头、`:3599-3620` 单元格，显示 `bomSys.hfPartNo`）+ 缩进 + `▼` 展开符；平铺时这一列整块不渲染（`:3595` 的 `{activeComponentBomTree && (...)}`），于是根行九个业务列全 null → 视觉上一行全空。

> ❌ **判否**：🚫 **不要从 `snapshot_rows` 剔除根行**。那会 ① 打掉树的根 ② 与 `BomNodeTypeResolver.java:46,148` 的 `__lvl==0` 根判定冲突 ③ 与 task-260909 B-1 的守卫口径打架。
> ⇒ **修法应指向 Q1（让树分支进得去）。**

## 5. Q4 · 两条是不是同一个根因

**同一个上游触发器，两个互相独立的下游缺陷 ⇒ 必须分开修，但可以一次交付、共用同一个前置条件。**

| | 问题 2（非树+空行） | 问题 4（项次空） |
|---|---|---|
| 上游触发器 | `quoteCardValues` 缺失 → `useSnapQuote=false` → 实时通道 | **同一个** |
| 下游缺陷 | `ExpandDriverResponse.Row` 无 spine 系统列（**后端 DTO 协议缺口**） | `inputDefaults.ts:52` 丢弃裸 number（**前端精度守卫过度**） |
| 引入时间 | spine 列自始就只在快照侧 | `fd83cac1`，2026-08-11 |
| 修 A 能顺带修好 B 吗 | **不能** —— 补上 `__sys` 后 `项次` 仍是裸 number，仍空 | **不能** —— 放行 number 后 `__sys` 仍缺，仍平铺 |
| 共同前置 | 只要 `quote_card_values` 在卡片首次渲染前就绪，**两条同时消失** | 同左 |

⚠️ 但**只做「保证快照先于渲染就绪」是治标** —— 两个代码缺陷仍在，任何回落到实时通道的场景（新增产品、warm 失败、`__cardValueFailed` 哨兵、大单 warm 未完）会立刻复发。
**实测**：`quotation 5f641c55`（PERF 大单基线）**1200 行全部 `quote_card_values IS NULL`**。
