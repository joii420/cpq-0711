### 环境口径（沿用 `task-260910` 的教训，逐条都踩过）

| 项 | 要求 |
|---|---|
| **构建隔离** | 🚫 `-Dmaven.build.dir=` **本项目无效**（`pom.xml` 无 `<directory>` 覆盖）。✅ **唯一有效**：`rsync --exclude target/` 到 scratchpad 副本 |
| **端口** | 临时端口，🚫 不占 8081/5174；**按 worktree 分百位段**。⚠️ 撞 `Port already bound` 会报成 `BUILD FAILURE`、**伪装成代码错**；vite 还会**静默 +1**（指定 5199 实际起在 5200） |
| **库辨识** | `SELECT current_database()`。🚫 **不要比对 `totalElements`**（随建单在涨，同日两片读到 156/161） |
| **共库断言** | 🚫 禁用全局计数/时间窗断言（会被别片打红 —— 实测查「新增指纹行」命中了并发片造的数据） |
| **量具** | 卡片可编辑单元格的值在 **`<input>.value`** 里；只读 `td.textContent` 会把有值的行读成全空 |
| **vitest** | 🚨 **`npx vitest run`（不带路径）在本仓是假红**（F-1 实测）：会把 `e2e/*.spec.ts`（Playwright）扫进来，`vite.config.ts` 没配 `test.include`。实测 `Test Files 210 failed / 99 passed`，但 **`Tests 1197 passed`、0 条测试失败** —— 210 个「失败」全是 Playwright spec 的收集错，**干净分支上同样如此**。<br>✅ **跑单测一律 `npx vitest run src`** |
| **Playwright** | 本环境装不上 chrome-headless-shell ⇒ 必须 `channel: 'chrome'`；`PW_BASE_URL` 覆盖 baseURL（默认 5174 = 主仓，会验错代码）；`global-setup` 的 auth state 按 origin 隔离，换端口要自己登录 |
