## 4. 子代理规避掉的坑（8 条，逐字要点）

1. 🚨 **`api.md §2.1` 那段 SQL 照抄会静默丢行** —— `LEFT JOIN ds_quote_material_bom` 后紧跟 `JOIN material_recipe`，**INNER 会把左连接补出的 NULL 行反向吞掉**，外购件与组合父料号（无材质行）直接从搜索结果消失。落成两条 SQL 才同时满足「料号 LEFT / 材质 INNER」。
2. **`QuoteRegistry` 给 `SELF_PROCESS_FEE.input_material_no` 挂了 `.masterNoCheck("recipe", …)`** —— 差点据此把 D-4 的「零件料号」改成材质料号。实查确认该校验只在 `DatasetImportValidator`（导入表头/值域）消费，`VersionedGroupWriter` 写路径不碰它。已写进 javadoc 防后人改回。
3. **COMPOSITE 分组键坍缩** —— 照搬成「循环里逐子件 `writeGroup`」会让后一次把前一次当删除、整组重写。
4. **`required=true` 不是 DB NOT NULL** —— 先查 schema（`item_seq`/`assembly_fee` 在 DB 里都 nullable，`required` 只被导入校验与维护端消费）⇒ D-5 的「写 0」和 `value` 留 NULL 都不需要 DDL ⇒ **没造迁移文件**（backtask 说从 V440 起，但不需要就不该占号）。
5. **`prepareParts` 在 `customerCode` 派生之前** —— 上移派生前先核了原注释的「先配件、后客户产品编号」校验顺序（那条约束是 `assertCustomerProductNoAvailable` vs `prepareParts`，不受影响），并 grep 确认无测试依赖抛出时机。
6. 🚨 **共享 worktree 的 quarkus:dev 假红/假绿** —— 本 worktree 里同时有前端、测试、以及 B-12~B-22 那一路在跑 maven（**一度 6 个 maven 进程**），`target/classes` churn 导致 8093 实例抛 `NoClassDefFoundError: LookupFingerprintResponse$Snapshot`（源文件明明在）和 `Error restarting Quarkus`（`SelDsQuoteWriter` 引用了对方尚未创建的 `SelQuotationScope`/`DsRecordDirectWriter`）。**没把它当成自己的 bug**：把源码 tar 到 scratchpad 做隔离副本，`SelDsQuoteWriter` 用 `git show HEAD:` 版本 + 只叠加自己的 B-1/B-2/B-3 追加块，得到「只含自己改动」的干净树再验证（该树独立 BUILD SUCCESS）。
7. **`backfill` 不搬单价** —— 切表后 `value` 就在同一行里，顺手 `SELECT *` 复制会**把 A 客户谈的价搬给 B 客户**。逐字保持老口径并写明原因。
8. **B-4 的自检口径比 backtask 更严** —— backtask 说「应只剩 `backfillProcessesForNewCustomer` 一处」，但 B-5 也换表了 ⇒ 实际应为 0 处。顺带清掉 `@Inject VersionedV6Writer` 与两条 import（否则留着无人使用的 V6 写入器注入，下一个人会以为还有 V6 写点）。

**三个方向的评估（决定权在主线）**：

| 方向 | 评估 |
|---|---|
| **甲**（接 patch 合并，读主表 + `_record`） | 唯一语义正确的方向；成本是复用 B-14 的 patch 实现（🚫 不能自己写第二套）**需跨路协调**。⚠️ **另有一个坑**：`_record` 按 `quotation_id` 存，而复用发生在**另一张单**上 ⇒ 甲也得先定「**读哪张单的 `_record`**」（取该料号最新一份？）—— 这本身是个待裁决语义点 |
