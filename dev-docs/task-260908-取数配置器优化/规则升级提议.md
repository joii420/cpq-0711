## 二、共享端口：起之前也要广播，不只是重启之前

**本次实证（双方各缺一半）**：
- 主线 06:20 起了共享 8081/5174 给用户做闸门 B 验收，**没广播**
- 并发会话 17:09 按其 RUNBOOK「由我第一个开门」重启了 8081，**接管时才知道有人在用**

对方的原话比 RUNBOOK 原条款准：
> **「我是第一个开门的人」不等于「屋里没人」。**

⇒ 规则应为**双向**：**起共享端口前广播 + 重启共享端口前广播**。只有其中一半时，另一半的人永远是被动发现。

**落点**：`docs/rules/git-worktree.md`（worktree 共享约束）

## 三、共享端口上判「自己的实例是否存活」，必须用身份不用存活

**本次实证**：测试代理探到 `http://localhost:8099/api/cpq/health` = 200 就判「恢复好了」——
但在两个实例争抢同一端口时，**那个 200 很可能是别人的后端在应答**。它最初判「我的后端没起来」也是同一个错位：起来了，只是不是它的。

**可执行形态**（主线本次实际用了）：
```bash
readlink /proc/<pid>/cwd     # 确认这个 PID 属于哪个 worktree，再决定动不动它
```
✅ 更省事的结构性解法：**各 worktree 各用各的端口**，从源头消除争抢。
本次实证：我们的 `PID 11979` 配 8099 但从 03:35 起一直绑不上、空转，正是「下次抢占」的风险源，已停。

**落点**：`docs/rules/git-worktree.md` + `docs/rules/testing.md`（探活必须验明正身）
