## 3. 🚨 四条量具纪律（不满足别报绿）

### 3.1 `AC-R1` 的「零变化」必须先证明量具会动

三步，顺序不能反：
1. 采基准，**断言样本数 > 0**（报价侧已配价格列的组件数；为 0 就是没样本，停手报主线）
2. **故意把 `keys.get(i).leftColumn` 写成别的列名** → 重采 → 确认 `diff` **有输出**
3. 改回，确认回到基准 → 才开始正式对照

📌 本任务族出过这个假绿：`shell heredoc` 转义被吃掉产出两个**空文件**，`diff` 比出"相同"，打了 ✅。

### 3.2 `AC-P3` 必须先证明两侧都非空

两边都空时「逐位相同」**恒成立**，是零证据不是弱证据。
✅ 顺序：先各自断言非空 → 再比对。样本 `CUST-0001 × S-3120014539 / 3120014539 × Ag`（当前应为 `43358.75`）。
⚠️ **样本随数据漂**：行情表更新会改 `Cu` 的实时价。⇒ **跑之前先查一遍现值**，🚫 不许把 `43358.75` 写死进断言。

### 3.3 `AC-P2` 必须同时断言「不含错误形态」

🚫 只写「含 `cep.material_no = …sales_material_no`」不够。
不改 B-1 时生成的是 `cep.material_no = …production_no` —— **语法合法、执行不报错、恒 0 命中**。
✅ 必须**同时**断言 SQL **不含** `= <锚点别名>.production_no` 作为价格 JOIN 条件。

### 3.4 `AC-B1` 的「显示空」不等于「查不到」

✅ 断言的是**渲染出空单元格或 `—`**，🚫 不是「SQL 返 0 行」。
`AP-31`/`AP-38` 族：DATA_SOURCE 渲染缺 fallback 会显示「加载中…」而不是空，**那是缺陷不是通过**。
