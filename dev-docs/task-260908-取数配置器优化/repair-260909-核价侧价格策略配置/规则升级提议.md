## 提议 1 · 落库纪律：从「迁移落库必须当即进 git」升级为**两阶段**

**落点**：`docs/rules/git-worktree.md` 迁移纪律 + `backend.md`

**本次实证**：那条既有规则**不够用**。V434 落库后视图多出派生列 `sales_material_no`，而
`CostAllVersionViewSelfCheck` 在 `@Observes StartupEvent` 里双向比对 `v_<主表>_all` 与主表列集、
多一列即 `IllegalStateException`，开关 `cpq.builder.costview-check.enabled` **全工程无覆盖**、默认 `true`
⇒ **只提交迁移文件，主仓 8081 照样起不来**。这比 checksum 报警严重：不是报警，是应用挂掉。

**提议的判据**：
> 🔑 **迁移改变了什么运行期不变量，就要问「master 上有没有承接这个不变量的代码」。**
> 有 ⇒ 那段代码必须**先于**迁移进 master。

**配套顺序**（本次实际执行，零窗口）：
```
1. 完成承接代码 + 迁移文件      —— 🚫 不触发落库
2. 先把承接代码提交进 master     —— 此时它无害
3. 再落迁移                      —— 或干脆迁移也先提交，然后才应用
```

⚠️ **「承接代码可安全先行」这条性质要逐次确认，不是通则**：本次成立是因为登记表只「允许」不「要求」
（登记了但列还没建出来，遍历 `viewCols` 时压根遇不到它）。换一个守卫可能不成立。

## 提议 2 · 预实验能证明什么、不能证明什么

**落点**：`docs/rules/testing.md`

**本次实证**：主线在闸门 A 前跑的「事务内 `CREATE OR REPLACE VIEW` + `ROLLBACK`」得出三条结论
（不需 `DROP` / 行数 7→7 / 桥接取值正确）—— **三条全都是对的**。
但它**从未重启过应用** ⇒ 那个只活在**启动路径**上的失败面完全没被触碰到。

> 🔑 **事务内验证 + 回滚能证明 SQL 层正确，证不了启动期不变量。**
> 判据：**问一句「这个改动会让什么代码在什么时机重新跑一遍？」** —— 那个时机没被覆盖，预实验就是不完整的。

📌 这是本任务族「**量具所在的层，和失败/改动生效的层，不是同一层**」的第 4 次实例
（前三次：`A0-5` 采样 SQL 过滤 `dialect='QUOTE'` 恒空 diff · `A0-6` 用 `order by ctid` 验 Java 层排序 ·
`task-260907` 的「起服务前跑差集」拦不住「服务已在跑」）。**已够 §6 的升级门槛。**

## 提议 3 · 选样纪律：指名样本后，先在 AC 断言的那张表上数一次

**落点**：`docs/rules/task-docs.md`（AC 编写规范）

**本次实证：同型事故 3 次，全部是主线的**

| AC | 指名样本 | 它活在哪 | AC 实际断言哪 | 后果 |
|---|---|---|---|---|
| `AC-B1` | `300001`/`300012` | 物料BOM | **元素BOM** | 0 行 ⇒ 断言恒真 |
| `AC-B1`（`COST_DETAIL`）| 指名了但不存在 | — | — | 该侧无桥不到的料号 |
| `AC-B2` | `TEST0813-P01-PROD` | `material_master` | **元素BOM视图** | 0 行 ⇒ 断言恒真 |

**共同形状**：**样本从「这个性质看得见的表」里挑，而不是从「AC 实际断言的表」里挑。**
`material_master` 里 1:N 一眼可见、物料BOM 里 `300001` 一眼可见 —— 但断言对象是元素BOM，样本在那里是 0 行。

**提议的强制动作**：
> **指名样本后，先在 AC 实际断言的那张表/视图上 `count(*)`，断言它 > 0，再把样本写进文档。**

三次事故里**任何一次**做了这个动作都会当场发现。
🔑 与既有的「先证明量具会动」互补：那条防的是**量具**，这条防的是**样本**。

## 提议 4 · 空读数不许直接当结论（「拿一层的标识去另一层查」族）

**落点**：`docs/rules/testing.md`

**本次实证：亲验期间 4 次，全部是主线的量具错**

| 现象 | 真因 | 不查会记成 |
|---|---|---|
| 下拉「找不到 BOM」 | 图侧 `tab_type='BOM'`，UI 标签是「**物料BOM**」 | 「核价侧 BOM 源没配上」 |
| 客户「搜不到 CUST-0001」 | 接口按**名称**搜，我传了**编码** | 「已知产品缺口：下拉无搜索」（而它明明有 `showSearch`）|
| 改搜名称仍失败 | `fill()` 不产生按键事件 ⇒ `onSearch` 未触发 | 「库里没有这个客户」 |
| 预览表格读到空串 | 结果表是原生 `table.svb-pv-table`，不是 antd Table | 「预览没返回数据」（而截图写着「返回 7 行·25ms」）|

**提议的判据**：
> 🚫 **空读数不是结论，是「量具可能够不着」的信号。**
> 先证明量具够得着 —— **对比两次读数是否变化**（第 3 例正是靠「两次逐字相同」发现 `onSearch` 没触发）、
> **先断言目标对象存在数 > 0**、**看截图**（第 4 例截图上明明有答案）—— 再读值。
