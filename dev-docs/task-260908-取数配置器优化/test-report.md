## 9. 我规避掉的坑

1. **探到别人的实例**：8099 上的 200 是**另一个 worktree（`task-260907-record-backfill`）的后端**。只看 HTTP 200 会让我把断言打在别人的代码上；靠 `ss -ltnp` → `/proc/<pid>/cmdline` 才发现我自己的实例**根本没绑上端口**（日志尾部 `Port 8099 seems to be in use by another process`）。
2. **跳过 ≠ 通过**：S3 第一轮 6 条被 `test.skip(!backendUp)` 静默跳过（global-setup 的 3 秒健康探测偶发失败），列表里长得和没跑一样。**重跑后 6/6 真绿**才敢记通过。
3. **两个 playwright 实例同时跑**：`pkill` 没杀干净，run4 与 run5 的浏览器一度并存 —— 会互相干扰且失败归因全乱。改成按 PID `kill -9` 并核对。
4. **拿被订正掉的旧口径当断言**：用例写在 AC 订正之前，`.toBe(全表行数)` 会红成「功能坏了」。按 §⑦ 原文改成两层口径。
5. **拿阶段性证据充当本轮结果**：`证据/e2e-s2/`、`证据/前端自测/` 里的 20 张图是**上一批代理**留下的，本报告一律不引用为通过依据。
6. **`test-results/` 会被清空**：所有当证据的截图/文本都由用例写进 `dev-docs/…/证据/`，不留在工具临时目录。
