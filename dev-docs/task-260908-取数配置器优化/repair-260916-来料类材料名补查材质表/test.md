## 3. 用例设计要点

### S-1（只读，验收库）

- **T1.1（AC-1）**：按 `(dialect, from node_key, to node_key)` 查连线与连接键，逐个断言 11 个数据源；从 `证据/基线-改动前/` 取改动前的连线/键清单，断言「物料连线键逐条相同」「其余 35 条逐条相同」「总数 = 前 + 11」。
- **T1.2（AC-11）**：**第一个跑**。调全量重编译预览得集合 `A`，落盘 `证据/AC-11-集合A.json` 后再做任何其他事。期望集合用 SQL 现查（`builder_config.columns` 里有 `MAT_NAME_LK`，且其余列的 `sourceNodeKey` 落在 11 个数据源内）。COMP-0002 / COMP-0003：以其 `builder_config` 调 `/builder/compile`，与基线文件里的改动前 SQL 逐字比较。
- **T1.3（AC-9）**：键集合与基线比较；`recompileViews` 与 `SELECT count(*) FROM component_sql_view WHERE builder_config IS NOT NULL` 比较（口径不一致时**报主线**，不许自行调判据）；调用前后对 `component_sql_view` / `template` 取 md5，断言不变。

### S-2（私有写，`cpq_db_test`）

- 放 `cpq-backend/src/test/java/com/cpq/repair260916/`，类名**不带** `Dev` 前缀（`Dev*` 是后端工程师的自测，互不修改）。
- 造数前先断言前置：`material_recipe` 有 `00144`；`ds_cost_basic_material` 中 `production_no='00144'` 为 0 行（否则 AC-5 ④ 的「只在材质表」前提不成立 → 报主线）。
- **T2.1~T2.4（AC-5 ①~④）**：每个情形一张独立的前缀数据；断言前先断言「结果行数 > 0」；打印每行的料号与材料名。② 要同时断言**行数**不少。
- **T2.5~T2.10（AC-8 ①~⑥）**：每个错误路径都要断言「零写入」—— 按**自己组件 id** 过滤 `operation_log` 与 `component_sql_view.updated_at`。⑥ 需要一个 `builder_config` 损坏的自造视图与一个正常自造视图放在同一请求里，断言正常的那个**也没写**。
- 🔁 **证伪（`testing.md §4.4`）**：AC-8 ② 的「存在的也不写」—— 先用同一组正常 id 单独执行一次，确认观察手段能看到写入（阳性对照），再跑混入缺失 id 的请求。
