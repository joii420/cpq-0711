## 为什么不改（逐条对应 AC）

| AC | 前端涉及点 | 为什么不用改 |
|---|---|---|
| AC-2 面板只有一个「材料名」 | `SqlViewBuilderTab.tsx` 渲染「可用字段」树 | 字段树由后端 `FieldTreeBuilder` 生成，同组查名连线按组去重、以顺序最小的那条（物料表）为代表 ⇒ 前端收到的仍是**同一个**字段（`sourceNodeKey='MAT_NAME_LK'`、`viewColumn='_物料_材料名'`、`lookupLib='物料（查名）'`），与改动前逐字段相同。物料BOM 数据源现网就是这个形态 |
| AC-3 生成的 SQL | 同上，「生成的 SQL」区只展示后端 `/builder/compile` 返回的文本 | 文本变化全在后端 |
| AC-4 预览出名称 | 预览表格展示后端 `/builder/preview` 返回的行 | 列名不变，值由后端给出 |
| AC-6 / 7 / 8 新接口 | — | 新端点是运维后台接口，由主线用命令行调用，**不做界面**（用户裁决 `D-3` 只要求更新 3 个组件，未要求界面入口） |
| AC-10 报价单渲染 | `ComponentCell` / 报价单编辑页 / 详情页 | 「材料名」字段类型仍是 `INPUT_TEXT`，绑定路径 `$<视图名>._物料_材料名` 不变；值由视图返回，渲染分支不变 |
| AC-5 空值 | 渲染层对空值显示「—」 | 既有行为，本次不变 |
