## 结论：前端零改动，本次**没有 `F-x`**

🚫 这不是「本次免派前端代理」，是**前端这一路本来就没有任务**（`CLAUDE.md §4.0` 的区分）。

## 为什么不改（判定依据，不是印象）

| 依据 | 实测 |
|---|---|
| **列名不变** | 取价函数从 `f_material_element_price` 换成 `f_customer_element_price`，但语义图登记的输出列仍是 `unit_price` / `currency` 两列，编译产物里的别名仍是 `cep.unit_price AS "元素单价"` ⇒ **前端拿到的字段名一个字都没变** |
| **字段类型不变** | 不新增也不修改任何 `field_type`（`元素单价` 仍是 `DATA_SOURCE`、`材料费用` 仍是 `FORMULA`）⇒ **`AP-44` 字段类型联动协议不触发**，17 个检查点无一命中 |
| **行集不变** | 只改 JOIN 的 `ON` 条件（`LEFT JOIN` 语义不变），元素BOM 行数不受影响（`AC-7`）⇒ 渲染层行键、墓碑、树结构全不涉及 |
| **HTTP 契约不变** | 见 `api.md` |
| **入口已存在** | `B-4` 用的「刷新基础数据」按钮**页面上已经有**（见 `现象-核价侧元素单价为空.png` 右上角），不需要新增 UI |

## 需要前端**回归确认**的清单（由测试片 `S-2` 执行，不需要前端代理进场）

1. 核价侧「材质元素」页签四行元素单价从 `—` 变为有值，材料费用与小计随之 > 0（`AC-1`）
2. 切页签、切走再切回、整页刷新四次读数一致（`AC-3`）—— 专防 `AP-31`/`AP-37` 族的 cache 与 fingerprint 问题
3. 报价侧「材质元素」显示值**不变**（`AC-4`）
4. 取不到价时显示 `—` 而**不是 `0`**（`AC-5`）

## 二期触发条件（什么情况下前端必须进场）

- 若决定做 `BACKLOG` 的**单据级元素价格表**：会新增「价格来源/版本」的展示与审计入口 ⇒ 前端有实质任务
- 若将来要求「取不到价时给出可见提示」（当前口径是静默显示 `—`）⇒ 前端要加提示态
- 若 `元素单价` 的字段类型或列名发生变化 ⇒ 触发 `AP-44`，按 `change-protocol.md` 走 17 检查点
