## `field-tree` 响应的变化（不是契约变化，但调用方要知道）

**结构完全不变**，变的是**数组顺序**：

```
groups[].fields[]  —— 「材料名」的下标从「分组末尾」移到「最后一个 PART_NO 列之后」
```

三条性质：
1. **前端无需任何改动** —— `SqlViewBuilderTab.renderGroup()` 按数组顺序 `map`，不做排序（见 `fronttask.md`）
2. **字段总数不变** —— 只是顺序变，不增不减。🚫 若发现数量变了，那是缺陷不是预期
3. **`roles` 数组的内容会变**（核价侧七类节点的 `ROW_KEY` 增删）—— 前端 F-2 据此自动带出行键列，**这正是 `AC-R8` 要验的效果**

## 一个不改契约的判断记录

**考虑过但否决**：给 `field-tree` 响应加一个显式的 `sortHint` / `insertAfter` 字段，让前端自己排序。
**否决理由**：那是把「服务端已经知道的顺序」翻译成一个前端要理解的协议 —— 多一个协议就多一处可漂移的地方，而顺序本身在服务端一次排好即可。`AP-44` 那类「加一个字段要改 17 处」的教训就来自这种协议扩散。
