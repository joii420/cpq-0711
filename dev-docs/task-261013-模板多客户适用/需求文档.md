## ① 背景与目标

当前 `template.customer_id` 只能保存一个客户，配置页面也是单选。目标是在不改变“客户匹配模板”既有规则的前提下，让一个模板可以同时对多个客户生效。客户匹配仍按客户、产品分类、模板类型、`PUBLISHED` 状态和既有优先级执行，只把“是否属于该客户”从标量判断替换为关联表判断。

## ② 范围

### 本期做

1. 新增 `template_customer(template_id, customer_id)` 关联表，主键为两列组合并建立必要的外键、索引。
2. 存量 `template.customer_id IS NOT NULL` 数据通过 SQL 回填关联表；保留旧列作为兼容期读写/回滚护栏，本期不删除、不清空。
3. 报价模板和核价模板的草稿配置支持多选客户；空选择继续表示通用模板/所有客户。
4. 更新模板列表、详情、创建、更新、复制草稿、报价模板匹配和核价模板过滤，使其消费关联表；客户匹配的类型、排序、分类、状态和 `MIXED` 语义保持不变。
5. DTO/API 在返回 `customerIds`/客户摘要的同时保留旧 `customerId`/`customerName` 兼容字段；旧请求只传一个 `customerId` 时仍可工作。
6. 提供 Flyway 迁移和可直接用于生产 PostgreSQL 的事务型 SQL 脚本，包含前置检查、幂等建表/回填和后置核对，不在本任务中执行生产库脚本。
7. 前端配置、列表、报价单选择和核价模板显示与筛选适配多客户，并提供页面原型和回归测试。

### 本期明确不做

1. 不修改客户匹配规则：不改变客户优先于通用、产品分类、模板类型、`PUBLISHED` 过滤、排序和 `MIXED` 返回约定。
2. 不修改报价单 `customer_template_id`、模板渲染、公式、价格快照或历史报价单数据；已有报价仍绑定单个模板版本。
3. 不直接编辑已发布模板的客户范围；发布模板仍冻结，需通过“生成新草稿 → 修改客户 → 发布”生效。
4. 不在本期删除 `template.customer_id`，不清理历史模板，不改动与本需求无关的 `customer_excel_template` 语义。
5. 不把客户范围改为 JSON/数组字段，也不复制模板行来模拟多客户。

## ③ 验收标准

### 单点

- **AC-1 生产 SQL 迁移**：在 PostgreSQL 16 的数据库副本上运行生产 SQL 脚本两次，第二次成功且无重复写入；`template_customer` 存在，关联行数等于迁移前 `template.customer_id IS NOT NULL` 行数，组合键无重复，历史模板、报价单行数不变，脚本输出前置/后置核对结果。
- **AC-2 存量单客户兼容**：选择一条由旧 `customer_id` 回填的已发布模板，匹配该客户时仍返回原模板；不在关联表中的其他客户不能把它识别为客户专属模板；通用模板仍按原规则返回。
- **AC-3 草稿多选保存**：在模板配置选择客户 A、B，保存、刷新、重新打开后仍显示两个客户；接口返回两个 `customerIds`。清空选择后保存，模板显示为“通用/所有客户”。
- **AC-4 已发布冻结与新草稿**：已发布模板的客户范围控件不可编辑，直接更新被拒绝；生成新草稿自动复制 A、B，改为 A、C 后发布，旧版本仍适用 A、B，新版本适用 A、C。
- **AC-5 匹配规则不变**：同一分类、模板类型和状态下，A/B 命中客户专属分支并保持既有顺序；C 按既有通用回退；草稿、归档和不匹配类型不进入结果，响应中的 `matchType`/顺序与基线一致。
- **AC-6 列表与筛选**：模板列表展示多个客户名称或数量；按客户 A、B 筛选均能找到该模板，通用筛选不包含它；后端批量加载客户摘要，查询次数不随模板行数线性增长。
- **AC-7 核价一致**：核价模板配置、列表和按客户过滤与报价模板使用同一多客户关系，不改变核价既有选择规则。

### 序列

- **AC-8 完整流程**：创建/生成草稿 → 选择 A、B → 保存 → 刷新 → 发布 → 新建 A 客户报价和 B 客户报价；两张报价均可选同一模板版本，旧报价刷新后仍可正常打开。
- **AC-9 多版本演进**：旧发布版本 A、B；新草稿改为 A、C 并发布后，A 可按既有发布时间/排序命中新版本，B 仍可命中旧版本，C 命中新版本；不得改写旧版本关联。

### 边界与反向

- **AC-10 输入校验**：重复客户 ID 去重；空数组、`null` 或兼容请求未传客户字段表示通用；不存在或无权限客户 ID 返回 400；非草稿更新返回明确错误。
- **AC-11 兼容请求**：旧客户端只提交单个 `customerId` 的创建/更新请求仍能保存为一条关联；新客户端提交 `customerIds` 时以数组为准，不产生一对多之外的隐式覆盖。
- **AC-12 渲染回归**：既有报价单仍通过 `quotation.customer_template_id` 读取同一模板快照并渲染相同内容；本任务不新增或改写报价单模板绑定字段。
- **AC-13 迁移安全**：迁移脚本不含 `DROP`、`TRUNCATE`、无条件 `DELETE` 或全表覆盖 `UPDATE`；只新增结构并按非空旧客户列插入关联，失败时事务回滚。
- **AC-14 生产可执行性**：脚本不依赖开发库 UUID/固定数量，支持重复执行，兼容生产 PostgreSQL 版本和现有迁移历史；脚本中的表/列/约束/索引检查失败时明确停止。
