# A0 技术勘察与方案裁决

## 1. 已核实现状

1. `cpq-backend/.../template/entity/Template.java` 只有标量 `customer_id`；`CreateTemplateRequest`、`TemplateDTO` 也以单个 `customerId/customerName` 表达。
2. `TemplateConfigPanel.tsx` 使用单选客户组件；`TemplateList.tsx` 按一个客户名称展示和过滤；`QuotationCreateForm.tsx` 多处以 `t.customerId === customerId` 判断。
3. `TemplateService.matchCustomerQuoteTemplate` 当前按“客户专属 → 通用模板”查询，过滤分类、`QUOTATION`、`PUBLISHED` 并按既有发布时间排序；成本模板也按专属/通用条件过滤。
4. `quotation.customer_template_id` 是报价单对模板版本的单值绑定，渲染依赖该绑定，不应因模板客户范围扩展而改动。
5. `V28__costing_template_and_customer_template.sql` 引入旧客户列，`V62__drop_template_published_unique.sql` 调整了发布唯一索引；现有发布历史允许同客户/分类多版本。
6. 源码目录在 2026-10-13 实查 Flyway 最大版本为 V449；并发开发时实现代理必须重新核对源码、`flyway_schema_history`、目标分支和 `target/classes`。

## 2. A0 选择的方案

采用“关联表 + 兼容旧列”的增量方案：

```text
template (旧 customer_id 保留兼容)
       1
       |
       | template_id + customer_id（组合主键）
       N
template_customer
```

创建/更新请求以 `customerIds` 为主；旧 `customerId` 只在数组字段未提供时兼容映射。空范围表示通用模板，关联表不写行。匹配查询用 `EXISTS`/关联表判断客户归属，客户优先级、分类、模板类型、状态、排序和 `MIXED` 组装不变。发布模板范围冻结，复制新草稿时复制全部关系。

## 3. 方案取舍

- **不选数组/JSONB**：无法复用现有关系约束，客户反查/去重/索引和权限校验更复杂，生产 SQL 可核对性差。
- **不选复制模板行**：会破坏版本与渲染快照语义，也会改变现有发布时间排序和报价单绑定。
- **不选立即删除旧列**：现有集成和旧客户端仍提交 `customerId`；保留兼容列可在观察期回滚应用版本。旧列与关系表的写入由服务层保持一致，后续另立任务清理。

## 4. 生产 SQL 设计

生产脚本采用 PostgreSQL 事务：前置检查 `template` 与 `customer_id` 存在、数据库类型/版本满足要求；幂等创建表、主键、外键和查询索引；只对旧列非空记录执行 `INSERT ... ON CONFLICT DO NOTHING`；后置检查关联行数、孤儿行和重复键。脚本不包含删除、截断、全表覆盖更新或固定业务 UUID，第二次运行应成功。Flyway 文件与 `deploy/db/update-261013-template-customer-many.sql` 共享同一业务 SQL，并在测试片校验语句等价。

## 5. 风险与闸门

- 旧前端/接口可能只认识标量字段，需保留兼容返回和请求。
- DTO 客户名称若逐模板查询会形成 N+1，必须批量加载并在测试中锁定查询次数。
- 已发布模板冻结是不可破坏的约束，不能把“多客户”实现成直接改发布行。
- 当前主工作区存在其他任务的 staged/unstaged 改动；A0 文档提交必须只包含本任务文件，之后从提交点创建独立 worktree。
