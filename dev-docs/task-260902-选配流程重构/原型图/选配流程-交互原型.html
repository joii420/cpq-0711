    这次改的是什么

    现状（两层）本次（三层）
    产品 └── 配件 ＝ 一个材质料号 ├── 材质（单个） ├── 元素含量 └── 工序 产品（客户产品编号 ← 前置到第 1 步） └── 配件 1..N ├── 零件（新建 / 已有） │ ├── 品名 / 规格 / 尺寸 / 总重 │ ├── 材质 1..N（各带占比，Σ=100%） │ │ └── 含量配置（标准 / 自定义） │ └── 工序 └── 外购件（从料号库选） └── 工序 └── 组合工序
    「配件≡材质料号」不是推测：PartRequest.recipeCode 是单值；前端提示语原文是「请至少新增一个材质料号」（ConfigureProductDrawer.tsx:271）；落库只写 1 行「自指物料行」。

    用户裁决（写进原型的都是已定案的）

    编号问题裁决
    D-1配件 / 零件 / 材质的层级三层，零件含多材质
    D-2多材质零件的重量怎么填材质填占比，零件填总重（克重 = 总重 × 占比）
    D-3客户产品编号已存在时挡住，改走产品库入口
    D-4外购件从哪来从现有料号库选（不建新主数据模块）
    D-5哪些维度不同就铸新料号材质占比 / 零件总重 / 品名·规格·尺寸进指纹；配方编号不进
    A0-1material_type 一列两义归位为料号类型（选配写 '零件'，材质名靠 component_usage_type）
    A0-2指纹 structure_version升到 v2（表内 0 行，升版零代价）
