## 0. 🚨 环境前提（先读，否则会污染开发库）

**`./mvnw test` 实测连的是 `cpq_db_0724`，也就是 dev 库本身**：

```properties
# cpq-backend/src/main/resources/application-test.properties:24
quarkus.datasource.jdbc.url=jdbc:postgresql://${DB_HOST:10.177.152.12}:${DB_PORT:5432}/${DB_NAME:cpq_db_0724}
```

⚠️ **这与 `CLAUDE.md` profile 表写的 `cpq_db` 不符**（该表已知有误，2026-09-02 实测发现，待用户批准后修正）。后果是**跑测试会往开发库写数据、并触发 Flyway 迁移**。本项目已因此发生过两起事故：① 材质会话的提交式夹具往 dev 库种了 4 条 demo 材质；② 两个会话的 V399 迁移撞号。

**因此本任务的测试纪律**：

| 规则 | 说明 |
|---|---|
| 🚫 **一律用 `@TestTransaction`**，禁止提交式夹具 | 除非该数据必须跨事务可见，且**必须在 `test-report.md` 点名说明并给出清理 SQL** |
| 🚫 **禁止任何清库 / `TRUNCATE` / 无 `WHERE` 的 DELETE** | `CLAUDE.md §3.2` 红线：共享库上不许跑会清库的测试，哪怕写在 `@BeforeEach` 里 |
| ✅ 造数据用**本任务专属前缀** | 客户产品编号 `T260902-*`、材质 `T260902-M*`、工序 `T260902-P*`，便于事后识别与清理 |
| ✅ E2E 跑 dev server（5174 + 8081），**用真实业务数据** | 不新建库、不改共享配置 |
| 🚨 **收尾污染核对（硬项）** | `test-report.md` **必须附**这两条查询的输出，非空即视为污染未清理：<br>`SELECT process_no, created_at FROM process_master WHERE created_at > '<开工时刻>';`<br>`SELECT code, symbol, created_at FROM material_recipe WHERE created_at > '<开工时刻>';` |

> 🔴 **这条纪律不是假想 —— 立项当天已发生三起同型事故**（评审 P0-6）：
> ① 材质会话的 `mvnw test` 往 dev 库种了 4 条 demo 材质（`AgCu85/AgCu90/AgNi90/AgNi95`，`created=11:17`），清理后**又被种回来**；
> ② 两个会话的 V399 迁移撞号；
> ③ **`process_master` 的 `TP10`/`TP20` 是 `created=11:54` 当天写入的** —— A 轮文档曾把它们当成「遗留数据」写进基线，是错的。
> ⇒ **`process_master 4 条` 不是稳定基线**，下一次 `./mvnw test` 随时会改变它。B-12 让 4 个单测改用 `Z100/Z101` 只解决了引用，**没有任何机制阻止继续污染** —— 这就是上面那条收尾核对存在的理由。
