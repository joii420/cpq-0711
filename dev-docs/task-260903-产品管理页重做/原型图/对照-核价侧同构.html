与核价侧的同构与差异

用户原话：「与核价侧的展示逻辑相同，但是只能查看不可以编辑」。
「相同」的部分照抄不要发明；「不同」的部分只有一处但是根本性的（只读）。 本页是给还原者的防抄错清单 —— 逐条核对，不要凭印象。

核价侧参照物：cpq-frontend/src/pages/master-data/part-costing/ （PartCostingTab.tsx / PartCostingDrawer.tsx / EditableSheetTable.tsx）， 路由 /master-data-hub →「料号核价」页签。 🚫 这四个文件一个字节都不许改 —— task-260902 的 F-1 正在把它们抽成公共件。

✅ 相同的部分（照抄，不要重新设计）

维度核价侧的做法本任务
列表形态裸 <Table> + 可点击行；服务端分页 / 服务端排序 / 服务端过滤相同
列表定位属「列表操作规范」例外白名单（纯查看 / Master-Detail 导航），不用 SelectableTable；工具栏自套 TOOLBAR_ROW_STYLE相同

⚠️ 不同的部分（差异全在这里，逐条核对）

维度核价侧本任务（销售产品）
可编辑性
唯一的根本差异		 可编辑：单元格是 input/select，有 保存 / 新增行 / 删除 按钮，保存走整组升版 全只读：editable={false}；不渲染保存/新增/删除；无 input；不调 PUT rows

历史版本切到历史版本才变只读（readOnly=true）当前版也只读；无论 readOnly 为何值一律只读
🚨 一个必须点名的规范例外
frontend.md §1.2 规定「禁止用 if(...) return null 隐藏不可用按钮」——理由是用户看不到按钮就不知道能力存在。
本任务不渲染保存/新增/删除按钮，形式上违反该条。判定为合理例外：那条针对的是「本可用但当前不可用」的动作， 需要让用户知道能力存在并给出禁用原因；而本页是整页无编辑能力（产品定位就是只读查看）， 渲染一排永久禁用的保存按钮反而误导用户「这里本来能编辑」。
此例外已在闸门 A 呈报时向用户点名。
🔍 只读渲染的已知风险（F-6 要专门验）
EditableSheetTable 的 editable={false} 分支目前只在「历史版本」路径上被用过 （task-260902 主线原话）。本任务是它第一次被当作常态使用。
需逐类核对：role=NAME 的 JOIN 展示列、type=DECIMAL 的数值列、 type=STRING 但值像数字的列（pricing_unit）、null 单元格。
