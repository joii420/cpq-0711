## 2. 逐项要点

### F-1 · 客户过滤下拉

- 文件：`cpq-frontend/src/pages/product/ProductCustomerPartTab.tsx`
- 位置：工具栏，**搜索框左侧**（见 `原型图/客户产品-过滤器.html`）
- 默认值文案 **`所有客户`**（AC-1）
- 🚨 **候选来自 `GET .../customer-parts/customers`，不是 `customer` 主数据表** —— `Q13CUST0617` / `C1` 未建档，从主数据取会漏掉它们的 3 行产品（AC-5）
- 未建档客户的下拉文案：`{customerNo}（未建档）`，与列表里客户名称列渲染 `—` 的口径呼应
- **切客户要重置到第 1 页**，但 🚫 **不要清空搜索框**（AC-3 断言两者叠加、清空搜索后回到 11 行而非 17 行）
- 空结果走 `Empty` + `共 0 条`，**过滤器本身仍可交互**（AC-14）

### F-2 · 生产料号可编辑单元格（本任务核心）

- 文件：`ProductSalesPartTab.tsx`
- **只有 `productionNo` 这一列**加编辑能力，其余 6 列的 `render` 一律不动
- 交互按 `原型图/销售产品-可编辑生产料号.html`：单元格常态显示文本 + 悬停出现编辑图标；进入编辑态为 `Input`；回车或失焦保存、`Esc` 取消
- 保存调 `PUT /dataset/quote/parts/{axisValue}`，body **只传 `{ productionNo }`**
  🚫 **不要整行回传** —— 后端只更新传入列，整行回传会把未改的列一起写（`api.md §1` 硬约束 1）
- 🚨 **`source` 不传、也不要期望它变**（AC-10 断言它保持 `IMPORT`）
- **清空是合法操作**（用户原话「生产料号选填」）：清空后保存，期望落库 `NULL`、列表渲染 `—`（AC-12）
  ⚠️ 与 AC-9 的 `COALESCE` 区分：**页面显式清空 ⇒ 真的变 NULL**；**导入时 Excel 空着 ⇒ 保留库里的值**。两件事，别混用同一条分支
- 超长输入（>128 字符）给可读提示，🚫 不要出现 500 或红色遮罩（AC-13）
- 保存失败时**回滚到原值并提示**，不要把失败的值留在界面上假装成功

### F-3 · 权限

- **四个角色都渲染编辑能力**（用户 2026-09-03 裁决）⇒ **不写任何角色分支**，这是最省事也最不容易错的实现
- 401 时提示重新登录；403（若后端将来收紧）提示无权限 —— 但**当前不应出现 403**

### F-4 · 回归守卫（不写新代码，是核对）

打开抽屉逐项确认：无 `保存`/`新增行`/`删除` 按钮、表格内 `input`/`select`/`textarea` **数量为 0**、双击不进编辑态。
🚨 **F-2 的可编辑单元格是列表级的，不得渗进抽屉。** 若发现抽屉出现编辑控件，**立刻停下报主线**。

### F-5 · 产品分类列

- ⏸ 依赖 `task-260902` 的 B-16。**字段未到位前，该列渲染 `—` 且不得崩**（与父任务处理 `productionNo` 缺字段同样的兜底）
- 字段名待对方确认（预计 `categoryCode` / `categoryName`），**以 `api.md §1 C-2` 为准**，联调时对齐
