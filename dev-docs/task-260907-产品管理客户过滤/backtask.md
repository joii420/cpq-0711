## B-1 · 客户候选端点

**契约**：`api.md` §1。

**要点**

1. 口径是**并集**：`customer` 表全集 ∪ 报价业务表中未建档的客户号。两个半集各自解决一个问题，`api.md` §1 的表格写明了缺任一半会怎样。
2. 🚫 **差集那一半不许写死表名清单** —— 扫哪些表由 **Registry 元数据推导**（凡带 `customer_no` 列的报价侧业务表）。写死的清单必然过期，这是 `task-260819` 在同一条 AC 上栽过三次的形态。
3. 🚫 **N+1 红线**：无论扫几张表，SQL 条数必须是**常数**，用一条 `UNION ALL` 聚合。每张表一条查询 = 违规。
4. `customerName` 对未建档客户返 `null`（**不是空字符串**），`registered` 标记必须下发 —— 前端靠它渲染「未建档」标记，且**不得**因名称为空而过滤掉候选项。
5. 排序：已建档在前、未建档置尾，各自按 `customerNo` 升序。

**自测判据**：接口返回的 `customerNo` 集合与 `api.md` §1 那段判据 SQL 的结果**排序后逐项相等**。

## B-2 · 销售产品列表加客户过滤

**契约**：`api.md` §2 / A-2。

**要点**

1. **过滤在 SQL 里做**，`count` 与 `page` 两条查询**共用同一份 where 与同一份绑定** —— 该文件既有注释已写明：不共用会让「总数」与「本页数据」对不上，翻页数字直接错。
2. `customerName` 必须在**同一条 SELECT** 里 `LEFT JOIN customer ON customer.code = m.customer_no` 带出。
   - 🚫 逐行查 = SQL 条数变成 `2 + 料号数`，违反 `backend.md` N+1 硬指标（**AC-8** 专门验）；
   - 📌 `customer.code` 有唯一索引 `customer_code_key` ⇒ 不会放大行数（与该文件已有的 `product_category.code` JOIN 同型）；
   - ⚠️ 该方法用**动态列下标递进**（`int dyn = 8; if (hasXxx) ... r[dyn++]`）。新增两列必须接进这个递进链，**🚫 不许各自写死常量下标** —— 写死的下标在下次再加动态列时会**静默错位**（取到隔壁列的值），这条纪律是该文件已有的成文注释。
3. **行语义变更**：一行 = 「客户 × 料号」。后端无需为此做特殊处理（复合轴落地后物料表天然如此），但**响应必须带 `customerNo`**，否则前端无法构造正确的 `rowKey`。
4. `sortBy` 白名单**本次不新增键**（客户列暂不支持排序）。

## B-3 · 抽屉三端点加客户过滤

**契约**：`api.md` §2 / A-3~A-5。

**要点**

1. 三个端点的过滤条件必须**一致**：`overview` 的配置计数、`rows` 的行、`versions` 的版本列表，全部只含该客户。
2. 🚨 **`versions` 不得把两个客户的版本号混排** —— 版本号按 `(customer_no, axisValue)` 各自独立递增，混排会让用户看到不存在的版本序列。
3. `rows` 的 `version` 参数与 `customerNo` 是**正交**的两个条件，同时生效。

## B-4 · 生产料号更新加客户定位

**契约**：`api.md` §2 / A-6。

**要点**

1. 🚨 **这是本次唯一的写端点，也是唯一「不传参数会造成数据损坏」的端点。**
   复合轴下不传 `customerNo` ⇒ `WHERE material_no = ?` 命中所有客户的同料号行 ⇒ 一次编辑改掉多个客户的数据，**页面上看不出来**。
2. ⇒ **必须加多行守卫**：更新语句命中行数 > 1 时**报错并回滚**，🚫 不许静默更新多行。
   > 读端点保留「不传即不过滤」是为向后兼容（AC-17）；写端点靠「多行即报错」兜住。两者不矛盾 —— 兼容保的是单客户场景的既有调用方，守卫拦的是复合轴下的误伤。
3. **沿用三条既有硬约束**（`task-260903-产品维护能力增强`，`api.md` §2/A-6 列全）：只更新传入的列、`source` 不变、可编辑列白名单在后端 Registry 上（**绕过 UI 直接打接口也必须被拦住**）。
4. `productionNo: null` = 显式清空，落库 `NULL` 而非空字符串。

## B-5 · 核价两套的参数忽略语义

**契约**：`api.md` §4。

**要点**

1. 定为**忽略参数、正常返回全部数据**。🚫 **绝对禁止静默返回空列表** —— 用户会读成「这个客户没有数据」，而真相是这套数据集没有客户维度。
2. **判据走 Registry 元数据**（沿用该文件既有的 `hasNonAxisColumn(reg, "...")` 手法），判断该数据集的物料表有没有 `customer_no` 列。
   🚫 **不许写死 `dataset.equals("quote")`** —— 该文件对 `production_no` / `material_type` / `category_code` 三列已经是这么做的，成文理由是「将来哪套数据集加了这一列都自动跟上」。
3. **AC-18 / AC-19 是回归 AC**：核价两套与电镀方案页签的行为必须与改动前**逐字一致**。同一份夹具，改动前后结果逐行 md5 比对。
