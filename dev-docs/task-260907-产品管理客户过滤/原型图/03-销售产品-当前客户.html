还原纪律 —— 四条
1. 🚨 rowKey = `${customerNo}|${axisValue}`。这是本屏最容易漏、症状最像「玄学 bug」的一处。
2. 客户两列置于最左，因为它们现在是行身份的一部分，不是附属信息。
3. customerName 为 null 时渲染 —（不是空白）。它来自后端同一条 SELECT 的 LEFT JOIN customer，🚫 前端不得逐行去查。
4. 🔄 D-8：AC-16 拆两层验 —— UI 层切到 CUST-0004 后仍能看到 T260907M-X， 但客户列变成 CUST-0004 且行内容不同（生产料号是 T260907M-P-B 而非 -P-A）； 后端层直接调 API 断言两个客户的行都在库里。
🔑 两层合起来才证伪得了「静默删掉别人的行」：只验 UI 单客户可见，抓不住「B 的行其实已被 A 的导入删掉」。
