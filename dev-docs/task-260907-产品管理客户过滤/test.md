## 4. 反向 AC 的 A/B 基线采集手法

AC-17 / AC-18 / AC-19 都要求「与改动前逐字一致」。

**手法**：同一份夹具，在**改动前**（对方 DDL 已落地、本任务代码未上）先跑一遍并把响应逐行落盘，改动后再跑一遍做 md5 比对。

⚠️ **三条纪律**（本项目实证教训）：

1. **基线必须在本任务改动之前采**，且要记下**采集时点的 master commit**。共享库多方并发写入 ⇒ 隔一段时间重采会退化成「基线 = 当前」的**恒真断言**。
2. **A/B 两侧必须同型对比** —— 判「是不是本次引入的回归」时，要在**干净 master** 上跑同一份用例做对照。本项目实证：`quotation-flow` E2E 在干净 master 上恒 3 条失败（夹具漂移），不做对照会误归因成本次回归。
3. 🚫 **A/B 切换时不要 `git stash` 掉迁移文件** —— 会造成 Flyway 校验失败，症状与业务回归完全不同但一样让人查半天。
