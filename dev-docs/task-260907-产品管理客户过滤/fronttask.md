## F-1 · 壳页全局客户选择器

**位置**：`ProductHubPage.tsx` 标题行右侧，与既有「产品分类管理」按钮同一行（原型 `01-壳页-默认态.html`）。

**要点**

1. 候选调 **`GET /dataset/quote/customers`**（`api.md` §1，新端点）。🚫 **不要**再调 `listCustomerPartCustomers` —— 那是旧口径，只有客户料号表的 DISTINCT。
2. 客户上下文是**壳页的 state**，通过 props 下发给两个页签。🚫 不要用 Context 之外的全局单例，也不要让两个页签各自持有一份。
3. 🔄 **客户必选（`D-7`，2026-09-07 用户变更）**：🚫 **下拉里不要「所有客户」选项**；**默认选中候选列表的第一个客户**（即 `GET /customers` 返回的 `items[0]`）。
   ⚠️ 原先「空串哨兵」那套（用 `''` 表示所有客户）**随之作废** —— 现在 `customerNo` 恒为一个真实客户号。
4. **请求恒带 `customerNo`**（不再有 `|| undefined` 的转换）。后端契约仍允许省略，但那是留给其它调用方的，本页面不走那条路。
5. **未建档客户**（`registered: false`）：编号后缀标「未建档」，配色 `#d46b08`，**置于列表尾部**。
   🚫 **不得因 `customerName` 为空而过滤掉候选项** —— 那等于把后端好不容易带出来的未建档客户又筛掉一遍（AC-14③）。
6. 支持按**编号与名称**两者搜索（antd `Select` `showSearch` + 自定义 `filterOption`）。
7. **候选端点 404 / 失败时（🔄 `D-7` 后降级形态已变）**：候选拿不到 ⇒ **没有任何客户可选**，而客户又是必传的
   ⇒ **选择器置为禁用 + 显示错误提示条，列表区显示「客户候选加载失败，无法展示数据」**（🚫 不再是「降级为所有客户」——该选项已不存在）。
   🚫 **不做任何 mock 兜底** —— 塞 mock 会把「后端没就绪」伪装成「这个客户真的没有产品」。这是 `productHubApi.ts` 已有的成文纪律。
8. **切换客户时两个页签都要回到第 1 页** —— 否则会停在「上一个客户的第 3 页」，而新客户可能只有 1 页，表现为空列表（假空态）。
9. ⚠️ **候选为空时的边界**：`GET /customers` 返回 0 项（理论上不会，`customer` 表非空即有候选）⇒ 选择器禁用 + 提示，🚫 不要崩溃，也不要退回「所有客户」（该概念已不存在）。

**极值**（AC-15）：选择器与选项均以省略号截断，`title` 可看全；见原型 `05-极值与未建档.html`。

## F-2 · 选择器状态持久化

1. 用 **localStorage** 记住上次所选客户号，key 建议 `productHub.customerNo`。
2. 🚨 **读写一律 try/catch** —— 隐私窗口 / 站点数据被清 / 浏览器禁用存储时访问器本身会抛，未捕获会让整页白屏。
3. **失效降级（AC-12）**：读到的客户号**不在本次候选里** ⇒ 静默回落到**候选列表第一个客户**（🚫 不是「所有客户」——该选项已不存在），并**清掉那条 localStorage**。
   断言要求：控制台**无 error 级输出**、不出现红色遮罩。
4. **首屏不要发无客户号的请求** —— 必须在候选加载完成、默认/记忆客户确定之后再发第一个列表请求。
   🔑 AC-10② 的断言形态是「刷新后**第一个** `/parts` 请求就带 `customerNo`」，不是靠肉眼看有没有闪烁。

## F-3 · 客户产品页签改收 props

**改动面刻意最小**：只把客户号的**来源**从页签内 `useState` 换成壳页 props。

- 摘掉页签内的 `<Select>` 与 `customerOptions` 加载逻辑（候选改由壳页统一加载）；
- `listCustomerParts` 的调用参数、列定义、渲染逻辑、`rowKey` **一行都不要改**；
- 🚫 该页签**已有的三条成文纪律**继续有效：照单全收后端 items（不按 `customerName` 是否为空再筛）、过滤必须在后端做、`page` 是 0-based（传 `current - 1`）。

**验收对照（AC-4）**：改动后在壳页选客户 A 的结果，与改动前在页签内下拉选 A 的结果**逐行相同**。

## F-4 · 销售产品页签

**要点**

1. `listParts` 调用加 `customerNo`（`api.md` §2/A-2）。
2. **新增两列**：客户编号、客户名称。位置与列宽见原型 `03-销售产品-当前客户.html`。
   `customerName` 为 `null` 时渲染 `—`（**不是空白**，AC-5④）。
3. 🚨 **`rowKey` 必须改为 `` `${customerNo}|${axisValue}` ``。**
   仍用 `axisValue` ⇒ 同料号跨客户的两行会被 React 认成同一行 ⇒ **表格渲染错乱、勾选串行**（AC-16②）。
   > 这是本任务最容易漏、且症状最像「玄学 bug」的一处。
4. **行语义已变**：一行 = 「客户 × 料号」，不再是「料号」。凡是按料号定位行的逻辑（编辑回填、抽屉打开、刷新后定位）都要跟着改成按 (客户, 料号) 定位。
5. 🔄 **客户必选后列表恒为单客户**（`D-7`）：不会出现同料号两行同屏。
   🚨 **但 `rowKey` 仍必须含客户号** —— **切换客户时 React 会复用行组件**，key 不含客户号会导致切换后仍显示上一个客户的单元格值（AC-16 的 `rowKey` 断言因此保留）。

## F-5 · 抽屉透传客户号

🔄 **2026-09-07 用户变更（`D-10`）：抽屉的客户上下文 = 壳页所选客户。**

> 用户原话：「销售产品抽屉内的内容都是产品管理选择的客户的数据。」

客户必选后列表只含当前客户的行 ⇒ 行携带的客户号与壳页所选**恒相等**，取谁结果一样。
🚨 **但契约以壳页为准**：实现不得依赖「行里碰巧有这个值」—— 那是巧合不是契约，将来列表若再支持跨客户展示就会静默出错。

- `getOverview` / `getRows` / `getVersions` 三个调用全部带上该行的 `customerNo`；
- 抽屉标题建议同时显示客户，让用户确认自己在看谁的数据（原型 `04-销售产品-抽屉.html`）。

## F-6 · 生产料号编辑携带客户号

- `updateDatasetPart` 调用**恒传** `customerNo`（取自被编辑的那一行），不依赖壳页选择器当前值；
- 🚫 仍然**只传要改的字段，绝不整行回传**（既有硬约束）；
- 后端对「命中多行」会报错 —— 前端要把该错误**如实展示**，🚫 不许吞掉或改写成「保存成功」。

## F-7 · 空态

选中一个没有任何数据的客户时（AC-13），两个页签都要给**空态提示**，而不是：

| 🚫 错误形态 | 为什么不行 |
|---|---|
| 报错 / 红色遮罩 | 这是正常业务状态，不是错误 |
| 「加载中…」永久占位 | 本项目 `AP-31` 缺陷族的典型形态 |
| 空白页 | 用户分不清是没数据还是页面坏了 |

空态文案与插图见原型 `06-空态.html`。切回其它客户后数据须正常恢复。
