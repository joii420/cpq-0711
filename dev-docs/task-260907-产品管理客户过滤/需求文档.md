## ① 背景与目标

### 背景

报价侧基础数据表体系（`ds_quote_*`）原本**没有客户维度**。`task-260907-报价侧加客户维度` 正在把 `customer_no` 补进 28 张表，并把 `SheetDef.axisColumn` 从**单列**改为**复合轴 `(customer_no, <轴列>)`**。

轴一旦复合，**同一个销售料号可以在多个客户下各有一套数据**。而产品管理页当前完全没有客户概念：

| 页签 | 现状 | 加了 `customer_no` 之后 |
|---|---|---|
| **客户产品** | ✅ 页签内**已有**客户下拉（`task-260903-产品维护能力增强` B-2），过滤 `ds_quote_customer_part` | 能力已有，但它是**页签级私有**的，与销售产品页签各管各的 |
| **销售产品** | ❌ 无任何客户输入。列表走 `GET /dataset/quote/parts`，抽屉走 `overview` / `rows` / `versions` 三个端点，**五个端点全部不带客户号** | 🔴 **同一料号跨客户的数据会混在一起展示，而用户看不出来** |

### 目标

把客户从「客户产品页签的一个私有筛选条件」提升为**整个产品管理页的上下文**：用户选一次客户，两个页签同时按它过滤，且「这个客户的客户料号 ↔ 它对应的销售料号」能对照着看。

### 不做会怎样

不是「少一个筛选器」，而是**销售产品页签会展示错误的数据且无从察觉**：

- 列表：同料号跨客户的两行长得完全一样（现有列里没有任何客户信息），用户无法分辨；
- 抽屉：`overview` / `rows` / `versions` 不带客户号 ⇒ **把两个客户的行拼在一张表里**，版本下拉也会把两家的版本混排；
- 编辑：`PUT /parts/{axisValue}` 不带客户号 ⇒ 改一个「生产料号」会**同时改掉所有客户的同料号行**。

⚠️ 第三条是**写操作**，且失败形态是静默的 —— 页面上看不出改多了。

### 🚧 前置：本任务的隔离类断言在现网数据下会空跑

实测（2026-09-07）：`ds_quote_material` **49 行 / 49 个不同 `material_no`**，`uq_ds_quote_material` 当前是 `UNIQUE(material_no)` 单列
⇒ **「同一料号跨多个客户」这件事在现网造不出来**，**AC-3 / AC-5③ / AC-6 / AC-7 / AC-11 / AC-16** 的隔离断言会以「通过」的形态空跑。

> ⚠️ **`uq_ds_quote_material` 是 `CREATE UNIQUE INDEX` 建的，不是表约束** —— 用 `pg_constraint WHERE contype='u'` 查会得到「0 个唯一约束」的**假结论**（实测该口径对 `ds_quote_%` 全部返 0）。判唯一性一律走 `pg_index`。
> 📌 用 `pg_index` 复核的结果：`ds_quote_%` 非主键唯一索引共 3 条，**全在免版本表上**（`customer_part` / `material` / `plating_scheme`）⇒ 13 张带版本表确实无业务唯一索引，隔离靠 `VersionedGroupWriter` 的整组删除 + 重插。

🚨 **所有隔离类 AC 必须自造前缀化夹具**，前缀 **`T260907M-`**（M = Maintenance，与并发三条线 `T260907B-` / `T260907Q-` / `T260907T-` 错开；清理一律用主键或完整名精确删，🚫 不许 `LIKE 'T260907%'`）。

### 单点 AC

**AC-1（壳页客户选择器就位）**
前置：以任意有权限角色打开 `/products-hub`。
断言：① 页面标题行右侧出现客户选择器，**位置与形态按 `原型图/01-壳页-客户产品-默认态.html`**（带「客户」addon）；② **默认选中候选列表的第一个客户**，🚫 **下拉里不存在「所有客户」选项**（客户必选，`D-7`）；③ 两个页签**各自内部不再有**客户下拉（客户产品页签原有的那个已上提）；④ 选择器支持按客户编号与客户名称搜索。

**AC-2（候选口径 = `customer` 表 ∪ 业务表未建档客户号）**
断言（不变量口径）：候选集合 **恒等于**
`SELECT code FROM customer` **∪** `SELECT DISTINCT customer_no FROM <报价业务表> WHERE customer_no NOT IN (SELECT code FROM customer)`。
判据 SQL 返回的集合与接口返回的 `customerNo` 集合**逐项相等**（排序后比对）。
③ 未建档的客户号在下拉里**必须可见且可选**，标记文案与配色、以及分组顺序（已建档 → 未建档置尾）**按 `原型图/02-客户选择器-展开.html`**。

> 📌 采集时点参考（🚫 不进断言）：`customer` 48 行 / 48 个不同 `code`（全 `ACTIVE`）；`ds_quote_customer_part` 中未建档客户号 2 个（`C1` 1 行、`Q13CUST0617` 2 行）⇒ 当前候选 50 个。
> 🔑 **这条推翻了 `task-260903-产品维护能力增强` AC-5 的一半**：那条 AC 要求候选**只**来自 `ds_quote_customer_part` 的 DISTINCT（刻意不查 `customer` 表），本任务按用户 2026-09-07 裁决改为**并集**。

**AC-6（抽屉按行携带的客户号取数）**
前置：壳页选中客户 A；夹具料号 `T260907M-X` 在 A、B 两客户下各有一套数据。
操作：点开列表中 `T260907M-X` 的抽屉。

🔑 **抽屉的客户上下文 = 壳页所选客户**（`D-10`，用户 2026-09-07 明确：「销售产品抽屉内的内容都是产品管理选择的客户的数据」）。
> 客户必选后列表只含当前客户的行 ⇒ 行携带的客户号与壳页所选**恒相等**，二者取谁结果一样；但**契约上以壳页为准**，实现不得依赖「行里碰巧有这个值」。

**AC-7（生产料号编辑只改该客户的行）**
前置：同 AC-6 夹具，A、B 两行的 `production_no` 初值不同且均非空。
操作：在列表中把 A 那一行的生产料号改为 `T260907M-P-NEW`，失焦保存。
断言：① A 行落库为 `T260907M-P-NEW`；② 🚨 **B 行的 `production_no` 逐字未变**；③ 两行的 `source` 均保持 `IMPORT`（继承 `task-260903-产品维护能力增强` AC-10）。

**AC-8（客户名称由后端一次 JOIN 带出，不产生 N+1）**
断言：`GET /dataset/quote/parts` 的 SQL 条数**与返回行数无关**，恒为常数（count 1 条 + page 1 条）。
判据：客户名称必须在**同一条 SELECT** 里 `LEFT JOIN customer ON customer.code = m.customer_no` 带出。
📌 实测 `customer.code` 有唯一索引 `customer_code_key` ⇒ 该 LEFT JOIN **不会放大行数**。
