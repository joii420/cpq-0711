# 报价单级元素价格表：业务与技术设计

> 本文是本任务的权威方案；验收以 `需求文档.md` 为准。日期 DSL 细节见 `日期条件与取价窗口统一方案.md`，AI 与策略执行见 `自然语言AI与策略执行补充设计.md`，所有配置的维护入口与缺口审计见 `配置管理模块补充设计.md`。若补充文档与本文冲突，以本文为准。

## 1. 已确认业务决策

1. 当前阶段，一张报价单只有一套元素价格事实，报价和依附该报价单的核价共同使用。
2. DRAFT 中销售员、销售经理均可改价；修改会触发报价和核价预览重算。
3. 报价提交后由财务/定价经理从 `costing_order` 审核；不存在本任务范围内的独立核价单。
4. 财务可查看报价提交快照、核价结果与最终生效元素价格表，并可切换料号/BOM 组成版本。
5. 价格使用追加式修订；新增元素不得改变已存在元素的值。
6. 前端计算只为页面即时反馈；后端独立计算、返回结果并严格比对，完成前不能提交。
7. 复制只复制产品内容和重算输入，不复制价格表或结果缓存；新单按客户策略和新基准日重新取价。
8. 是否另建“真实财务成本价表”不在本期。未来需求成立时新建核价价格分支和迁移消费者，不在当前链路双写。

## 2. 核心概念与版本语义

### 2.1 三条版本轴

| 版本 | 回答的问题 | 升级时机 | 不升级的情况 |
|---|---|---|---|
| `priceRevisionNo` | 这次计算使用哪组元素价格，为什么改变 | 首次取价、新元素、人工改价、显式调价/刷新、核价换版新增元素 | 打开页面、策略发布、只改数量、只重试计算、换版未新增元素 |
| `userDataVersion` | 当前用户输入是否被别人改过 | 产品、数量、属性、工艺、条款等持久化输入变化 | 后台投影重试、只读访问 |
| `projectionId` | 某组输入与价格产生了哪套完整派生结果 | 任何影响公式/卡片/Excel/合计的输入变化或重试 | 只读访问；单纯发布新策略 |

`policyVersion`、`calendarVersion`、`exchangeRateSnapshotId` 是每个价格明细的来源证据，不是报价单业务版本。

### 2.2 价格修订是完整快照，不是差量补丁

修订 Rn+1 以 Rn 为母版创建完整明细集。未变化项目逐字段复制，变化项目写新值并记录原因。完整快照使读取不需要层层叠加，差异仍可由母修订和事件还原。

修订生命周期：

```text
BUILDING ──全部明细与校验成功──► SEALED
    └────任何失败──────────────► ABORTED
```

只有 `SEALED` 可绑定报价、核价或投影；`SEALED` 后禁止 UPDATE/DELETE 明细。失败修订不可见、不可绑定，但保留最小失败审计。

### 2.3 使用状态不属于价格版本

价格修订保存“本单已经建立过的元素价格目录”，元素当前是否被产品使用由对应 `userDataVersion/projection` 的元素使用集合表达。移除最后一个引用时不创建价格修订、不删除明细；页面把该元素派生显示为 `DORMANT`。重新加入时复用当前修订中的既有价格，同样不升级价格修订。只有首次新增元素或价格值/来源发生业务变化才升级价格修订。

## 3. 数据模型

字段名是设计契约，最终迁移可按现有命名规范微调，但语义与约束不得缩水。

### 3.1 报价单字段

```text
quotation
  price_mode                         LEGACY | SNAPSHOT, NOT NULL
  user_data_version                  integer, NOT NULL
  current_calc_input_snapshot_id     uuid, nullable for LEGACY
  current_price_revision_id          uuid, nullable for LEGACY
  desired_quote_projection_id        uuid
  active_quote_projection_id         uuid
  submitted_calc_input_snapshot_id   uuid
  submitted_price_revision_id        uuid
  submitted_quote_projection_id      uuid
```

`current_*` 仅表示 DRAFT 当前工作状态；`submitted_*` 一经提交只在撤回并重新进入草稿的既有合法流程中重新冻结，不能被核价操作覆盖。

### 3.2 不可变计算输入快照包

```text
quotation_calc_input_snapshot
  id, quotation_id, user_data_version
  template_version_id, schema_version
  parent_snapshot_id                 同单编辑来源，可空
  copied_from_snapshot_id            跨单复制来源，仅审计
  status                             BUILDING | SEALED | ABORTED
  content_hash
  first_business_bound_at, payload_purged_at
  created_by, created_at, sealed_at, completed_at

quotation_calc_input_snapshot_line
  snapshot_id, quotation_line_item_id
  parent_line_item_id
  product_identity_json              稳定产品/层级/属性事实
  user_input_json                    模板声明的用户输入
  structure_input_json               数量/年用量/工艺/锁定组成/树差异
  source_fact_json                   带来源、敏感级别和复制策略的输入事实
  line_input_hash
```

约束：

- `(quotation_id, user_data_version)` 唯一；行主键为 `(snapshot_id, quotation_line_item_id)`。SEALED 头和明细由应用与数据库触发器共同禁止更新/删除。
- 每个 `source_fact_json` 项必须包含稳定 `factKey`、值类型、值、`sourceKind/sourceRef`、`sensitivityClass` 和 `copyPolicy`。`copyPolicy` 只允许 `COPY_WITH_PRODUCT` 或 `RE_RESOLVE`；Secret 与未声明字段禁止进入快照。
- 快照只保存计算输入，不保存客户快照、价格策略/日历选择结果、价格修订、币种/汇率/税率快照、单价、金额、小计、公式结果或四类缓存。客户/报价范围事实必须标记 `RE_RESOLVE`，复制时不携带值。
- 模板版本提供版本化输入 schema：声明允许字段、类型、是否必填、跨模板映射键和默认复制策略。运行期不从 `snapshot_rows` 猜字段性质。
- 投影和报价当前/提交绑定都显式引用快照 ID；`user_data_version` 继续作 CAS 版本，不能替代快照外键。封存前按 `CPQ-JCS-1` 计算行/包摘要；任何缺字段、类型错误或黑名单字段使整包 ABORTED。
- 同模板复制读取源单明确绑定的 SEALED 快照，只复制 `COPY_WITH_PRODUCT` 项并生成目标单自己的新快照；不共享可变引用。跨模板还必须经过目标模板显式映射。`RE_RESOLVE` 项按目标客户、目标模板和新报价事实重新解析。

### 3.3 价格修订头

```text
quotation_element_price_revision
  id, quotation_id, revision_no
  idempotency_key
  parent_revision_id
  scope                              QUOTATION | COSTING
  reason_code                        INIT | ADD_ELEMENT | MANUAL_OVERRIDE |
                                     RESOLVE_MISSING | EXPLICIT_REFRESH |
                                     PRICE_ADJUSTMENT | COSTING_ADD_ELEMENT
  status                             BUILDING | SEALED | ABORTED
  price_base_date
  quote_currency_code
  exchange_rate_snapshot_id
  element_catalog_digest
  content_hash
  created_by, created_at, sealed_at
  reason_text, source_job_id
```

约束：

- `(quotation_id, revision_no)` 唯一，修订号从 1 严格递增。
- `parent_revision_id` 必须属于同一报价单；R1 为空，其他修订必填。
- 封存时 `content_hash`、基准日、币种与所有必要明细完整。
- 同一幂等键/内容哈希重试返回已有修订，不重复加号。

### 3.4 价格修订明细

```text
quotation_element_price_revision_item
  revision_id, element_id
  element_code_snapshot, element_name_snapshot
  canonical_unit_code
  cny_unit_price                     numeric(38, 12), 应用写入前 HALF_UP 到 9 位
  quote_currency_code
  quote_currency_unit_price          numeric(38, 12), 应用写入前按元素价规则规范化
  source_type                        STRATEGY | MANUAL | ADJUSTMENT | REUSED
  source_strategy_version_id
  source_rule_id
  source_calendar_version_id
  source_market_price_ids            jsonb
  target_dates, excluded_dates        jsonb
  target_to_source_date_map           jsonb
  aggregation_type, factor, premium
  automatic_cny_price
  manual_override_reason
  inherited_from_item_id
  item_hash
```

主键 `(revision_id, element_id)`；`element_id` 是稳定关联键，编码只作冻结显示。空值为缺价，零不能代表缺价。

### 3.5 原子计算投影

```text
quotation_projection
  id, quotation_id
  idempotency_key
  scope                              DRAFT_BUNDLE | COSTING_REVIEW
  user_data_version
  calc_input_snapshot_id
  price_revision_id
  template_version_id
  composition_digest
  used_element_digest
  base_quote_projection_id           nullable, COSTING_REVIEW 时指向提交报价投影
  hash_protocol, input_hash, frontend_result_hash, backend_result_hash
  engine_version
  build_status                       BUILDING | VALIDATING | READY | FAILED | SUPERSEDED
  comparison_status                  PENDING | MATCHED | MISMATCH
  attempt_no, retry_count, next_attempt_at
  error_code, error_detail
  totals_json, formula_errors_json
  created_at, completed_at, activated_at, payload_purged_at

quotation_projection_line
  projection_id, quotation_line_item_id
  quote_card_values
  quote_excel_values
  costing_card_values
  costing_excel_values
  line_totals_json

quotation_projection_diff

```

`DRAFT_BUNDLE` 的四类结果与合计属于同一投影，四类字段都必须完整；不能只原子更新四个 JSON 而让头部合计仍是旧值。提交后的 `COSTING_REVIEW` 只重建核价卡片/Excel/合计，同时用 `base_quote_projection_id` 引用不可变的报价提交投影，不重复计算或覆盖报价结果。

### 3.6 核价单绑定

```text
costing_order
  submitted_quote_price_revision_id
  submitted_quote_projection_id
  applied_price_revision_id
  applied_composition_revision_id
  desired_costing_projection_id
  active_costing_projection_id
  composition_override_digest
  review_version
```

前两项指向销售提交事实；`applied_*` 与活动核价投影是财务审核期间的当前核价事实。二者允许不同，但都必须显式展示。

### 3.7 核价组成候选、预览 token 与审批证据

```text
costing_composition_revision
  id, costing_order_id, revision_no, parent_revision_id
  status                             CANDIDATE | ACTIVE | FAILED | SUPERSEDED
  content_digest
  source_preview_token_digest        审计摘要，不外键引用可清理 token 行
  created_by, created_at, activated_at, completed_at, payload_purged_at

costing_composition_revision_item
  composition_revision_id, component_id, part_no
  source_view_version, target_view_version
  override_payload, item_digest

costing_version_preview_token
  id, token_digest
  costing_order_id, actor_id
  expected_review_version
  expected_quote_price_revision_id, expected_quote_projection_id
  expected_costing_price_revision_id, expected_costing_projection_id
  expected_composition_digest, candidate_composition_digest
  preview_payload_digest, expires_at, consumed_at, created_at

costing_review_decision_evidence
  id, costing_order_id, decision       APPROVED | REJECTED
  review_version
  quote_price_revision_id, quote_projection_id
  costing_price_revision_id, costing_projection_id
  composition_revision_id, composition_digest
  actor_id, reason, decided_at, evidence_digest
```

- 组成修订及明细创建后不可原位编辑；只有最终 CAS 成功的候选写 `ACTIVE/activated_at` 并绑定 `costing_order`。失败或过期候选不可见，不得回写旧 `costing_order_version_override`。
- token 只向客户端返回随机原文，数据库仅保存密码学摘要。确认事务锁定 `costing_order` 后以摘要匹配，并在校验全部预期绑定的同一事务中写 `consumed_at`；一次性、过期、操作者和核价单范围均由数据库状态约束。
- 批准或驳回都追加一条不可变 decision evidence；请求绑定与当前任一字段不一致返回 409，不产生证据行。

### 3.8 调价接入命令

```text
quotation_price_adjust_command
  id, source_job_id, quotation_id, base_price_revision_id
  idempotency_key
  status                             PENDING | PROCESSING | SUCCEEDED | FAILED | SUPERSEDED
  target_price_revision_id, target_projection_id
  attempt_count, next_attempt_at, error_code
  created_at, completed_at
```

`UNIQUE(source_job_id, quotation_id, base_price_revision_id)` 保证同一调价来源不重复生成修订。worker 只能在 `DRAFT + currentRevision + userDataVersion` 仍匹配时激活新修订/投影；正式状态报价记录“已冻结跳过”，不修改提交事实。

## 4. 唯一解析与计算规则

### 4.1 元素价解析器

所有 SNAPSHOT 消费者调用：

```text
resolve(quotationId, consumer, boundRevisionId, elementId, targetUnit, targetCurrency)
```

解析器只读绑定修订，不查询“当前最新”策略或行情。返回价格、规范单位、币种换算、来源解释和阻断状态。产品卡片、公式变量、报价/核价 Excel、导出与审批不得各自实现后备取价。

LEGACY 单据显式进入旧适配器；禁止以 `revision_id IS NULL` 猜分支。

### 4.2 新元素解析

1. 锁定报价/核价绑定及预期版本。
2. 集合化计算产品组成，得到实际元素并集。
3. 与母修订比较，只选新增 `elementId`。
4. 使用报价客户、原 `priceBaseDate`、操作时最新已发布策略版本解析新元素。
5. 批量读取策略、日历、行情、汇率和单位换算。
6. 任一新元素失败则整个新修订 ABORTED；旧绑定不变。
7. 全部成功后封存新修订，再创建目标投影。

“最新策略”只用于新增元素或显式刷新，不能覆盖母修订既有元素。

### 4.3 前后端比对

前后端共用规范输入格式、舍入点、空值语义和排序规则，但必须独立执行。普通公式遵守项目“计算 12 位、显示 9 位、存储按列 scale”的基线；元素单价单独遵守 DEC-0020“写入前 HALF_UP 到 9 位”，不得把两套精度混为一个全局常量：

1. 用户编辑后前端即时计算，页面标为 `待后端校验`。
2. 前端按 `api.md §1.1` 的 `CPQ-JCS-1` 生成规范输入/结果：精度敏感数字先成为规范十进制字符串，每类数组按声明的业务稳定键排序，再执行 RFC 8785 JCS；发送 `hashProtocol`、`userDataVersion`、`priceRevisionId`、模板/组成摘要、引擎版本、输入摘要和结果摘要，需要定位差异时上传逐格规范值。
3. 后端从持久化冻结输入重新构造上下文并计算，绝不把前端结果写成权威值。
4. 后端独立实现同一协议，以 UTF-8 和带 `0x00` 分隔的输入/结果独立域前缀计算 SHA-256；先比较输入摘要，再按统一精度比较结果并生成 `MATCHED` 或逐格 `MISMATCH`。稳定键缺失/重复或协议未知时直接阻断，不能按当前数组顺序兜底。
5. MISMATCH 时页面展示后端值和差异，要求同步输入/引擎并重新计算；本期没有“忽略后提交”。

`hash_protocol` 随投影永久保存。协议升级只能新增版本与域前缀，历史投影继续按原版本复验；实现构建号 `engine_version` 只用于定位，不得冒充协议版本。前后端共用数据夹具及期望字节/摘要，但不共享运行时代码，以保持独立计算证据。

## 5. 原子投影协议

“原子投影”不是把四次 UPDATE 放进一个方法，而是让未完成结果对任何正式读者不可见：

```text
输入变化
  └─► 创建目标投影 P2（BUILDING，不可见）
        ├─► 批量计算所有行与四类结果
        ├─► 计算行/单据合计、公式错误和哈希
        ├─► 与前端结果比较
        └─► 条件切换 active P1 → P2
              条件：desired=P2、输入版本/价格修订/组成摘要仍一致、P2 READY+MATCHED
```

活动指针切换与 P2 状态封存在同一事务中。读者只通过活动指针读；提交和导出额外要求 `active=desired`。过期任务可以完成自己的行写入，但条件切换失败后只能成为 `SUPERSEDED`。

失败时：

- P1 继续服务只读，不会出现半套 P2。
- 页面显示 P2 失败原因，但不得把 P1 冒充“已按最新输入计算”。
- 重试只创建/重跑投影，不推进价格修订。

## 6. 业务流程

### 6.1 新建与日常编辑

```text
创建 SNAPSHOT 报价
→ 保存产品/冻结计算输入
→ 解析全单元素并生成 R1
→ 建目标报价投影 P1
→ 前端预览 + 后端独立计算
→ MATCHED 后原子激活 P1
```

改数量/属性、移除元素或重新使用已有元素只推进 `userDataVersion` 和投影；人工改价推进价格修订和投影；新增只用既有元素的产品不推进价格修订。

### 6.2 提交

提交请求携带预期 `userDataVersion/currentPriceRevisionId/activeProjectionId`。事务内再次验证：

- 状态与提交权限合法；
- 无缺价、待确认、单位/币种错误和公式错误；
- 活动投影等于目标投影；
- 投影绑定当前输入与价格修订；
- 后端 READY 且 MATCHED。

成功后写 `submitted_*` 并创建 `costing_order`，其报价绑定和核价初始绑定均指向提交修订/投影。

### 6.3 财务审核与换组成版本

审核页同时展示：

- 报价提交：价格修订 Rs、投影 Ps，只读；
- 核价当前：价格修订 Rc、投影 Pc、组成版本和 override；
- 若 Rc≠Rs，突出列出仅核价新增元素及来源，不能用含糊“最终价格”掩盖差异。

换版两阶段：

1. **预览**：以当前绑定和目标组成版本生成确定性 `previewToken`，展示增删部件、元素并集、新增元素、预计修订变化和缺价。
2. **确认**：携带 `previewToken`、预期 `reviewVersion`、Rc/Pc 和组成摘要。

无新元素：只写组成 override，生成新核价投影。

有新元素：生成 Rn+1，复制所有旧明细，新元素按客户策略和原基准日补齐，再生成核价投影。任何步骤失败时事务/状态机不切换当前 binding；报价 Rs/Ps 永不变化。

### 6.4 审批

批准/驳回请求必须绑定审核页面实际看到的报价修订、报价投影、核价修订、核价投影、组成摘要和 `reviewVersion`。任何一个已经改变都返回 409。审批记录保存这些标识和摘要，保证以后可以还原。

### 6.5 复制

允许复制：

- 报价头允许字段、客户/模板选择规则所需字段；
- 产品行、数量、属性、工艺选择、用户输入、树增删差异；
- 源单 SEALED 计算输入快照中标记 `COPY_WITH_PRODUCT` 的输入事实；目标单生成自己的新快照。

禁止复制：

- 价格修订和明细；
- 四类派生结果、投影、金额/公式结果；
- 提交、审批、核价绑定与状态；
- 原报价基准日（新单按复制时业务规则确定）。

同模板复制用复制后的冻结输入重算，不回查源报价私有待发布数据；跨模板仅映射目标声明的输入。可补录的目标必填输入缺失进入 `INCOMPLETE`；禁止复制、来源无法证明或命中黑名单则 `FAILED`，禁止以 0 填充。新报价先持久化产品内容，再生成自己的 R1 和 P1；缺价时保留可修复 DRAFT。

复制状态机固定为：

1. 锁定源报价并选择明确来源快照：DRAFT 使用当前快照，已提交及后续状态使用报价提交快照；不得读取核价换版输入或“最新一份”未绑定快照。
2. 以幂等复制命令创建目标 DRAFT、产品关系和 BUILDING 输入快照；结构创建属于受控任务步骤，异常不得像现有 `ensureStructure` 一样吞掉后返回成功。
3. 同模板按 `copyPolicy` 复制，跨模板再应用目标 schema 映射；客户/报价范围事实只重新解析。白名单之外的 `snapshot_rows`、价格和派生字段无论字段名是否相同都不得进入目标快照。
4. 用户能够补录的目标必填输入缺失时，目标单进入 `INCOMPLETE`，列出稳定 input key 且保持禁止提交；禁止跨客户复制、来源无法证明或载荷含黑名单字段时任务 `FAILED` 并返回 `COPY_SOURCE_PRIVATE_DATA_UNAVAILABLE`，不得产生可用报价。
5. 输入快照 SEALED 后，才按目标客户、新 `priceBaseDate` 生成 R1/P1。缺价进入可修复 `INCOMPLETE`；任何金额保持待计算，不显示源单结果。

## 7. 状态与提交门禁

| 状态 | 页面行为 | 可提交 |
|---|---|---|
| `BUILDING/CALCULATING` | 显示旧活动结果 + “新结果计算中”，明确旧结果对应版本 | 否 |
| `VALIDATING/PENDING` | 显示前端预览、等待后端比对 | 否 |
| `READY/MATCHED` 且 active=desired | 显示已验证标识、后端时间与版本 | 是，仍需事务内复核 |
| `READY/MISMATCH` | 展示逐格差异与重新同步动作 | 否 |
| `FAILED` | 展示错误码、阶段和重试；旧结果只读 | 否 |
| `SUPERSEDED` | 不主动展示，仅审计可见 | 否 |

提交按钮禁用只是体验；后端必须用同一门禁拒绝绕过 UI 的请求。

## 8. 策略、日期与 AI 边界

- 策略和交易日历采用不可变发布版本。
- 条件 DSL 和日期生成器以补充设计为准，周期采样统一名为 `PERIOD_POINT`。
- 策略可保存日历选择器或显式版本：选择器在执行时解析覆盖区间的已发布具体版本并冻结；显式版本覆盖不足直接失败。
- 每条规则只配置一个 `missingPricePolicy`，统一处理它生成的所有缺价目标日；逐日映射是结果证据，不是逐日可编辑规则。
- AI 只在配置期把自然语言转换为受限 DSL；未经结构化确认不能发布。运行期、复制、加产品和核价换版均不调用 AI。
- 交易日历必须通过独立管理模块维护不可变发布版本；价格源管理维护默认日历绑定。无绑定或覆盖不足直接阻断，不允许用周末推断兜底。
- AI Provider、Prompt、Schema 和 Parser Release 通过专用安全配置模块管理；数据库仅保存 Secret 引用。

## 10. 错误与恢复原则

| 场景 | 原则 |
|---|---|
| 新元素缺价 | 新修订不封存，旧绑定不变，列出元素和原因 |
| 后端计算失败 | 新投影失败，旧活动投影继续只读，提交阻断 |
| 前后端不一致 | 返回逐格 diff，不允许忽略 |
| 并发冲突 | 409 + 当前版本摘要，不做最后写入覆盖 |
| 复制输入缺失 | 可补录的目标必填输入进入 `INCOMPLETE`；禁止复制/来源不明/黑名单进入 `FAILED`，均不填 0、不继承金额 |
| 核价换版中断 | 当前组成、修订和投影均不切换 |
| 重复请求 | 幂等键返回已有成功结果或既有进行中任务 |

## 11. 保留与安全清理

### 11.1 永久排除清理的业务证据

下列对象随所属业务单据保留，任何部署参数都不能把它们变成清理候选：

- 所有 `SEALED` 价格修订及明细；
- `first_business_bound_at/activated_at` 非空，即曾被正式激活的输入快照和报价/核价投影；
- 被当前、目标、提交、核价、审批、导出证据或成功复制溯源引用的对象；
- 已生效组成修订、已发布策略/日历/AI release 及其历史引用。

“当前已经不是活动指针”不等于未生效；曾激活的 P1 在切到 P2 后仍是正式历史，不能清理。外键均使用 `RESTRICT`，清理不得通过级联绕过本规则。

### 11.2 从未生效终态候选的冻结周期

仅同时满足“从未激活、未被任何业务/复制引用、已进入不可重试终态、超过冻结期”的对象可清理：

| 数据 | 冻结期 | 到期动作 |
|---|---:|---|
| FAILED/SUPERSEDED 投影行、逐格 diff、大型结果/错误载荷，以及 ABORTED/失败输入或组成候选的大字段 | 90 天 | 分批删除重载荷；头部写 `payload_purged_at` |
| 上述技术头的状态、摘要、绑定、耗时和错误码 | 365 天 | 再次确认无引用后删除头；清理批次审计独立保留 |
| 已消费或已过期的数据库预览 token | 30 天 | 删除 token 行；消费/过期事件继续存在操作审计 |
| SUCCESS/FAILED/CANCELLED 等终态异步命令、发件箱和幂等执行记录 | 180 天 | 确认无待投递/待重试后分批删除 |

冻结期从对象进入终态、token 消费/过期或命令终态的较晚时间开始计算。进行中、仍可重试、当前目标或处于回退窗口的对象没有清理时钟。

### 11.3 清理执行约束

- 首版部署基线固定为 `90/365/30/180` 天；监控页只读显示。部署配置只允许延长；缩短属于数据治理契约变更，必须另行裁决并评估存量。
- 清理器先运行 dry-run，输出候选数量、预计字节、最早/最晚时间和排除原因；正式任务按小批量事务并使用数据库抢占，避免长事务和多实例重复处理。
- 每批删除前在同一事务重新检查全部指针、外键、`activated_at/first_business_bound_at`、复制溯源、终态和重试资格；任一不满足即跳过。不能依赖几分钟前的扫描结果。
- 清理审计至少记录策略版本、批次、表、数量、字节、时间水位、执行人/实例和失败原因；监控接口只报告，不提供手工强删端点。
- 测试数据的分片清理由测试隔离规则负责，不得调用生产清理器跨前缀删除。

## 13. 实施分期与门禁

### Phase 1：事实与原子计算闭环

- 模式分流、价格修订、统一解析器；
- 前后端独立计算/比对与原子投影；
- 计算投影任务监控与安全重试；
- 报价编辑、提交、导出；
- 复制；
- 核价审核、组成换版和审批并发保护。

Phase 1 必须作为一条端到端闭环交付，不能先把可变 JSON 上线再补版本化。

### Phase 2：策略 v2 与 AI 配置

- 条件/日期 DSL、日历版本、缺价策略；
- 交易日历管理、价格源默认日历绑定与策略版本发布；
- AI Provider/Prompt/Schema/Release 管理及配置期解析；
- 试算、解释和批量执行性能。

如果 Phase 2 延后，Phase 1 必须通过稳定策略适配器生成相同的来源证据；不能留下无法追溯的“临时价”。
