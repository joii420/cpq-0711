# 测试方案与 AC 可追溯矩阵

## 1. 测试原则

- 测试从 `需求文档.md` 的 AC 推导，不以最终实现结构反推。
- 每条 AC 只有一个主证据分片；其他分片可提供辅助证据，但不得互相声称主验收。
- 数据库类测试使用独立 PostgreSQL 测试库/副本；共享开发库只允许只读基线查询，未经授权不写入。
- 精度、数据分布和迁移版本必须在 Gate A/实现开始前对实际环境实查；容量与 P95 验收值以已裁决 AC 为准，不把开发库当前条数误写成业务固定值。

## 3. 核心测试设计

### 3.1 价格修订测试

1. 用包含共享元素/新增元素的两个产品生成 R1，验证 `(revision, element)` 唯一和完整来源。
2. 人工改价、首次新增元素和价格调整依次生成修订，逐字段比较“不应改变”的旧元素；删产品、重新加入既有元素只推进用户数据/投影，断言价格修订号和值不变。
3. 直接 SQL/ORM 尝试更新或删除 SEALED 明细，必须失败；失败构建不能绑定。
4. 对缺价、零价、超精度、单位不可换、汇率缺失做整批回滚断言。

### 3.2 双引擎黄金向量

建立语言无关的 `CPQ-JCS-1` 黄金夹具，每例同时固定语义 JSON、JCS 后 UTF-8 字节和输入/结果 SHA-256。覆盖：对象键乱序、数组乱序、稳定键重复/缺失、字段缺失/null/空串/零、正负零、末尾零、禁止指数、Unicode/转义、负数/零阻断、9 位小数、聚合、单位换算、汇率、跨页签依赖、树公式、舍入临界值和错误传播。前端与后端以各自实现计算同一夹具并逐字节、逐摘要比较；加入输入相同但结果差一格、结果相同但输入绑定不同、输入/结果域互换、未知协议和历史协议复验反例，验证逐格 diff 与阻断行为。

### 3.3 原子投影并发测试

- 在 P2 写完部分行时并发读取，所有正式读仍返回完整 P1。
- P2 构建时创建 P3；让 P2 后完成，验证 CAS 失败、P2=SUPERSEDED、活动指针最终只指 P3。
- 在活动指针切换前后高频读取，任一响应只含单一 `projectionId` 且头/行/合计哈希闭合。
- 注入任务宕机、数据库死锁、超时和重试，验证旧活动结果继续可读、提交阻断、无价格修订误增。

### 3.4 财务换版事务测试

- 候选 V2 无新元素：修订号不变，只更核价投影。
- 候选 V3 新增两个元素：一次生成完整 Rn+1，旧元素逐字段不变，报价提交绑定不变。
- 第二个新增元素缺价或投影失败：组成 override、修订绑定、活动投影全不变化。
- 两个财务页面并发预览/批准：token 重放、超过 30 分钟、操作者/核价单不匹配、任一报价/核价/组成绑定或 `reviewVersion` 变化均返回 409；确认返回 202 后、最终 CAS 前正式绑定完全不变。

### 3.5 复制隔离测试

在源单不可变输入快照、现有 `snapshot_rows`、价格/金额/公式/四类缓存、审批和核价字段分别写唯一哨兵值；复制后只允许 `COPY_WITH_PRODUCT` 哨兵进入目标单自己的 SEALED 快照，其余哨兵在目标输入、价格、投影和页面响应中均不存在。直接 SQL/ORM 更新或删除 SEALED 头/行必须失败。删除公共源数据可见性后复制同模板，验证允许的冻结来源事实仍可重算；客户范围 `RE_RESOLVE` 事实不得跨客户携值。跨模板分别验证可映射、可补录缺失进入 `INCOMPLETE`、来源不明/黑名单导致 FAILED，所有路径都不得填 0 或继承源金额。另验证 DRAFT 选择当前快照、已提交状态选择提交快照，未绑定更新快照和核价输入不能被误选。

### 3.6 性能与查询基线

采用用户裁决的兼容现有大单基线：正式上限为单张报价单 2000 个产品、64 个不同价格元素。S6 在固定提交、固定数据库资源的一次性测试环境执行；报告必须记录 CPU/内存、数据库规格、前后端构建版本、批大小、数据构成和测试时段，环境变化后旧数字不得冒充新基线。

1. 每个时延场景先预热至少 3 轮，再执行至少 20 个独立样本并保留全部原始值；P95 使用升序样本的最近秩法计算，不删除超时或失败样本。
2. 异步任务受理从客户端发出创建请求到收到已持久化任务标识计时，P95 ≤ 1 秒。
3. 投影完成从任务成功受理到目标投影进入可读取终态计时：8 产品普通单 P95 ≤ 5 秒，2000 产品大单 P95 ≤ 60 秒；失败和超时计为未达标，不能只统计成功任务。
4. 分页结果首屏从浏览器发出列表请求到首屏行、合计和状态全部完成渲染计时：普通单 P95 ≤ 2 秒，大单 P95 ≤ 5 秒。首屏接口必须分页，测试同时记录响应体大小，禁止预取全部明细后在前端伪分页。
5. 普通单固定为 8 个产品，大单固定为 2000 个产品；两者均构造 64 个不同价格元素在单据内有实际引用，并包含价格解析、公式、四类结果和合计，不能使用空行或无公式产品降低负载。
6. 逐阶段记录 SQL 总数并通过查询监听器断言不存在逐产品/逐元素 N+1；允许按固定批大小拆批，但每批只能使用集合查询，报告须给出 8 与 2000 产品的查询数及拆批公式。

### 3.7 配置管理闭环

- 日历：三类主档、非法时区、草稿复制、每日状态、Excel 整批拒收、覆盖完整性、发布不可变、停用引用保护和历史复现。
- 选择器：固定版本、固定主档、价格源默认三条路径，覆盖不足/无绑定/歧义都必须失败，不能回退周末推断。
- 策略：旧可变策略兼容、新版本草稿/验证/发布/归档，以及角色对草稿和发布的不同权限。
- AI：DTO/日志/异常/浏览器网络四层 Secret 泄漏扫描；金标失败阻断发布；禁用 AI 后结构化路径可用。
- 监控：只读字段、业务范围权限、当前 FAILED 可重试、过期拒绝和不存在危险端点的契约测试。
- 保留：时间推进覆盖 89/90、364/365、29/30、179/180 天边界；曾激活后被替换、复制溯源、当前/目标/提交/核价/审批引用均不得入候选。从未激活无引用对象先 dry-run，再清重载荷并保留头，最后清头；删除前注入新绑定验证二次检查会跳过。并发运行两个清理器不得重复处理或越界，清理审计数量/字节与实际一致。

## 5. 回归清单

- LEGACY 报价的打开、编辑、提交、详情、导出和核价不发生首次访问重算。
- 既有模板、公式、树计算、税率/汇率/单位快照、价格调整任务不出现静默口径变化。
- 现有提交权限不因“销售经理可改价”而被无意扩大。
- `costing_order` 现有通过、驳回、版本选项和换版基本流程继续可用。
- 任务未涉及的独立 `costing_summary` 页面不得因本任务 DTO/路由变化而报错。

## 6. Gate B 证据要求

1. 所有 AC 均有主证据，失败后修复需保留原失败与复验记录。
2. S1～S8 完成后由主线执行 S0，不以分片自报代替亲验。
3. 产出独立 `test-report.md`，记录命令、环境、提交、数据库版本、结果与已知限制。
4. 执行 `check-decisions.sh`、`check-selfcheck.sh`、`guard-redline.sh` 等等价 hook；更新 PRD/基线/RECORD/INDEX 和 `main-api.md`。
5. 未收到用户明确“打包/部署”指令时，不生成或更新 `deploy/` 产物。
