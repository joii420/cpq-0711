# 配置管理模块补充设计

> 目的：检查报价单级元素价格表及客户价格策略依赖的所有配置，确保每项都有明确的维护入口、版本规则、权限和运行时读取方式；不把固定业务规则误做成可随意修改的系统参数。

## 1. 配置闭环审计

| 配置/依赖 | 当前系统事实 | 本任务处理 | 管理入口 |
|---|---|---|---|
| 客户元素价格策略 | 已有策略页面和 CRUD，但当前记录可覆盖修改，只支持简单窗口 | 升级为不可变策略版本、草稿/发布、条件与日期 DSL、试算和历史差异 | 扩展现有“定价策略 → 客户元素价格策略” |
| 元素价格源 | 已有价格源管理，字段只有名称、网址、备注和状态 | 增加默认交易日历绑定；价格源本身继续由原模块维护 | 扩展现有“元素管理 → 价格源管理” |
| 元素每日价 | 已有明细、矩阵、导入和历史 | 直接复用，不另建模块；正式策略执行只读已入库价格 | 现有元素价格中心 |
| 交易日历 | 当前代码、数据库和前端均无管理模块 | **新增交易日历管理** | “定价管理 → 交易日历” |
| AI 服务连接 | 当前无 LLM 客户端和配置 | **新增 AI 解析配置**；密钥不进入通用系统配置 | “系统管理 → AI 解析配置” |
| Prompt/Schema | 当前无版本库 | 纳入 AI 配置模块，采用不可变版本和金标验证后发布 | AI 解析配置内的版本页签 |
| 投影任务/重试 | 当前无本任务投影任务 | **新增计算投影监控**，提供诊断和安全重试 | “系统管理 → 计算任务监控” |
| 投影保留周期 | 本任务前无统一策略 | 固化为未生效重载荷 90 天、技术头 365 天、过期/已消费 token 30 天、终态命令 180 天；正式证据随单保留。部署配置只许延长，监控页只读 | 部署配置 + 监控页只读 |
| 投影并发、超时、队列参数 | 本任务前无对应投影 worker | 属于可逆部署容量参数；实现后以 AC-35 压测结果固化初始值，监控页只读显示，修改需重启/发布并留运维记录，不得通过调参放宽 AC | 部署配置 + 监控页只读 |
| 客户、元素 | 已有主数据管理 | 直接复用稳定 ID；策略不得保存自由文本替代 ID | 现有客户/元素管理 |
| 币种、汇率 | 已有币种、历史汇率和客户汇率策略 | 直接复用报价汇率快照 | 现有币种管理/客户汇率策略 |
| 单位及换算 | 已有单位管理 | 直接复用；不可换算时阻断取价 | 现有单位管理 |
| 报价价格基准日 | 当前报价链路以建单日期为基准 | 本期固定为报价单持久化字段：新建/复制时取新单创建业务日；提交后不可改。不是系统配置 | 报价单头只读展示 |
| 计算/显示精度 | 已由 DEC-0004、DEC-0020 固化 | 作为代码与数据库基线，不提供 UI 修改 | 无管理入口，变更必须另立任务 |
| 前后端引擎版本/哈希算法 | 属于发布制品 | 由构建版本记录并回传，不允许管理员在页面改写 | 监控页只读 |
| DSL 最大窗口、回溯和规则数 | 尚未实现 | 作为安全上限随代码版本发布，不进入普通系统配置，避免绕过性能边界 | 代码常量 + 页面提示 |
| 跨模板复制 INPUT 白名单 | 来源是目标模板字段定义 | 复用模板/组件配置，不再建立重复白名单模块 | 现有模板/组件管理 |
| 角色与审计 | 已有权限矩阵和操作日志 | 增加新资源权限和审计事件 | 现有用户/操作日志 |

结论：需要新增两个配置模块、一个运维监控模块，并扩展两个既有模块；其他依赖都有明确来源或属于不可配置基线。

## 2. 交易日历管理

### 2.1 业务定位

交易日历回答“某价格源在某个具体日期是否正常交易/报价”。它不同于价格数据：日历判断市场状态，`element_daily_price` 记录实际价格。即使日历标记休市，只要当天存在有效价格，策略仍按 `DIRECT` 使用并记录“休市日存在实际价格”；只有无价格时才进入缺价政策。

### 2.2 日历主档

```text
trading_calendar
  id
  calendar_code                 全局唯一，发布后不可改
  calendar_name
  calendar_type                 MARKET | COUNTRY | CUSTOMER
  country_code                  COUNTRY/MARKET 可选
  market_code                   MARKET 可选
  owner_customer_id             CUSTOMER 必填
  zone_id                       IANA ZoneId，例如 Asia/Shanghai
  description
  status                        ACTIVE | DISABLED
  version
```

校验：

- `CUSTOMER` 必须有客户且不得配置其他客户策略引用。
- `MARKET` 应填写市场/国家；`COUNTRY` 至少填写国家。
- `zone_id` 必须是有效 IANA 时区；不接受服务器默认时区。
- 已被策略或价格修订引用的主档不得物理删除；停用只阻止新绑定，不影响历史读取。

### 2.3 不可变日历版本

```text
trading_calendar_version
  id, calendar_id, version_no
  status                        DRAFT | PUBLISHED | ARCHIVED
  coverage_start, coverage_end
  source_type                   MANUAL | EXCEL_IMPORT
  source_description
  content_digest
  created_by, created_at, published_by, published_at

trading_calendar_date
  calendar_version_id, calendar_date
  day_status                    OPEN | CLOSED
  reason_type                   NORMAL | WEEKEND | PUBLIC_HOLIDAY |
                                MAKEUP_WORKDAY | TEMP_CLOSURE | OTHER
  reason_text
```

发布版本不可编辑、不可删日期。修改时从已发布版生成新草稿；发布时物化覆盖区间内每一天的最终 `OPEN/CLOSED` 状态，不能把“未配置”默认成开市。

版本选择规则：

1. 策略固定 `calendarVersionId`：只能使用该版本，覆盖不足直接失败。
2. 策略绑定 `calendarId`：从已发布版本中选择 `version_no` 最大且单一版本完整覆盖全部目标日和最大回溯区间。
3. 策略选择 `PRICE_SOURCE_DEFAULT`：先读取价格源的 `defaultCalendarId`，再执行规则 2。
4. 没有绑定、无完整覆盖版本或出现不可唯一选择时返回 `CALENDAR_NOT_AVAILABLE`；禁止隐式回退到“中国法定节假日”或周末推断。

### 2.4 页面与操作

日历列表显示类型、时区、当前发布版本、覆盖区间、未来覆盖天数、绑定价格源数和状态。详情页提供：

- 新建主档、编辑未冻结元数据、启用/停用；
- 从上一发布版本生成草稿；
- 月历/列表双视图编辑日期状态和原因；
- 下载 Excel 模板、导入草稿、导出版本；
- 完整性/重复日期/非法日期/覆盖断档检查；
- 发布前预览差异和受影响的价格源/策略；
- 版本历史和相邻版本 diff。

Excel 至少包含：`日期*、是否开市*、原因类型*、原因说明`。同一文件日期重复、超覆盖范围、状态/原因非法时整份拒收，不部分导入。

第一期不做外部节假日 API 自动同步，因此不出现没有维护入口的 `EXTERNAL_IMPORT` 配置。未来如接入官方/商业日历源，必须另建数据源、凭据、调度、失败重试和数据质量闭环。

### 2.5 权限

- `PRICING_MANAGER`、`SYSTEM_ADMIN`：维护草稿、导入、发布和停用。
- 销售角色：在策略配置/试算中只读可选日历及覆盖提示。
- 发布、停用、导入和绑定变更均写操作日志。

## 3. 价格源管理扩展

现有 `element_price_source` 与页面继续保留，新增：

```text
default_calendar_id             nullable FK trading_calendar
market_zone_id                  IANA ZoneId；未填时继承日历 zone_id
```

- 启用价格源不强制绑定日历，因为只用于 LATEST 且不判断交易日时仍可能合法；但任何选择 `PRICE_SOURCE_DEFAULT` 的策略发布前必须校验已绑定。
- 变更默认日历只影响此后解析出的新元素；不改变已发布策略固定版本或已有价格修订。
- 停用日历时，如仍是启用价格源默认日历，应阻止停用并列出引用；先解绑/替换后才能停用。
- 价格源名称、网址、备注和状态沿用现有角色权限；默认日历/市场时区使用独立绑定接口，只有 `PRICING_MANAGER`、`SYSTEM_ADMIN` 可修改，避免扩大既有通用更新接口的高影响字段。

## 4. 客户价格策略管理升级

现有策略页面从“直接覆盖当前行”升级为：

1. 策略版本列表：草稿、已发布、已归档、有效期和摘要。
2. 草稿编辑：默认规则、元素例外、日期条件、日期生成器、排除、价格源、日历绑定、缺价政策、聚合、系数和加价。
3. 试算：选择客户、元素和试算基准日，展示目标日、排除日、日历状态、实际来源日、样本和最终价格。
4. 发布检查：唯一兜底、规则冲突、价格源启用、日历绑定/覆盖、单位/币种一致、DSL Schema 和窗口上限。
5. 发布版本不可修改；生成新草稿才可调整。已发布策略变化不重算已有价格修订。

草稿编辑沿用现有策略页面角色范围；发布、归档和影响分析仅允许 `PRICING_MANAGER`、`SYSTEM_ADMIN`。这既不让旧客户端直接改写已发布版本，也不在本任务无提示删除既有草稿编辑权限。

## 5. AI 解析配置管理

### 5.1 配置对象

```text
ai_provider_profile
  id, profile_code, provider_type, base_url, model_name
  secret_ref                    只保存安全存储引用，不保存密钥明文
  connect_timeout_ms, read_timeout_ms, max_retries
  enabled, version

ai_prompt_version
  id, use_case                  ELEMENT_PRICE_POLICY_PARSE
  version_no, prompt_template
  output_schema_version_id
  status                        DRAFT | PUBLISHED | ARCHIVED
  content_digest

ai_schema_version
  id, schema_code, version_no, json_schema
  status                        DRAFT | PUBLISHED | ARCHIVED
  content_digest

ai_parser_release
  id, release_no
  provider_profile_id, prompt_version_id, schema_version_id
  status                        DRAFT | PUBLISHED | DISABLED
  gold_case_set_version_id
  gold_case_result_summary

ai_gold_case_set_version
  id, version_no, status        DRAFT | PUBLISHED | ARCHIVED
  cases_json                    输入、期望状态、期望 DSL/错误
  content_digest
```

运行时解析只读取唯一已发布、启用的 `ai_parser_release`，并记录 release/provider/model/prompt/schema 版本。报价取价运行期不读取这些配置。

### 5.2 密钥规则

- 密钥存放于部署环境的 Secret/Vault；数据库只保存 `secret_ref`。
- 管理页面不提供密钥回显，最多显示“已配置/未配置”和引用名称。
- 如果支持页面轮换，只允许写入不回显的专用安全接口，并由 `SYSTEM_ADMIN` 执行；不得复用会明文返回的 `system_config`。
- 连通性测试只返回成功、延迟和脱敏错误，不返回请求头、密钥或完整模型响应。

### 5.3 发布门禁

- Prompt/Schema 发布后不可编辑；修改生成新版本。
- 金标集通过 AI 配置模块维护不可变版本，支持 JSON/Excel 导入草稿、Schema 校验、发布和历史 diff；Release 必须显式绑定一个已发布金标集版本。
- AI release 发布前必须运行所绑定的版本化金标用例，记录通过数、失败数和差异。
- 有失败用例时默认禁止发布；如未来允许豁免，必须另立决策，不在本期预留无审计绕过。
- 禁用 AI release 只关闭自然语言入口，不影响结构化策略编辑和已发布策略执行。

权限：只有 `SYSTEM_ADMIN` 可维护/发布；`PRICING_MANAGER` 可查看当前版本、金标结果和连通状态，不可查看 Secret。

## 6. 计算投影任务监控

这是运维模块，不是价格业务配置。列表按报价单、核价单、scope、状态、创建时间和错误码筛选，显示：

- 用户数据版本、价格修订、目标/活动投影、引擎版本和输入摘要；
- 构建阶段、耗时、重试次数、MISMATCH 数、错误码和是否已过期；
- 与正式报价/审批绑定关系。

允许动作：查看逐格 diff、对仍为当前目标的 FAILED 投影安全重试。禁止动作：手工把状态改为 READY、强制切活动指针、删除被正式单据引用的投影、忽略 MISMATCH。

保留策略在部署配置中固化并只读展示：SEALED 修订、曾激活或被复制/当前/目标/提交/核价/审批引用的输入快照、投影和组成修订随单保留；从未激活且无引用的终态候选重载荷/技术头分别为 90/365 天，过期或已消费 token 为 30 天，终态命令/发件箱为 180 天。部署侧只允许延长；缩短必须另行裁决，不在页面自由修改。

权限：`SYSTEM_ADMIN` 可查看和重试；`PRICING_MANAGER` 可查看其业务范围内的失败/差异，不可执行系统级清理。

## 7. 明确不新增管理模块的项目

- `priceBaseDate`：报价单业务事实，不是全局参数；新建和复制时写入，提交后冻结。
- 精度、哈希规范、状态机和版本升级时机：架构契约，不能让管理员在线修改。
- 引擎版本：构建产物元数据，只读展示。
- DSL 最大窗口、回溯、规则数以及投影并发/超时：代码或部署安全上限，只读展示，不允许普通管理员在线突破。
- 复制 INPUT 白名单：由模板/组件定义派生，避免第二份配置漂移。
- 节假日处理方式：属于每条客户价格规则，在策略页面维护，不在日历中配置。日历只回答日期状态。
- 某天实际价格：由元素每日价模块维护，不在日历中维护。

## 8. 模块依赖与发布顺序

```text
交易日历主档/版本
    └─► 价格源默认日历绑定
          └─► 客户价格策略草稿、试算与发布
                └─► 报价单价格修订
                      └─► 原子计算投影

AI Provider + Prompt + Schema + 金标
    └─► AI Parser Release
          └─► 只生成客户策略候选草稿
```

交易日历和策略 v2 必须先具备管理闭环，再允许 SNAPSHOT 报价依赖它们正式取价。AI 模块可以后置：没有 AI 时结构化策略编辑器仍能完整工作。
