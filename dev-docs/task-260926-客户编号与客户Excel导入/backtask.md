# 后端任务分解 · 客户编号与客户 Excel 导入

> 后端只按本文件做；AC 原文见 [`需求文档.md`](./需求文档.md)，接口以 [`api.md`](./api.md) 为准。
> 必读：`docs/rules/backend.md`、`docs/方案制定前必读.md`、`docs/rules/change-protocol.md`。

## B-1 客户编号与名称规范化校验

- 服务 AC-1~AC-6、AC-15。
- 扩展 `CreateCustomerRequest` 的可选 code；创建时保留手填 code 或回退序列生成。
- CustomerService 统一实现首尾空格/大小写规范化、长度检查、名称与编号查重；更新名称排除自身。
- 采用事务级客户写入锁，避免并发请求在查询与写入之间穿透；不得删除或改名存量重复客户。

## B-2 客户 Excel 模板

- 服务 AC-7。
- 新增模板生成服务，按 `api.md` 的 15 列和中文说明生成 `.xlsx`；复用 Apache POI，不把状态/统计字段放入模板。

## B-3 客户 Excel 全量导入

- 服务 AC-8~AC-14。
- 新增 multipart Resource、解析/校验/写入服务和 DTO；单 sheet、一行一个客户+一个主要联系人。
- Phase 1 零写库，批量预加载既有规范化名称/编号、行业、产品分类；循环体不得查询（N+1 自检）。
- 所有错误聚合后整份拒绝；Phase 2 单事务创建客户和联系人；导入失败不得留下半批数据。
- 行业按 code/name 解析，产品分类按 code/name 解析；未知引用、枚举、格式、长度均为整份错误。

## B-4 后端测试

- 服务 AC-3~AC-6、AC-8~AC-15。
- 增加规范化、查重、导入零写库、全量错误聚合、空文件、并发锁和既有接口回归测试；测试不得清理共享库或使用无范围 DELETE。
