# 客户编号手填与客户 Excel 导入

> 立项日期：2026-09-26  
> 任务类型：新功能（路径 A）· 标准档  
> A0 裁决：采用方案甲——不清理存量重复名称、不新增数据库名称唯一索引；在客户写入事务中统一做规范化校验并串行化客户写入。

## ① 背景与目标

当前客户创建时后端无条件按 `CUST-xxxx` 生成客户编号，销售无法沿用外部客户号；客户列表也没有 Excel 批量建档入口。目标是让人工建档和批量建档都支持业务编号，同时保证新写入数据的客户编号、客户名称不重复，并保留现有客户关联、联系人和权限语义。

## ② 范围

### 本期做什么

1. 新增客户时客户编号可选填写：填写后原样保存合法输入；若原始值首尾含空格则拒绝，留空继续使用原 `CUST-xxxx` 生成规则。
2. 客户编号全局唯一：合法值按 `lower(trim(code))` 进行比较，英文大小写不敏感；编号长度遵守现有 `varchar(50)` 上限。
3. 客户名称全局唯一：比较时对首尾空格做规范化、英文大小写不敏感；手工新增、编辑和 Excel 导入统一校验。原始值首尾含空格时直接拒绝并提示“首尾不能有空格”。
4. 新增 Excel 模板下载与客户 Excel 导入抽屉。模板为单 sheet、一行一个客户、包含一个联系人；客户编号可空。
5. Excel 导入覆盖新增客户表单的全部可编辑字段：客户编号、客户名称、客户等级、所属行业、产品分类、区域、地址、信用额度、付款方式、备注、联系人姓名、职务、电话、邮箱、微信。系统统计字段和状态不导入。
6. Excel 导入采用全量预校验：文件格式、表头、字段长度/枚举、客户名称/编号重复、行业/产品分类引用、联系人必填与电话格式全部校验通过后才写库；任一错误则整份拒绝、零客户零联系人写入，并返回全部错误行。
7. 导入成功后返回读取行数、新增客户数、新增联系人数；前端展示成功摘要并刷新客户列表。

### 本期明确不做

1. 不清理或改名现有数据库中的重复客户名称，不新增数据库函数唯一索引（已登记方案甲；存量重复由历史测试夹具和业务数据保留）。
2. 不支持 Excel 一客户多联系人；多联系人导入另行进入 `BACKLOG.md`。
3. 不通过 Excel 更新/覆盖已有客户，不导入客户状态、累计金额、历史订单数、平均折扣率。
4. 不新增客户导出能力；沿用既有列表查询。
5. 不改变客户停用、报价关联检查、权限角色及联系人维护接口。

## ③ 验收标准（AC）

### 单点

- **AC-1**：销售经理打开“新增客户”，客户编号字段可留空；填写客户名称、分类和一个主要联系人后保存，响应返回 `code` 为 `CUST-` 开头的系统编号，列表和详情显示同一编号。
- **AC-2**：填写合法编号 `AbC-001`（无首尾空格）后保存，详情返回填写后的编号；刷新列表仍保持该编号，不被系统序号覆盖。
- **AC-3**：已有编号 `ABC-001` 时，再以 `abc-001` 创建客户，接口返回 HTTP 409，提示编号已存在，客户表和联系人表均不新增行。
- **AC-4**：已有客户名称 `华东客户` 时，再以 `华东客户` 或英文大小写不同的同名值创建，接口返回 HTTP 409，原客户数据不变。
- **AC-5**：新增或编辑客户时，客户编号或名称原始值首尾含空格，接口返回 HTTP 400 且明确提示“首尾不能有空格”；不得静默保存带空格值。
- **AC-6**：编辑客户名称为另一客户已占用名称时返回 HTTP 409；编辑失败后原名称仍可在详情和列表中读取。
- **AC-7**：点击“下载客户导入模板”，浏览器下载 `.xlsx`；第一行表头按模板顺序包含 15 列，示例行说明客户编号可空、电话需 11 位，且不包含状态/统计字段。
- **AC-8**：上传含 2 行合法客户的模板文件（1 行手填编号、1 行编号留空），导入返回 HTTP 200，摘要为读取 2 行/新增客户 2/新增联系人 2；两行客户及联系人均可在列表/详情读取，留空编号行获得唯一系统编号。

### 序列

- **AC-9**：先手工创建客户 `ABC-001`，再上传包含该编号及另一个合法客户的 Excel；导入整体返回 HTTP 409，错误报告指出冲突行，另一个合法客户也不得写入；刷新列表确认客户总数和联系人总数均未因本次导入增加。
- **AC-10**：先成功导入客户，再关闭抽屉、刷新客户列表并打开详情；客户编号、名称、产品分类、信用额度和联系人字段逐项与 Excel 一致，且列表搜索能按编号/名称命中。

### 边界与反向

- **AC-11**：Excel 文件内两行客户名称规范化后重复，或两行编号仅大小写不同，导入返回 HTTP 409，报告列出重复的 Excel 行号，整份零写入。
- **AC-12**：Excel 同时存在缺少客户名称、缺少联系人姓名、电话非 11 位、非法等级、未知行业、未知产品分类、超长编号/名称等错误时，接口一次返回全部错误（不少于每个错误行一条），整份零写入，不出现 HTTP 500。
- **AC-13**：上传非 `.xlsx`、损坏文件或表头不匹配文件，导入返回 HTTP 400，前端显示失败原因，不改变客户和联系人数据。
- **AC-14**：Excel 只有表头无数据行时，导入返回 HTTP 200，读取/新增客户/新增联系人均为 0，不创建空客户。
- **AC-15**：两个并发请求尝试创建规范化后相同的客户名称时，最多一个成功，另一个返回冲突；不得产生新的同名行（存量历史重复不在本 AC 的新增范围内）。
- **AC-16**：无权角色访问模板下载、导入和客户创建时仍按现有角色策略返回 401/403；现有客户列表、编辑、停用和联系人维护回归通过。

## ④ 依赖与影响面

- 后端影响 `Customer`、`CreateCustomerRequest`、`CustomerService`、`CustomerResource`，新增客户导入 DTO/服务/测试；不新增 Flyway 迁移，不改存量数据。
- 前端影响 `CustomerManagement.tsx`、客户 service，新增客户导入 Drawer/报告展示；遵循 Ant Design Drawer 和列表工具栏规范。
- Excel 解析复用 Apache POI 与现有用户/主数据导入模式；导入阶段必须满足后端 N+1 硬指标：预加载行业、产品分类、已有客户名称/编号，循环体不得查询。
- 客户写入使用事务级客户写入锁 + 规范化查询，弥补本期不增加数据库名称唯一索引后的并发窗口；现有 `customer.code` 数据库唯一约束继续保留。
- 不触碰 `docs/架构基线.md` 三大核心渲染模块；需回归客户列表、客户详情/编辑、报价单客户选择和联系人接口。
- 主数据名称映射：行业允许填行业编码或名称，产品分类填分类名称或编码；未知引用是整份导入错误。

## ⑤ 用户原话与决策记录

用户原话：

> 我现在要优化客户编号的问题,现在客户编号在创建客户的时候是系统生成的编号.
> 现在要两个功能:
> 1. 客户编号支持让用户创建的时候手填,只要保证全局唯一即可
> 2. 支持excel导入客户列表.

澄清裁决：客户编号手填可选；Excel 一行一个客户；客户名称也统一做全局唯一；原始值首尾含空格直接拒绝，合法值查重使用 `lower(trim(...))`，英文大小写不敏感；Excel 冲突全表拒绝；导入字段按新增表单全部可编辑字段；采用方案甲，不清理存量重复名称、不加数据库名称唯一索引。
