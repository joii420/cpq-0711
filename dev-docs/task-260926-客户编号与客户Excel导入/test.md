# 测试方案 · 客户编号与客户 Excel 导入

> 闸门 A 前置产物。测试分片按写入面切分；所有测试使用 `CUST-260926-` / `IMP-260926-` 前缀，禁止清库。

## §0 环境与可信前提

- `mvnw test` 使用 test profile 的专用测试库；共享开发库只做只读基准和主线亲验。
- 客户表已有历史重复名称，测试断言只验证本次新增未产生新重复，不断言全表天然唯一。
- 测试必须确认 Redis/RBAC 配置后再解释 401/500；不得把登录基础设施失败当业务绿。
- Excel 样例用例由测试工程师在任务目录生成，均为可读 `.xlsx`，不依赖网络。

## §3 证伪实验

1. 在导入 Phase 1 发现第二行错误时，比较导入前后 customer/customer_contact 计数与本次前缀指纹，证明零写库。
2. 同时提交 `ABC-001`/`abc-001` 与 `同名客户`/`同名客户`，证明规范化冲突而非仅精确字符串冲突。
3. 两个并发同名创建请求，证明锁后只有一个 200，另一个 409，且新增行最多一条。
4. 将一个合法行与一个重复行混合，证明不是“跳过坏行”而是整份拒绝。
