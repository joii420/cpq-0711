## 一、分片计划

**分片依据是「写入面」，不是 AC 编号。** 本任务的写入面天然分成 5 类，且其中两类**改全局状态**：

| 片 | 写入面 | 造数前缀 / 隔离口径 | 能否并行 |
|---|---|---|---|
| **S-1 只读结构片** | **无写入** | 无 —— 纯 `SELECT` / `grep` | ✅ 可与任何片并行 |
| **S-2 视图 DDL 片** | 🌍 **全局**：`CREATE OR REPLACE VIEW` / `DROP VIEW` / `costing_bom_tree_config` 配置行 | 无造数；**独占 DB 对象层** | 🚫 **串行殿后**，不与任何片并行 |
| **S-3 业务序列片** | 业务数据：报价单 / `_record` | 前缀 **`RETIRE0909-`**（报价单名、导入批次名、料号全部带此前缀） | ⚠️ 可与 S-1 并行；**不可与 S-2 并行**（视图在它脚下变） |
| **S-4 启动期片** | 🌍 **全局**：重启应用 | 无造数；**独占进程** | 🚫 串行，紧跟 S-2 |
| **S-5 测试配置片** | 配置文件 + 测试库 | 无 —— 但会改**所有人**的测试环境 | ⚠️ 最先做，做完广播 |

**执行顺序**：`S-5` → （`S-1` ∥ `S-3`）→ `S-2` → `S-4` → 复跑 `S-1`

🚫 **共库片禁用全局计数断言**：`S-1`/`S-3` 的断言一律写成「**存在性**」或「**相对基线的差值**」，
不许写 `SELECT count(*) FROM quotation = 130` 这类全局计数 —— 并发会话随时在建单。

⚠️ **不要为了并行而分片**：`S-2`/`S-4` 本可合并，拆开是因为**失败面不同** ——
`S-2` 失败在 SQL 层（立刻可见），`S-4` 失败在**启动期**（`CostAllVersionViewSelfCheck`），
而后者只有真重启才碰得到（`repair-260909` 教训）。

## 三、几条必须写死的测试纪律

### 1. 🚨 每个批次执行前**重采基线**，不许用文档里的数字

文档里的 `48/85/64/429/667/185/22/12/13/61`、`2733/28/2693`、`14 行 pending`、`2715` 全是 **2026-09-09 的快照**。
本库有十余个并发会话在写。**「几小时前采的基线」不是基线，是快照**（`task-260907` 原样教训）。

### 2. 🚨 `AC-5` 必须有阳性对照，不能只验「变的那 3 个」

要同时断言**其余 39 个料号逐字不变** —— 否则「3 个变了」与「全表漂移但恰好那 3 个被看到了」在证据上长得一样。

### 3. 🚨 `AC-7` 必须真重启，不许用事务内 `CREATE OR REPLACE` + `ROLLBACK` 代替

`CostAllVersionViewSelfCheck` 只活在 `@Observes StartupEvent` 上。
**量具所在的层，和失败发生的层，不是同一层。**

### 4. 🚨 `AC-11` 是 `P-2` 作废裁决的兜底闸

若它发现 pending 计数变化 ⇒ **`P-2` 的作废裁决立即失效**，停下报主线，回头重做建单臂并重新评估 `D-1`。

### 5. ⚠️ 一律 `/usr/bin/grep -a`

本环境 `grep` 是 `ugrep -I`，中文多的大源文件被**静默判为二进制返空**。

### 6. ⚠️ `文件:行` 必须声明基线 commit

前置审计的实测教训：同一文件在 master 与 worktree 可差 20 行，**差值随其它会话推进而变**。
