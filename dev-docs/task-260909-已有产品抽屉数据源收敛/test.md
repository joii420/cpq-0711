## 4. 用例设计要点

### 4.1 AC-1 必须做「改动前 vs 改动后」对照

🚫 只跑改动后看到 2662 行**不构成证据** —— 那可能本来就有。必须证明这是本次改动带来的：

1. 在**主仓 master**（未改动）打开同一客户的抽屉 → 记录 total（应为 1）
2. 在 **worktree**（已改动）打开 → 记录 total（应为 2662）
3. 两者对照

> 这是「同库 A/B 验收手法」，`repair-0727-backfill-patch-semantics` 教训。

### 4.2 AC-7 的三重证据缺一不可

| 证据 | 手段 | 防的是 |
|---|---|---|
| UI 无预览面板 | DOM 断言无「⤢ 交互查看」 | 只删了样式没删组件 |
| 无网络请求 | F12 Network 过滤 `model-configs`，连续切 5 行 | 组件删了但 useEffect 还在发请求 |
| JSON 无字段 | 接口原始响应断言无 `has3d` / `thumbnailUrl` | 前端不渲染但后端还在查（多一个 JOIN） |

### 4.3 AC-9 是「应该消失」的反向断言

⚠️ 这条容易被写成 bug 报上来。**老选配产品消失是用户裁决的预期行为**（存量不迁）。
用例要同时验两面：① `sel_product_no` 独有的料号**不出现**（正向） ② dqcp 的 `MANUAL` 料号**必须出现**（反向，防止修过头把选配产品也弄丢）。

### 4.4 Playwright 选择器已知坑（`cpq-playwright-selector-pitfalls`）

| 坑 | 对策 |
|---|---|
| antd 类名不稳定 | 优先用文本/role，别锁 `.ant-*` 内部类 |
| 两字按钮渲染成「保 存」（中间有空格） | 用正则或 `:has-text` 模糊匹配 |
| 下拉虚拟滚动 | 先输入过滤再选，别直接滚 |
| 列表勾选入口 | 勾选框在行首，注意 `rowSelection` 的 DOM 层级 |

**这四个坑都表现为 timeout**，🚫 别一 timeout 就报「产品 bug」——先排除选择器问题。

### 4.5 断言非空（防空跑）

每条列表断言前**先断言结果集非空**。空列表 / 0 行 / `—` 一律不算通过（`CLAUDE.md §4.5` 步骤 4d）。
