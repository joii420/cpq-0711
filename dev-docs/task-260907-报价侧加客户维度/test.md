## 2. 🔴 AC-2 的判据形态（本任务的核心，写错就白测）

```
以 CUST-0004 导入料号 X → 再以 CUST-0001 导入同一料号 X
① 写入的每张表 customer_no 全 = 本次所选客户，NULL 行数 = 0
② 🚨【两个客户的行并存，第一次导入的行未被删除】
```

🔑 **只断言 ① 抓不住静默删除 —— ① 在删除发生后照样成立。**

> 判据设计来自 `报价导入切ds新表` 会话的 AC-22，本任务同型采用。
> 🚨 **失败形态是静默删数据，不是撞键报错**（主线曾判反）：`ds_quote_*` 的 13 张带版本表**无任何业务唯一索引**，
> 隔离全靠 `VersionedGroupWriter` 的整组删除+重插。

📌 **存量统一回填 `CUST-0001` 反而让证伪更容易**：所有存量都是同一个客户
⇒ **任何其它客户的导入都不该动到它们**，这是个干净的判据，且存量基数大（7585 行）。
