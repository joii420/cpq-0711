## §0 环境与红线（先看，否则测出来的绿不可信）

### 0.1 🚨 共享库红线

`mvnw test` 走的 `test` profile **实连共享开发库 `cpq_db_0724`**（`CLAUDE.md` profile 表已实证更正，不是独立测试库）。

- 🚫 不许清理 `element` / `process` / `material_recipe` / `customer` 等**共享主数据**，只读不写。

### 0.2 ⚠️ RBAC 恒 401 的既有缺陷

`src/test/resources/application.properties:5` = `false` 被 `application-test.properties:86` = `true` 覆盖（profile-specific 优先）
⇒ `@QuarkusTest` 里任何走 RestAssured 且**不带 session** 的请求一律 401。

- **本任务不修该缺陷**，用例一律自带 session。
- 🚩 看到 `Expected <200> but was <401>` **先怀疑这个坑**，不要误判成「端点没做 / 权限判错」。

### 0.3 ⚠️ 共享库数据在漂移

实测同一条 `count(*)` 几分钟内会变（其他会话在写）。
⇒ **所有断言写成「与同一时刻基准查询相等」的不变量，不写死行数。**
例：`AC-10` 断言「导入前后 `count(*)` 逐表相等」，而不是「等于 128」。

### 0.4 三份 Excel 的可用性

⚠️ `核价1 - 数据导入与表格建表.xlsx` 于 2026-09-03 一度损坏（`BadZipFile`）。
**测试进场第一件事**：三份文件各跑一次 `openpyxl.load_workbook` 确认可读，不可读立即报主线。

### 3.1 夹具来源

**以三份 Excel 模板自带的示例行为基准**，复制成夹具文件后把轴值加 `TEST-DS-` 前缀：

## §4 必做的证伪实验（`testing.md` 要求）

**「首次 PASS 也可能是空验证」** —— 以下 4 条必须做「还原实验」：把修复/实现改回去，确认测试**真的变红**。

| # | 实验 | 改回什么 | 期望 |
|---|---|---|---|
| FT-1 | 指纹规范化 | 去掉 `stripTrailingZeros()` | `TV-07`（`5.5` vs `5.500000`）**必须变红** |
| FT-2 | 多重集比较 | 改成按顺序逐行比对 | `TV-05`（行序对调）**必须变红** |
| FT-3 | Phase 1 零写库 | 把物料表写入提前到校验之前 | `TI-05`（45 表 count 全不变）**必须变红** |
| FT-4 | 增量语义 | 改成「未出现的轴值也升版」 | `TV-08` **必须变红** |

**不变红 = 该用例是空验证**，必须重写。四条实验结果逐条写进 `test-report.md`。

> 反面教材（`RECORD.md`）：`AC-15` 曾出现「删中间那条时 `max(ACTIVE)` 恰等于 `max(全部)`，破坏发号器也不变红」—— AC 本身不可证伪。
> ⇒ 设计 `TV-*` 的夹具时，**故意让版本号、行数、指纹三者互不相等**，避免巧合掩盖。

## §5 E2E 注意事项（`docs/E2E测试方法.md` + `RECORD.md` 踩坑）

- **选择器坑**：antd 两字按钮实际渲染为 `保 存`（中间有空格）；下拉是虚拟滚动，选项要先滚动到可见；`.ant-select-content` 是采样陷阱。
  ⇒ 4 个坑都表现为 timeout，**易误判成产品 bug**。
- **中文 UTF-8**：spec 文件编码问题会让中文断言静默失配。
- **admin 账号**：E2E 反复跑会把 `admin` 置 `INACTIVE`，需 SQL 改回 `ACTIVE`。
- **不得与改工作树的代理并发**：`RECORD.md` 实证「亲验环境热重载 → 三次假红」，**端口避让保护不了文件**。
