## 一、问题本质（已实证，不是推测）

**产品分类在报价单链路里从来不是"数据"，只是前端用来匹配出模板的一次性参数。**

| 环节 | 新建路径 | 导入路径 |
|---|---|---|
| 前端表单有分类 | ✅ 客户绑定带出（`QuotationWizard:1509 lockedCategoryId`） | ✅ 用户在抽屉里选 |
| 建单请求发给后端 | ❌ **压根没发**（`handleCreateQuotation` payload 无该字段） | ✅ 发了 `categoryId` |
| 后端 request DTO 接住 | ❌ `CreateQuotationRequest` 无此字段（仅注释提及） | ✅ `CreateQuotationFromImportRequest.categoryId` 有 |
| 服务层读取 | — | ❌ `V6QuotationCommitService` 全文**零处** `category` |
| 落库 | ❌ `quotation` 表无 `product_category_id` 列 | ❌ 同左 |

全后端读 `.categoryId` 的只有 product 模块；`SaveDraftRequest` 里 0 次。

**编辑态**：`lockedCategoryId` 被有意置 `undefined`（D4：客户改绑分类不追溯已有单），DTO 又没有分类 ⇒ 唯一来源退化为「从 `customer_template_id` 反查 `template.category_id`」（`QuotationCreateForm.tsx:125-142`）。该字段为空即永久空白。

**实证影响面**（`cpq_db_0724` 全库 29 单）：8 张 DRAFT 单 `customer_template_id IS NULL` ⇒ 编辑页必现红字「请选择产品分类」，且因 `:227` 校验含 `customerTemplateId`，「下一步」同时被禁用。这 8 张全部是程序化创建（E2E 夹具 / 验收脚本），正常 UI 建单被 `:227` 挡住产生不了。

**附带偏差**：现方案反查的是**模板当前的** `category_id`——模板改分类会让所有已建单的显示跟着变，这**违反它自己想守的 D4**。持久化后该偏差自动消失。

---

## 二、方案裁定

**让产品分类成为报价单的一等数据**：建单时落库，编辑时优先读库，模板反查降级为存量兜底。

### 已裁定的边界（不得扩大）

| 项 | 裁定 |
|---|---|
| **存量数据** | **不处理**（业务方 2026-07-29 裁定）。迁移**只加列，不回填**；那 8 张无模板单不管 |
| 模板反查 | **保留**为 fallback，不删——存量单唯一的显示来源 |
| DTO 字段名 | **必须叫 `categoryId`**（不是 `productCategoryId`）——前端 `QuotationWizard:353` 已写好 `q.categoryId \|\| prev.categoryId`，字段名对上则前端回填零改动 |
| 表列名 | `product_category_id`（与 `customer.product_category_id` 同名同义） |
| 分类值来源 | 建单时前端传什么就存什么，后端**不做二次推导**（不去反查客户绑定），避免与 D4 冲突 |

## 三、Task A —— 后端

### A1 Flyway 迁移 `V364__quotation_product_category_id.sql`

```sql
ALTER TABLE quotation ADD COLUMN IF NOT EXISTS product_category_id uuid;
COMMENT ON COLUMN quotation.product_category_id IS
  'task-0729: 建单时的产品分类(不追溯客户改绑, 守 D4)。存量不回填, 为 NULL 时前端回落"从 customer_template_id 反查模板分类"。';
```

- **只加列，不回填、不加外键、不加 NOT NULL**（存量全 NULL 是预期状态）。
- 落号前**必须重新探一次**当前最大版本（共享库并发会占号）：
  `SELECT max(version::int) FROM flyway_schema_history WHERE version ~ '^[0-9]+$';` + `ls db/migration | sort -V | tail`。本文档撰写时两者均为 **363**，故用 V364；若已被占，顺延并在报告里说明。
- **不要**手工 `psql -f`，让 Quarkus dev 的 `migrate-at-start` 跑（项目铁律）。

### A2 实体与 DTO

| 文件 | 改动 |
|---|---|
| `quotation/entity/Quotation.java` | 加 `@Column(name = "product_category_id") public UUID productCategoryId;` |
| `quotation/dto/QuotationDTO.java` | 加 `public UUID categoryId;`（**字段名 categoryId**，见 §二裁定）+ 在 `from(Quotation q)`（`:96`）里映射 `dto.categoryId = q.productCategoryId;` |

### A3 三个写入口接收并落库

| 入口 | 文件 | 改动 |
|---|---|---|
| 新建 | `quotation/dto/CreateQuotationRequest.java` | 加 `public UUID categoryId;` |
| 新建 | `QuotationService#create`（建单落库处） | `q.productCategoryId = request.categoryId;` |
| 存草稿 | `quotation/dto/SaveDraftRequest.java` | 加 `public UUID categoryId;` |
| 存草稿 | `QuotationService#saveDraft` | **仅当 `request.categoryId != null` 时**才覆盖（`null` 不清空已有值——前端旧版本或异常 payload 不该抹掉已存分类） |
| 导入 | `basicdata/v6/service/V6QuotationCommitService#createQuotation` | 建 `Quotation` 时 `q.productCategoryId = req.categoryId;`（request DTO 已有该字段，只差落库这一行） |

### A4 禁止事项

- 不得回填存量数据（无论迁移里还是代码里）
- 不得删除/改动 `QuotationCreateForm` 的模板反查逻辑（那是前端 Task B 的范围，且要保留）
- 不得给 `product_category_id` 加外键或 NOT NULL
- 不得在后端做"分类推导"（如 categoryId 为空时去查客户绑定）——违反 D4

## 四、Task B —— 前端

### B1 建单 payload 补发 `categoryId`

`QuotationWizard.tsx#handleCreateQuotation`（`:1106`）的 `quotationService.create({...})` 补 `categoryId: step1FormValue.categoryId`。
（`create` 的 TS 类型若在 `services/quotationService.ts` 里有显式接口，同步加可选字段。）

### B2 存草稿 payload 补发 `categoryId`

`buildDraftPayload` 里补 `categoryId: step1FormValue.categoryId`，让编辑期的分类也能落库。

### B3 编辑页「无模板」时的误导文案

`QuotationCreateForm.tsx:318-319` 现在无条件在 `!value.categoryId` 时报红字「请选择产品分类」。改为区分两种成因：

- `readOnly && !value.customerTemplateId` → 提示「该报价单未绑定报价模板，无法带出产品分类」（指向真正的问题）
- 其余仍保持原文案

注意：**不要动 `:227` 的校验逻辑**（`customerTemplateId` 必填是有意的，改了会让无模板单能走下一步 → 下游拿不到模板）。

### B4 回填 effect 不动

`QuotationCreateForm.tsx:125-142` 的模板反查**保持原样**（存量兜底）。DTO 带上 `categoryId` 后，`Wizard:353` 会让 `value.categoryId` 先有值，`:126` 的第二个守卫 `value.categoryId` 命中 → 反查自然短路，无需改代码。

### B5 禁止事项

- 不得改 `:227` 校验
- 不得删模板反查
- 不得改 `lockedCategoryId={quotationId ? undefined : ...}`（D4 语义）
