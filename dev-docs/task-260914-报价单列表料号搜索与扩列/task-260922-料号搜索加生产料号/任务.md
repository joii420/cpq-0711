## ① 背景与目标

### 用户原话（归档，勿改写）

> 报价单管理 按料号搜索 现在支持 搜索生产料号吗?

（主线答：不支持，只搜销售料号与客户料号，并说明了生产料号的取法与难点）

> 加上生产料号搜索

路径确认选项卡：用户选 **「A 轻量档 (Recommended)」**（2026-09-22）。

### 目标

在【报价单管理】列表页的料号搜索框里输入**生产料号**（或其中一段），能找出**产品行对应该生产料号**的报价单。
「对应」的口径与报价单产品卡片上「销售料号」徽标点开看到的生产料号**完全一致** —— 搜得到的单，打开后在卡片上就能看到那个生产料号；卡片上显示「未绑定生产料号」的，搜生产料号就搜不到它。

### 不做会怎样

业务按生产料号（车间 / 核价口径的号码）找报价单时，只能先去别处查出它对应哪个销售料号再来搜；
现网 **71 张单 / 183 个产品行** 带有生产料号，按生产料号全部搜不到（例：输 `300001` 现在得 **0** 条，实际有 **33** 张单的产品对应它）。

### 5.4 性能

若采用「先取命中单 id 再 `IN (:ids)`」的手法：id 个数上限 = 报价单总数（现 210）。PostgreSQL 单语句绑定参数上限 32767 —— 报价单到**万级**前无虞，后端回报里须写明所选手法在这一点上的上限。

📌 **开工后实测（后端回报，2026-09-22）**：选的正是「先取命中单 id 再 `OR id IN (:ids)`」。Hibernate 会把 IN 列表**补齐到 2 的幂**（`3000` 命中 48 个 id → count 语句 64 个 id 占位）。按 32767 参数的保守上限，**生产料号这一路命中单数 ≤ 16384** 时安全（上限看的是这一路的命中单数，不是报价单总数）；驱动 42.7.x 实际上限是否为 65535 **未实测**。关键字里的 `%` / `_` 会被当通配符，与原有两路行为一致，本期未改。

### 基准 SQL（验收现场重算，`cpq_db_0724`；把 `:kw` 换成**小写**关键字）

```sql
-- Q0 全量
SELECT count(*) FROM quotation;

-- Q1 旧口径：只看销售料号 + 客户料号
SELECT count(*) FROM quotation q WHERE EXISTS (
  SELECT 1 FROM quotation_line_item li WHERE li.quotation_id = q.id
    AND (lower(li.product_part_no_snapshot) LIKE '%'||:kw||'%'
      OR lower(li.customer_part_no)        LIKE '%'||:kw||'%'));

-- Q1′ 新口径：再加生产料号（按本单客户）
SELECT count(*) FROM quotation q WHERE EXISTS (
  SELECT 1 FROM quotation_line_item li WHERE li.quotation_id = q.id
    AND (lower(li.product_part_no_snapshot) LIKE '%'||:kw||'%'
      OR lower(li.customer_part_no)        LIKE '%'||:kw||'%'
      OR EXISTS (SELECT 1 FROM customer c
                   JOIN ds_quote_material m ON m.customer_no = c.code
                  WHERE c.id = q.customer_id
                    AND m.material_no = li.product_part_no_snapshot
                    AND lower(m.production_no) LIKE '%'||:kw||'%')));
-- 叠加条件：∧ 草稿 = 追加 AND q.status = 'DRAFT'；
--          ∧ 左框关键字 = 追加 AND (lower(q.name) LIKE '%'||:k2||'%' OR lower(q.quotation_number) LIKE '%'||:k2||'%'
--                                   OR lower(q.snapshot_customer_name) LIKE '%'||:k2||'%')

-- Q-漏客户（AC-5 对照值：错误实现会得到的数）
SELECT count(DISTINCT li.quotation_id) FROM quotation_line_item li
  JOIN ds_quote_material m ON m.material_no = li.product_part_no_snapshot
 WHERE lower(m.production_no) LIKE '%'||:kw||'%';
```
