## 4. 🚨 代理的证伪实验当场抓到 3 条它自己写的假绿

把脚本打到 8081（改动前代码，三个新参数不存在、会被静默忽略返全量），第一轮 `PASS=3 FAIL=15`：

| 原写法 | 为什么改动前也 PASS | 已改成 |
|---|---|---|
| TC-API-01 只抽 **1 单**核实 | 返全量时**首行恰好**含 S0004 | 整页 20 单逐单核实（改后 6/20 不含 → FAIL） |
| TC-API-02 同上 | 同上 | 逐单核实（改后 11/20 不含 → FAIL） |
| TC-API-03 断言 `s000 == S000` | 参数被忽略时两向**都返 187**，相等**平凡成立** | 先守卫「两向都等于全量 ⇒ 参数没生效」 |

修完重跑：**`PASS=0 FAIL=18 未验证=2 不稳定=0`** —— 每条断言都有区分力。基线已归档（合并后 8081 变成改动后代码就取不回来了）。

其他规避：`pipefail` 开着、psql 带 `ON_ERROR_STOP=1` 且**校验返回是数字**（空串不当 0）、不用 `cmd | head || echo OK`、`grep` 一律 `/usr/bin/grep -a`、curl 全部 `--noproxy '*'`、逐行校验拿到 0 行判 FAIL 而不是「没有不符的行 ⇒ 通过」。
