## 3. 规避掉的坑 / 主动加的守卫
- **硬编码数字**：文件里不存在 187/117/43 这类字面量，全部现场重算。
- **共库全局计数串扰**：`expectTotalEqualsSql` 做 **SQL 三明治**，UI 读数前后各采一次；两次不等直接判「采样窗口内被并发写入，本条结论无效，🚫 不要据此判产品缺陷」。
- **跨进程并发**：`beforeAll` 内建 `otherPlaywrightPids()`，按 `/proc` ppid 链**排除自身进程树**后硬失败（直接 `pgrep` 会永远误报自己）。
- **只读硬护栏**：`guardReadOnly()` 在 helper 层拦掉任何非 SELECT 语句。
- **断言空跑**：每个遍历断言前先断 `行数 > 0`；T-5 有阳性对照；T-17 先断 `Q9 > 0`。
- **四个 Playwright 选择器坑**：按钮用 `hasText` + 正则 `/导入\s*报价\s*数据/`；下拉**滚动收集**不用一次 count；页签用 4 种形态候选依次尝试、全不命中时打印页面文本而非静默跳过。
- **证据直接写进任务目录** `测试/s-ui/证据/`，不落 `test-results/`（会被清空）。
- **tsc「0 错误」可能是空验证**（`e2e/` 历史上不在任何 tsconfig include 里）：做了证伪实验 —— 注入 `const x: number = "字符串"` → 报 `TS2322(707,7)` 且退出非 0；**还原用绝对路径 + 还原后复验**（`__falsify` 命中 = 0，tsc 再跑 EXIT=0 / 0 行输出）。
