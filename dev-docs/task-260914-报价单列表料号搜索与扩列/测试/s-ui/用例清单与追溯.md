## 6. 防假绿措施（逐条对应本项目踩过的坑）

| 风险 | 本片的对策 |
|---|---|
| **断言空跑**（数据为空 → 循环 0 次照样绿） | 每个遍历断言前都先 `expect(行数).toBeGreaterThan(0)`；T-5 先做「搜索前有数据」的阳性对照；T-17 先断言 `Q9 > 0` |
| **硬编码全局计数**（共享库随时被别的会话写） | 全部计数一律现场重算；🚫 文件里不存在 187/117/43 这类字面量 |
| **共库并行串扰**（AC 原文要求的全局计数无法回避） | `expectTotalEqualsSql` 做 **SQL 三明治**：UI 读数前后各采一次，两次不等即判「采样窗口内被并发写入」并给出「不要据此判产品缺陷」的失败文案 |
| **跨进程并发**（`workers:1` 不跨进程） | `beforeAll` 内建 `otherPlaywrightPids()`，按 `/proc` ppid 链排除自身进程树后硬失败 |
| **选择器坑被误判成产品 bug**（antd 类名/两字按钮含空格/虚拟滚动/勾选入口） | 按钮用 `hasText` + 正则（`/导入\s*报价\s*数据/`）；下拉一律**滚动收集**，不用一次 count；页签用 4 种形态候选依次尝试，全不命中时打印页面文本而非静默跳过；T-P0 探针专门用于失败时区分「选择器错」与「产品错」 |
| **tsc「0 错误」是空验证**（`e2e/` 曾不在任何 tsconfig 的 include 里） | 已做证伪实验：注入 `const x: number = "字符串"` → `tsc -p e2e/tsconfig.e2e.json` 报 `TS2322` 且退出非 0；**还原用绝对路径 + 还原后复验**（`__falsify` 命中 = 0，tsc 再跑 0 错误 0 输出） |
| **「验证不了」被写成 skip**（skip 长得和通过一样） | T-20b 🚫 不用 `test.skip`。C-6 降级前是**硬失败 + 写清缺什么**；降级后改为**取证 + 落一份写明「本次未验证」的证据文件**，并把结论原文交主线写进闸门 B —— 两种形态都保证「没验」不会长成「验过了」 |
