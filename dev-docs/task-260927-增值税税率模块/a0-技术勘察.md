## 1. 已核实的真实链路

| 业务面 | 当前真实入口 / 落点 | 对 VAT 的影响 |
|---|---|---|
| 报价创建 | `QuotationResource.create` → `QuotationService.create` | 报价头默认值应在创建事务内固化；不能只在前端显示。 |
| Step2 从基础数据导入 | `QuotationResource.listCustomerPartCandidates`（`GET /api/cpq/quotations/customer-part-candidates`）及 V6 物化服务 | 不新增“导入销售产品”按钮；导入候选需要带出销售产品税务分类，物化报价行时生成快照。 |
| 选配/添加产品 | `ConfigureProductService.configureBySelection` → `insertLineItem` | 该路径也必须调用同一 VAT 快照服务；不能只修批量导入。 |
| 报价行读取 | `QuotationService.loadLineItems` → `quotation_line_item` | 现有报价行没有 VAT 快照字段；新增字段需同时进入实体、DTO、查询和 Step2 卡片。 |
| 重新计算 | `QuotationResource.recalculate` → `QuotationService.recalculate` | 现有重算会读取产品/公式数据；VAT 只能从报价行快照上下文读取，禁止重算时回查当前税率覆盖快照。 |
| 公式求值 | 后端 `FormulaCalculator`、`FormulaCalculationService`；前端 `formulaEngine.ts` 等多条公式路径 | `[增值税]` 是显式可选 token，不是全局自动加税；所有实际可达求值器须共享同一上下文键和缺失态语义。 |
| 产品主数据 | `ds_quote_material` 是销售产品主记录；V425 后业务唯一键为 `(customer_no, material_no)`；`ds_quote_customer_part` 只存客户视角资料 | 若沿用单一来源，客户产品页应 JOIN 销售产品税务分类，不在客户产品表复制 VAT。 |
| 元素 BOM | 现有元素单价来自 V6 物料/元素数据与价格策略 | “含税单价”应是可选展示/策略结果，不能回写未税单价，也不能绕过公式配置自动加税。 |

## 2. 当前发现的硬约束

1. 不能只改一个公式引擎：前后端至少有 `FormulaCalculator`、`FormulaCalculationService`、前端 `formulaEngine.ts` 等并行路径。
2. 不能以当前主数据查询结果替代报价行快照；重新计算、导出和历史打开都必须尊重行快照。
3. 不能新增独立产品导入页面或“更换产品”动作；现有删除后添加流程保持不变。
4. V6 报价基础资料按客户隔离，销售产品逻辑键是 `(customer_no, material_no)`；任何 SQL/缓存键漏客户维度都会串税务分类。
5. 已发布模板和报价快照遵守冻结协议；新增公式标签/含税策略需评估组件快照、`PublishedTemplateReader`、导入导出和三视图渲染的传播点。

## 3. A0 四项选择（已裁决：全部采用方案甲/推荐项）

用户裁决：2026-09-28，四项均采用推荐方案。以下保留备选方案，仅用于说明被排除的实现路径。

### A0-1 税务分类与版本表结构

- **方案甲（推荐）**：`tax_category` 主表 + `tax_category_vat_version` 版本表。分类 ID 稳定，版本表用生效区间约束；产品绑定主表分类 ID，报价行快照分类 ID、版本 ID、税率和来源。
- **方案乙**：同一表每个版本一行。实现较少，但产品绑定需要额外维护“默认版本/逻辑分类”语义，历史引用和默认分类管理更容易混淆。

### A0-2 系统最终兜底

- **方案甲（推荐）**：默认税务分类既是“新产品空值默认分类”，也是报价税率链路的最终兜底；按报价日期取该分类当前有效 VAT，不再维护独立 `system_default_vat_rate`。
- **方案乙**：保留独立系统默认 VAT；默认分类只负责新产品绑定，产品和客户都缺失时读取另一套系统默认税率。

### A0-3 销售产品绑定存储

- **方案甲（推荐）**：`ds_quote_material` 增加 `tax_category_id`，以已有 `(customer_no, material_no)` 为绑定键；客户产品页只读 JOIN。
- **方案乙**：新增独立 `product_tax_category` 绑定表，销售产品主表不加列。该方案会增加导入、保存、查询和唯一性同步边界。

### A0-4 无报价上下文的 `[增值税]`

- **方案甲（推荐）**：没有报价行 VAT 快照时返回明确的“待报价税率”状态；引用该标签的公式不静默使用当前系统税率，具体 UI 阻断/标记在真实核价调用点落地。
- **方案乙**：按默认分类当前有效 VAT 计算并标记为预览值。实现简单，但预览结果有被误认为正式报价结果的风险。

## 4. 尚未进入 A0 的实现前提

- Excel 导入列名、未知税务分类整批拒绝、默认分类提示需要纳入 API 契约。
- 旧 `quotation.tax_rate`、旧 `customer_tax` 和历史“税率”字段的只读兼容边界要在 A0 后写入 API/后端任务；不做存量回填。
- 税率生效区间、金额精度、权限菜单映射和审计字段要以现有权限/精度实现为依据核实，不能只按原型臆造。
- 输出（HTML/PDF/Excel）不新增税率配置入口；如输出显示税率、税额或含税金额，必须使用报价行快照，并在 A0/闸门 A 明确本期展示范围。
