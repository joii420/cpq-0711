# 增值税税率模块

> 立项日期：2026-09-27  
> 任务类型：新功能（路径 A）· 标准档  
> 当前阶段：原型已获用户认可，A0/闸门 A 已裁决；特性分支实现中，已完成数据库、后端快照链路、公式标签及现有页面增量，正在进行验证收尾

## ① 背景与目标

现有报价系统的税率字段含义不够明确，组件公式、产品导入、元素价格策略和报价渲染之间也没有统一的增值税取值规则。销售需要在报价中同时处理一般货物、服务等不同税率，并确保税率政策变化后历史报价仍可复算出原结果。

本任务目标是建立明确的中国增值税口径：产品税务分类决定产品的有效 VAT；报价单默认 VAT 只作为产品税率缺失时的兜底；报价明细保存税率快照；公式标签 `[增值税]` 读取明细快照；含税元素单价按快照计算。

## ② 范围

### 本期做什么

1. 组件公式配置提供可插入标签 `[增值税]`，内部返回税率比例值，例如 13% 返回 `0.13`。
2. 添加产品时，优先使用产品税务分类在报价日期有效的 VAT；无有效产品税率时使用报价单默认 VAT。
3. 报价单默认 VAT 在创建时按客户默认 VAT、默认税务分类当前有效 VAT 顺序初始化并保存；能看到对应菜单的用户均可维护税率配置，不另设隐藏的税率专属权限。
4. 报价明细保存税率、税务分类、税率来源和生效日期等快照信息。
5. 修改系统、客户或产品主数据税率时，不影响已经生成的报价明细；报价重新计算仍使用明细快照。
6. 本期不提供报价明细“原位更换产品”功能；沿用现有“删除产品 + 添加产品”流程，新增产品生成新的报价行及税率快照。单纯修改原报价行价格、数量或重新计算不刷新该行税率。
7. 产品导入支持默认税务分类；系统配置中维护一个默认税务分类，建表语句初始化一条默认记录；新产品未填写税务分类时使用该默认分类，并在预校验结果中提示。
8. 报价、基础核价、明细核价的物料元素 BOM 增加“含税单价”价格策略展示，计算公式为：`元素单价 × (1 + VAT)`。
9. 含税单价原始价格继续来自既有元素单价策略，VAT 来自报价明细快照；无报价上下文时不得静默使用当前系统税率。组件公式编辑器默认展示并允许插入 `[增值税]`，是否参与计算、如何组合由用户配置的公式决定，系统不自动给所有价格加税。
10. 保留旧 `tax_rate` 和历史公式的兼容边界，新的业务字段统一使用明确的 `vat_rate` 命名。

### 本期明确不做

1. 不把客户绑定到税务分类；客户只提供默认 VAT。
2. 不把税率硬编码为 13%、9%、6%；税率必须由有生效日期的税务分类或系统配置提供。
3. 不在公式运行时重新读取当前产品、客户或系统税率替代报价明细快照。
4. 不把含税单价直接写回通用的未税元素价格策略。
5. 不在本期实现出口退税率、进口关税、目的国 VAT/GST；这些税种保留明确命名的后续扩展位置。
6. 不维护、不回填存量报价和存量产品的税率数据；不因本期新增 VAT 配置而批量修改历史数据。旧字段和历史公式的兼容范围在 A0/闸门 A 定稿时单独确认。
7. 不新增报价行原位更换产品能力；产品调整沿用现有删除后重新添加流程。

## ③ 验收标准（原型评审版）

### 单点

- **AC-1**：以报价默认 VAT 为 13% 创建报价，添加税务分类为“一般货物（13%）”的产品，报价明细显示产品税务分类来源、VAT 快照 13%，并可在明细中读取该快照。
- **AC-2**：以报价默认 VAT 为 13% 创建报价，添加税务分类为“现代服务（6%）”的产品，明细 VAT 快照显示 6%，不能被报价头的 13% 覆盖。
- **AC-3**：组件公式编辑器按[公式配置-增值税标签.html](./原型图/公式配置-增值税标签.html)提供“增值税”标签；公式运行时 `[增值税]` 返回 `0.13` 而不是 `13` 或 `1.13`。
- **AC-4**：元素单价为 100、明细 VAT 快照为 13% 时，含税单价按 `100 × (1 + 0.13)` 显示为 113；未税反算 113 ÷ 1.13 显示为 100。

### 序列

- **AC-5**：先生成含 13% VAT 快照的报价明细，再新增/切换默认税务分类的有效 VAT 为 9%、客户默认 VAT 改为 6%，重新打开报价并点击“重新计算”；该明细仍显示 13%，含税金额不变。
- **AC-6**：本期不提供产品更换功能；用户删除产品 A 后添加产品 B，产品 B 作为新报价行按“产品有效 VAT → 报价单默认 VAT”生成新的税率快照；原有报价行只修改价格、数量并重新计算时不刷新其 VAT 快照。现有页面只保留“添加产品 / 删除”入口。
- **AC-7**：报价单同时包含 13% 产品和 6% 服务时，按[报价编辑-Step2-税率快照.html](./原型图/报价编辑-Step2-税率快照.html)在现有产品卡片的物料与元素BOM页签分别展示两条明细的税务分类、税率来源、VAT 快照和含税金额；该页面由报价编辑 Step2 触发，不新增独立路由。

### 边界与反向

- **AC-8**：产品没有有效税务分类税率、报价单有默认 VAT 时，明细使用报价单默认 VAT 并将来源标识为报价单默认；产品有有效税率时不得回退到报价单默认。
- **AC-9**：在报价单管理的[从基础数据导入](./原型图/报价单管理-从基础数据导入.html)抽屉中，文件未填写税务分类时展示默认分类和受影响行数；确认导入后产品绑定该默认税务分类。
- **AC-10**：产品导入文件包含不存在的税务分类编码时，导入整体拒绝，显示 Excel 行号和错误原因，任何产品不得部分写入。
- **AC-11**：组件公式编辑器始终展示可用标签 `[增值税]`；没有具体报价单 / 报价行快照的组件预览、基础核价或明细核价运行环境，不得伪造或静默读取当前系统税率。若配置公式实际引用该标签，应显示“待报价税率”并说明缺少报价行上下文，具体禁用交互待实现阶段按该规则落地。
- **AC-12**：旧模板中已有普通字段“税率”且值为 `1.13` 时，新增 `[增值税]` 标签不改变旧字段的既有含义；历史报价可以继续打开。

## ④ 依赖与影响面

- 组件公式编辑器、前后端公式 token 和报价明细上下文。
- 产品主数据、V6 物料导入和产品税务分类主数据。
- 报价单头、报价明细和重新计算链路。
- 物料元素 BOM 的报价、基础核价、明细核价三类字段/价格策略配置。
- 组件模板快照、SQL 视图输出和报价渲染链路，需按 AP-44 检查跨端协议。
- 现有 `quotation.tax_rate`、旧 `customer_tax` 读取函数、已有手工“税率”字段需要兼容评估；新功能不得继续把 V44 `customer_tax` 作为正式税率来源。
- 本任务触碰金额计算、数据库迁移和跨端公式契约，按标准档处理。A0 技术方案已裁决；闸门 A 以本目录 API、前后端任务和测试契约为准。
- 税务分类与 VAT 税率需要独立维护入口：支持编码、名称、VAT 税率、生效日期、失效日期、启停状态和历史版本；同一分类的生效区间不得重叠，已被产品或报价引用的版本不可物理删除。

## ⑤ 用户原话与决策记录

用户需求原话及已确认规则：

> 公式抓取[增值税]标签的数值进行参与计算时，应当是抓取产品的税率》报价单的税率进行计算.并且生成快照后,以后修改价格,重新计算也是快照后的税率,系统税率被修改不会影响已经生成的报价行的税率.

已确认业务口径：产品税率优先于报价单税率；报价明细保存税率快照；修改价格或重新计算不刷新快照；系统税率、客户默认税率和产品主数据税率变化不影响既有报价行；本期没有原位更换产品功能，删除后重新添加的产品作为新报价行生成新快照。

### 本轮原型修正：客户产品与销售产品的税率字段来源

- 当前真实页面中，「客户产品」读取 `ds_quote_customer_part`；「销售产品」读取报价数据集物料表（当前实现为 `ds_quote_material`）。这两张表目前都还没有正式的 VAT 字段。
- 原型阶段确定采用**单一来源**：税务分类 / VAT 只挂在销售产品主记录（逻辑键为 `customer_no + material_no`）上；客户产品列表通过客户编号 + 销售料号关联销售产品，只做只读展示，不在客户产品表重复保存一份税率。
- 报价创建时从该单一来源解析产品 VAT，随后复制到报价行快照；客户产品页和销售产品页显示的税率必须一致，查不到关联记录时显示「未设置」，不得自行回退到客户默认税率。

原型素材：本目录 `原型图/` 下九份真实入口页面原型（含税务分类与税率维护页、客户默认 VAT、销售产品税务分类补绑、报价创建默认 VAT 与报价行快照）及导航页。

### 用户裁决补充（2026-09-28）

- **维护权限**：能看到税率相关菜单的用户即可修改税务分类、税率版本、客户默认 VAT 和产品税务分类绑定；本期不另设隐藏的税率专属权限。
- **默认税务分类**：数据库建表 / 初始化时必须插入一条默认税务分类；新产品未填写税务分类时自动使用该默认分类。用户确认初始值为 `GENERAL_GOODS / 一般货物 / 13%`。
- **公式标签**：组件管理公式编辑器默认显示 `[增值税]`，用户自行决定是否插入公式、如何参与计算；系统不对所有价格自动加税。
- **无报价上下文**：指组件预览、基础核价、明细核价等运行时没有具体报价单 / 报价行快照的场景；不得静默读取系统当前税率，统一返回“待报价税率”状态，不把该状态当金额结果。
- **税率版本**：新报价行按报价日期选取有效版本；已生成报价行只使用自身快照，主数据后续变更不回溯。
- **存量数据**：不回填、不维护历史报价和历史产品税率数据。
- **产品更换**：用户确认本期不新增原位更换产品功能，只沿用现有“删除产品 + 添加产品”；添加后的产品按新报价行生成 VAT 快照。

### A0 技术方案裁决（2026-09-28）

- **税务分类与版本**：采用 `tax_category` 主表 + `tax_category_vat_version` VAT 版本子表；分类 ID 稳定，版本按生效日期区间维护，报价行快照同时记录分类、版本、税率和来源。
- **默认分类兜底**：系统维护一个默认税务分类；它既是新产品未填写分类时的默认绑定，也是产品、客户默认 VAT 均不可用时的最终兜底。按报价日期读取该分类的有效 VAT，不再另设独立 `system_default_vat_rate`。
- **产品绑定来源**：在销售产品主记录 `ds_quote_material` 增加 `tax_category_id`；逻辑键为 `(customer_no, material_no)`。`ds_quote_customer_part` 不复制分类或税率，只通过关联只读展示。
- **无报价上下文**：组件预览、基础核价、明细核价没有报价行 VAT 快照时，`[增值税]` 返回明确的“待报价税率”状态，不读取当前系统税率，也不伪造 0；具体页面以状态提示/阻断方式呈现，但不得把它当正式报价结果。

## ⑦ 本轮补原型（2026-09-27）

为闭合上表中的页面断点，补充以下真实入口原型；均为现有页面的局部增量，不新增独立业务路由：

1. [客户管理-默认VAT.html](./原型图/客户管理-默认VAT.html)：在现有客户编辑抽屉的基本信息之后增加“报价默认值 / 默认 VAT”，并展示 `default_vat_rate` 导入列和“仅默认 / 兜底”口径。
2. [产品管理-销售产品税务分类.html](./原型图/产品管理-销售产品税务分类.html)：在现有产品管理的销售产品列表、销售产品抽屉内增加税务分类补绑；客户产品只读关联展示，不复制税率字段。
3. [报价创建-默认VAT与快照.html](./原型图/报价创建-默认VAT与快照.html)：严格对应现有 `QuotationWizard` 的 5 步向导、Step1「报价单基本信息 / 联系人 / 客户概况 / 选择模板」，仅增加默认 VAT 增量；Step2 的产品卡片快照单独由[报价编辑-Step2-税率快照.html](./原型图/报价编辑-Step2-税率快照.html)表达，避免把报价创建页画成汇总表。

本轮校正：产品管理原型移除实际页面不存在的“导入销售产品”按钮；销售产品仍沿用现有列表工具栏与点击料号打开抽屉的入口。报价 Step2 原型恢复实际产品卡片头部（客户产品名称 / 客户产品编号 / 产品名 / 销售料号 / 删除）、产品属性、组件页签、BOM 表格和产品小计；不虚构“改价格 / 更换产品”按钮。

本轮原型只定义页面入口、字段位置、状态和触发关系；客户实体字段、数据库快照字段、API、审计和计算实现仍需 A0/闸门 A 定稿后开发。默认分类初始值和产品更换范围已确认。
