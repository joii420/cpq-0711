## 3. A/B 对照方法（AC-15 / AC-16 专用）

「零回归」不能靠「看起来没坏」。两条都必须做**同库背靠背对照**：

```
1. 在 master（改动前）跑一遍目标操作，把响应体 / 表内容落盘为基线
2. 切到本任务分支，同一库、同一份数据、同一操作，再落一份
3. diff 两份文件；差异为 0 才算通过
```

📌 **AC-15 的 A 侧基线已于 2026-09-07 落盘**（`证据/AC-15基线/`，15 个文件，`master=a81f2c40` 时三条并发线均零代码改动）。
🚨 **采集时踩过的坑，重采 B 侧时同样适用**：第一轮按 `parts` 列表的首个轴值 `S0003` 取样，`rows`/`versions` 都是 **0 行** ⇒ A/B 变成「空 vs 空」**恒相等恒通过**。已补采 `0526-2609000004`/`0526-2609000005`（2/4/5 行非空）。**判据：基线本身必须非空。**

⚠️ **AC-16 的 V6 八表对照要用内容 md5，不能只比行数** —— 回填改的是 `is_current` 与列值，行数可能不变而内容已变。

⚠️ **判「是不是本次引入的回归」必须 A/B 同型对比。** 记忆中的实证：干净 master 上 `quotation-flow` E2E 本就恒 3 条失败（夹具单缺产品分类），不做对照会误归因给本次改动。

## 5. 🔬 证伪实验（4 条，防「测了个寂寞」）

自动化用例首次全绿**不等于它真的在验**。每条都做一次「还原实验」：把被测行为改回去，用例必须变红；**不变红 = 白测**。

| # | 实验 | 干预 | 期望 |
|---|---|---|---|
| **R-1** | AC-4 的「一行未写」是真的吗 | 临时把 Phase 1 校验器的客户编号校验注释掉 | T1.4 的「16 表 count 逐表相等」**必须变红**。不变红说明基线本就没写入，断言空跑 |
| **R-2** | AC-16 的 no-op 是真的降级不是没跑 | 临时把新组件的 `$view` 表名改成 `material_bom_item` | `QuoteBackfillService` 摘要**必须不再是 0/0/0/0**。仍是 0 说明回填压根没被调用，AC-16 验的是「没跑」不是「跑了但降级」 |
| **R-3** | AC-6 的非空断言真的在看行数 | 临时把某个页签的 `$view` 加一个恒假谓词 | 该页签用例**必须变红**。不变红说明断言写成了「元素存在」而非「行数 > 0」 |
