## 4 · 后端推翻我的两处预估（如实记，因为它们改了闸门 B 的呈报口径）

| 我的预估 | 实测 | 依据 |
|---|---|---|
| 「改指纹口径 ⇒ 存量 6 组各空转升一版」 | **存量 0 组** | `toRawString(Boolean.TRUE)` 本来就返 `"true"`，STRING 与 BOOLEAN 两分支对它归一**结果相同** ⇒ 读回侧从来不是分叉源。改动前后的预览判定**逐行 diff 为空** |
| 「还有更窄的修法：在 `toRawString` 特判 `Boolean`」 | **那修不好** | 分叉在**导入侧**（Excel「是」在 STRING 分支被原样保留），特判 `Boolean` 碰不到它。⇒ 不是取舍，改声明是唯一可行修法 |

⇒ **闸门 B 的正确呈报**：一次性代价推迟到「**下一次导入**」，`4 组 / 4 行`，各升一版一次，之后永久稳定；**核价通过路径 0 影响**。
