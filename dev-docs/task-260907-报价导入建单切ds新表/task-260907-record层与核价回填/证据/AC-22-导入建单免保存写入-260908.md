## 1 · 夹具与两次失败尝试（留档，因为失败本身有信息）

### 尝试一：没传 `customerTemplateId` ⇒ 组件数据 0 行

`POST /api/cpq/dataset/quote/create-quotation` 只传了 `importRecordId / customerId / name`：

```
① 明细行=6  轴值非空=6            ✅
② 组件数据行=0  component_id非空=0  🚫
_record: element_bom=0  material_bom=0
```

🔑 **前提阳性对照第②条把它拦下来了。** 没有这道闸，我会直接读到 `_record=0` 并报一个
「D-40 挂点没生效」的 P0 —— 而真因是 `QuotationImportDTOs.CreateQuotationRequest:109` **本来就收
`customerTemplateId` 而我没传**。**是我的操作失误，不是缺陷。**
📌 这正是 AC 原文要求这三条闸在 `_record` 断言之前跑的理由：「用来把『夹具选错料号』与『挂点没生效』分开，
这两者失败的样子一模一样」。

### 尝试二：料号跨客户 ⇒ 提交撞 422

补传模板后一切正常（组件数据 84 行、`_record` material_bom=12、`udv=0`），但**提交返 422**：

```
行键重复，无法提交：组件「c6a71e5e」行键 [T260907-M1] 在第 1,2 行重复
```

追下去发现的是 **BL-0229**（ds 原生视图主表 `WHERE` 无客户谓词，同一料号跨客户时页签串行）。
`T260907-M1/M2` 同时存在于 `CUST-0001` 与 `CUST-0004` ⇒ 物料页签返 2 行。
🚦 用户 2026-09-08 裁决：**登记 BACKLOG，不在本期修**。

📌 顺带一条：夹具生成脚本 `gen_fixtures.py:42` 的注释就记着这件事 ——
前缀由 `T260907-` 改名为 `T260907T-`，理由「**并发会话用同前缀写了 `T260907-M1/M2`**」。
我撞的正是那个。**换用 `T260907-主文件-CUST0004.xlsx`（`T260907T-` 前缀）后料号跨客户数 = 1，绕开。**

## 3 · ④ 为什么不批准 —— D-44（P0）

预览预测**这张用户一个字都没改的单**会把主表撑大：

```
合计 base=43 → result=71   （净增 28 行，26 个组里 14 个变大）
```

🚫 **主线拒绝执行 `costing-approve`** —— 那会往共享 dev 库的 `ds_quote_*` 写 28 行脏数据。
根因、机制、修法与用户裁决见 **台账 D-44**。

⚠️ **注意 `unanchoredRows=28` 这个数字出现在 ⑤ 的 summary 里** —— 也就是说，
**AC-22⑤ 的绿与 D-44 的红来自同一次预览**。⑤ 只断言 `noRecordSnapshot`，它管不到行数膨胀。
📌 判据只在它声明的维度上有效；同一份响应里的绿不能替另一个维度背书。
