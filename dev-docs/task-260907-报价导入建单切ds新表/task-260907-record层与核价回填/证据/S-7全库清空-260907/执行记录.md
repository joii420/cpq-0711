## 7. 沉淀（供结案呈报）

1. **用户批准的是一句话，脚本执行的是一个 WHERE** —— 两者之间的落差正是不可逆操作最容易出事的地方。
2. **批准的有效性取决于批准时他掌握的信息**；信息变了就得重新问，🚫 不能拿「他批过了」当继续执行的依据。
3. **不可逆操作的放行判据，不是「我准备好了」也不是「他批过了」，而是「依赖方已确认自己不再依赖」**
   （`页签属性` 实证：它以为克隆完就等于不依赖，但真正的依赖方是用户不是它）。
4. **只列「删什么/不删什么」的广播会误导** —— 读者按「我的表在不在清单里」判断，而真正该问的是
   「我依赖的东西还在不在」。**保留了名词，删掉了动词**（数据在、读取入口没了）同样是删除。
5. **跨会话核对行数对不上时，先问「这张表上有没有会自生自灭的东西」**，再判「是不是对方动了我的数据」
   （`修复产品管理` 实证：差异是它自己的测试夹具在两次采样之间被精确清理了）。
