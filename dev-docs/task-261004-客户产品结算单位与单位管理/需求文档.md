# 客户产品结算单位与单位管理

状态：开发中（闸门 A 已通过；2026-10-05 用户确认“开工”）
任务日期：2026-10-04
关联待办：`BL-0321`

## ① 背景与目标

当前单位换算规则散落在前后端代码中，换算关系不可由业务人员维护；客户产品也没有结算单位，导致绑定了单位来源的数值列无法按客户产品的结算口径换算。

本任务目标：在不改变组件字段 `unit_source_field`（同组件内单位字段名）的存储和语义前提下，增加报价侧客户产品结算单位、核价侧生产料号计价单位、可编辑的全局单位与有向换算关系，并让同类型单位按各业务链路的目标单位换算。

## ② 范围

### 本期做什么

1. `ds_quote_customer_part` 增加可空字段 `settlement_unit`，并在客户产品列表通过 Drawer 维护。
2. “系统管理”新增“单位管理”菜单；仅 `SYSTEM_ADMIN` 可以进入和维护。
3. 预置数量单位 EA、PCS、KPCS；预置重量单位 g、kg、t、盎司。
4. 每个单位维护到同类型其他目标单位的有向换算系数；来源单位到自身隐含系数为 1，不单独维护。
5. 换算时以客户产品结算单位作为目标单位：`结果 = 原值 × 系数(单位列单位 → 结算单位)`。
6. 单位代码匹配不区分大小写；展示保留单位定义中的标准写法。
7. 客户产品未维护结算单位、来源/目标类型不同、单位未知、关系缺失或单位停用时，不进行换算，原值透传；页面提供非阻断提示，接口不得因此返回 500。
8. 草稿/新计算在下一次重算时使用当前有效关系；已提交或已发布报价使用冻结时的关系，不因后台维护而回算。
9. 保持组件字段管理中 `unit_source_field` 的字段名存储规则及同组件约束不变。
10. 基础核价、详细核价两套“物料”导入页分别增加可选“计价单位”列，分别写入各自物料表，互不覆盖、互不回退。
11. 核价侧以销售料号绑定的根生产料号为目标料号；基础核价使用 `ds_cost_basic_material.pricing_unit`，详细核价使用 `ds_cost_detail_material.pricing_unit`；BOM 子件不切换目标单位。
12. 报价与核价共用单位定义和有向关系管理，但各自目标单位来源和快照上下文独立。

### 本期明确不做什么

1. 不把 `unit_source_field` 改成单位代码、字段 ID 或跨组件引用；不支持直接 BNF 路径/VARIABLE 作为单位来源。
2. 不设置 PCS/kg 等全局基准单位，也不维护 `factor_to_base`。
3. 不自动按倒数生成反向关系；每个方向独立维护。例如 `PCS → KPCS` 与 `KPCS → PCS` 是两条关系。
4. 不自动回算已提交/已发布报价及历史导出结果。
5. 不删除被历史数据引用的单位；本期使用停用代替删除。
6. 不重构现有币种管理页面。
7. 不将基础核价和详细核价的“计价单位”合并为一列或互相回填；不以另一套数据集的单位补空。
8. 不把核价 BOM 子件生产料号的计价单位作为换算目标。

## ③ 验收标准（AC）

### 单点 AC

- **AC-1 客户产品字段持久化**：以 `SYSTEM_ADMIN` 进入“产品管理 → 客户对应主数据”，选择一个结算单位为空的客户产品，点击顶部“编辑”，在 Drawer 选择 `PCS` 并保存；列表“结算单位”列显示 `PCS`，刷新和重新登录后仍显示 `PCS`。
- **AC-2 单位预置**：首次完成迁移后，单位管理列表至少包含本任务的七条预置单位：数量 EA、PCS、KPCS；重量 g、kg、t、盎司，全部启用；单位代码按大小写不敏感唯一；若环境已有其他单位，不影响这七条记录的存在和关系。
- **AC-3 有向关系维护**：在单位管理选择 `PCS` 并打开“换算关系” Drawer，能分别维护 `PCS → EA` 与 `PCS → KPCS`；保存后刷新仍显示相同系数。`KPCS → PCS` 是独立记录，修改前者不自动改写后者。
- **AC-4 数量换算**：客户产品结算单位为 `KPCS`，绑定单位字段返回 `pcs`（小写），绑定数值为 `2000`，存在 `PCS → KPCS = 0.001`；重算结果为 `2`。反向场景结算单位 `PCS`、来源 `KPCS`、原值 `2`、关系 `KPCS → PCS = 1000`，结果为 `2000`。
- **AC-5 重量换算**：客户产品结算单位为 `kg`，来源单位为 `g`、原值 `1000`、关系 `g → kg = 0.001`，结果为 `1`；客户产品结算单位为 `t` 时，来源 `kg`、原值 `1000`、关系 `kg → t = 0.001`，结果为 `1`；单位代码的大小写变体仍匹配同一关系。
- **AC-6 跨类型不换算**：结算单位为 `PCS`、来源单位为 `kg`、原值 `12.5` 时，结果仍为 `12.5`，且不查询/套用重量到数量关系。
- **AC-7 保持 unit_source_field 契约**：在组件字段管理选择同组件单位字段 `unit_code` 作为“单位换算来源”，保存内容仍为 `unit_source_field: "unit_code"`；报价新建、编辑、只读与导出均从该字段读取单位。
- **AC-8 无结算单位不换算**：客户产品 `settlement_unit` 为空、来源单位为 `g`、原值 `1000` 时，页面、公式、小计和导出消费值均保持 `1000`。

### 序列 AC

- **AC-9 草稿使用最新关系**：管理员将草稿所用的 `PCS → KPCS` 从 `0.001` 改为 `0.002`，返回草稿并触发重算后，原值 `2000 PCS` 的结果从 `2` 变为 `4`；刷新页面后仍为 `4`。
- **AC-10 历史快照冻结**：同一关系修改前先提交一张结果为 `2` 的报价；关系改为 `0.002` 后重新打开该已提交报价，页面、详情和导出仍为 `2`；新建报价或草稿重算使用新系数得到 `4`。
- **AC-11 页面连续操作**：管理员在客户产品 Drawer 保存结算单位 → 切换“系统管理 → 单位管理”编辑对应有向关系 → 返回客户产品页并刷新；结算单位仍保持，下一次草稿重算使用新关系。单位列表筛选切换和刷新不丢失已保存关系。

### 边界与权限 AC

- **AC-12 缺失/未知/停用**：结算单位未知、来源单位未知、关系缺失或任一单位停用时，消费值均原值透传；汉字单位值不再识别，也按未知单位处理；管理/计算接口不返回 500，并产生可定位的非阻断提示或日志。停用单位不出现在客户产品的新选择项中。
- **AC-13 系数校验**：系数必须为大于 0 的十进制数；同一来源/目标组合大小写不敏感唯一；来源与目标必须属于同一类型且不能相同。非法请求返回 400 和明确错误信息，不产生部分写入。
- **AC-14 管理员权限**：仅 `SYSTEM_ADMIN` 可访问单位管理页面、单位/关系写接口以及客户产品结算单位编辑动作；其他角色菜单不可见，直接访问页面被 RoleGuard 拦截，直接调用写接口返回 403。
- **AC-15 并发更新**：两个管理员读取同一单位关系后依次保存，后提交的过期版本返回 409；页面提示“数据已被其他用户更新，请刷新后重试”，不得静默覆盖。
- **AC-16 页面状态**：客户产品页和单位管理页的默认态、空态、错误态、选择不足时的禁用态及最长单位文案均与 `原型图/` 当前基准一致；禁用按钮可见且 Tooltip 说明原因。
- **AC-17 核价导入列**：基础核价“物料”和详细核价“物料”均显示可选“计价单位”列；旧模板缺列仍可导入，带列时分别写入各自物料表的 `pricing_unit`。
- **AC-18 核价单位独立**：对同一生产料号，修改基础核价物料的计价单位不会改变详细核价物料的计价单位；反向同理；单位列表和导入回显分别取各自数据集。
- **AC-19 核价换算目标**：销售料号绑定根生产料号 `P-001`，基础核价物料 `P-001` 的计价单位为 `kg`，来源单位 `g` 的原值 `1000` 换算为 `1`；详细核价物料的目标单位按详细核价表自己的 `pricing_unit` 取值。BOM 子件 `P-CHILD` 的单位不改变目标。
- **AC-20 核价绑定缺失透传**：销售料号无生产料号绑定、对应数据集物料无计价单位、单位无效/停用/缺关系时，核价公式、小计、核价快照和核价导出均保持原值，不返回 500。
- **AC-21 核价冻结**：报价提交生成核价单时冻结基础/详细两套核价上下文中的根生产料号、计价单位和实际系数；后台修改计价单位或关系后，已提交核价单普通打开、刷新、重算仍使用冻结值。
- **AC-22 核价新草稿**：新建报价或尚未提交的草稿重新计算时，基础/详细核价分别读取当前有效 `pricing_unit` 和单位关系；两套数据集互不串值。

## ⑤ 用户原话与素材归档

初始需求：

> 组件字段管理中，通过“单位换算来源”选择同组件内的单位字段名，存储为 `unit_source_field` 这个规则没有错,保持这个规则不变
> 1.客户产品-> 增加属性 结算单位
> 2.换算管理在页面中可以编辑,单独做一个单位管理的菜单页面
> 3.预设单位有 : 数量单位: EA,PCS,KPCS. 重量单位: g,kg,盎司
> 4.数量单位之间设置换算系数, 重量单位之间设置换算系数.
> 5.根据产品的结算单位, 把绑定单位列的列根据单位列的单位* 结算单位的换算系数. 如果单位列的单位是重量单位,结算单位是数量单位,则不进行换算.也就是单位类型不同,不换算

A0 裁决原话：

> 首先原型图中,换算关系的维护在抽屉中,一个单位会对应其他几个单位都维护换算系数.
> 1.换算没有基准,使用客户产品对应的结算单位作为基准单位. 如果客户产品没有维护结算单位,则不进行换算
> 2.预置系数现在都是维护各个单位的换算管理列表.单位->每个目标单位都要维护系数.
> 3.增加字段
> 4.是的.生效时机正确.
> 5.仅管理员可以维护
> 6.停用单位正确
> 7.页面布局使用推荐方案A
> 关于系数的识别问题,匹配时不区分大小写

核价侧扩展原话：

> 核价侧一并统一,与报价侧使用客户料号的结算单位的逻辑相同.
> 1.核价侧使用生产料号的结算单位.
> 2.料号基础数据导入时,在物料页增加计价单位列,用于定义生产料号的结算单位
> 3.在核价侧公式计算中,所有单位换算以销售料号绑定的生产料号的计价单位为基准单位进行换算
> 1.都增加计价单位列,各自维护,独立维护,两边不互相影响
> 2.是的,子件不切换目标单位
> 3.取消复合单位,只保留管理中的有效单位
