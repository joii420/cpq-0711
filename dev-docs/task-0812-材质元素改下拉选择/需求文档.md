## 1. 背景与目标

**现状**：主数据维护 →「材质」→ 新建/编辑材质抽屉的「元素组成」表里，**元素 code** 与 **元素名** 两列都是自由文本输入框（`MaterialRecipeEditDrawer.tsx:174-198`），用户手打。

**问题（已在现网发生，非假设）**：`cpq_db_0724` 实测 `material_recipe_element` 共 621 行，其中 **2 行把「元素编号」当成符号填进了 code 列**：

| 材质 code | 材质符号 | element_code | element_name | element_no |
|---|---|---|---|---|
| `00262` | `Sn02` | `10004` | `Sn` | NULL |
| `992` | `AgNi11#-Ⅰ` | `10001` | `Ag` | NULL |

这两行的 `element_code` 与元素字典（`element` 表，37 条，如 `10004 / Sn / 锡`）对不上，属于**错填**且无任何校验拦截。

**目标**：元素改为从元素字典下拉选择，可按「元素编号 / 元素符号 / 元素中文名」任意片段过滤；两列合并为单一「元素」列，选中后框内显示 `元素编号 / 符号 / 中文名`。使**新产生的数据不可能再填错**，并让老的错填数据在被编辑时暴露出来。

## 3. 澄清结论与决策记录

| # | 决策项 | 结论 | 理由 | 被否决的方案及原因 |
|---|---|---|---|---|
| D1 | 列结构与显示格式 | 「元素 code」+「元素名」两列合并为单列 **「元素」**（Select）；选项与选中态文本统一为 `元素编号 / 符号 / 中文名`（例：`10001 / Ag / 银`） | 用户原始需求；三段同屏，编号与符号不会再互相填错 | —— |
| D2 | 下拉候选范围 | 只列 `status = ACTIVE` 的元素 | 停用元素不应被新引用 | 「全列出可选」被否：停用形同虚设；「全列出置灰」被否：列表变长且无收益 |

| D4 | 字典里**匹配不到**的老数据（上表 2 行） | **清空该行元素 + 标红 + 阻断保存**，必须重选后才能保存 | 用户决策；错填数据在被触碰时逆向清干净 | 「原值显示 + 黄标提示」被否（用户选择更强口径）；「静默显示」被否：脏数据隐形 |
| D5 | 字典里没有的元素怎么办 | **纯下拉，不可自由输入**；需先到「主数据维护 → 元素」新增 | 元素字典是唯一入口，杜绝错填 | 「自由输入兜底」被否：问题只解决一半；「下拉内联新建」被否：新建元素需 SYSTEM_ADMIN，非管理员会失败 |
| D6 | 搜不到时的引导方式 | **只给文案提示**（「未找到该元素，请先到「主数据维护 → 元素」维护」），**不跳转、不提供刷新按钮** | 用户决策。元素 Tab 与材质 Tab 同属 `MasterDataHubPage`，跳转会关闭抽屉丢失未保存内容 | 「跳转 + 二次确认」被否：丢录入；「加刷新按钮」被否：用户选择最小改动 |
| D7 | 同材质内重复选同一元素 | 下拉中**已被其他行选中的元素置灰不可选**（本行自身选中项不置灰） | 当场拦截优于保存时报错；后端既有「elementCode 重复」校验保留作兜底 | 「保存时才报错」被否：体验差且需回改 |
| D8 | 元素名称可编辑性 | **不可行内编辑**，符号与中文名完全跟随字典 | 避免同一元素在不同材质里叫不同名字 | 「允许行内覆盖名称」被否：名称漂移 |
| D9 | 落库口径 | **后端零改动**，提交体仍为 `elementCode` + `elementName`（取自字典），不新增 `elementNo` 字段 | 用户决策：改动面最小、零后端风险 | 「同时落 element_no」被否（用户选择），副作用见 §2.2 → BL-0163 |
| D10 | 存量脏数据 | 不做数据迁移 | 用户决策；量极小（2 行），由 D4 自然收敛 | 「Flyway 修正」被否（用户选择） |
| D11 | 字典数据获取方式 | 抽屉打开时 `GET /api/cpq/elements`（无 keyword）**一次性全量拉取**，过滤在前端本地做 | 现网仅 37 条，本地过滤零延迟；避免每次输入打后端 | 「按 keyword 走后端搜索」被否：数据量小，徒增请求 |
| D12 | 权限 | 无需处理 | `MaterialRecipeResource` 与 `ElementResource` 的读权限完全一致（`SALES_REP` / `SALES_MANAGER` / `PRICING_MANAGER` / `SYSTEM_ADMIN`），能打开材质抽屉的角色必然能读元素字典 | —— |

## 4. 功能需求

- **FR-1**「元素组成」表去掉「元素 code」「元素名」两列，替换为单列「元素」，控件为 antd `Select`（`showSearch`，列宽 260px）。
- **FR-2** 下拉选项文本 = `${elementNo} / ${elementCode} / ${elementName}`（例：`10001 / Ag / 银`）；选中后收起态显示同样的三段文本。
- **FR-3** 过滤：输入任意片段，对 `elementNo`、`elementCode`、`elementName` 三个字段做**不区分大小写的包含匹配**，命中任一即保留。
- **FR-4** 候选仅含 `status = ACTIVE` 的元素（D2）。
- **FR-5** 已被同一材质其他行选中的元素在下拉中 `disabled` 置灰（D7）；本行当前选中项不受影响。
- **FR-6** 过滤无命中时，下拉空态文案：`未找到该元素，请先到「主数据维护 → 元素」维护后再选择`。不提供跳转与刷新（D6）。
- **FR-7** 打开编辑抽屉时，按已存的 `elementCode` 反查字典：
  - 命中 ACTIVE 项 → 正常回显选中态；
  - 命中但 `INACTIVE` → 正常回显，并在该行元素列右侧加灰色 `已停用` 标记，允许保存（D3）；
  - **未命中** → 该行元素置空，标红提示 `原值「<原 element_code>」不在元素字典中，请重新选择`，且点「保存」被前端拦截（D4）。
- **FR-8** 提交体保持现有契约：`elements[].elementCode` = 选中项的 `elementCode`，`elements[].elementName` = 选中项的 `elementName`，其余字段（`defaultPct` / `minPct` / `maxPct` / `isLocked` / `sortOrder`）逻辑不变（D9）。
- **FR-9** 新建材质时默认那一行的元素为空（原本 `elementCode: ''`），未选择元素时点保存要被拦截并提示 `请为第 N 行选择元素`。
- **FR-10** 元素字典加载失败（接口 4xx/5xx）时：`message.error` 提示且下拉显示为加载失败空态，**不得静默呈现为「无可选元素」**。

## 5. 数据与规则

| 项 | 内容 |
|---|---|
| 元素字典表 | `element`（现网 37 行，全部 `ACTIVE`）；字段 `element_no`（不可改业务主键）/ `element_code`（符号，被引用即锁）/ `element_name`（中文）/ `status` |
| 材质元素表 | `material_recipe_element`（现网 621 行）；本期**写入字段与现状完全一致**：`element_code` / `element_name` / `default_pct` / `min_pct` / `max_pct` / `is_locked` / `sort_order`；`element_no` 继续由 `MaterialRecipeService.insertElement()` 不写入（保持 NULL） |
| Flyway | **无**（本期不涉及任何 DDL / DML 迁移） |
| 接口 | 复用 `GET /api/cpq/elements`（返回全状态，含 `status` / `referencedCount` / `codeLocked`），详见 `api.md` |
| 校验口径 | 前端新增：①元素必选 ②同材质内元素不重复（置灰即预防）③字典外元素阻断保存。后端既有校验（`elementCode` 必填 / 重复 / 含量和=100 / recipeType 与 min-max 组合）**全部保留不动** |

## 6. 验收标准

- **AC-1**「元素组成」表列头依次为：`元素 | 默认 % | 最小 % | 最大 % | 锁定 | 操作`，不存在「元素 code」「元素名」两列，且「元素」列是下拉框而非输入框（新建、编辑两个入口均满足）。
- **AC-2** 在元素下拉里分别输入 `10001`、`ag`、`银`，三次都能筛出同一项，且选项文本恰为 `10001 / Ag / 银`（`ag` 小写验证大小写不敏感）。
- **AC-3** 选中该项后下拉收起，框内文本为 `10001 / Ag / 银`。
- **AC-4** 用「主数据维护 → 元素」把某个未被引用的元素停用后，重新打开材质抽屉，该元素**不出现**在下拉候选中；恢复启用后再次出现。
- **AC-5** A 行选中 `Ag` 后，展开 B 行下拉，`10001 / Ag / 银` 呈灰色不可点；A 行自身下拉里 `Ag` 仍可点（保持选中）。
- **AC-6** 在下拉搜索框输入 `zzz`，出现文案 `未找到该元素，请先到「主数据维护 → 元素」维护后再选择`，且无任何跳转按钮/链接。
- **AC-7** 打开材质 `00005`（3 个元素、数据正常）→ 各行元素自动回显对应字典项 → 不做任何改动直接保存 → SQL 对比保存前后该 recipe 的 `material_recipe_element` 所有列（`element_code` / `element_name` / `default_pct` / `min_pct` / `max_pct` / `is_locked` / `sort_order`）**逐字段一致**。
- **AC-8** 打开材质 `992`（脏数据 `element_code='10001'`）→ 元素框为空且显示红色提示 `原值「10001」不在元素字典中，请重新选择` → 直接点保存被拦截并给出提示；重选 `10001 / Ag / 银` 后保存成功，SQL 查得该行 `element_code='Ag'`、`element_name='银'`。
- **AC-9** 表格中不存在可编辑元素名称的输入框（元素名只作为下拉文本的一部分展示）。
- **AC-10** F12 Network：打开材质抽屉时 `GET /api/cpq/elements` **恰好 1 次**；在下拉里连续输入过滤 5 次，**不产生任何新请求**；保存时只发 1 次 `PUT/POST /api/cpq/material-recipes*`。
- **AC-11** 保存请求体 `elements[]` 的字段集合与改动前完全一致（不新增 `elementNo` 等字段），后端零改动下返回 200。
- **AC-12** 自检：`npx tsc --noEmit -p tsconfig.json` 0 错误；`curl -s --noproxy '*' -o /dev/null -w '%{http_code}' http://localhost:5174/src/pages/config/MaterialRecipeEditDrawer.tsx` = 200。

| 主要风险 R1 | **回显映射错**：编辑老材质时若映射逻辑写错，可能把正常行误判为「字典外」而阻断保存。由 AC-7（621 行里的正常材质保存后逐字段一致）守住 |

| **R4（开发期实测补充）** | **元素引用计数的量化更正**：那 2 行脏数据的 `element_code` 存的是元素编号（错值），**按 `element_no` 与按 `element_code` 两种口径 JOIN 都匹配不上**（实测 Ag 138/138、Sn 18/18 完全相等），因此它们当前对任何元素的 `referencedCount` 贡献都是 0 —— §2.2 原写的「少算这 2 行」不准确。真正的少算要等 D4 把它们修正后才出现，仍归 `BL-0163` 跟踪 |
| **D8 实现口径实证** | 回显命中字典的行时，`elementCode`/`elementName` 取**字典当前值**而非历史存储值（符合 D8「完全跟随字典」）。实测现网 619 行命中字典的元素行中，`element_name` 与字典**不一致的为 0 行**，故 AC-7「不改动直接保存后逐字段一致」不受该实现影响 |
| 已知遗留 | `element_no` 仍不落库（D9）+ 2 行存量脏数据不迁移（D10）→ 合并时登记 `BL-0163`，P2 |

## 8. 已知坑位

| 坑 | 规避方式 |
|---|---|
| **antd `Select` 的 `filterOption` 默认只匹配 `children`/`label`** | 必须自写 `filterOption`，显式匹配 `elementNo` / `elementCode` / `elementName` 三字段（FR-3）。用 `optionFilterProp` 走 label 只能匹配到拼接串，虽然也覆盖三段，但对大小写与空格敏感，仍以自写 `filterOption` 为准 |
| **受控 Select 的 value 用错身份** | `value` 必须用元素的稳定标识 `elementNo`，不要用 `elementCode`（符号可改）或数组下标。参考 AP-54：渲染下标与写回下标错配会导致改 A 行写到 B 行 |
| **`docs/反模式.md` AP-50（渲染层 single-source）** | 材质抽屉是新建/编辑共用组件，改造后必须**两个入口都验**（AC-1 明确要求），避免只改到其中一条路径 |
| **`onRecipeTypeChange` 会整表刷新元素行** | 切换 `locked/editable/partial` 时 `setElements` 会重建行对象，改造后要确认元素选中态不被清空（test.md 需覆盖） |
| **API 响应拦截器已 unwrap `response.data`** | `elementService.list()` 返回的即数组本身，不要再取 `.data`（现有服务层已正确处理，直接复用） |
| **ugrep 静默返空** | 本任务如需全仓检索中文，必须用 `/usr/bin/grep -a`（见记忆 `cpq-grep-ugrep-binary-pitfall`） |
