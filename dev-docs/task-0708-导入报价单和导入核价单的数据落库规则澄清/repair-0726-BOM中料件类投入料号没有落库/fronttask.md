## 1. 为什么前端仍要进场

后端把「料号先进暂存表、核价通过才进正表」换成了「直接进正表 + 行级 pending 标记」。这条链路的下游全在前端可见：

| 变化 | 前端可观测点 |
|---|---|
| 导入后料号即刻进正表 | 报价单页签 / BOM 树的**品名、单重从空变有**（本需求要修的现象） |
| 主数据列表加 `pending_quotation_id IS NULL` 过滤 | 料件主数据列表**内容不应变化**（旧机制下这些料号本就不在正表） |
| 核价通过由 upsert 改为 flip 标记 | 核价通过后料号**出现在**主数据列表 |
| 预览 token 数据源改变 | 核价「预览 → 提交」两步**不应出现异常 409** |

## 3. 前端强制自检（CLAUDE.md「修改后强制自检」）

即使**零代码改动**，交付前也要跑一遍确认工作区干净、dev server 正常：

```bash
cd cpq-frontend && npx tsc --noEmit -p tsconfig.json                     # 期望 0 错误
curl -s --noproxy '*' -o /dev/null -w '%{http_code}\n' http://localhost:5174/   # 期望 200
curl -s --noproxy '*' -o /dev/null -w '%{http_code}\n' http://localhost:8081/api/cpq/components  # 期望 401
```

> ⚠️ 两个坑（CLAUDE.md 已记）：本机 `http_proxy` 会让 curl localhost 返 502 → 必须加 `--noproxy '*'`；后端没装 smallrye-health，`/q/health` 返 404 不是健康探针 → 看业务端点 401。

> 🔁 dev server 是全会话共享的，**先探端口，已在跑就复用**，不要在 worktree 里另起。
