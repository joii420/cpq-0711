## 2. 需求背景与目标 ⭐

### 2.1 现象与根因（已定位）

- **现象**：报价单基础数据导入后，物料 BOM 中的非材质类（零件 / 外购件）投入料号，在 `material_master` 料件主表里查不到。
- **根因（非写入链路 bug）**：`MaterialBomMergeHandler.java:122-133` 对 ASSEMBLY/OUTSOURCED 分支**有**登记动作（`material_type` 写「零件」/「外购件」），但 task-0721 B9 引入了「主档暂存」机制：
  - `QuoteImportService.java:95` 令 `ctx.pendingQuotationId = importRecordId`（**恒非空**）；
  - `MaterialMasterRepository.java:253-292` 的三个 pending 感知重载在 `pendingQuotationId != null` 时**改写 `pending_material_master_staging` 暂存表，不落 `material_master` 正表**；
  - 只有报价单走到「核价通过」（`QuoteBackfillService.java:67 promoteStaging`）才 upsert 进正表。
- **需求方实测确认**：`material_master` 正表查不到、`pending_material_master_staging` 暂存表里有 → 卡在暂存机制，不是漏写。

### 2.2 本次要达成的目标

1. 报价单导入完成的当下，零件类 / 外购件类料号即出现在 `material_master` 正表（不再等核价通过）。
2. 保留「未核准料号不污染主数据列表」的隔离语义 —— 改用**行级 pending 标记**实现，而非独立暂存表。
3. 顺带关闭两个既有隐患：料号发号查重看不到本批新铸号导致的重号风险；BACKLOG **BL-0072**（`clearPreviousPending` 未覆盖暂存表的孤儿行）。

### 2.3 业务动机（需求方确认，两项）

| 动机 | 说明 |
|---|---|
| **报价单渲染拿不到数据** | 报价单向导 / BOM 树 / 页签的 SQL 视图 join `material_master` 取品名、单重等，正表无行 → 显示为空 / 断链 |
| **料号唯一性、发号冲突** | `MaterialNoResolver.resolve()` 按名查的是 `material_master` **正表**，本批新铸号只进暂存 → 跨批次 / 重导时可能二次发号。现状仅靠单次导入内的 `BatchState` + `nameToCodeSeed` 兜底 |

### 2.4 不做什么（明确边界）

- **材质类（RECIPE）投入料号仍不登记 `material_master`** —— 维持 repair-2 决策 A/B（材质有独立 `material_recipe` 主表，登记正表曾导致跨客户串号）。
- **核价（PRICING）侧导入不动** —— 核价侧本就无 pending 机制、直落正表，本次不排查不改动。
- 其余落库规则（字段映射、三态推断、发号规则本身）一律不动。
- 前端页面无功能改动（见 §12.5）。

## 4. 功能详述 ⭐

### 4.1 用户场景 / 操作流程

1. 报价单管理 → 从基础数据导入 → 选客户（罗克韦尔 CUST-1269）→ 上传 `报价系统模板0723.xlsx` → **导入完成即刻**，`material_master` 能查到 `S-80011`（零件）、`W-1001`（外购件），带 `pending_quotation_id = importRecordId`。
2. 创建报价单 → pending 归属过户为 `quotationId`。
3. 报价单渲染 → 页签 / BOM 树 join `material_master` 能取到品名、单重（不再断链）。
4. 核价通过 → `pending_quotation_id` 清空转正，料号出现在「料件主数据」列表。
5. 报价单删除 → 该单 pending 料号行回收（带引用守卫，见 §4.3）。

### 4.2 界面与交互（前端相关）

**本次前端零改动。** 料件主数据列表的 pending 过滤在后端查询实现，前端不感知；不新增「待核准」标签或筛选项（需求方明确否决扩大到前端）。

### 4.3 业务规则与计算逻辑（后端相关）

#### 规则一：写入语义（8 个写入点统一，repo 层实现，call site 不改）

```sql
INSERT INTO material_master (..., pending_quotation_id) VALUES (..., :pq)
ON CONFLICT (material_no) DO UPDATE SET ...   -- 关键：DO UPDATE 子句不含 pending_quotation_id
```

| 场景 | 结果 |
|---|---|
| 料号在正表不存在 | INSERT，打 `pending_quotation_id = :pq` |
| 已存在且是正式行（NULL） | **保持 NULL，不降级**（需求方裁决） |
| 已存在且归属别的 pending 单 | 保持原归属，**不抢占** |
| 描述性列 | 仍按 `preserveDescriptive=true`（只补空不覆盖），语义零变化 |
| `pendingQuotationId == null`（非导入路径 / 单测） | 逐字节沿用原直写正表行为，零回归 |

#### 规则二：可见性三口径（各自独立，互不叠加）

| 消费方 | 谓词 | 改动量 |
|---|---|---|
| 报价渲染 / SQL 视图 join `material_master` | **不加谓词，全局可见** | 零改动，`QuotePendingRewriter` 不碰 |
| 料件主数据列表 `MaterialMasterCrudService.list` | `pending_quotation_id IS NULL` | 加一个 where |
| 发号查重 `MaterialNoResolver` | **不加谓词，全局可见**（防重号） | 零改动，隐患自愈 |
| 报价候选 `ExistingProductService` / `CustomerPartCandidateService` | 闸门已在 `material_customer_map.pending_quotation_id` 上 | **不再叠加**，避免双重过滤 |

> 📌 **跨单引用裁决**：渲染侧不做单据隔离 —— 单 1 铸的 pending 号被同客户单 2 复用时，单 2 也能 join 到品名。理由：`material_master` 是字典表，渲染只取品名/单重，全局可见不构成业务泄露；真正的单据隔离由 8 张 V6 业务表承担。

#### 规则三：生命周期（复用现有 pending 基建，把 `material_master` 加入表清单）

| 事件 | 代码位置 | 动作 |
|---|---|---|
| create-quotation 过户 | `V6QuotationCommitService.java:134 repointPendingOwnership` | `recordId` → `quotationId` |
| 重导覆盖同一单 | `QuoteImportService.java:269 clearPreviousPending` | 清本单旧 pending 料号行（**顺带关闭 BL-0072**） |
| 核价通过 | `QuoteBackfillService.java:67` | `promoteStaging` → `UPDATE material_master SET pending_quotation_id = NULL WHERE pending_quotation_id = :qid` |
| 核价驳回 / 撤回 | — | **不动**，保持 pending（对齐 task-0721 B8 语义） |
| 报价单删除 | `QuotationService.java:1638 cleanupPendingV6Data` | 删本单 pending 行，**带引用守卫** |

#### 规则四：删单回收的引用守卫（需求方已确认要加）

单 1 铸的号被单 2 复用后单 1 被删 → 直接 DELETE 会让单 2 的 BOM 拿不到品名。故删除条件收窄为：

```sql
DELETE FROM material_master mm
WHERE mm.pending_quotation_id = :qid
  AND NOT EXISTS (SELECT 1 FROM material_bom_item  x WHERE x.component_no = mm.material_no
                    AND (x.pending_quotation_id IS NULL OR x.pending_quotation_id <> :qid))
  AND NOT EXISTS (SELECT 1 FROM material_bom       x WHERE x.material_no  = mm.material_no
                    AND (x.pending_quotation_id IS NULL OR x.pending_quotation_id <> :qid))
  AND NOT EXISTS (SELECT 1 FROM material_customer_map x WHERE x.material_no = mm.material_no
                    AND (x.pending_quotation_id IS NULL OR x.pending_quotation_id <> :qid))
```

> 注：`cleanupPendingV6Data` 内**必须先删 8 张 V6 表的 pending 行、后删料号行**，否则本单自己的 BOM 行会把守卫顶住导致料号永不回收。

#### 规则五：附带修正 —— Q02 销售料号补 `material_type`

`Q02CustomerMapHandler.java:124` 现只写 `material_no`，`material_type` 恒空。本次补写 `'零件'`，与 `PartTypeInferenceService` 的权威集口径一致（销售料号 = 主件，存储类型 = 零件），也让库内兜底推断能命中真值而非落默认。

### 4.4 数据字段

| 字段 | 含义 | 类型 | 必填 | 示例 / 取值 |
|------|------|------|------|------------|
| `material_master.pending_quotation_id` | 该料号行由哪张未核准报价单新建；NULL = 已生效的正式料号 | `UUID` | 否（可空） | `null` / `3f2a…`（导入期=importRecordId，建单后=quotationId） |
| `material_master.material_type`（Q02 路径） | 料号存储类型 | `varchar(50)` | 否 | 本次 Q02 补写 `'零件'`；BOM 路径既有 `'零件'` / `'外购件'` |

## 6. 数据与迁移

- **表结构变更**：`material_master` 新增 `pending_quotation_id UUID NULL` + 部分索引。
- **历史数据迁移**：需求方选定 **「Flyway 一次性迁回正表 + 暂存表退役」** —— `INSERT … SELECT` 把 `pending_material_master_staging` 存量行写回 `material_master`（`pending_quotation_id = 原 quotation_id`），随后 `DROP TABLE pending_material_master_staging`。已导入的单**不需要重导**。
- **兼容性**：`pendingQuotationId == null` 的调用路径行为逐字节不变；核价侧完全不受影响。

## 12. 方案定稿（技术总监）

### 12.1 数据模型

```sql
ALTER TABLE material_master ADD COLUMN pending_quotation_id UUID NULL;
CREATE INDEX ix_material_master_pending ON material_master(pending_quotation_id) WHERE pending_quotation_id IS NOT NULL;
```

与 8 张 V6 表的**语义差异**：`material_master` 按 `material_no` 唯一，**不做 pending 副本行**，只做**行级标记** —— 一个料号恒一行，标记表示「这行由某张未核准报价单新建」。

### 12.2 写入路径

改动集中在 `MaterialMasterRepository` 的三个 pending 感知重载实现内（`upsertBatchNameType` / `upsertBatchWithWeight` / `upsertBatchMaterialNoOnly`），**8 个 handler 的 call site 一行不改**。

### 12.3 退役清单

`stageOne` / `listStaging` / `promoteStaging` / `clearStaging` 四个方法 + `StagedRow` 记录 + `pending_material_master_staging` 表；`QuoteBackfillPlan.materialMasterStaging` 与 `QuoteBackfillCollector:222` / `QuoteBackfillPreviewService:153` 改读正表 pending 行。

### 12.4 8 个 material_master 写入点（本次口径统一，call site 不改）

`MaterialBomMergeHandler:169`、`Q02CustomerMapHandler:124`、`Q04ElementBomHandler`、`Q06FixedProcessFeeHandler`、`Q07IncomingOtherFeeHandler`、`Q09IncomingRecoveryHandler`、`Q13ComponentOtherFeeHandler`、`Q18UnitWeightHandler:51`。

### 12.5 前端

零功能改动，仅需回归验证（详见 `fronttask.md`）。
