## ① 问题描述

报价单**详情页预览**时，报价侧（QUOTE）的 **BOM 类型页签**表头多出一列「版本」，行内显示 BOM 版本号（或 `—`）。

按业务裁决（2026-07-22，见 `7fadf5e8` 提交说明）：**报价树无版本切换语义，报价侧不应有版本列**，系统固定列只保留「料号」一列。核价侧（COSTING）保留「料号 + 版本」两列不变。

对照现状：

| 视图 | 组件 | 报价侧 BOM 树页签系统列 | 是否符合裁决 |
|---|---|---|---|
| 报价单**编辑页**（Step2 产品卡片） | `QuotationStep2.tsx` | 料号 | ✅ 正确 |
| 报价单**详情页 / 预览**（只读卡片） | `ReadonlyProductCard.tsx` | 料号 + **版本** | ❌ **本 BUG** |
| Excel 关联视图 | `LinkedExcelView.tsx:216` | 料号 | ✅ 正确（已按 `isCosting` 过滤） |

> 用户未提供截图；现象描述来自用户口述，代码侧证据见 ④。

## ② 复现 / 发现方式

**发现方式**：用户在报价单详情页预览时肉眼发现，与编辑页对照后报出。

**复现步骤**（环境：本地 dev，前端 `http://localhost:5174`，后端 `8081` → `10.177.152.12:5432/cpq_db_0724`）：
1. 打开任一含 **BOM 树页签**（组件 `tab_type='BOM'` / 后端下发 `__sys.nodeId` 系统列）的报价单；
2. 进入**编辑页**（报价向导 Step2），切到该 BOM 页签 → 表头 = `料号 | <业务列…>`，**无版本列** ✅；
3. 退出编辑，进入该报价单**详情页**（只读预览），切到同一 BOM 页签 → 表头 = `料号 | 版本 | <业务列…>` ❌。

**触发条件的一般化描述**：`side === 'QUOTE'` 且当前页签的 driver 展开行带 `__sys.nodeId`（即被判定为 BOM 树页签）时，只读卡片恒定多渲染一列「版本」。与具体报价单、客户、模板无关 —— **报价侧所有 BOM 树页签的详情页 100% 复现**。

## ③ 需求结果

- **E-1**：报价侧（`side === 'QUOTE'`）BOM 树页签在**详情页/只读视图**中，系统固定列只出「料号」一列，**不出「版本」列**——与编辑页逐列一致。
- **E-2**：**核价侧（`side === 'COSTING'`）行为逐位不变** —— 树页签仍出「料号 + 版本」两列，版本单元格仍按 `canSwitchTreeVersion && editable` 决定「下拉 / 纯文本」（task-0713 F2/F3/F4 契约不得被削）。
- **E-3**：**非树页签的版本列（`activeComponentVersionable`，task-0713 F2）不受影响** —— 该开关本身已含 `isCosting` 闸门，报价侧恒 false，本次不得顺手改动其判定。
- **E-4**（反向期望，防止修成「把列关了」）：报价侧详情页去掉版本列后，**表体单元格与表头必须仍严格对齐** —— 空数据占位行的 `colSpan`、tfoot「小计」行与「合计」行的占位 `<td>` 数量都必须随之从 2 格降为 1 格，不得出现整表错位一列。
- **E-5**：树的层级缩进、折叠箭头、`isCycle` 红字提示、料号文本等「料号列」既有能力全部保留。

## ④ 问题原因 / 报告

### 根因（一句话）

## ⑤ 修复方案

> **裁决时间**：2026-08-14 · 用户拍板（方案对比报告已于对话输出，此处只记裁决结果）

**为什么选它**：本 BUG 的性质是「一条业务裁决只落地了一半」，最忠实的修法就是把编辑页那三处已验证的写法原样搬到只读页。改动纯渲染、不触碰取值/快照/公式，回归面最小，且与 `QuotationStep2.tsx` 的判据（`cardSide === 'COSTING'` ↔ `isCosting`）逐字同源，不引入第二套口径。

## ⑥ 验收标准

| AC | 判定方式 |
|---|---|
| **AC-1（阴性·主诉）** | 报价单详情页打开含 BOM 树页签的产品卡片 → 该页签表头列序 = `料号 | <业务列…>`，**不含「版本」** |
| **AC-2（阳性·核价不塌）** | 核价单 / 核价管理详情页同类树页签表头仍为 `料号 | 版本 | <业务列…>`，版本单元格内容（下拉 or 纯文本）与改动前逐字一致 |
| **AC-3（无副作用·对齐）** | 报价侧详情页该页签：① 有数据时每行单元格数 = 表头列数；② 无数据时「暂无数据」占位行横跨整表不溢出；③ tfoot「小计」/「合计」行与业务列对齐（`is_subtotal` 列的数值落在正确的列下） |
| **AC-4（无副作用·树能力）** | 报价侧树缩进层级、折叠箭头展开/收起、`isCycle` 红字提示、料号文本均与改动前一致 |
| **AC-5（无副作用·值不变）** | 页签小计 / 合计 / 产品小计数值与改动前逐字节一致（纯渲染改动，不得触及任何取值） |
| **AC-6（非树页签）** | 报价侧非树页签、核价侧非树页签的版本列行为均不变（报价侧本就无、核价侧按 `view_version` 出） |
| **AC-7（自检证据）** | ① `npx tsc --noEmit` 0 错误；② `curl http://localhost:5174/src/pages/quotation/ReadonlyProductCard.tsx` → 200；③ 按 `CLAUDE.md` 强制自检第 5 条，`ReadonlyProductCard.tsx` 在 E2E 强制清单内 → 跑 `quotation-bom-tree.spec.ts` + `quotation-flow.spec.ts`，附结果与「加载中 final count = 0」 |
| **AC-8（防回归）** | E2E 补一条**详情页**表头断言（报价侧树页签不含「版本」），堵住 `7fadf5e8` 时的同款漏检口 |
