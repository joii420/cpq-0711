## F-4 建单物化期间禁用保存（交付后返修，2026-08-29 追加）

| 编号 | 服务的 AC | 任务内容 |
|---|---|---|
| **F-4** | AC-30, AC-31, AC-32, AC-33 | 编辑页在**建单物化未完成**时禁用「保存草稿」按钮并显示可读原因；物化完成后**自动恢复可用**（无需刷新） |

### 为什么要做（根因，不是猜测）

用户在**刚建好的**单上点保存，报 **409 `Duplicate value for Key (line_item_id, component_id)`**。日志实证是**两个流程并发写 `quotation_line_component_data`**：

```
18:10:10~21  executor-thread-5  建单物化 snapshotQuotation 在 UPSERT 自建 componentData 行
18:10:24     executor-thread-6  saveDraft 进入
18:10:28     INSERT 撞 uq_qlcd_line_component
```

等物化跑完后用**同一个 payload** 重发 → **200 成功**，证明是纯并发时序。

### 实现要点

- 判定依据：`POST /v6/quote/create-quotation` 响应里的 **`materializing`** 标志 + 既有的 `ensure-card-values` 轮询（**两者前端都已有，不需要新接口**）
- 禁用期间给出可读提示（如「基础数据正在准备中，请稍候…」），**不要只是灰掉按钮不给原因**
- 物化完成后**自动恢复**，不要求用户刷新页面
- 🔒 **老单（物化早已完成）必须立即可用**，不得引入任何等待（AC-32）

### 🚫 不做什么

- 🚫 **不改后端**。唯一约束 `uq_qlcd_line_component` 保留作最后一道防线（AC-33）
- 🚫 **不用 `ON CONFLICT DO UPDATE`** —— 该方案已被 A0 第二轮推翻，理由见 `问题说明.md` ⑤ F-4 段：① 会把「响亮的失败」换成「沉默的数据倒退」（用户旧数据覆盖物化新成果）；② 物化侧走原生 SQL，`@SQLInsert` 对它无效，反方向冲突仍会 409
