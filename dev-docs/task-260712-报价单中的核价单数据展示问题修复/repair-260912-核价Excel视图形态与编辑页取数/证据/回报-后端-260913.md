## 4. 规避掉的坑

1. **报价侧判据没用「有没有 cardValues」这种隐式条件** —— 会在「报价侧某天也开始写 cardValues」时静默串味；改用显式模板归属，报价侧结构上恒走老分支。
2. **把 `parseEffectiveRows` 拆成 `loadEffRowsCtx` + 纯解析两段** —— 原方法每次调用都 `findById` + `readTree(componentsSnapshot)`，直接放行循环里虽有 L1 缓存挡 SQL，但**大 JSON 会被解析 N 次**。
3. **比对器差点用错**：既有 `cmp.py` 走 float，**实测漏报第 18 位有效数字差异**（`203420.599086531655` vs `…656` 判 SAME），而报价侧的值恰好 15 位以上。改写 Decimal 版并做 4 组变异实验才用它下结论。
4. **还原实验做了「复位再验」** —— 只做前半段的话，红有可能是热重载没生效或环境抖动。
5. **没用 `git stash`**，还原实验一律 `cp` 备份 + 复位，最后 grep 确认残留清零。
6. **测试用例内置鉴别力断言**，避免「开关没接上、两边都返 1 行、用例照样绿」。
7. `rm -rf` 清 `target/test-classes` 被 hook 拦下后**没有绕路**。
