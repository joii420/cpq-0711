> # ⛔ 本任务已废弃（2026-08-30 当日立项、当日废弃，未写一行代码）
>
> **废弃原因**：方案能消除「版本号无谓爬升」，但**消除不了「行按单各存一份」**，而后者才是用户真正在意的。

> 结论已实证、已收录进 `INDEX.md` §0 按症状反查。下次再遇到同样的现象，读这里即可，不必重查。

> **未采纳的方案设计（§②~§③ 的 S-1~S-6 与 19 条 AC）保留作历史追溯**，若将来重启本方向可直接复用。

## ① 背景与目标

### 现象

用户重复导入同一个 Excel（`1800笔产品订单.xlsx`，Excel 11536 行 → 匹配 1845 行），**每一次都生成新版本号**，且每一次都在库里堆一整份数据。

实测快照（2026-08-30 清库前，`cpq_db_0724`）：

| 观测项 | 实测值 |
|---|---|
| 料号 `202601010001` 的 `material_bom` 版本 | **29 个版本（2000 → 2029）**，`is_current=true` 的**一行都没有** |
| 时间跨度 | `08-26 00:43` 落 2000 → `08-30 05:24` 涨到 2029，4 天 29 次导入，一次一版 |
| `material_bom` 全表 | 53,610 行，其中 **53,583 行（99.95%）是 pending 影子行**，分属 75 张报价单 |
| 归属单状态 | DRAFT 68 张（53,571 行）/ SUBMITTED 3 张 / 孤儿 4 张；**全库 0 张 APPROVED** |

### 根因（已实证，三处代码咬合）

1. **pending 行永远不进基线**。`VersionedV6Writer:416` / `:854` 的基线查询写死 `AND is_current = TRUE`，而 pending 分支（`:158`）落库时不 flip、不 delete、写 `is_current=false`（类头注释「pending 行恒 `is_current=false`」）⇒ **上一次导入写的行，下一次导入根本看不见**。
2. **「内容相同 → 复用版本」的出口结构上不可达**。`:150` 的 `if (triggerSame && contentSame) return currentVersionOf(...)` 是唯一能不升版的路径，但 `existing` 恒为空集 ⇒ `multisetEqual(空, 1845行)` 恒 `false` ⇒ 永远走不到该 return。
3. **版本号 MAX 跨全部影子行统计**。`maxNumericVersion:981` 的 WHERE 只有 groupKey，既无 `is_current` 也无 pending 过滤 ⇒ 版本号只会单调爬升，永不回落。

兜底的 `QuoteImportService.clearPreviousPending()` 对本场景恒为 no-op —— 其自身注释写明「当前 UI 流程每次上传都会铸新 importRecordId」。

### 不做会怎样

- 每导一次永久堆约 5,500 行（`material_bom` 1845 + `material_bom_item` 1845 + `unit_price` 1847 + `element_bom_item` 4153…），**无任何回收路径**
- 版本号无意义爬升，「版本」不再反映任何真实变更，用户无法据此判断数据是否变过
- 影子行占着唯一约束的位置，后续导入同键数据可能撞 `uq`

### 目标

**① 内容与正式基线相同的重复导入 = 零写入 + 版本号不变。**
**② 内容与正式基线不同、但彼此相同的连续重复导入 = 复用同一版本号（行仍各存一份，见 §② 已否决项）。**

## ② 范围

### 做什么

| 编号 | 交付项 |
|---|---|
| S-1 | `VersionedV6Writer` 的 4 个 pending 分支入口（`:158` / `:325` / `:617` / `:758`）加前置判断：**该组从未有过任何行**时，不写影子行，直接走正式写入（`is_current=true` + `pending_quotation_id=NULL`） |
| S-2 | 「从未有过任何行」的判据用**显式 exists 查询**，批量路径按常量前缀一次查完（禁 N+1） |
| S-3 | 存量清理：`material_customer_map` 中归属报价单已不存在的孤儿 pending 行（清理前先量化影响面并经用户确认，§3.2 红线） |
| S-4 | **版本号内容寻址**：pending 写入时，若新内容与该组**最新一版**（不论正式还是 pending）逐字相同，**复用其版本号**，不再 `MAX+1` |
| S-5 | **5 张表唯一键加 pending 维度**：`uq_material_bom_v6` / `uq_material_bom_item` / `uq_unit_price` / `uq_element_bom_v6` / `uq_element_bom_item` 各加 `COALESCE(pending_quotation_id, '00000000-0000-0000-0000-000000000000'::uuid)`，使不同单可共用同一版本号 |
| S-6 | **核价转正去重**：`QuoteBackfillService.executeFlip` 转正前判定——若正式货架已存在同版本号且内容相同的行，则**删除本单 pending 行而非转正**（否则两单先后转正必撞 uq） |

### 明确不做什么

| 不做 | 去向 / 理由 |
|---|---|
| ~~改 5 张表的唯一键~~ | ⬆️ **2026-08-30 已改为本期范围（S-5）** —— 用户确认「改完 Excel 反复导同一份」是高频场景，仅做首次落地盖不住该场景 |
| 让内容相同的**不同单**共享同一份行（真正的零堆行） | **已否决**：会破坏单间隔离。反例已实证于设计推演 —— Q3 核价通过若走 REBUILD 会新建版本并**下线**共享的那一版，指着它的 Q4/Q5 当场读不到数据。**每单各存一份是隔离的必要成本，本期只消除版本号爬升，不消除行** |
| 跟该组**所有历史版本**比对内容（而非只比最新一版） | **已否决**：全量比对需读入该组所有版本的所有行（该类表历史堆积过 5 万行），性能不可控。已知代价见 §③ AC-19 备注 |
| 加「临时正式行 / 已审核正式行」标记列 | **已否决**：两个可见性闸门查的都是占号表，加列是多余成本（见 §4 证据） |
| 改 `material_customer_map` / `material_master` 的 pending 语义 | **刻意保留**：它们是 B7 闸门的把关处，改了会让未核价料号提前可见 |
| 让已爬升的版本号回落 / 重排（2029 退回 2000） | **不做**：版本号单调性是历史事实，回落会破坏既有引用 |
| 改 PRICING（核价导入）侧 | **不涉及**：`pendingQuotationId=null`，根本不进 pending 分支 |
| 改读侧 `QuotePendingRewriter` | **不需要**：正式行天然满足其第二个分支 |
| pending 行的定期自动回收机制 | **进 `BACKLOG.md`**：本次只做一次性孤儿清理，不建常驻任务 |
| 删单时回收首次落地的正式行 | **已裁决不做**：基础资料落地即公司资产，不随某张单生死 |

## ③ 验收标准（AC）

> 统一前置环境：dev 库 `cpq_db_0724`（默认 profile），后端 8081，前端 5174，客户 `CUST-0004`，导入文件 `1800笔产品订单.xlsx`（匹配 1845 行）。
> 「7 张版本化表」= `material_bom` / `material_bom_item` / `element_bom` / `element_bom_item` / `unit_price` / `capacity` / `plating_scheme`。

### 单点 AC

**AC-1 全新组首次导入落正式行**
- 前置：`material_bom` 中不存在 `system_type='QUOTE' AND customer_no='CUST-0004' AND material_no='202601010001'` 的任何行（含 `is_current=false`）
- 操作：以销售角色新建报价单 → 上传 `1800笔产品订单.xlsx` → 完成导入
- 断言：`SELECT count(*), bool_and(is_current), bool_and(pending_quotation_id IS NULL), min(bom_version) FROM material_bom WHERE system_type='QUOTE' AND customer_no='CUST-0004' AND material_no='202601010001'` → **恰好 `1 | t | t | 2000`**

**AC-2 占号表仍走 pending**
- 前置：AC-1 完成，报价单 id 记为 `:q1`
- 断言：`SELECT pending_quotation_id FROM material_customer_map WHERE system_type='QUOTE' AND customer_no='CUST-0004' AND material_no='202601010001'` → **= `:q1`（非 NULL）**

**AC-3 料号可见性一字不变**
- 前置：AC-1 的单仍为 `DRAFT`，从未提交
- 操作：新建第 2 张报价单（同客户 `CUST-0004`）→ 打开「从已有产品添加」→ 按料号 `202601010001` 搜索
- 断言：**列表返回 0 条**（B7 闸门仍然拦住）

### 序列 AC

**AC-4 重导零写入零升版（本任务核心）**
- 前置：AC-1 已完成；记录 7 张版本化表各自的 `count(*)` 为基线值
- 操作：新建第 3 张报价单 → 上传**同一个** `1800笔产品订单.xlsx` → 完成导入
- 断言：
  - 7 张表逐表 `count(*)` 与基线值**逐表相等（差值全部 = 0）**
  - `material_bom` 中该 `material_no` **仍恰好 1 行**，`bom_version` **仍 = `2000`**，行 `id` 与 AC-1 时**逐字相同**（证明未删旧行重写）

**AC-5 内容有差异时仍升版（反向期望，防止修成「永不升版」）**
- 前置：AC-4 已完成
- 操作：将 Excel 中料号 `202601010001` 的净重列改为原值 +1 → 新建第 4 张单 → 导入
- 断言：
  - `material_bom` 该组**新增 1 行**：`bom_version='2001'`、`is_current=false`、`pending_quotation_id` = 第 4 张单 id
  - 原 `2000` 行**仍 `is_current=true`**，值未被改动

**AC-6 首次落地的数据核价通过走 NOOP**
- 前置：AC-1 的单，**不在报价单里改任何值**
- 操作：提交 → 以财务角色核价通过
- 断言：
  - 核价通过响应体 `backfill.versionedGroups` 中**不包含该组**（NOOP 整组跳过，不进 plan）
  - `material_bom` 该组**仍恰好 1 行**、`bom_version='2000'`、行 `id` 与核价前**逐字相同**

**AC-7 首次落地 + 报价单改值 → 核价通过走 REBUILD**
- 前置：另起一张单走完 AC-1 流程
- 操作：在报价单某页签把该料号的一个数值列改为新值 V → 提交 → 核价通过
- 断言：
  - `material_bom` 该组新增 `bom_version='2001'` 且 `is_current=true`；原 `2000` 行 `is_current` 翻为 `false`
  - 新行对应列的值 **= V**

### 边界 AC

**AC-8 并发首次导入不产生双 current**
- 操作：两个会话**同时**对同一个全新料号发起导入
- 断言：该组 `is_current=true` 的行**恰好 1 行**（`pg_advisory_xact_lock` 生效，不出现同组两行 current）

**AC-9 非数字版本组不被误判为空组**
- 前置：构造一组只含 `bom_version='V_DEFAULT'` 的行，且 `is_current=false`
- 操作：导入该组数据
- 断言：**不走首次落地路径** → 落 pending 行（`is_current=false`、`pending_quotation_id` 非空）
- 理由：`maxNumericVersion` 用 `~ '^[0-9]+$'` 过滤非数字版本，MAX 为 null **不等于**组为空

**AC-10 整组已下线后再导入不走首次落地**
- 前置：某组曾有正式行，现已被 `executeOffline` 整组下线（`is_current` 全 `false`，但行仍在）
- 操作：导入该组数据
- 断言：落 pending 影子行，**不写正式行**（「首次」判据是「从未有过任何行」，不是「当前无 current 行」）

**AC-11 删单后正式行保留**
- 前置：AC-1 完成
- 操作：删除该报价单
- 断言：`material_bom` 该组 **1 行仍在**，`is_current=true`、`pending_quotation_id IS NULL`

**AC-12 存量孤儿清理**
- 前置：`material_customer_map` 中存在归属报价单已不存在的 pending 行（立项时实测 1,849 行）
- 操作：执行清理
- 断言：
  - `SELECT count(*) FROM material_customer_map m WHERE m.pending_quotation_id IS NOT NULL AND NOT EXISTS (SELECT 1 FROM quotation q WHERE q.id = m.pending_quotation_id)` → **0**
  - 归属单**仍存在**的 pending 行数**清理前后不变**（不许误删在途单的占号）

### 版本号内容寻址 AC（S-4 / S-5 / S-6）

**AC-14 连续导入内容相同的改过文件 → 复用版本号（本组核心）**
- 前置：AC-1 已完成（该组存在正式行 `bom_version='2000'`）；把 Excel 中料号 `202601010001` 的净重改为原值 +1，得文件 `F2`
- 操作：新建 Q3 导入 `F2` → 新建 Q4 导入 `F2` → 新建 Q5 导入 `F2`（**三次导入同一个 F2**）
- 断言：
  - 三张单落库行的 `bom_version` **全部 = `2001`**（而非 2001 / 2002 / 2003）
  - `SELECT count(*) FROM material_bom WHERE <该组> AND bom_version='2001'` → **恰好 3 行**，`pending_quotation_id` 分别为 Q3 / Q4 / Q5，`is_current` 全为 `false`
  - 正式行 `2000` 不受影响，仍 `is_current=true`

**AC-15 唯一键加 pending 维度后不撞键**
- 操作：同 AC-14
- 断言：
  - 三次导入均**无 uq 冲突异常**
  - `SELECT indexdef FROM pg_indexes WHERE indexname='uq_material_bom_v6'` → 定义中**含** `COALESCE(pending_quotation_id, '00000000-0000-0000-0000-000000000000'::uuid)`；其余 4 个唯一键同款核对

**AC-16 先后两单核价通过不撞键（序列）**
- 前置：AC-14 已完成
- 操作与断言：
  1. Q3 核价通过 → 断言 Q3 的 `2001` 行转正（`is_current=true`、`pending_quotation_id IS NULL`），原 `2000` 行翻 `false`；**Q4 / Q5 的 `2001` 行仍在且不受影响**
  2. Q4 接着核价通过 → 断言 **Q4 的 `2001` 草稿行被删除**（不转正），**无 uq 冲突异常**
  3. 终态：`SELECT count(*) FROM material_bom WHERE <该组> AND is_current=true` → **恰好 1 行**，`bom_version='2001'`

**AC-17 内容与最新一版不同时仍编新号（反向期望）**
- 前置：AC-14 已完成（该组最新一版为 `2001`）
- 操作：把净重再 +1 得 `F3` → 新建 Q6 导入
- 断言：新增 `bom_version='2002'` 的 pending 行；**不复用 `2001`**

**AC-18 A→B→A 序列不复用旧版本号（已知代价，本条用于钉死行为）**
- 操作：导入内容 A（得 `2001`）→ 导入内容 B（得 `2002`）→ **再次导入内容 A**
- 断言：第三次得 `bom_version='2003'`，**不复用 `2001`**
- 说明：这是「只与最新一版比对」的**已知代价**，非缺陷。本 AC 的作用是把该行为固化，防止后续会话误判为 bug 而擅自改成全量比对（性能理由见 §② 已否决项）

**AC-19 唯一键迁移前置校验（边界）**
- 操作：执行 S-5 迁移**前**，先跑冲突检测——按新唯一键定义对 5 张表各跑一次 `GROUP BY <新键列> HAVING count(*)>1`
- 断言：**返回 0 行**
- 🚨 若非 0 行：**迁移必须停下并报主线**，不许自动删除或合并冲突行（§3.2 数据销毁红线）

**AC-13 PRICING 侧无回归（无副作用）**
- 操作：执行一次核价导入（PRICING 侧任一 sheet）
- 断言：写入行为与改动前**逐字一致** —— 落库行 `pending_quotation_id` 全为 `NULL`，版本升级/复用判定结果与改动前 A/B 对比无差异

2. **料号可见性 B7 闸门** —— AC-3 覆盖

4. **报价单渲染读侧**（`QuotePendingRewriter`）—— 正式行走其第二分支，AC-1 后打开报价单数据应正常显示

### 关键证据：为什么占号表/主档必须除外

全工程把 `pending_quotation_id IS NULL` 当「已审核」判据的可见性闸门共 **2 处，查的都是 `material_customer_map`**：

```java
// ExistingProductService:49
"AND mcm.pending_quotation_id IS NULL "
// CustomerPartCandidateService:75,81 —— m 与子查询同为 material_customer_map
"AND m.pending_quotation_id IS NULL "
"WHERE p.material_no IN (SELECT material_no FROM material_customer_map ... AND pending_quotation_id IS NULL)"
```

**没有任何一处可见性判据查 7 张版本化表** ⇒ 只要占号表与主档照旧走 pending，料号可见性行为一字不变，无需加标记列。

## ⑤ 用户原话与素材归档

### 立项触发（2026-08-29）

> 「发现个问题,为什么我重复导入同一个excel,会每次都生成新的版本号,你查询相关的导入任务的任务记录,分析下问题原因」

用户同时提供了导入写入统计：

> 报价单：58d146f6-81c6-42dd-b59f-dbcf4a90cc47，DRAFT，来源文件 1800笔产品订单.xlsx（Excel 11536 行 → 匹配 1845 行），导入 2026-08-30 05:24:38。
> 阶段一：基础资料落库（05:24，V6 表）—— `element_bom_item` 4,153 / `unit_price` 1,847 / `element_bom` 1,845 / `material_bom` 1,845 / `material_bom_item` 1,845 / `import_record` 1，小计 11,536。

### 机制确认

> 「所以是因为核价没有通过,导致pending行没有作为版本吗?然后后续导入的数据继续升级新的版本,等待pending生效?」

主线答复要点（已实证）：机制方向正确，三处精确化 —— ① 不是「没作为版本」而是「没作为**基线**」；② pending **不会自动生效**，只有核价通过转正与删单回收两个出口；③ 每次导入是**新建一张 DRAFT 单**，不是同单排队。且实测全库 0 张 APPROVED，属「连核价都没走到」。
