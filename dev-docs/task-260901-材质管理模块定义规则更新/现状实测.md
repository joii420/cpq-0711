## E-1 材质规模与「名 / 号」重合度

```sql
SELECT count(*) 材质数, count(DISTINCT symbol) 材质名数, count(DISTINCT code) 编号数 FROM material_recipe;
```
输出：`258 | 258 | 258` —— 三者相等，**库里一条同名不同号都没有**。这不是数据天生干净，而是原导入器那条路走不通（见 `repair-260901` 根因）。

## E-2 元素组合的重合度（决定 D2「按材质名判 vs 按元素组合判」的关键数据）

```sql
WITH s AS (
  SELECT mr.id,
         string_agg(mre.element_code,'+' ORDER BY mre.element_code) AS elemset,
         string_agg(mre.element_code||'='||mre.default_pct::text,',' ORDER BY mre.element_code) AS ratio
  FROM material_recipe mr JOIN material_recipe_element mre ON mre.recipe_id=mr.id
  GROUP BY mr.id)
SELECT count(*) 有元素的材质, count(DISTINCT elemset) 不同元素组合数, count(DISTINCT ratio) 不同含量配比数 FROM s;
```
输出：`258 | 82 | 223`
⇒ **若按元素组合判身份，258 条材质会坍缩成 82 条。**用户 D2 裁决按材质名判，故本次零坍缩。

## E-3 `{Ag, Ni}` 组合下挂了 10 个材质编号（§1.2 问题 1 的样例）

```sql
SELECT mr.code, mr.symbol,
       string_agg(mre.element_code||' '||trim(trailing '.' from trim(trailing '0' from mre.default_pct::text))||'%',
                  ' / ' ORDER BY mre.sort_order) AS 含量
FROM material_recipe mr JOIN material_recipe_element mre ON mre.recipe_id=mr.id
WHERE mr.id IN (SELECT recipe_id FROM material_recipe_element GROUP BY recipe_id
                HAVING string_agg(element_code,'+' ORDER BY element_code)='Ag+Ni')
GROUP BY mr.code, mr.symbol ORDER BY mr.code;
```
10 行。注意 `00006 / AgNi10` 与 `00197 / AgNi10/Ag15CuP` 含量**逐字相同**（Ag 90 / Ni 10）—— 后者是复合材，业务上不是同一种东西。这是「纯按元素组合归并」会静默合错的实证。

## E-4 含量存储口径 = 100 制，列 `numeric(16,12)`

```sql
SELECT mre.element_code, mre.default_pct FROM material_recipe_element mre
JOIN material_recipe mr ON mr.id=mre.recipe_id WHERE mr.code='00006';
```
输出：`Ag | 90.000000000000` / `Ni | 10.000000000000`
⇒ 文件里的 0~1 制含量在 `MaterialRecipeImportService:284` 被 `×100` 归一后落库。
⇒ 0~1 制的 12 位小数 ×100 后是 10 位小数，`numeric(16,12)` **完全容得下，无损**（AC-8 据此断言）。

## E-5 材质编号自增的起点与脏值

```sql
SELECT code, symbol FROM material_recipe ORDER BY code DESC LIMIT 3;
SELECT min(code), max(code) FROM material_recipe;
```
`code` 是 5 位补零文本 `00001`~`00262`，另有一个脏值 `992`（材质 `AgNi11#-Ⅰ`）。
按 D8 裁决，自增只统计 `^[0-9]{5}$` 的 code ⇒ 下一个是 `00263`；`'00993'` 与 `'992'` 是不同字符串，永不撞键。

⚠️ `992` 被 `element_bom_item.material_part_no` 引用着，改号会断链 —— 故 §2.2 明确不清理。

## E-6 元素主表规模、编号段与脏行

```sql
SELECT count(*) FROM element;                                          -- 38
SELECT max(element_no::bigint) FROM element WHERE element_no ~ '^[0-9]+$';  -- 10095
SELECT element_no, element_code, element_name FROM element
WHERE element_no !~ '^[0-9]+$' OR element_code ~ '^[0-9]+$';
```
最后一条返回 10 行：9 行是**合法数字牌号**（`301/304/316/430/191/206/223/258/721`，`element_code` 是纯数字但 `element_no` 正常）+ 1 行脏数据 `element_no='白银'`（把符号当编号）。
⇒ AC-27 据此断言「纯数字符号不得被判非法」；AC-6 据此断言新元素编号 = `10096`。

## E-7 材质库里唯一匹配不上元素主表的符号（D7 / X-2 的依据）

```sql
SELECT DISTINCT mre.element_code FROM material_recipe_element mre
LEFT JOIN element e ON e.element_code = mre.element_code WHERE e.id IS NULL;
-- 10004
SELECT mr.code, mr.symbol FROM material_recipe mr JOIN material_recipe_element mre ON mre.recipe_id=mr.id
WHERE mre.element_code='10004';
-- 00262 | Sn02
```
⇒ 全库唯一一个匹配不上的符号是 `10004`，而 `10004` 恰恰是 **Sn 的元素编号** —— 业务把编号填进了符号列（`task-260812` 已记载这条脏数据）。
⇒ **D7 选了「自动建档」，这条数据会被自动造出一个假元素 `10004`。**这是 X-2（导入报告列出自动新建元素清单）的直接依据。

## E-8 组件 SQL 视图对 `material_recipe` 的真实用法（§4.2 最关键的一项）

```sql
-- 真正 FROM/JOIN material_recipe 的组件视图数

WHERE sql_template ~* '(from|join)[[:space:]]+material_recipe([[:space:]]|$)';        -- 107

-- 这些视图一共用到 material_recipe 的哪些列（去重全量扫描）
SELECT DISTINCT (regexp_matches(sql_template,'mr\.[a-z_]+','g'))[1] FROM component_sql_view
WHERE sql_template ~* '(from|join)[[:space:]]+material_recipe([[:space:]]|$)';        -- mr.code, mr.name
```

## E-9 下游绑定的存量情况

```sql
SELECT count(*) FILTER (WHERE material_recipe_id IS NOT NULL) 绑材质的物料,
       count(*) FILTER (WHERE config_fingerprint IS NOT NULL) 有指纹的物料,
       count(*) 物料总数 FROM material_master;                       -- 0 | 0 | 1890

SELECT count(DISTINCT material_part_no) FROM element_bom_item;       -- 17
SELECT count(*) FROM (SELECT DISTINCT material_part_no p FROM element_bom_item) t
JOIN material_recipe mr ON mr.code = t.p;                            -- 10
```
⇒ `material_master.material_recipe_id` / `config_fingerprint` **1890 行全 NULL**，选配自定义材质料号机制从未被真实使用过。
⇒ `element_bom_item` 24966 行 / 17 个材质料号，其中 10 个命中 `material_recipe.code`。D2 按材质名判 ⇒ 编号不变 ⇒ 这 10 个继续命中。
