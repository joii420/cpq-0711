## 1. 🚨 全局状态登记（`testing.md §4.3`，本任务最大的测试风险）

**材质库与元素主表是共享库里的公共基础数据，不是临时资源。** 本任务的 AC 夹具会往里写东西：

| 用例会改的全局状态 | 具体 | 还原方式（必须在 `finally`） |
|---|---|---|
| `material_recipe` 新增材质 | `AC测新材` / `AC测新元素` / `AC测12位` / `AC测重名`×2（`AC测和不对` 与 `AC测集合不一致` **本就不该入库**，但还原脚本仍要覆盖 —— 实现有 bug 时它们会残留） | 按 `symbol LIKE 'AC测%'` 物理删除，**级联 `material_recipe_composition` + `material_recipe_config` + `material_recipe_element` 三张子表** |
| `material_recipe_config` 新增配置 | `00006-02`（挂在真实材质 AgNi10 上）等 | **按 configNo 精确删除**，🚫 不许按 `recipe_id` 批删 —— 那会连 `00006-01` 一起删掉，那是存量迁移来的真实数据 |
| `element` 新增元素 | `Xx` / `element_no=10096` | 按 `element_code='Xx'` 物理删除 |
| `material_recipe.allow_custom_content` | AC-16/AC-19 会把 `00006` 置 true | 用例结束改回 `false` |
| **`material_recipe_composition`** | AC-31 会改 `00263` 的元素组成（Cu → Ni） | `00263` 属 `AC测%` 系列，随材质一起物理删除。🚨 **但 AC-10 用到的 `00006` 是真实材质，其元素组成绝对不许被改** —— 用例结束加断言：`00006` 的组成仍恰为 `Ag + Ni` |

三条纪律：

- 🚫 **不许用「跑完手工清一下」代替 `finally`** —— 用例中途失败就不会清，下一轮变成恒定失败，而且长得像业务回归（`testing.md §4.3` 第 3 层）
- 🚫 **共享库上不许跑任何形式的清库**，哪怕写在 `beforeAll`（`CLAUDE.md §3.2` 环境销毁红线）
- ⚠️ **后端 `mvnw test` 走 `test` profile → `10.177.152.12:5432/cpq_db`，与 dev 库 `cpq_db_0724` 不是同一个库，但同样是共享库**，本节同等适用

**还原自检**：每个测试类结束后跑一次
`SELECT count(*) FROM material_recipe WHERE symbol LIKE 'AC测%'` = 0 且
`SELECT count(*) FROM element WHERE element_code='Xx'` = 0，不为 0 直接让测试失败。

## 4. 必做的三个证伪实验（`testing.md §4.4`）

**首次 PASS 不能证明守卫有效。** 本任务有五处新守卫，各配一个「故意破坏 → 确认硬失败」：

| # | 守卫 | 证伪做法 | 期望 |
|---|---|---|---|
| **FT-1** | 配置编号不回收（M-2） | 把发号的 `max(seq)` 改成只统计 `status='ACTIVE'` | AC-15 的用例必须**变红**。不变红 = 该用例从没真正验过「不回收」 |
| **FT-2** | 元素集合一致校验（AC-10） | 把该校验分支直接 `return true` | AC-10 用例必须变红，且**报告里那条 skip 消失** |
| **FT-4** | **UI 与导入共用同一份「元素种类一致」判据（M-0a）** | 只改导入侧那一处判据（例如把集合比较改成「子集即可」），**不动 UI 侧** | 若 AC-34（UI 新建）**没有跟着变红**，说明两边各写了一套代码 —— 这正是 M-0a 要防的分叉，必须重构成共享方法后重跑 |
| **FT-3b** | 含量去尾随零**只作用于显示**（AC-30） | 把去零函数换成会真改值的实现（`Number(s).toString()`），再提交一条含 `12.345678901200` 的配置 | AC-30 的 **SQL 断言必须变红**（库里会变成 `12.345678901`，尾数被 JS `number` 吃掉）。不变红 = 那条 SQL 断言从没真正查过库 |
| **FT-3** | 全局状态还原（§1） | 把某个 `finally` 里的清理注释掉，连跑两轮 | 第二轮必须因「还原自检」失败，而**不是**因业务断言失败 —— 这条验的是清理机制本身接上了没有 |

⚠️ **测试子代理自己写的验证 SQL 脚本同样适用**：先确认脚本「能输出东西」。
命令写错导致全程空输出，看起来和「全部通过」一模一样（`RECORD.md` 有前科）。
