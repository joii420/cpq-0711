# AC-11 第 3 个对照行补证（主线亲验 · 开发库只读 SQL · 2026-09-18 23:4x）

**缺口**：亲验脚本原定对照行 `PERF600-B00001 / B00100 / B00999`，但 `QT-20260911-0842` 的 PERF600 行只有 `B00001`~`B00600`（600 行），`B00999` 不存在 → `lineStates` 静默只返回 2 行，`controlsUnchanged=true` 实际只比了 2 行。AC-11 要求「任取 3 个产品行」。

**补证方法**：AC-9 之前的状态已无法回取；改用系统自己封存的初版快照（`quotation_price_revision` 初版 `R26091801`，`sealed=true`，`last_updated_at=06:09:12 UTC`，早于 AC-8 / AC-9 / AC-10 三批）当「之前」基准，比较对照行现状与初版快照中该行的三列。

| 料号 | 角色 | 报价卡片值 = 初版 | 核价卡片值 = 初版 | 页签行数据（snapshot_rows）= 初版 |
|---|---|---|---|---|
| PERF600-B00001 | 对照 | t | t | t |
| PERF600-B00100 | 对照 | t | t | t |
| **PERF600-B00300** | **补的第 3 行** | **t** | **t** | **t** |
| PERF600-B00230 | 阳性对照（本批被通过） | **f** | t | **f** |

阳性对照为 `f` ⇒ 该比较对「被改过的行」敏感，不是空验证。
局限：初版快照不含 `row_data` 与 `subtotal`；这两项对 B00001 / B00100 由脚本的通过前后 md5 覆盖（`mainline-results.json` → `ac11.ctlBefore/ctlAfter`），对 B00300 只覆盖到快照三列。

另：7 个被通过行的「调整后小计」X 均为 `9118.2`（性能夹具数据同构），逐行 `subtotal = X` 成立，但**值互不相同**这一维度无法用本数据验证（行间串值不可辨）；行间区分由 S-BE 测试片的自造数据覆盖。

复跑 SQL：
```sql
with q as (select id from quotation where quotation_number='QT-20260911-0842'),
 ri as (select r.* from quotation_price_revision r join q on q.id=r.quotation_id where r.based_version_id is null),
 li as (select li.id, li.product_part_no_snapshot mat, li.quote_card_values, li.costing_card_values from quotation_line_item li join q on q.id=li.quotation_id
        where li.product_part_no_snapshot in ('PERF600-B00001','PERF600-B00100','PERF600-B00300','PERF600-B00230')),
 cd as (select li.id, coalesce(jsonb_object_agg(coalesce(c.component_id::text,'null'), c.snapshot_rows) filter (where c.line_item_id is not null),'{}'::jsonb) comp
        from li left join quotation_line_component_data c on c.line_item_id=li.id group by li.id)
select li.mat,
  (ri.quote_card_values -> li.id::text) is not distinct from coalesce(li.quote_card_values,'null'::jsonb) qcv_eq,
  (ri.costing_card_values -> li.id::text) is not distinct from coalesce(li.costing_card_values,'null'::jsonb) ccv_eq,
  (ri.snapshot_rows -> li.id::text) = cd.comp rows_eq
from li join cd on cd.id=li.id cross join ri order by 1;
```
