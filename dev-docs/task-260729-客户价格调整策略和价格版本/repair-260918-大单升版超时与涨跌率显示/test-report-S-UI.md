## 2. 失败项与判断

### ① AC-16 软断言「执行中 N 为蓝 #1677ff」失败 —— 判：**用例（量具）问题**

- 原文：`Error: 原型：「执行中 N」为蓝 #1677ff（原型还原项，非 AC 原文） Expected: "rgb(22, 119, 255)" Received: "rgba(0, 0, 0, 0.88)"`
- 同一次读取里，「成功」「失败」「冲突」的颜色也都读成了 `rgba(0, 0, 0, 0.88)`，但截图 `AC-16-执行中.png` 上它们分别是绿、红、橙，「执行中 1」**肉眼是蓝色**。
- ⇒ `readCounts` 取的是计数行各子节点**外层包装元素**的颜色，颜色实际设在更内层的元素上。量具读错了，不是实现错了。
- 这是原型还原项、不是 AC-16 原文；AC-16 的四个硬断言全部通过。**「执行中」的颜色自动化未验证，只有截图目视为蓝。**

### ② AC-4 审核抽屉 `changeRate=0.000000034611` —— **未验证**；判：用例 / 环境问题

- 原文：`Error: 审核列表应出现料号 S0011 … locator('tr.ant-table-row').filter({ hasText: 'S0011' }) … Timeout: 30000ms … element(s) not found`
- 这一次审核列表 30 秒内没出现目标行，日志里也没有这次的列表请求改写记录。同一流程的其余 5 次（AC-2②，以及审核抽屉另外 4 个取值）都在约 2 s 内正常打开。
- ⇒ 卡在进入抽屉之前的列表加载，与涨跌格式化无关。根因未定位（未重跑，时间盒已到）。
- **`+<0.0001%` 红**这个取值在版本明细、元素矩阵两处已通过，审核抽屉这一处未验证。
