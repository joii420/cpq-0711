## 2. 关键用例设计

### T-9（AC-9 · 序列 AC，本次最重要的一条）

**为什么最重要**：它验证的是「修复没有把 `is_current` 分支搞坏」。
用户在 A0 阶段提出过「只用 `pending_quotation_id = p_pq` 行不行」，
已实测否决 —— 而这条用例就是**防止实施时又滑回那个错误**的守门人。

**步骤**（全部在**测试库**）：
1. 造一份等价数据：客户 X，BOM/元素行 `is_current=false, pending_quotation_id=Q1`，元素已建档且有行情
2. 以 `p_pq=Q1` 调用三参函数 → **断言有价**（中间态）
3. 执行转正：`UPDATE … SET is_current=true, pending_quotation_id=NULL`（等同 `QuoteBackfillService:116`）
4. 以 `p_pq=Q1` 再次调用 → **断言仍有价**
5. 以 `p_pq=NULL` 调用（模拟核价侧）→ **断言也有价**（转正后应对所有上下文可见）

**断言中间态与最终态两者**，缺一不可。

### T-4 / T-5 / T-6（零回归三件套）

统一手法：**改动前先跑一遍存基线**，改动后再跑一遍**逐字比对**。

```
基线：git stash（或用干净 master 的 worktree）→ 跑脚本 → 结果存文件
验证：应用改动 → 跑同一脚本 → diff 必须为空
```

⚠️ **`git stash` 不要把迁移文件 stash 掉**（见 `cpq-worktree-flyway-migration-verify`）——
迁移一旦已在测试库应用，stash 掉文件会导致 Flyway `validate` 失败、应用起不来。
推荐改用**干净 master 的独立 worktree + 独立端口**做基线侧。

### T-12（AC-12 · 防 `AP-31`/`AP-38` 族）

未建档元素的 2440 行必须显示**空**，🚫 **不得出现「加载中…」**。
这是 `AP-31`（"加载中…"永久占位族）与 `AP-38`（0 行 driver 鬼魂行）的已知症状面，
本次虽不改 driver expand 链路，但取价结果从"全 null"变成"部分有值"，
属于该族的**触发条件变化**，必须显式验。
