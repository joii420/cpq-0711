## 1. `GET /api/cpq/price-adjust/reviews`（列表）

### 1.1 返回体新增字段

```jsonc
{
  "content": [
    {
      // …既有字段一律不变（reviewId / customerNo / materialNo / budgetStatus / budgetError / …）
      "quoteCostAdjusted": null,   // 🔒 budgetStatus != "READY" 时**必须为 null**，🚫 不许返 0
      "costingCost":       null,   // 同上
      "diffAdjusted":      null    // 同上
    }
  ],
  "page": 1, "size": 20, "total": 4527,
  "notComputedTotal": 4510,        // 🆕 当前筛选条件下 budgetStatus ∈ (QUEUED, COMPUTING) 的**总条数**（不是本页）
  "excludedByNotComputed": 0       // 🆕 仅当 breachedOnly=true 时有意义：因「未计算」而未纳入本次筛选的条数；其余情况恒 0
}
```

> 🔒 **为什么金额必须是 `null` 而不是 `0`**：前端 `fmt()`（`PriceAdjustReviewPage.tsx:26-28`）对 `null` 已渲染为 `—`，对 `0` 会渲染成 `0.00` —— 未计算的行显示 `0.00` 会被当成「算出来就是 0」。后端返 `null` 即天然满足 `AC-1`，**前端无需为此改动**。

### 1.2 `breachedOnly=true` 的语义收窄

- **改动前**：`breachedCount > 0`。未计算行 `breachedCount=0` ⇒ 被静默当作「未超阈值」排除。
- **改动后**：`breachedCount > 0 AND budget_status = 'READY'`，并通过 `excludedByNotComputed` 告知**有多少条因未计算而没参与**。
- 前端据此出提示（`fronttask.md` F-6），🚫 不许前端自己算这个数。

## 2. 🆕 `POST /api/cpq/price-adjust/reviews/{reviewId}/compute-now`（单条即时试算 · 同步）

服务 `AC-5` / `AC-6` / `AC-7` / `AC-20` / `AC-21`。

**语义**：**插队**立即试算该条并**写回**审核行，**同步返回最终结果**。与 §0 的 `recompute-budget`（异步提交）是两个端点，互不影响。

**请求**：无 body。

**响应 200**：
```jsonc
{
  "reviewId": "…",
  "budgetStatus": "READY",        // READY | FAILED
  "budgetError": null,            // FAILED 时为可读原因（同 PriceAdjustFailureTranslator.forBudget 口径）
  "columnCount": 3, "breachedCount": 1, "amberCount": 0, "missingCount": 0, "staleCount": 0,
  "rowRed": true,
  "quoteCostCurrent": "12345.670000", "quoteCostAdjusted": "12400.120000",
  "costingCost": "11000.000000", "diffCurrent": "…", "diffAdjusted": "…"
}
```
> 🔒 字段形状与列表行 (`ReviewListItemDTO`) 的对应字段**一致**，前端拿到后可直接就地替换该行，无需重新拉整页。

**错误**：

| 码 | 何时 | body |
|---|---|---|
| `404` | `reviewId` 不存在 | 标准错误体 |
| `409` | 该审核行所属版本**已被作废**（非 `PENDING`）⇒ **不写库** | `{"code":"VERSION_SUPERSEDED","message":"该价格版本已被新版本取代，无需再计算"}`（`AC-20`）|
| `200` + `budgetStatus=FAILED` | 试算本身失败（依据单缺失 / 超时等） | 见上，**不是 5xx**（`AC-7`）|

**并发**（`AC-21`）：同一 `reviewId` 并发调用**不得**产生第二条审核行、不得撞 `uq_mpr_version_material`；第二次调用可等待或返回首次结果，两种都可以，但**最终落库值必须与单次调用逐位相同**。

## 3. 🆕 `POST /api/cpq/price-adjust/reviews/compute-batch`（批量试算 · 通过前守门用）

服务 `AC-8` / `AC-11`。

**请求**：`{"reviewIds": ["…", "…"]}`

**语义**：对其中 `budgetStatus ∈ (QUEUED, FAILED)` 的逐条试算（复用 §2 的同一实现），已是 `READY` 的原样跳过。
🚫 **只算不升版** —— 本端点**不得**产生任何 `material_price_update_job`（`AC-9` 验这条）。

**响应 200**：
```jsonc
{
  "total": 5, "computed": 4, "skipped": 1, "failed": 1,
  "items": [
    { "reviewId": "…", "materialNo": "PERF600-B00432", "budgetStatus": "READY",  "budgetError": null },
    { "reviewId": "…", "materialNo": "PERF600-B00433", "budgetStatus": "FAILED", "budgetError": "预算试算超时（超过 60 秒）" }
  ]
}
```

### `POST /api/cpq/price-adjust/reviews/impact` 返回体新增

```jsonc
{
  // …既有字段不变
  "notComputedCount": 0,          // 🆕 入参里仍未算完（QUEUED/COMPUTING）的条数
  "computeFailedCount": 1,        // 🆕 入参里 budgetStatus=FAILED 的条数
  "computeFailedMaterialNos": ["PERF600-B00433"],  // 🆕 上一条对应的料号清单（供确认框逐条列出，AC-11）
  "materials": [                                   // 🆕 逐料号金额（AC-8 / AC-10）—— 只含 budgetStatus=READY 的料号
    { "materialNo": "S3120011203",
      "quoteCostCurrent":  "0.324083231000",       // 同列表行同名字段口径（col-default 比对列）
      "quoteCostAdjusted": "1.717061326000",
      "diffAdjusted":      "1.717061326000",
      "status": "NORMAL" }                         // NORMAL | MISSING | STALE —— MISSING 时三个金额可为 null
  ]
}
```

> 🔒 **为什么金额由 `impact` 给而不是前端从列表行拼**：`AC-10` 要求「确认框里的调整后 = 升版后的实际值」逐位一致。由后端在同一次请求里给出，才能保证确认框看到的与即将提交的是同一份数据；前端拼的话，列表行可能是几秒前的旧值（尤其在后台还在算的时候）。
> 🔒 **既有字段一个不删**：`materialCount / quotationCount / versionPaths / byStatus / excludedQuotationCount / excludedByStatus / breachedMaterials` 原样保留，现网确认框的全部区块依赖它们。

## 4. `POST /api/cpq/price-adjust/reviews/approve` 新增守门

服务 `AC-8` / `AC-11`。

入参 `reviewIds` 中若存在 `budget_status ∈ (QUEUED, COMPUTING)` 的行 ⇒ **拒绝整批**：

```jsonc
// 409
{ "code": "BUDGET_NOT_READY",
  "message": "有 3 个料号的金额尚未计算完成，请先完成计算再提交",
  "notComputedMaterialNos": ["…","…","…"] }
```

🔒 **这是服务端保证，不许只靠前端拦**（`backtask.md` B-9）。`budget_status=FAILED` 的行**不在**本守门范围 —— 它们由前端在确认框里显式排除（`AC-11`），服务端按既有逻辑处理。
