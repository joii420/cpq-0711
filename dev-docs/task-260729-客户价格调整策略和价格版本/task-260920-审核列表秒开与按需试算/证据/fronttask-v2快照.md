## 任务分解

| 编号 | 服务的 AC | 任务内容 |
|---|---|---|
| **F-1** | AC-1, AC-27 | **「未计算」与「计算中」拆开 + 未计算数提示**：<br>· `QUEUED` → **静态**灰标「未计算」+「计算」链接（触发 F-2），🚫 转圈（它可能要等十几分钟才轮到）；<br>· `COMPUTING` → Spin +「计算中」；<br>· 🔒 **只对 `reviewStatus==='PENDING'` 的行这样渲染**；已通过 / 已驳回 / 已作废的行不显示「未计算 / 计算」（`AC-27`）；<br>· 查询栏右侧提示「共 N 条，其中 M 条未计算，正在后台计算…」，N=`total`、M=`notComputedTotal`，M=0 时不显示。<br>形态以 `原型图/审核列表-未计算态.html` 状态 1 为准。 |
| **F-2** | AC-5, AC-7, AC-20, AC-21 | **点击即算**（两个入口共用一个函数：F-1 的「计算」链接；点料号打开抽屉）：<br>① 调 `POST …/{id}/compute-now` → 202 → 每 1 秒轮询 `GET …/{id}/row`，直到 `READY`/`FAILED` 或 `reviewStatus≠PENDING`，90 秒未结束则停轮询并提示「计算较慢，可稍后刷新」；<br>② 期间该行显示「计算中」并禁用重复点击；结束后**就地替换该行**（`row` 返回的字段与列表行一致），🚫 整页 `load(page)`；<br>③ **按状态区分**：`QUEUED` → 自动算；`FAILED` → **不自动算**，抽屉内显示原因 +「重新计算」按钮（点了才调 compute-now）；`COMPUTING` → 只轮询等待；`READY` → 直接显示；<br>④ **抽屉先算、后取详情**：未计算的行打开抽屉时，整个抽屉显示「正在计算…」，等 compute-now 结束**再**调 `GET …/{id}` 取详情，🚫 两者并发（并发会对同一行同时试算两次，见评审【2】）；<br>⑤ 失败原因取 `GET …/{id}` 新增的 `budgetError`；<br>⑥ 轮询到 `reviewStatus==='VOIDED'` ⇒ 提示「该价格版本已被新版本取代」并刷新列表（`AC-20`）；compute-now 返回 409 `REVIEW_NOT_PENDING` 同样处理。<br>形态以 `原型图/审核抽屉-触发计算.html` 为准。 |
| **F-3** | AC-1, AC-27 | 🚨 **轮询策略**（不改即性能回归：开局 4500 行全是 `QUEUED`、持续十几分钟，现逻辑会每 5 秒全量拉列表，而列表每行还要查客户名 / 依据单）：<br>① 本页存在 `COMPUTING` 且 `reviewStatus==='PENDING'` 的行 ⇒ 5 秒；<br>② 只存在 `QUEUED`（待处理）行 ⇒ **≥30 秒**低频刷新（只为更新 `notComputedTotal`）；<br>③ 页面不可见（`document.hidden`）时暂停；<br>④ 🔒 筛选为「已通过 / 已驳回 / 已作废」时**不轮询**（`AC-27`）。<br>回报须给出改动前 / 后「15 分钟内发起的列表请求次数」实测值。 |
| **F-4** | AC-8, AC-9, AC-11, AC-25 | **通过与驳回的守门拆开**（`D-6`、`J-2`）：<br>· 把 `allPendingReady` 拆成两个函数；<br>· **驳回**：维持现状（全部待处理且全部 `READY`），不满足时置灰并提示「含 n 项尚未计算金额，需先计算才能驳回」；<br>· **通过并升版**：含非待处理行 → 置灰（原样）；含 `COMPUTING` 行 → 置灰，提示「有 n 项正在计算，请稍候」；含 `QUEUED`/`FAILED` → **可点**，旁边提示「其中 n 项未计算，点通过会先计算」；<br>· 点击后：对 `QUEUED`/`FAILED` 行**逐条依次**调 compute-now 并轮询（🚫 并发一次全发；用 `runBatch` 就显式传 `concurrent: false`，或另写串行循环），显示「正在计算 n/N」与逐行状态（等待 / 计算中 / 已完成 / 失败）；全部结束后，**只用 READY 行**调 `impact` 并打开 `ApproveImpactModal`，失败行清单一并交给它；<br>· ⚠️ 勾选受 `BL-0311` 限制（只拿得到当前页的行），本次不修，验收限定同页勾选。<br>形态以 `原型图/批量通过-试算与确认.html` 第 1 步与 `原型图/审核列表-未计算态.html` 状态 2 为准。 |
| **F-5** | AC-8, AC-10, AC-11 | **影响面确认框：只增不删**。`ApproveImpactModal.tsx` 现有区块（料号数 / 单数、版本推进路径、按状态分组、不会被更新的单、跌破预警线）**原样保留、顺序不变**，新增两块：<br>① **各料号金额表**（放在「按状态分组」之后）：读 `impact` 的 `materials[]`，列 料号 / 报价侧·现 / 报价侧·调整后 / 差异；**按缺失侧显示** —— 缺核价侧时报价侧两个值照常显示、差异列显示「—（缺数据：核价侧）」；<br>② **「n 个料号计算失败，不参与本次升版」**（放在**最上方**）：用 F-4 传进来的失败行清单，逐条列料号与原因；<br>· 标题与「料号数」只统计 READY 行；点确认时提交的 `reviewIds` **只含 READY 行**；<br>· 🔒 金额即升版后的实际值（`AC-10` 逐位比对），🚫 二次运算或改位数（`fmt` 已统一为 `DISPLAY_SCALE`）。 |
