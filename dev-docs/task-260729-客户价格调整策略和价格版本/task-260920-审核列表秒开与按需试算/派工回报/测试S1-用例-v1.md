## 3. `T920Hooks.java` 是什么、需要实现方提供什么

**作用**：AC-2 要在**同一个事务、同一份快照**上比较两种判定：
- **旧判定**（`oldDecision`）：按 AC-2 原文的分支树，**原样调用**四个现有函数：`findBasisLine`（private，反射调用）、`MaterialPriceReview.hasEverRejected`、`MaterialPriceVersionRef.findRef`、`hasRelevantPriceChange`（包内可见，反射调用）。组合逻辑取自 AC 原文，没有另写判定。`BasisLine` 的行 id 字段、`MaterialPriceVersionRef` 的版本字段，我**没读实现**，是按候选名（`lineItemId/lineId/basisLineItemId/liId`、`versionId`）反射取的。取不到时会报出实际字段清单，执行时自己暴露问题。
- **新批量判定**（`newDecision`）：**依赖实现方提供钩子**。现在的生成入口会把「判定」和「写审核行/推进指针」在它自己的事务里一起提交，测试没法在回滚事务里只拿判定结果。

**需要后端（B-1）提供**：
1. 在 `PriceAdjustBudgetService` 上提供一个**只读**的批量判定方法，默认名 `decideEnqueueBatch`（名字可以不同，告诉我即可，用 `-Dt260920.batchDecision.method=` 指定）；
2. 参数 `(UUID versionId, String customerNo)`，或 `(UUID versionId, String customerNo, Collection<String> materials)`，其中 `materials=null` 表示该客户的全部范围；
3. 返回对象要有**进池料号集合**和**推进料号集合**两个访问器，名字从 `pooledMaterials/pooled/toPool/pooledMaterialNos` 和 `advancedMaterials/advanced/toAdvance/advancedMaterialNos` 中选一个（或告诉我实际名字）；
4. 🔒 **必须加入调用方的事务**（不能 REQUIRES_NEW），不能写库；生成入口实际用的必须是**同一个**判定函数，否则 AC-2 比的是一份副本；
5. 如果 `findBasisLine` 或 `hasRelevantPriceChange` 自带 REQUIRES_NEW，就看不到回滚事务里新建的正泰目标版本。执行时会表现为全量对比不一致，需要后端说明。
