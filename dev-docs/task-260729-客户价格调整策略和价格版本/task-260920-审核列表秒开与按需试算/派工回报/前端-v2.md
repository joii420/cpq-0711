## 2. 序号判定放在哪一层
放在**页面唯一的列表加载函数 `load` 里**（经 `loadLatest`），不在服务层、不在 axios 拦截器。理由：审核列表所有刷新都经过 `load`，一处判定覆盖全部入口；放在服务层会误伤其它页面对同一个 `getReviews` 的调用。

## 3. 覆盖的加载路径（全部经 `load` → `loadLatest`，逐条核对过调用点）
| # | 路径 | 调用点 |
|---|---|---|
| 1 | 首屏（含 React StrictMode 成对发出的那一次） | `useEffect(() => { load(1) }, [status, breachedOnly, load])` |
| 2 | 改搜索词（边输边查：`keyword` 变 → `load` 引用变 → 上面的 effect 重跑） | 同上 |
| 3 | 点「查询」/ 回车 | `handleQuery = () => load(1)` |
| 4 | 翻页 | `pagination.onChange: (p) => load(p)` |
| 5 | 勾 / 取消「只看标红」、切审核状态下拉 | effect 依赖 `breachedOnly` / `status` |
| 6 | 静默轮询（F-3） | `setTimeout(() => load(page, { silent: true }), delay)` |
| 7 | 计算失败 / 已被取代后的回退刷新 | `computeRow` 里 `load(page, { silent: true })`（两处） |

另外：**加载转圈只由最新一次请求关掉**。旧写法里，一个过期的非静默请求晚到时会先把 loading 关掉，而新请求还在途。

## 7. 规避掉的坑
1. **还原实验不碰被页面引用的文件**：在副本上做，避免 5230（S-2 空闲中）和 5295（主线亲验）的页面热更新两次。
2. **loading 标志也要受序号约束**：只拦数据写入的话，过期的非静默请求晚到时会先把转圈关掉，而更新的请求还在途，用户会看到一张不转圈的旧表。
3. **判定没有放进服务层或 axios 拦截器**：那样会误伤其它调用 `getReviews` 的地方。
4. **没有给边输边查加防抖或改成点查询才查**：派工明确不改这一交互；乱序问题靠序号解决，不靠减少请求。
5. **一次改完再保存**：页面与工具模块各只写了一次，没有反复小改。
