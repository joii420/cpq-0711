## 🔴 采集时踩的坑（两条，都属"守卫本身是空的"）

**① 我的第一版采集脚本产出了空基线，而我的非空守卫打了 ✅**

根因：该端点响应**不带 `data` 信封**，我写成 `json.loads(r.stdout).get('data', {})` → 回退成空字典 ⇒ 所有坐标都被跳过。
而我的守卫写的是「收集字段数为 0 的坐标，列表为空即通过」—— **全都没采到时，那个列表自然为空，于是恒真通过**。

⇒ 修法：守卫必须**先断言集合本身非空**，再断言集合内元素合格：
```python
assert len(out) > 0,  "采集坐标数=0，基线为空 —— 拒绝落盘"
assert not empty,     "以下坐标字段数为 0，基线会退化成空验证"
```
🔑 **教训：守卫在被守卫对象的下游时，它跟着一起失效。** 顺序必须是「先证明有东西，再证明东西是对的」。

**② 同型的另一个实例（由 `报价导入建单切ds新表` 会话贡献）**
> 该会话采 `AC-15` 基线时，按 `parts` 列表返回的**首个**轴值 `S0003` 采样，结果 `rows`/`versions` 都是 0 行。
> 拿它当基线，这两个端点的 A/B 就是「空 vs 空」，**恒相等、恒通过**。已补采两个真实有数据的料号。
> 📌 判据：**基线本身必须非空，否则对照通不过也发现不了。**
