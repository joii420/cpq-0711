## 3. 🚨 本任务专属的假绿陷阱

| # | 陷阱 | 规避动作 |
|---|---|---|
| ① | 🚨 **"快了"和"对了"必须同时验** | 只验快 → 可能是**少查了行**（漏了本该返回的）；只验对 → 可能是**根本没走合桶**（退回逐行查也对）。⇒ **AC-1（次数）与 AC-3（各行取到自己的）必须成对出现**，缺一不成立 |
| ② | **性能基线采晚了** | AC-12 的改动前基线**必须在动第一行代码前采**并落盘。改完再回头造基线，跑的已经是新代码 |
| ③ | 🚨 **还原实验：回滚代码 ≠ 回滚行为**（`testing.md §5.5` 形态④，上个任务刚晋升的规则） | 本任务同样经过"落库的产物"（`sql_template` + `semantic_node_column`）。只回滚 Java 而产物还是新的，实验**必然不变红**并被误读成白测。⇒ 用**两版产物对跑** / **正向控制**（改客编看渲染是否跟着变）/ **判别性反例**（填表中不存在的客编：1 行且列空=谓词在 ON；0 行=误入 WHERE；N 行=谓词没生效） |
| ④ | **AC-5 是最易静默失败的一条** | 集合谓词下"挑不到行"会悄悄变成 0 行。前置数据要**实查确认**该明细行 `customer_part_no` 确实为空（全库 2026-09-11 实测 128/3970），且断言必须包含"物料侧列有值"这一半 |
| ⑤ | **AC-9 的"零 Java 改动"要用 `git diff` 证明** | 🚫 不许只凭"我没改"。跑 `git diff --name-only -- '*.java'` 附原始输出；同时确认新列的谓词真的出现在编译产物里（否则"没改代码"可能只是"没生效"） |
| ⑥ | **测到旧代码 / 旧产物** | 改后端后确认热重载完成（判健康看业务端点返 **401**，🚫 不用 `/q/health`，恒 404）；改语义图后确认**视图已重编译**（比 `sql_template` 的 md5），否则跑的是旧产物 |
| ⑦ | **并发 maven 互删 class**（`testing.md §4.2.5`） | 跑测试前确认 `target/` 无其他 maven 在写（`quarkus:dev` 热重载同样改写 `target/classes`）；按 **mtime 确权**，🚫 不用 `-Dsurefire.reportsDirectory`（3.5.4 静默失效） |
| ⑧ | **`mvnw test` 不可能全绿** | `mat_*` 表本库从未创建，235 处红是既有状态。只对本次相关测试类做绿判 |
| ⑨ | **必现 ≠ 缺陷** | 确定性复现只证明不是 flaky。报缺陷前先补一个"用户实际看到什么"的维度（`testing.md §4.1.5`） |
