## 2. 用例

### T-00　`MaterializeRegistry` 冒烟（B-4）
`begin` 后 `isInProgress==true`；`end` 后 `false`；**`materialize()` 抛异常时 `finally` 仍清干净**（构造一个必抛的下游，断言异常后 `isInProgress==false`）。
落地后把**包名/类名/方法签名**报主线，由主线转告并发会话。

### T-01　导入建单自动跳转后页签有数据（AC-1）
1845 料号 +「正泰模板1」走完整导入建单 → **等抽屉自动跳转** → 立即打开 Step2。
**断言**：4 个 driver 页签（产品/物料/材料成本/其他费用）各有非空数据行；产品小计 ≠ 0；总价 ≠ 0；**全程无需手动刷新**。
**证据**：页面截图 + 至少一个页签的具体数值。

### T-02　数据层（AC-2）
```sql
-- 所有页签 baseRows 合计 > 0 的行数，断言 = 1845
WITH t AS (SELECT li.id, COALESCE((SELECT sum(jsonb_array_length(COALESCE(tab->'baseRows','[]'::jsonb)))
             FROM jsonb_array_elements(li.quote_card_values->'tabs') tab),0) tb
           FROM quotation_line_item li WHERE li.quotation_id=:qid)
SELECT count(*) FILTER (WHERE tb>0) FROM t;
-- subtotal 非 0 行数，断言 = 1845；total_amount ≠ 0
```

### T-03　骨架值可自愈（AC-3）
构造「`quote_card_values` 为骨架值（`baseRows` 全 0）+ `snapshot_rows` 非空」的行 → 调 `ensure-card-values`。
**断言**：该行**被重算**且结果 `baseRows > 0`（不再被 `IS NULL` 永久跳过）。
> 修复前此场景恒不重算 —— 本条在基线上必然失败，有区分度。

### T-04　还原实验（AC-4）🚨 **不可省、不可委托、必须并发**
在 ①步进行中（`materialize` 启动后 5~20 秒窗口内）**并发触发 ≥5 次** `ensure-card-values`：
- **改动前**：出现骨架值锁死行（所有页签 `baseRows` 合计 = 0 而 `snapshot_rows` 非空）
- **改动后**：**零**骨架值锁死行
**证据**：两次的 SQL 原始输出 + 改动前后的 WARN 日志对照。
> 🚫 **不许用单发端到端代替**。`0205` 正常/`0206` 中招证明单发是随机的。

### T-05　算早了要拦住并留痕（AC-5，阳性）
人为使 `snapshot_rows` 齐全但渲染返回空 → 触发 ③步。
**断言**：日志出现 **WARN** 级「算早了，跳过落库」；`quote_card_values` **保持 NULL**（不写骨架值）。
> 零改动基线上此场景静默落库骨架值、无 WARN ⇒ **基线必然失败**，符合阳性判据。

### T-06　合法空结果照常落库（AC-6）🚨 **与 T-05 成对，缺一不可**
组件视图合法返 0 行（`snapshot_rows = '[]'`、业务上确实没数据）。
**断言**：`quote_card_values` **正常落库**、内容为空页签；**不触发** B-1 守卫；**无** WARN。
> 这条守着判据的**条件②**。若实现只判「算出来是空的」，本条会红。

### T-07　自愈判据收益保留（AC-7）
对一张卡片值已就绪的 1845 行单**连续两次**调 `ensure-card-values`。
**断言**：第二次识别出的「需要补算」行数 **== 0**，耗时显著低于首次。
> 防止修成「每次全量重算」（1845 行实测 27s，那是不可接受的回归）。

### T-08　其它路径逐位不变（AC-8）
对同一张已物化的单依次跑 `saveDraft` / 加产品 / 从基础刷新 / 核价侧渲染，
比对 `quote_card_values`、`costing_card_values`、`subtotal`、`total_amount` 的 md5 与改动前相同。
> ⚠️ 用 `git stash` 背靠背对比，不要靠历史快照。

### T-09　契约不变（AC-9）
`POST /quotations/{id}/ensure-card-values` 的路径/方法/请求体/响应体字段集/状态码与改动前**逐项一致**。
⚠️ 并发会话正在相关端点加字段，**比对时以本线分支为准**，不要把对方的改动算成本线的契约变更。

### T-10 / T-11 / T-12　边界不误判（AC-10）
- T-10：明细行 0 条的单 → 不触发守卫、不报 WARN
- T-11：模板 driver 组件 0 个 → 同上
- T-12：🚨 **`SUBTOTAL` 页签**（如「正泰产品小计1」，`baseRows` 恒为 0）——健康单里它单独为 0 属正常，**不得**因此判「算早了」。
  判据必须是「**所有**页签 `baseRows` 合计为 0」，写成「**任一**页签为 0」本条必红。

### T-13　序列（AC-11）
导入建单 → 自动跳转 → **立即**打开 Step2（物化可能仍在跑）→ 等物化完成 → 切走再切回 → 刷新页面。
**断言**：最终 4 个数据页签均有内容、金额非 0；**中间态不产生骨架值**（物化完成后无需人工干预）。
