【⚠️ 本次实验顺带抓到的新缺陷 → 已立 B-30，未修完不合并】
  同样只锁 300 行：③ 只连带 300 行，④ 却连带 600 行（失败 2 批）。
  根因：两处「挑待补算行」的 SELECT id 都【没有 ORDER BY】(CardSnapshotService :1064 / :1313)，
        行序由 PG 物理堆顺序决定。③ 跑时物理序≈插入序≈sort_order，被锁 300 行整齐落一批；
        但 ③ 刚 UPDATE 过这些行 → 堆位置变动 → ④ 再查时物理序已变 → 被锁行散落到两批。
  性质：非正确性 bug（IS NULL 谓词保证重跑必补齐，本轮已实测自愈到 1845/1845），
        但批边界不确定 → 连带损失不可预测、故障难复现、测试无法稳定复现批边界。
