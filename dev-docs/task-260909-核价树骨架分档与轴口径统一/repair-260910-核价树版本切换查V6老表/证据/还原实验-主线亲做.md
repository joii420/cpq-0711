# 两个还原实验（`test.md §4` 要求）· 主线亲做

**目的**：证明 `AC-1`/`AC-3`/`AC-4` 不是空验证 —— 把修复改回去，它们**必须变红**。
**纪律**：两个实验均**先备份、后注入、再逐字节还原**，还原以 md5 / `git status` 校验，不靠"看起来一样"。

---

## 实验① · B-1 树分支改回查 V6 老表 → `AC-3` / `AC-4` 必须变红

**注入**：`CostingVersionService` 树分支查询改回
```java
"SELECT bom_version, is_current FROM material_bom_item " +
"WHERE system_type='PRICING' AND customer_no='_GLOBAL_' AND material_no=:p AND bom_version IS NOT NULL"
```

**变红证据（两条独立）**：

1. **源码级守卫测试变红**
   ```
   Tests run: 8, Failures: 1, Errors: 0  <<< FAILURE!
   ```
   （`CostingVersionTreeSourceGuardTest` 有「可执行代码中不得出现 `material_bom_item`」的断言）

2. **数据侧必然退化**
   | 料号 | 还原态（老表命中） | 新态（新视图） |
   |---|---|---|
   | 300001 | **0** | 3 |
   | 300012 | **0** | 1 |
   | 300013 | **0** | 1 |
   | 300015 | **0** | 1 |

   ⇒ `AC-3` 的 `["3","2","1"]` 退化为「无可选版本」、`AC-4` 的 `["1"]` 同样归零 —— **正是用户报障时的原始症状**。

**还原校验**：
```
还原后 md5 = d7398154b34d21d23f9f67593fb55041
PRISTINE   = d7398154b34d21d23f9f67593fb55041      ← 逐字节相同
git status -- CostingVersionService.java → 空      ← 与已提交版本一致
守卫测试回绿 Tests run: 8, Failures: 0
```

## 实验② · 骨架 SQL 的 `bom_version` 改回 `ch.version_no` → `AC-1` 必须变红

**注入**：递归体那段子查询改回 `ch.version_no::text AS bom_version`（宏由 3 处退回 2 处）。

**变红证据**：同一棵树、同一份数据，版本列整体回到旧语义

| 节点 | 还原态（旧语义） | 新态（AC-1 期望） |
|---|---|---|
| 300001 | 3 | **3** |
| 300012 | **3** ❌ | **1** |
| 300013 | **3** ❌ | **1** |
| 300014 | **3** ❌ | **—**（叶子） |
| 300015 | 1 | **1** |
| 991 | **1** ❌ | **—**（叶子） |
| 992 | **1** ❌ | **—**（叶子） |

⇒ 7 行里 **5 行不符**，`AC-1`（每行显示自己那张清单的版本）与 `AC-2`（叶子无版本）**双双变红**。

**还原校验**：
```
md5    = 0b69d87d5c0a2755ac0db2c64a5bad8c    ← 与工作态记录逐字一致
长度    = 2521
含新写法 = t
```

### ⚠️ 还原过程中发现的一个坑（值得记）

REAPPLY 后 md5 一度是 `d849666d…`／长度 **2522**，比工作态多 1 个字符（末字符 ascii 10 = 换行）。
根因：**`psql -t` 读回文本会附加尾部空白**，我的 REVERT/REAPPLY 脚本是基于"从库读回的文本"重建的，
⇒ **每次「读回 → 写入」往返都会漂移 1 个字符**，且功能上完全无感。

用 `left(sql_template, 2521)` 精确削回后 md5 才回到 `0b69d87d…`。

📌 **可复用判据**：改配置类数据，要么**在库内用 `replace()` 直接改**（不经文本往返），要么**每次核对 md5**。
只看「功能正常」会让还原点文档里的 md5 逐次失真，下一个人拿它对不上。

## 结论

两个实验**全部变红**，`AC-1` / `AC-2` / `AC-3` / `AC-4` 均**非空验证**；代码与配置均已**逐字节还原**到工作态。
