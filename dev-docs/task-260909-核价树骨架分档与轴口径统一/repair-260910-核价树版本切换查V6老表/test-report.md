### 我自己踩的工具坑（与产品无关，但会伪装成产品缺陷）

1. `pkill -f <pattern>` **误伤监控自身** —— Monitor 的命令行里含同一 pattern，表现是「监控静默消失」，像「跑完了没通知」。⇒ 改用**精确 PID `kill`**
2. `Monitor` 的**多行 `command` 被压成一行** —— `done echo "…" grep …` 没有分隔符，**整个第三轮从未跑起来却不报错**。⇒ 一律用 `;` 显式分隔

## §6 量具/工具坑清单（共 10 个，全部「不报错的静默错值/静默 0 命中」）

| # | 坑 | 症状 |
|---|---|---|
| 1 | NULL 哨兵转义：TS 侧 `'\x00NULL'` 被转义成 NUL 字符，与 SQL 字面量不等 | 叶子永远判不出 null |
| 2 | `sqlRows` 读含换行的 `sql_template` | 按 `\n` 切行，**1 条配置读成 60 条** |
| 3 | `boolean::text` 返 `'true'` 不是 `'t'` | 正则判定恒 `false` |
| 4 | `test.describe.configure({mode:'serial'})` fail-fast | P3 一红就把毫无依赖的 P4 整片跳过，报告看着「只有一个问题」 |
| 5 | 版本控件只认 antd `.ant-select` | 编辑页 Step2 是原生 `<select>` ⇒ 读成「整表都没渲染」 |
| 6 | `enterCostingReviewPage` 漏切「核价单」分段 | **URL 对、卡片数对、树也渲染出来了**，只有列语义整个错位 |
| 7 | 行定位正则被单元格拼接击穿 | `▼3000013…` ⇒ 词边界断言命中 0 行 |
| 8 | 基线采集晚于配置改动 5.5 分钟 | before 侧被污染，得出「配置没改」的错误结论 |
| 9 | `pkill -f` 误伤监控自身 | 监控静默消失 |
| 10 | Monitor 多行脚本被压平 | 整轮测试从未启动却不报错 |

> 📌 **共同特征**：全部**不抛错**，只是安静地给出错值或 0 命中。
> 唯一救回来的机制是**每条断言前先跑阳性对照** —— AC-2 的阳性对照 `[]` 是让我没把 #5 读成产品缺陷的唯一线索。
> 📌 **可晋升的通用判据**：**在表格 DOM 上做文本匹配，永远不要假设单元格之间有分隔符。要么按列取 `td`，要么按下标定位；比对首列前先剥掉 `▼/▶` 等装饰符。**
