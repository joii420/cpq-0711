### 2.3 AC-19 导出→回导闭环（本任务的核心价值）

UI 筛「状态=启用」→ 列表共 **262** 条 → 点导出 → 文件 **629** 行（全量 263/630 减去唯一停用材质的 1 条/1 行，✅ 自洽）。

```

**顺带发现的已知限制** —— 629 行里有 **3 行回导不进去**：
```
行 99  AgCu     → 材质名对应多条材质记录，请先在材质管理页处理
行 148 AgNi     → 同上
行 484 SnO2 组2 → 元素组合与该材质的元素组成不一致

根因（查库确认）：库中有 **2 组同名材质** —— `AgCu`→`AgCu85`/`AgCu90`、`AgNi`→`AgNi90`/`AgNi95`（材质名同、编号不同、均 ACTIVE）。导出「材质」列写的是材质名，两条记录导出成同一个值，回导无法区分 ⇒ 跳过。第 3 行是既有的 `material_recipe_composition` 列错位脏数据。
⇒ **「导出→回导」闭环对同名材质不成立**。非本任务引入（同名材质是既有数据状态），且**不是静默失败**（报告逐行报明原因）。

## 3. 子代理自己揭穿的一个假绿（值得记进反模式）

组件层「非管理员看不到导出按钮」**曾经是绿的，但它是空验证**：
`renderToStaticMarkup` 走 SSR 路径，zustand 取不到 `setState` 写入的角色 ⇒ 那个角色判断对**任何角色**都返回 false。于是
- 「管理员应看到」**恒红**（会被追查）
- 「非管理员不该看到」**恒绿** —— 却不是因为判断正确，而是因为**谁都看不到**

⚠️ **恒红会被追查，恒绿不会。** 处置：整个「按角色显隐」维度移到 E2E，拿到有分辨力的证据（管理员 5 个按钮 / 非管理员 4 个）。
