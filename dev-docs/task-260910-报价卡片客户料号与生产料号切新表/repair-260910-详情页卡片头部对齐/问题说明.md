## ④ 问题原因

### 一句话根因

**详情页 `ReadonlyProductCard.tsx` 有一套与编辑页各自独立的头部实现**（只有 `header-left`、没有 `header-right`），
主任务只改了编辑页 `QuotationStep2.tsx` 那一套 ⇒ 这是 `docs/反模式.md` **AP-50「详情页/编辑页渲染层 single-source 反模式」的同型复发**。

### 证据链（可复跑）

`ReadonlyProductCard.tsx:534-565` 现状：

```tsx
<div className="qt-card-header">
  <div className="qt-card-header-left">          {/* ← 只有 left，没有 right */}
    <span className="qt-product-name">
      {lineItem.customerPartName || attrValues['产品名称'] || … }   {/* 客户名顶掉产品名 */}
    </span>
    <span className="qt-sku-badge">
      {lineItem.customerProductNo ? `客户产品编号: …` : `料号: …`}
    </span>
    {lineItem.productPartNo && lineItem.customerProductNo && (
      <span className="qt-sku-badge" style={{…蓝色…}}>料号: {lineItem.productPartNo}</span>
    )}                                            {/* ← 截图里那个「料号: S0001」*/}
    {lineItem.snapshot?.productCategory && <span className="qt-template-badge">…</span>}
  </div>
</div>                                            {/* ← 到此结束，没有 header-right */}
```

⇒ 三个徽标全在左块、产品名被客户料号名称顶掉、销售料号只是个静态 `<span>` 没有 `Popover`。

### 引入时间线

- **不是本次改动引入的** —— 详情页头部一直是这个结构（`ReadonlyProductCard.tsx:537` 的注释「与 QuotationStep2 编辑卡片对齐」写于更早的任务）
- 主任务 `a60de7d1` 让两边**差距变大**：编辑页改成左右分区 + 浮层，详情页原地不动
- **`hfPartInfo` 数据其实已经到位** —— 后端 `B-2` 换源对两个页面同时生效，详情页只是**没有渲染它**

### 影响面

纯渲染层。不影响数据、不影响编辑页、不影响导出。波及 `ReadonlyProductCard` 的两个使用场景：报价单详情页 + 核价单详情页。

### 🚩 为什么测试没拦住 —— 这才是真正要记的一条

**测试和亲验都按 AC 执行了，而 AC 本身就把详情页排除在外了。**

- 主任务 `AC-10` 我只写了「详情页头部显示客户料号名称与客户产品编号（后端换源自动生效），**布局与改动前一致**，不新增红框、不新增浮层」
- 测试片按此断言 → **绿**；主线亲验按此比对 → **通过**
- 实测详情页左块 `["示例客户料号", "客户产品编号: A002", "料号: S0001"]` —— 这个结果**完全符合我写的 AC**

⇒ **不是验证环节失效，是需求边界划错。** 用户原话说的是「**卡片**最左侧…最右侧…」，从未区分编辑页与详情页；
是主线在立项时自行把详情页收窄进「本期不做」，且**闸门 A 呈报时没把这个取舍单独点名**，只埋在文档的表格里。

📌 **本条应计入结案统计的「用户验收」拦截点** —— 它是被用户验收拦下的，不是被测试或亲验拦下的。

## ⑤ 修复方案

> A0 **无岔路**：期望结果是「对齐编辑页」，编辑页的实现已是既定基准，不存在第二种合理改法。
> 唯一的自由度是「详情页要不要浮层」，已由用户 2026-09-10 明确要求**要**。

**改动面：`cpq-frontend/src/pages/quotation/ReadonlyProductCard.tsx` 一个文件。后端零改动。**

1. `qt-card-header` 内拆出 `qt-card-header-right`，头部改左右分区
2. **左块**：`[客户料号名称] [客户产品编号: xxx]` + **保留产品分类徽标**（`E-6`）；两个客户料号元素都为空时左块零子元素（`E-5`）
3. **右块**：`[产品名] [销售料号: xxx]` —— 🚫 **无删除按钮**（`E-7`）
   - 产品名走**详情页原有的完整回退链**，但**去掉链首的 `customerPartName`**（它已移到左块，否则两边重复）（`E-9`）
4. 销售料号徽标包 `Popover`，`title="生产料号"`，五行取 `lineItem.hfPartInfo`，两种降级与编辑页同款（`E-3`/`E-4`）
5. 删掉原来那个「同时存在客户产品编号与生产料号时并列显示」的蓝色 `料号:` 徽标 —— 它的职能被右块的销售料号徽标接管
6. 🚫 **不复用编辑页的 `.qt-product-name--secondary`**：详情页产品名是主标题语义，样式沿用详情页现有的 `.qt-product-name`

**已否决备选**：
- ~~抽公共 `ProductCardHeader` 组件给两个页面共用~~ —— 方向正确（能根治 AP-50），但两边的产品名回退链、删除按钮、可编辑性都不同，抽象要带 3~4 个开关；属重构，**超出返修范围**，登记为后续改进

### 无副作用

**AC-R6 · 产品分类徽标未被删**
断言（两条）：① `ReadonlyProductCard.tsx` 中 `qt-template-badge` 的渲染分支**仍在**；② `quotation.css` 的 `.qt-template-badge` 规则**仍在**。
⚠️ **该徽标现网恒不显示**（实测全库 `quotation_line_item_snapshot.product_category` **0 行非空**；
📌 **注意别搞混**：单据级 `quotation.product_category_id` 是**另一个字段**，`QT-20260909-0794` 挂着「默认分类」指的是它，

**AC-R7 · 产品名回退链未退化**

> 🔴 **2026-09-10 判据修订（主线实查后）**：原文要求的严格样本（`customerPartName` 空 + `attrValues['产品名称']` 有值）
