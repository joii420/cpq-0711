# 文件加解密服务接口调用文档

## 1. 服务说明

统一加解密服务基于天锐加解密组件，为业务系统提供文件识别、解密和加密接口。

### 外部业务系统调用地址

其他服务器通过独立服务的 IP 和 9502 端口调用：

```text
http://172.16.18.45:9502
```

例如，识别接口为 `http://172.16.18.45:9502/v1/inspect`。服务源码和部署文件位于 `/home/hf/knowledge/lddf/file-crypto-service`，不依赖知识库系统，也不需要加入知识库 Docker 网络。

知识库和其他服务器统一使用独立服务地址；18.117 不接入该服务。令牌只保存在加解密服务的 `crypto.env` 和受控调用方配置中，不能写入前端、日志、浏览器请求或本文档。

业务系统的「系统设置 → 文件加解密接入」控制开关：

- 上传：识别为天锐加密文件后先解密，再保存明文当前版本。
- 在线预览：读取明文当前版本。
- 下载：从明文版本临时生成加密流后返回，原文件名保持不变。
- 历史迁移：只新增明文版本并切换当前版本，原加密版本保留，失败时不覆盖原版本。

## 2. 认证和通用请求头

除 `/healthz` 和 `/readyz` 外，接口都需要：

```http
Authorization: Bearer <CRYPTO_API_TOKEN>
Content-Type: application/octet-stream
X-File-Name: <encodeURIComponent后的文件名>
X-Request-Id: <调用方请求编号，可选>
```

`X-File-Name` 必须使用 URL 编码，中文文件名不要直接放入 HTTP 请求头。例如：

```js
headers: {
  Authorization: `Bearer ${process.env.CRYPTO_API_TOKEN}`,
  'Content-Type': 'application/octet-stream',
  'X-File-Name': encodeURIComponent(fileName),
  'X-Request-Id': requestId
}
```

请求体是原始文件二进制流，不是 JSON，也不要使用 base64 包装。服务默认单文件上限为 2 GiB，超限返回 `FILE_TOO_LARGE`。

## 3. 健康检查

### `GET /healthz`

仅检查 HTTP 服务进程是否存活，不需要令牌。

```bash
curl -fsS http://172.16.18.45:9502/healthz
```

成功响应：

```json
{"status":"ok"}
```

### `GET /readyz`

检查天锐组件和授权是否可用，不需要令牌。未就绪时返回 HTTP 503。

```bash
curl -i http://172.16.18.45:9502/readyz
```

## 4. 识别文件

### `POST /v1/inspect`

读取文件并返回识别结果，原始文件不会被修改。

```bash
curl -fsS -X POST http://172.16.18.45:9502/v1/inspect \
  -H "Authorization: Bearer ${CRYPTO_API_TOKEN}" \
  -H 'Content-Type: application/octet-stream' \
  -H 'X-File-Name: report.xlsx' \
  --data-binary @report.xlsx
```

响应会包含天锐组件返回的识别字段，并附加 `sizeBytes` 和 `fileName`。业务判断使用：

```json
{"encrypted":true,"sizeBytes":12345,"fileName":"report.xlsx"}
```

兼容旧组件时也可读取 `isEncrypted` 字段；`encrypted` 或 `isEncrypted` 为 `true` 即表示已加密。

## 5. 解密文件

### `POST /v1/decrypt`

请求体必须是天锐加密文件，成功返回解密后的原始文件二进制流。接口不会把文件落到业务系统的公共目录。

```bash
curl -fS -X POST http://172.16.18.45:9502/v1/decrypt \
  -H "Authorization: Bearer ${CRYPTO_API_TOKEN}" \
  -H 'Content-Type: application/octet-stream' \
  -H 'X-File-Name: report.xlsx' \
  --data-binary @report.xlsx \
  -o report.decrypted.xlsx
```

## 6. 加密文件

### `POST /v1/encrypt`

请求体必须是明文文件，成功返回天锐加密文件二进制流。

```bash
curl -fS -X POST http://172.16.18.45:9502/v1/encrypt \
  -H "Authorization: Bearer ${CRYPTO_API_TOKEN}" \
  -H 'Content-Type: application/octet-stream' \
  -H 'X-File-Name: report.xlsx' \
  --data-binary @report.xlsx \
  -o report.encrypted.xlsx
```

服务会返回 `Content-Disposition`、`Content-Length`、`X-Request-Id` 和 `X-Crypto-Operation` 响应头。

## 7. Node.js 调用示例

```js
import { createReadStream, createWriteStream } from 'node:fs';
import { pipeline } from 'node:stream/promises';
import { Readable } from 'node:stream';

// 所有业务系统使用独立 file-crypto 服务地址，默认端口为 9502。
const baseUrl = process.env.CRYPTO_SERVICE_URL ?? 'http://172.16.18.45:9502';
const token = process.env.CRYPTO_API_TOKEN;
const fileName = '罗格朗014整改报告.xlsx';

const response = await fetch(`${baseUrl}/v1/decrypt`, {
  method: 'POST',
  headers: {
    Authorization: `Bearer ${token}`,
    'Content-Type': 'application/octet-stream',
    'X-File-Name': encodeURIComponent(fileName)
  },
  body: Readable.toWeb(createReadStream('/data/input.xlsx')),
  duplex: 'half'
});
if (!response.ok || !response.body) throw new Error(await response.text());
await pipeline(Readable.fromWeb(response.body), createWriteStream('/data/output.xlsx'));
```

## 8. 错误处理

错误响应统一为 JSON：

```json
{"code":"FILE_NOT_ENCRYPTED","message":"文件不是天锐加密文件"}
```

常见错误码：

| HTTP | code | 处理建议 |
|---:|---|---|
| 400 | `EMPTY_FILE` | 检查上传内容是否为空 |
| 401 | `UNAUTHORIZED` | 检查令牌是否正确、是否带 `Bearer` |
| 413 | `FILE_TOO_LARGE` | 调整文件大小或服务限制 |
| 422 | `FILE_NOT_ENCRYPTED` | 解密接口收到明文文件 |
| 422 | `FILE_ALREADY_ENCRYPTED` | 加密接口收到已加密文件 |
| 422 | `CRYPTO_FAILED` | 检查文件格式和组件日志 |
| 503 | `CRYPTO_NOT_INITIALIZED` / `CRYPTO_NOT_AUTHORIZED` | 检查授权文件和组件初始化 |
| 503 | `CRYPTO_LICENSE_EXPIRED` / `CRYPTO_NO_ENCRYPT_LICENSE` | 更新对应授权 |
| 500 | `INTERNAL_ERROR` | 查看服务日志并按 `X-Request-Id` 排查 |

## 9. 运维命令

在加解密服务器的 `/home/hf/knowledge/lddf/file-crypto-service` 执行：

```bash
docker compose ps file-crypto
docker compose logs --tail=100 file-crypto
docker exec file-crypto /usr/local/lddf/lddf --mcode
```

业务开关通过系统设置修改，不要修改前端代码或把加解密逻辑写死在页面中。修改开关后新的上传、下载请求立即按最新设置执行。
