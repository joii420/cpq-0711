### [交互] BL-0215 · dataset 维护页改「项次」提示保存成功、实际未存

- [ ] 待开发 · 优先级 **P2** · 来源：`task-260907-移除料号核价功能` 亲验期（2026-09-07）

**现象**：主数据维护 →「基础核价」/「详细核价」抽屉里**只改「项次」列**（`item_seq`）→ 点保存 → 提示成功、无报错 → 重开抽屉，值回到改动前。

🚩 **这不是缺陷，是既定设计的 UX 缺口 —— 修法方向别搞反**：

`cpq-backend/src/main/java/com/cpq/dataset/fingerprint/RowFingerprints.java:17-18` 白纸黑字：

> `row_fingerprint = SHA-256( 各「对比项」列的规范化值 … )`
> **只有** `compared=true` 的列参与 —— **典型是「项次」建字段但不参与指纹，故改项次不升版（AC-17）**。

⇒ 是 `task-260902` 的 **AC-17 既定设计**。任何**单独**修改 `item_seq` 的保存都会返 `UNCHANGED`，**与方向无关**。

**主线三组实验（2026-09-07，端点 `PUT /api/cpq/dataset/{ds}/parts/{no}/sheets/{key}/rows`）**：

| 实验 | 结果 |
|---|---|
| 不改任何值原样回传 | `UNCHANGED` |
| 改 `item_seq`，**保留**旧 `row_fingerprint` | `UNCHANGED` |
| 改 `item_seq`，**删掉** `row_fingerprint` 字段 | `UNCHANGED` |

> ⚠️ 曾有一次「10→11 存下来了」，看似方向不对称 —— 全列比对后发现那次**同时**变了 `source: IMPORT → MANUAL`（首次手工编辑），是 `source` 驱动的升版，`item_seq` 只是搭便车。

🚫 **不要按「静默丢数据的 bug」立项修** —— 那会改掉 AC-17 的既定设计。
✅ **该做的是 UI 告知**：保存时若整组指纹未变，提示语不应是纯粹的成功态，应明确告诉用户「项次调整不参与版本比对，未产生新版本」，或在项次列旁标注该列不触发升版。

**顺带的踩坑提醒（写给后来做该页测试的人）**：抽屉里第一个 `input.ant-input-number-input` 就是「项次」列。拿它当「改值保存」的被改字段，会验不到写路径、还可能留脏数据（`task-260907` 实际发生过，已复原）。要验写路径请用**参与指纹**的列，如「组成用量」（`component_qty`）。
