# 规则分册 · 子代理

> **何时必读**：**闸门 A 呈报前**（要在那时报派工计划）；**收到「开工」时**；收到子代理回报时；子代理失联时。
>
> 🚨 **注意触发条件不是「你打算派子代理时」。** 那样写会形成死循环：不打算派 → 不读本册 → 读不到「默认必须派」→ 更不会打算派。
> 实测就栽在这：连续两个任务它读了其他 6 份分册、唯独没读本册，全程一个字没提子代理 —— 不是权衡后放弃，是这件事**压根没进入视野**。
> 所以本册的触发点绑的是**阶段**（闸门 A 前 / 收到「开工」），不是意图。
> **效力**：与 `CLAUDE.md` 同等，不是参考资料。冲突时以 `CLAUDE.md` 为准。

---

## 0. 一句话前提

**子代理是一个全新的、看不见你上下文的执行体。** 它不知道你和用户聊过什么、不知道 AC 是什么、不知道别的子代理在干嘛、不会主动重读改过的文件。
**本册的每一条，都是在补这个信息差。**

---

## 1. 步骤 2~4 的执行编排（进入开发阶段就生效）

**编排绑的是「进入了步骤 2（起步）」这个阶段，不是「用户说了开工」这句话。**

闸门 A 通过后用户说「开工」「开始吧」「可以了」是最常见的入口——**等同于下达以下全套指令，用户不需要每次重复交代**。

> 🚨 **闸门豁免不豁免编排。** 用户豁免闸门 A（§4.2 规则 3）豁免掉的是「停下来等我点头」，**不是**「改成单线程一个人干」。豁免之后照样从这里往下走。
> 这是实测踩到的坑：用户在路径确认里选了「A + 豁免 A0/A」，结果整套并行编排跟着一起没了 —— 而他要的只是别停下来问他。
>
> 🚨 **偏离编排分两种，处理方式完全不同 —— 不要混为一谈：**
>
> | | 处理 |
> |---|---|
> | **做不到**（客观不可能）<br>例：仓库不是 git 仓库 → 没有 worktree → 派工六段第一段「工作区坐标」填不出来 | 在汇报里**点名说明**，然后照常往下走。写一句「本任务未派子代理，因为无 git 仓库无法提供工作区坐标，全部改动由主线在主工作区完成」 |
> | **做得到，但你判断不该做** | 🚦 **必须回来问用户，不许自己批。** 呈报「建议怎么偏 + 任务特定的理由」，等一句话确认 |
>
> 🚫 **「报告了偏离」≠「获得了豁免」。** 声明只是让偏离可见，不是自我授权 —— 放行由用户给（`CLAUDE.md` §4.2 规则 1）。
> **静默跳过和做过了，在产物上长得一模一样** —— 而这两件事后续要采取的动作完全相反。

### ① 先提交任务文档，再建 worktree（顺序不能反）

```bash
git add dev-docs/task-YYMMDD-xxx/ docs/BACKLOG.md dev-docs/INDEX.md
git commit -- <上述路径>      # docs-only commit，遵守只提交指定路径的纪律
# 然后才 git worktree add
```

> 🚨 **为什么必须先提交**：`git worktree add` 是**从某个 commit 检出**的，主工作区里**未提交/未跟踪的文件不会带过去**。任务文档是在闸门 A 之前于主工作区写的，此时若没提交，**新建的 worktree 里根本没有 `dev-docs/task-xxx/`** —— 子代理进去按路径找 `fronttask.md` 会扑空，然后大概率不是停下来报错，而是**自己猜该实现什么**，整条 AC 追溯链当场作废。
>
> 顺带两个好处：立项对其他并发会话可见（避免撞车）；索引与 Backlog 的登记同时落地。
> 开工后对任务文档的更新（如 `test-report.md`）直接写在 worktree 内，随特性分支走。

### ② 并行派三类子代理（默认如此，不要串行，也不要一个代理包揽）

```
├─ 后端工程师 → 只按 backtask.md 逐项实现
├─ 前端工程师 → 只按 fronttask.md 逐项实现
└─ 测试工程师 → 按 test.md + AC 编写测试用例
```

#### 🚫 没有「我判断这次不必派」这种豁免

这是 `CLAUDE.md` §4.0 定的**分工铁律**，不是可优化的默认值：**主线只做统筹，实现交给子代理。**

**唯一豁免是「客观做不到」** —— 指物理上无法构造合规的派工 prompt，例：仓库不是 git 仓库 → 没有 worktree → 六段的第一段「工作区坐标」填不出来。
这类情况**照常在汇报里点名说明**，然后往下走。

以下**全部不构成理由**，写出来也不算数：

| 说辞 | 为什么不成立 |
|---|---|
| 「子代理有假绿风险」 | 这在**每个**任务上都成立 —— 永远成立的理由不构成某次例外 |
| 「串行更稳 / 没有并发压力」 | 同上，万能理由 |
| 「工作量小，编排开销超过收益」 | 工作量判断权在用户。真的小 → 那该走路径 B，不是走 A 却单线程干 |
| 「契约还没定型，并行会对不齐」 | 那说明 `api.md` 没写完，是闸门 A 的质量问题，不是不派的理由 |

🚦 **闸门 A 呈报文档时一并说明派工计划**（派哪几类 + 每类认领哪些 `F-x`/`B-x` 编号）。
这不是征求「能不能不派」，是让用户看清工作怎么分。

> 📌 **测试工程师那一路的唯一例外**：用户明确说了「不写测试」时它自然出局 —— 这是用户的范围裁决，不是你的判断。仍要在派工计划里写明。

### ③ 🔍 主线审核测试用例（用例一产出就审，不等开发完成，不可省）

逐条对照立项文档的 AC 核四项：

- a. 每条 AC 都有用例覆盖 —— 追溯矩阵无缺行
- b. 用例断言的是 AC 里的可观测断言，不是实现细节
- c. 三类覆盖齐全：单点 / 序列 / 边界
- d. 前置数据是真实业务数据，不是能让断言空跑的空夹具

❌ 任一项不合格 → 打回重写，不进入 ④

### ④ 前后端都完成后 → 测试进场执行，产出 `test-report.md`

失败项回流给对应工程师修，修完重跑，直到全绿。
⚠️ **回流时要带上原始 AC 原文**，不要只丢一句「T1.2 失败」—— 子代理是全新上下文，它不记得这个用例在验什么。

### ⑤ 转入「主线亲验」

⚠️ **测试全绿只是进入亲验的前提，不是亲验的结论。**

### 三个必须说清的边界

1. **`test.md` ≠ 测试用例代码。** `test.md`（方案 + 追溯矩阵）是**闸门 A 的前置产物**；测试用例**代码**才是开工后依据 `test.md` 和 AC 写的。两者都不读实现代码。
2. **「开工」不豁免闸门 B。** 它只是闸门 A 的放行信号，覆盖步骤 2~4。
3. **子代理报「已完成」一律不采信** —— 按 §3 逐项复验。

## 2. 派工 prompt 必含六段（缺一段就会踩一个已知的坑）

### a. 工作区坐标

> worktree 绝对路径 + 分支名。「**所有读写/构建/测试都在此路径内，不要 cd 出去，不要动主工作区的任何文件**」
> \+ 「**你不要执行 `git commit`，提交由主线统一做**」

**不写 → 子代理在主仓动手，提交打进 master、测的是旧代码**（§3 假绿第 2、3 类的成因）。

### b. 必读文档 + AC 原文

> 路径**一律给 worktree 内的绝对路径**，不许指向主工作区（两边可能不同版本）。
> 「先读 `<worktree>/…/需求文档.md` 的 `AC-x`、`AC-y` **原文**，再按 `F-1`/`B-2` 实现」——**子代理不会主动去读它**。
> \+ 冲突裁决：「任务分解是分解结果，**AC 原文才是验收标准**，两者有出入以 AC 原文为准并向主线报告」

### c. 可读范围

> 测试工程师**禁止读任何实现代码**（**点名禁止的目录**），只能读立项文档 / `test.md` / `api.md`；信息不足就停下来报告缺什么，不许翻实现补齐。

**上下文隔离 ≠ 访问隔离。** 不显式禁止，它自己就去把 `src/` 读了，读完又和实现同源，「测试独立于实现」这条就白设了。

### d. 越界纪律

> 只做自己那份任务，**不许改别人的产出**。
> 发现别人的代码/测试有 bug → **只报根因 + 修法，不动那个文件**，由主线裁决谁来修。
> 发现契约有问题 → **停下来报告，不许自行改契约**。
> 🚨 遇到 `CLAUDE.md` §3.2 红线操作（删表 / 清库 / `rm -rf` / `git reset --hard` / `git push -f` / 改已应用的迁移）→ **停下来报告，你没有批准权**。

### e. 回报格式

> 做了什么（逐项，每项注明服务的 AC）/ 证据（实际输出值、命令原始输出）/ 哪些没做到、哪些**未验证**
> \+ 「**过程中你规避掉的坑**」（差点做错但被你挡住的）

### f. 自检口径

> 共享 dev server 服务的是**主工作区代码**，看不到你在 worktree 里的改动 —— **拿它验证自己的改动 = 假绿**
> - **端口避让**：起服务一律用**临时端口**，**声明端口保留给主线亲验**，你不要占
> - **依赖**：按 `git-worktree.md` 的三分支判断该软链还是该装；装了要在回报里说明
> - **前端**：靠 `tsc` / lint + `grep` 确证文件内容；确需跑起来就用临时端口，用完即停
> - **后端**：同样不要 curl 主工作区端口；构建与测试必须在 worktree 内执行；worktree 里的 DB 迁移**不会**被主仓 dev server 跑
> - **测试**：所有测试命令都在 worktree 路径内执行，不要 cd 出去
>
> → **验证不了就在回报里明说「未验证」，不许写「应该没问题」。**

## 3. 交付验收纪律：四类假绿

子代理**会虚报完成**。派出后主线必须亲自复验：

| 假绿 | 表现 | 复验手段 |
|---|---|---|
| **虚报完成** | 报告"已实现/已通过"但代码或测试并不存在 | 亲跑测试、亲查 DB、亲跑 E2E |
| **提交跑错分支** | 在 worktree 开发，却 `cd` 主仓把提交打进 master | `git branch --contains <commit>` 逐个确认 |
| **测错代码树 / 测到陈旧产物** | ① 在主仓而非 worktree 跑测试，测的是未改动的旧代码；② 探到的是**别人或上一轮遗留的运行实例**；③ 构建产物目录里的**旧编译结果**还在，跑的是幽灵 | 主线在 **worktree 内**亲跑一遍：**先清产物再构建/测试**；探活要验明正身 |
| **断言从未执行** | 数据为空 → 循环 0 次 / 分支没走到 → 断言压根没跑，测试照样报绿 | 要求测试打印实际值；断言前先断言「结果非空」 |

⚠️ 子代理报「这是既有问题、非本次引入」时，也要自己在基线分支跑一次 **A/B 对照**确认 —— 两类误判（假阳性阻断、假阴性放行）代价对称。

## 4. 子代理失联 / 无回报时的处理

🚫 **绝不要把「没收到回报」等同于「它什么都没做」。**

真实失败模式：子代理中途断线或超时，**但它的写入已经落盘了**。此时若按「没回报 = 没做」直接重派一个新代理，就是在已有产物上叠加——轻则重复代码，重则两版实现互相覆盖，而且这种损坏**在编译和测试里都看不出来**。

按序做：

1. **先查工作树的实际变更** —— `git status` / `git diff` / 看文件时间戳，确认它到底动过哪些文件
2. **判断完成度** —— 动过的部分是否自洽（能编译、逻辑成篇）
3. **再决定**：
   - 一点没动 → 重派，prompt 不变
   - 动了但明显没做完 → **新代理的 prompt 里必须写明「已有 X 文件被改到什么程度，你在此基础上续做，不要重写」**，并附上实际 diff
   - 动完了只是没回报 → 直接按 §3 复验，不必重派
4. **无论哪种，都在闸门 B 汇报里注明「有子代理失联，已按 X 方式处理」** —— 不要隐去，这是后续排查的重要线索

## 5. 角色定义文件（`.claude/agents/*.md`）的维护

若项目用了自定义 agent，它们的定义文件与 `CLAUDE.md` **同时**进入子代理上下文。

- 🚫 **不要把 `CLAUDE.md` 或本册的规则复制进 agent 定义** —— 重复即漂移源
- agent 定义只放三样：**角色边界**（不做什么）、**角色特有的产出格式**、**指向规则分册的指针**
- ⚠️ **定期核对 agent 定义引用的路径是否还存在** —— 文档归档/改名后，agent 会继续指向空路径，而且**不报错**，只会自己猜
- 冲突时在 agent 定义里明写「以 `CLAUDE.md` 为准」

## 6. 本册自检清单（派工前 / 收工时）

派工前：
- [ ] **派工计划已在闸门 A 呈报过**（派哪几类 + 每类认领哪些 `F-x`/`B-x`）
- [ ] **本次没有主线自己写业务实现代码**（§4.0 分工铁律）；未派的话理由是「客观做不到」而非判断
- [ ] 六段齐全（工作区坐标 / 必读文档+AC原文 / 可读范围 / 越界纪律 / 回报格式 / 自检口径）
- [ ] 任务文档**已提交**，worktree 里确实能看到它
- [ ] 给的是 worktree 内的绝对路径，不是主工作区路径
- [ ] 测试代理被显式禁止读实现目录（点名了目录）

收工时：
- [ ] 四类假绿逐项复验过，不是采信回报
- [ ] `git branch --contains` 确认过提交没跑错分支
- [ ] 在 worktree 内**清产物后**亲跑过构建/测试
- [ ] 子代理若失联，已查实际变更而非直接重派
