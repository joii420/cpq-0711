# 规则分册 · 前端

> **何时必读**：改前端源码（`.tsx` / `.ts` / `.vue` / `.jsx` / `.css`）、动 UI 交互、修 UI Bug。
> **效力**：与 `CLAUDE.md` 同等，不是参考资料。冲突时以 `CLAUDE.md` 为准。
> **适用前提**：本册假定前端是**组件化 SPA**，示例语汇取自 React + Ant Design。技术栈不匹配时**整册替换**为等效约定 —— 但保留「规则 + 理由 + 例外白名单 + 自检项」这个骨架。只写规则不写例外，会被在不该用的地方硬套。

## 1. UI 交互规范

### 1.1 统一使用抽屉（Drawer）替代弹窗（Modal）

所有弹出式交互（新建/编辑表单、详情查看、多步骤向导、批量导入、确认配置）一律用抽屉从右侧滑出。

- **例外**：轻量即时反馈类组件（`message` / `notification` / 简单二次确认）不属于"弹窗功能"范畴
- **技术实现**：`placement="right"`，宽度按内容复杂度选 480 / 720 / 960 / 1200
- **理由**：抽屉与主页面上下文并存便于对照；更适合表单/多步流程；视觉层级统一、移动端体验更好
- **适用范围**：新增需求、旧页面重构、代码审查均须遵循

⚠️ **发现遗留 Modal 时怎么办，取决于你是谁**：
- **主线**在做本任务范围内的改动 → 顺手迁移可以，但要在汇报里列出
- **子代理** → 🚫 **不许顺手迁移**。那属于超范围（见 `subagents.md` 越界纪律），只报位置，由主线裁决

### 1.2 列表操作统一走「表格 + 顶部工具栏动作」模式

- **行内不放动作按钮**：变更 / 状态切换 / 危险动作（编辑、发布、归档、删除、停用…）一律上提到顶部工具栏，行内只保留"主入口"链接（点击进详情/编辑）
- **选择驱动启用**：每个动作声明 `enabledWhen(selectedRows): true | reason 字符串`，禁用时 hover tooltip 显示原因
  🚫 **禁止用 `if (...) return null` 隐藏不可用按钮** —— 用户看不到按钮就不知道这个能力存在，也不知道为什么用不了
- **统一多选**：单选场景用 `enabledWhen` 限定 `length === 1`，不要单独搞 radio
- **危险动作走弹层列出所选项二次确认**，不用零散的行内确认
- **批量操作的"部分失败"必须聚合**并列出失败明细，不能只报一句"部分失败"
- **何时不用**：纯查看页（详情/下载无副作用）、Master-Detail 双栏、树 + 编辑器、抽屉内部子表 —— **需维护「例外白名单」**

### 1.3 🎨 页面设计类改动：先出 HTML 原型图，定稿后 1:1 还原

**触发条件**（命中任一即必须出原型）：新页面 / 新抽屉或弹层 / 布局与信息架构改动 / 交互流程改动 / 表格列与工具栏动作的增删。
**不触发**：纯逻辑与取数改动、纯文案、单点样式微调（改个颜色/间距）、后端改动。判不准就出——**补一份原型的代价，远小于照着想象做完再返工**。

### 产物

`dev-docs/<任务目录>/原型图/`，**一个页面/一个关键状态一个 `.html`**，另加 `index.html` 做导航。

🚨 **覆盖面判据：本任务动到几个页面，就要有几份原型 —— 只出一份不算完成。**
逐个数：`fronttask.md` 里的 `F-x` 涉及哪几个页面/弹层？每一个都要有对应的 `.html`。
> 实测教训：任务动了列表页 / 编辑页 / 详情页三处，只出了 `列表页.html`，另外两页事实上没有视觉基准 ——
> 而「1:1 还原」对没有原型的页面**无从谈起**，开发只能凭想象做，这条规则对那两页等于没生效。

🚫 **必须是「所见即所得」的静态 HTML**，判据是四条硬指标：

1. **双击就能在浏览器打开**，不依赖构建、不依赖 dev server、不依赖网络（样式内联或同目录 CSS，图标用字符或内联 SVG）
2. **真实文案 + 真实示例数据** —— 🚫 禁止 lorem ipsum、禁止「标题标题标题」、禁止灰色占位块。数据取自 seed 或真实业务样例
3. **视觉语汇与项目组件库一致**（本项目是 AntD：间距、字号、圆角、主色、表格与按钮形态都要对齐）—— 否则 1:1 还原时会和组件库打架，开发只能二选一
4. **状态要画全**，因为**开发只会照着画出来的做**：
   | 必画的状态 | 不画的后果 |
   |---|---|
   | 默认态（有数据） | — |
   | **空数据** | 开发随手来个空白页或红色遮罩 |
   | **禁用态**（含 hover tooltip 文案） | 违反 §1.2「禁用但可见 + 说明原因」 |
   | **最长文案 / 极值数据** | 上线才发现撑破布局 |
   | 错误态 | 错误形状各页面各写一套 |

### 原型图自己也要守规矩

⚠️ **原型必须先符合 §1.1（抽屉替代弹窗）和 §1.2（工具栏动作 + `enabledWhen`）。**
画了一个行内操作按钮的原型，然后 1:1 还原 —— 那是把违规固化成了验收标准。原型评审时先过这两条。

### 🕰️ 每份原型必须标明自己是「当前基准」还是「历史快照」

**原型过期是必然的**（实现会继续演进），所以规则不该去追「让所有原型永远最新」——追不上，而且回改旧图等于篡改交付记录。

**真正的病根是身份不明**：同一个页面积累了 N 份原型，散在 N 个任务目录里，**长得都像基准，照哪份全凭手气**。下一个任务照着一份过期的抄，bug 原样回来。

所以每个 `原型图/` 的 `index.html` 顶部必须标身份：

| 标记 | 含义 | 配套 |
|---|---|---|
| 📌 **当前基准** | 本页面此刻的视觉标准，**照这几张做** | 全项目同一页面**只能有一份**带此标记 |
| 🕰️ **历史快照** | 交付当时是对的，之后实现演进了 | 附**逐项偏差清单**（哪个控件/哪个值变了、被哪个任务改的） |

**新任务出原型时**：把上一份的 📌 摘掉改成 🕰️ 并补偏差清单，新的这份挂 📌。**这是新任务的收尾动作之一，不是可选项。**

🚫 **不要回改历史快照的内容** —— 它是那次交付的验收记录，改了就再也说不清当时验收的是什么。
✅ **例外：原型本身就画错了**（交付当天就与需求不符，从来没对过）→ 那是**缺陷**不是漂移，就地修，并在 `RECORD.md` 记明。
> 判据：**它交付当天是对的吗？** 是 → 漂移，打快照标记；否 → 缺陷，修。

⚠️ **原型里的图标/资源尽量取自实现真正依赖的包**（如 `@ant-design/icons-svg` 的原始 SVG），不要手画近似物 —— 手画的东西在你机器上好看，在别人机器上可能是豆腐块，而且它**本来就不等于实现会渲染出来的那个**。

### 定稿与效力

- **原型图是闸门 A 的前置产物**（与 `test.md` 同级），🚫 **不新增闸门**：在闸门 A 随整套文档一并定稿
- 有**两种以上布局方案**时 → 走闸门 A0 呈报候选（各附一份原型），由用户裁决，**不要自己选一个画完了事**
- **AC 必须引用原型元素**（「按 `原型图/列表页.html` 的工具栏顺序」「空态文案与 `原型图/列表页-空态.html` 一致」），否则原型和验收标准是两张皮
- 🚨 **定稿后原型即验收基准，改原型 = 改验收标准** → 走 `task-docs.md §4`「开工后 AC/契约变更」四步：回用户确认 → 同步四处 → 通知在跑的子代理 → 重跑闸门 A 自检

### 还原纪律（前端开发照此执行）

- **视觉基准是原型图，不是你的审美，也不是「差不多就行」**：布局结构、控件类型与顺序、文案、空态与禁用态文案，逐项对齐
- 允许的偏差只有一类：**组件库能力所限的等价实现**（原型手写的下拉换成 `Select`）。偏差要在回报里列出来
- 🚫 **原型没画到的地方不许自由发挥** —— 停下来问，那是需求缺口
- 🚨 **原型与 AC 冲突时以 AC 为准，并立即报告** —— 两份验收标准打架本身就是缺陷

## 2. 前端改动强制自检

**背景**：类型检查（`tsc --noEmit`）**不覆盖**打包器的解析阶段错误（字符串嵌套引号、JSX 解析、syntax 报错）。因此每次改完必须**亲自跑一遍编译 / transform 验证**，再向用户报告"完成"。

### 2.1 必跑四步（cpq 实际命令，不是示例）

**前端改动**（含 `.tsx` `.ts` `.css` 修改）：
1. `cd cpq-frontend && npx tsc --noEmit -p tsconfig.json` → 必须 0 错误
2. **对每个改动的 `.tsx` 文件**跑 `curl -s -o /dev/null -w "%{http_code}\n" http://localhost:5174/src/<相对路径>` → 必须 HTTP 200
3. 如果是新加的列表页/Drawer/抽屉，再 `curl http://localhost:5174/` 看主入口 200
4. 如果用户描述的故障路径含具体页面，必须**真的把那个 url 透过 curl 拿到 200**才能宣布修复
5. **协议级改动必须跑 Playwright E2E**（不是可选）—— 改动以下任一文件时:
   - `useDriverExpansions.ts` / `usePathFormulaCache.ts` / `QuotationStep2.tsx` / `QuotationWizard.tsx` / `ReadonlyProductCard.tsx` / `BulkImportPartsDrawer.tsx` / `component/types.ts` / `component/FieldConfigTable.tsx`
   - 后端 `ComponentDriverService.java` / `FormulaCalculationService.java` / `ComponentService.java` / **`TemplateService.java#refreshSnapshotsByComponent`**
   - 模板 snapshot 数据迁移（Flyway V*）
   - 详细规范见 `docs/E2E测试方法.md`
   - 执行命令:
     ```powershell
     cd cpq-frontend
     Remove-Item e2e\screenshots\qf-*.png -ErrorAction SilentlyContinue
     npx playwright test --config=e2e/playwright.config.ts e2e/quotation-flow.spec.ts --reporter=list
     ```
   - **必须看到** 所有 test `passed` (当前 `quotation-flow.spec.ts` 含 1 个 test, 后续可能加), `'加载中' final count = 0`, 全部 8 Tab `'加载中'=0`
   - PR 必须附 qf-19 (确认添加后) + qf-21~28 (8 Tab) 9 张截图作为渲染证据
   - 跳过 E2E 等于跳过自检 — AP-37 / AP-38 / AP-40~43 类协议 bug 只在 E2E 暴露, API/TS check 看不到

5.5 **driver expansion 行数纪律**（AP-51，2026-05-22）：
   - 触发场景：改动 `snapshotRows` / `computeTabSubtotal` / 任何涉及 `expansion.rowCount` 的行迭代逻辑
   - **禁止**：`Math.max(expansion.rowCount, baseRows.length)` — driver 权威优先，baseRows 仅在 rowCount=0 时使用
   - **正确**：`const rowCount = expansion?.rowCount > 0 ? expansion.rowCount : baseRows.length`
   - 原因：baseRows.length 是历史持久化值，可能含脏数据（前一次错误写入的 28 行）；driver expansion 才是当前正确行数的唯一来源
   - 自检：E2E 刷新 3 次后行数稳定 = 未累加 ✅

6. **字段类型变动 / 新增** 是**特殊场景**（AP-44 核心规范，2026-05-19 立项, 2026-05-20 扩到 17 处）：
   - 触发: 在「组件管理」改 `field_type`（如 INPUT_NUMBER → LIST_FORMULA）/ 加新枚举 / 给现有类型加 sub-type / 加新 config JSON 键 / 改 `VALID_FIELD_TYPES`
   - **双轨场景** (2026-05-20 新增): 同模板双轨字段 (`basic_data_path` + `basic_data_path_composite` / `data_driver_path` + `data_driver_path_composite`) — 详见 `docs/archive/同模板双轨支持组合产品.md`（已废弃归档，仅历史追溯）
   - 影响: **17 个协议检查点跨约 13 个独立文件** — 前端 enrich / normalizeFieldType / cache key / 渲染分支 / computeAllFormulas 字段值循环 / 所有 ProductCard callsite prop / 详情页 ReadonlyProductCard 同步 + 后端 校验 / 路径采集 / 公式 token / refreshSnapshotsByComponent + (新增) useDriverExpansions tasks 切换 + QuotationStep2 渲染层 isCompositeItem 参数
   - 漏一处必有静默失败（不报编译错也没运行时错，只是 UI 渲染不对）
   - **强制 SOP**:
     - 写代码前 grep 全工程列清单（详见 `dev-docs/rule-260724-组件模板配置/5-公式与Excel列.md §5.2 字段类型联动协议（AP-44 核心规范）`）
     - 写代码中对照 15 项 checklist 勾掉每格
     - 写完**跑 E2E + 复测报价单 + 核价单 + 详情页三个视图** + admin 端点验证 snapshot 各 Tab fields_override 独立保留
   - **PR 必含**:
     - 矩阵 17 处 grep 命中输出
     - E2E `1 passed` + `'加载中' final count = 0` — **双轨场景必须跑两个 spec** (`quotation-flow.spec.ts` SIMPLE + `composite-product-flow.spec.ts` COMPOSITE)
     - 报价单视图 + 核价单视图 + 详情页三处的关键 Tab 截图（修复前 vs 后）
     - `POST /api/cpq/components/{id}/refresh-template-snapshots` 跑过后所有 Tab snapshot.fields 列表打印

### 2.2 ⚠️ 在 worktree 里改动时，上面第 2 步是陷阱

**共享 dev server 服务的是主工作区代码，看不到你在 worktree 里的改动。拿它"验证" = 假绿。**
worktree 内的自检手段与降级顺序见 `git-worktree.md`。

## 3. 出现"500 / 红色报错遮罩"反馈时

1. **不要立刻假设"是浏览器缓存"** —— 先 `curl` 拉一次原始响应，看错误是不是已经修了
2. 文件确实是好的而遮罩仍在 → 让用户**强刷（Ctrl+Shift+R）** 清 HMR overlay
3. 文件本身有问题 → 立即修，再跑完整自检后通报

## 4. 渲染主链路：改之前先查历史契约

**列表 / 编辑 / 详情共用的取数、缓存、展开逻辑**属于渲染主链路，是「改一处、多处静默失效」的高发区。

改这类文件前：
1. 查 `dev-docs/INDEX.md` 的「按代码文件反查」表 —— **这个文件压着什么历史契约**
2. 跑影响面分析（`codegraph_impact` 或等效工具），不要靠 grep 估
3. 按 `change-protocol.md` 走强联动 SOP

> 项目里具体哪些文件属于「渲染主链路」，随经验登记进 `INDEX.md` 的「按代码文件反查」表。**这份名单是长出来的，不是一开始就写死的。**
