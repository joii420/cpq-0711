## 怎么写一条

**条目标题行** = `<两个井号><空格>` + `DEC-` + 四位编号 + ` · ` + 一句话标题。
标题行之下是**七个字段**（`验法:` 是 `前提:` 的紧随子行，前导两个空格）：

```
<两个井号><空格>DEC-0019 · AC-22 不造夹具

- 对象: costing_template
- 作用域: task-260908 取数配置器优化
- 结论: AC-22 全库无样本，本期不造夹具，该 AC 降级为代码层论证
- 前提: [有效] 核价卡片需要独立的 COSTING 模板实体
  验法: test "$(psql -tAc 'SELECT count(*) FROM costing_template')" != "0"
- 前提: [有效] 造夹具成本为「绑模板 + 建单 + 物化」三步
  验法: 无 —— 由上一条前提推导，随其一同成立或倒塌
- 取代: 无
- 出处: dev-docs/task-260908-取数配置器优化/ · D-19 · RECORD 2026-09-08
```

| 字段 | 规则 |
|---|---|
| `- 对象:` | 🚨 **必须是符号原名**：函数名 / 表名 / 列名 / 文件路径 / 接口路径 / 脚本名。🚫 禁止自然语言描述（`f_customer_element_price` ✅ ／ `核价元素取价函数` ❌）。<br>⚠️ **已知漏报边界**：同对象检查靠**字符串相等**分组，名字不一致就**静默漏报**——限定符号原名只是缓解，不是根治 |
| `- 作用域:` | 一个。不适用写 `全局` |
| `- 结论:` | 一句话 |
| `- 前提:` | 可多行，每行以 `[有效]` 或 `[已证伪]` 开头。写「这条结论**建立在什么之上**」，不是写「为什么这么定」。**任一前提被标 `[已证伪]`，该裁决即判失效** |
| `  验法:` | 二选一，🚫 不许留空：① 一条**只读**命令，退出码 `0` = 前提仍成立；② 逐字以 `无` 开头 + 说明为何不可验。<br>🔑 写得出验法的才是**前提**；写不出的是**理由**或**业务裁决** —— 后者合法，但必须显式标 `无` |
| `- 取代:` | `无`，或本条所取代的 `DEC-NNNN` |
| `- 出处:` | 任务目录路径 · 原编号 · `RECORD` 日期 —— **指得回原文**，这是台账相对流水账的全部价值 |

🚦 **什么样的裁决要登记**：**跨任务仍然有效的才登；只在本任务内成立的不登。**
详细判据、正反例与归档规则见 `docs/rules/task-docs.md` 的「决策台账登记规范」一节。

🗄️ **失效条目要有出口**：结案时把条目**全文**移入 `docs/archive/决策台账-归档.md`，
并在下面的「已归档」段留一行 `~~DEC-NNNN~~` 指针。🚫 **漏写指针会让脚本报 `取代指向未知`（追溯链断了）。**

## DEC-0002 · Bash 工具里的 `grep` 实际是 ugrep，会静默跳过中文文件

- 对象: grep
- 作用域: 全局
- 结论: Claude Code 的 Bash 工具把 `grep` 注入为 **shell 函数**（不是别名、不是 `/usr/bin/grep`），实际执行 `ugrep … -I`；含大量中文的源文件与文档会被 `-I` **静默判为二进制返空**。检索项目文件一律用 `/usr/bin/grep -a`。🚨 空结果 ≠ 不存在
- 前提: [有效] `/usr/bin/grep` 存在且是 GNU grep —— 「改用 `/usr/bin/grep -a`」这条出路才成立
  验法: /usr/bin/grep --version 2>/dev/null | /usr/bin/grep -qa 'GNU grep'
- 前提: [有效] Claude Code 的 Bash 工具把 `grep` 注入为调用 ugrep 的 shell 函数
  验法: 无 —— 该注入只活在 Bash 工具的**交互 shell** 里；本判定器用 `bash -c` 起子进程，天然看不到它。2026-09-12 实测：写成 `declare -f grep | grep -q ugrep` 会**恒报「前提可疑」**，那是验法的假阳性，不是前提塌了
- 取代: 无
- 出处: CLAUDE.md §5 · MEMORY `cpq-grep-ugrep-binary-pitfall` · 2026-09-12 实测**更正措辞**（原记「别名」，实为 Claude Code 注入的函数）

## DEC-0006 · 建 worktree 必须基于 HEAD，不能用默认 fresh

- 对象: origin/master
- 作用域: 全局

- 前提: [有效] `origin/master..master` 的提交数 > 0
  验法: test "$(git rev-list --count origin/master..master 2>/dev/null || echo 0)" -gt 0
- 取代: 无
